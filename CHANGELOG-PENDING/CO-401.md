## CO-401 — Staging fixtures + CO_STAGING_ADMIN_TOKEN — unlock the deep staging suite (3949 skips → coverage)

Seeds the data and credential the deep staging suite (CO-374) preconditions on,
so the Thursday release gate exercises real scenarios instead of skipping.

- **Synthetic funnel/lead fixtures** — boot-time staging seeder
  (`seed_staging_funnel_fixtures`, `CO_ENV=staging` only) inserts a deterministic
  set of leads across the qualify pipeline (`new` → `triaged` → `in_progress` →
  `closed_won`/`closed_lost`). New `leads.synthetic` flag (migration v81) marks
  them so the acquisition-funnel rollup (`query_funnel_steps`) excludes them from
  the capture/qualify counts an operator reads. Idempotent; real leads are never
  deleted.
- **Scoped admin token** — when the `CO_STAGING_ADMIN_TOKEN` secret is present,
  the staging seeder installs its SHA-256 hash as an `api_tokens` row owned by a
  dedicated `staging-admin` user (tier `admin`). Only the hash is stored. The
  same value is a GitHub Actions secret, so `staging-suite.yml` passes it to the
  Playwright suite as `Authorization: Bearer …` and the authed tests run instead
  of skipping. Rotation documented in `docs/cross-env-auth.md`.
- **Production safety** — all staging fixtures stay behind the
  `WebConfig::is_staging()` gate; a regression test
  (`seed_staging_fixtures_never_runs_in_prod`) asserts nothing seeds for
  `prod`/`production`/`uat`/`dev`/`test`, and the companion test proves they do
  seed under `staging`.

The recursion-a → recursion-ab → recursion-abc universe chain (CO-379) is reused
as-is; this task adds the funnel/lead data, the token, and the analytics gate on
top of it.

### Why
The staging suite was skipping ~3949 tests because the fixtures and an admin
credential it preconditions on did not exist. Seeding them at boot (env-gated)
plus wiring the scoped token through CI turns those skips into real coverage
without leaking any fixture data into production analytics or the prod database.
