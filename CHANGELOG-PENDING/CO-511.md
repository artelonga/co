## CO-511 — CO self-host kit (local-network deployment)

CO is now self-hostable on a LAN/M4 with the same operational pattern proven on
quilomboaraucaria — no Fly required (CO-497 invariant: identical code).

- `scripts/selfhost/run.sh` — build + boot co-web for network self-host (binds
  `0.0.0.0` via `CO_WEB_HOST`; `--localhost` for loopback-only). Fails closed if
  `JWT_SECRET` is unset or the insecure dev fallback.
- `scripts/selfhost/com.artelonga.co.plist` — launchd autostart + keepalive.
- `scripts/selfhost/cloudflared-config.example.yml` — CGNAT-proof public reach (+ a
  Caddy reverse-proxy alternative for operators with a public IP).
- `scripts/selfhost/litestream.yml` + `verify-restore.sh` — off-box backup of
  `meta.db` (+ documented companion snapshot for the dynamic per-universe `data.db`).
- `docs/SELF-HOST.md` — full runbook; `docs/LOCAL-DEV.md` — local testing quick start.

### Why
Self-host must be a first-class path, not a Fly afterthought. This is the operational
wrapper around the already-self-host-ready engine (SQLite, CO-446, CO-439 allowlist,
CO-497 cascade). Thin-binary distribution (CO-484/485/486) is the remaining gap so a
node needs no Rust toolchain — tracked in CO-513.
