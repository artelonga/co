## CO-489 — WhatsApp tenant routing + local end-to-end verification

One bot deploy serves many customers: the inbound WhatsApp business number
(`phone_number_id`) selects the tenant universe, so onboarding a customer is a
config edit, not a code change.

- The inbound `phone_number_id` is parsed from the Cloud API webhook metadata and
  forwarded to the bot brain (`whatsapp_cloud_routes.rs` → `CO_BOT_BRAIN_URL`),
  which maps it to a universe + that universe's `bot/profile`.
- **`scripts/whatsapp-webhook-smoke.sh`** — a Meta→co-web→brain integration test
  that runs locally with no Meta: posts an HMAC-signed Cloud payload and asserts
  the fast 200, `phone_number_id` forwarding, forged-signature 401, and the GET
  verification handshake. Sample payloads use fictional numbers only.
- **`docs/whatsapp-launch.md`** — launch runbook: the end-to-end path, the
  cheapest→live test ladder, the secret/env matrix, zero-code per-customer
  onboarding, and the pre-live gaps (durable bot `CO_TOKEN` identity, cross-tenant
  authorization, and gating the keyless-degrade reply).

### Why
A single multi-tenant deploy keeps per-customer cost at zero marginal code, and
the signed-webhook smoke makes the otherwise Meta-dependent inbound path provable
on every change without a live WhatsApp round-trip.
