## CO-308 — `--staging` implies UAT-login enabled (admin login locally)

`co serve --staging` now allows the UAT-login flow (and seeds `yuri@uat.local`) without needing to also set `CO_ENV=uat`. Previously the admin login tab was hidden and `POST /api/v1/auth/uat-login` returned 404, even though the whole point of `--staging` is local prod-equivalent testing.

### Why
Surfaced this afternoon trying to demo `co serve --staging`: clicking "admin login" with `yuri@uat.local`/`uat` did nothing because `allows_uat_login()` was strictly `co_env in {uat, test}`. `--staging` is an explicit opt-in to prod-equivalent local behavior, so it should also enable the local-testing credentials path.

### Effect

`allows_uat_login()` now returns true when **any** of:
- `CO_ENV=uat` (deployed UAT)
- `CO_ENV=test` (Playwright global-setup)
- `self.staging` (new — `co serve --staging`)

That single check gates three places: uat-login endpoint, admin login tab in SPA, and the `yuri@uat.local` user seed at boot.

Production behavior unchanged: prod sets `CO_ENV=prod` and never enables `--staging`.
