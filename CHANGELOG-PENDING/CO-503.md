## CO-503 — Canonical tool contract + external-tool adapter (the composability spine)

Tools are now composable: any open-source software — a CLI/script or an HTTP
service — becomes a tool via a manifest entry, with **zero binary recompile**.
This is the foundation the agent runtime (CO-504) and every tool extraction
(CO-521/522) plug into. NOT MCP — CO's own adapter.

- **`CanonicalTool`** (additive — the legacy `Tool` trait is untouched):
  `name · description · input_schema(JSON) · tool_type(deterministic|predictive) ·
  run(args: Json) -> Json` — the LLM-callable shape, matching the bot's CoTools and
  `tools/schema.yaml`. Plus a `CanonicalToolRegistry` (register/get/list).
- **External-tool adapter** behind an injectable `ExternalInvoker`:
  `SubprocessInvoker` (core, std-only — `env_clear()` + per-manifest secrets
  allowlist, JSON over stdio, non-zero exit → error) and an `HttpInvoker` (reqwest,
  wired in co-web). An `ExternalTool` validates `input_schema` then delegates — so a
  new OSS tool is a manifest YAML, not a code change.
- **Manifest discovery** from a **trusted location only** (`CO_TOOLS_DIR`, default
  `tools.d/`) — never from universe/observed content — and **opt-in, default OFF**
  (`CO_ENABLE_EXTERNAL_TOOLS`); a default deploy executes nothing external.
  `tools.d/` ships `echo.example.yaml` + `yt-summarizer.example.yaml` + a README.
- **Legacy bridge** (`LegacyToolAdapter`): wraps a legacy `dyn Tool` as a
  `CanonicalTool` so the existing tools are callable through the canonical registry.

### Why
Composability without a binary rewrite is the whole point: add the RAG framework,
an R kernel, or any OSS as an optional add-on by dropping a manifest. Security is
designed in (trusted-manifest-only, opt-in, no ambient secrets, validated args,
timed HTTP) — verified by the CO-503 trust-boundary review.

### Remaining (follow-ups)
- Wire the 3 concrete legacy tools into a canonical registry in production (the
  bridge mechanism is built + tested; the production wiring is pending).
- Build the registry into a runtime path — done when CO-504 (agent runtime) consumes it.
- Stateful session/kernel tool kind (R/REPL) → CO-524.
