## CO-538 — Fly → M4 prod-cutover tooling + runbook

Tooling and a 7-step runbook to make the Mac M4 the sole self-hosted prod (reached
via Cloudflare Tunnel) and retire the managed Fly app.

- **`scripts/migrate-fly-to-m4.sh`** — one-time data migration. Dry-run by default
  (prints the exact plan, touches nothing); `--apply` tars `/data` (meta.db +
  per-universe DBs) on the Fly app over `flyctl ssh`, downloads it, backs up any
  existing local target and asks for confirmation, restores into `~/.co/data`, then
  proves it with `smoke-selfhost.sh` + `selfhost/verify-restore.sh`. The remote side
  is read-only toward the live DB.
- **Runbook** `work/co/CO-538.md`: merge de-embed → build+boot M4 loopback →
  Cloudflare tunnel on a TEST host → migrate data → harden (firewall/secrets/Ollama/
  backups/anti-sleep) → cut DNS → soak → retire Fly. Includes the single-box
  availability profile (`pmset disablesleep`/`autorestart`, UPS, launchd KeepAlive).
- Cloud failover/standby for the single box is captured as deferred follow-up
  (CO-539); the near-term profile is anti-sleep + UPS + verified off-box backups.
- `docs/SELF-HOST.md` now references `smoke-selfhost.sh`, `disk-gate-selfhost.sh`,
  and `migrate-fly-to-m4.sh` (and that smoke-selfhost replaces smoke-prod for the M4).
