## CO-61 — Sync Protocol v1 — op log + content-addressed blobs + 3-way merge + recursive resolution

Formalized the v1 sync protocol that all CO clients (quilombo-blog interim,
co-web, co-cli, Obsidian plugin, future Tauri desktop and federated peers) sync
against. The op log is the canonical model; state is a pure derivation of it.
This is the layer underneath the existing file-based sync track — file sync
becomes a projection of the op log, not a replacement for it.

### Added

- **Spec.** `docs/sync-protocol-v1.md` — canonical protocol document covering op
  log shape, Hybrid Logical Clock semantics, content-addressed blob store, the
  three-way merge algorithm, recursive conflict resolution (with a termination
  proof), idempotency/atomicity guarantees, transport, auth, and the GitHub
  pull-request analogy. Dedicated sections explain the prod-wins policy and
  `copia` semantics.
- **JSON Schemas.** `docs/sync-protocol-v1/schemas/` — Draft 2020-12 schemas for
  every wire type: `Operacao`, `Hlc`, `Ator`, `Alvo`, `Manifesto`, `Proposta`,
  `RelatorioMesclagem`, `Conflito` (with `$ref` composition).
- **Test vectors.** `docs/sync-protocol-v1/fixtures/` — 10 fixtures
  (`01-clean-add` … `10-reversibility`) each pairing an input
  `(base_hlc, ops_prod, ops_uat)` with the expected `RelatorioMesclagem`. All 22
  ops across the fixtures validate against the schemas.
- **Rust skeleton.** `core/src/sync/mod.rs` — `Hlc` (total order + text
  serde), `Ator`, `Alvo`, `Operacao`, `Manifesto`, `Proposta`, `Conflito`,
  `RelatorioMesclagem`, the `SyncProtocol` trait, the `mesclar` / `mesclar_com_blobs`
  three-way merge reducer, a transitive `causal_ancestor` walk, and a
  deterministic conflict-id hash.
- **Fixture tests.** `core/tests/sync_fixtures.rs` — fixture loader +
  parameterized test (one per vector) comparing the reducer output against the
  expected report.

### Why

UAT↔prod sync (quilombo-blog today, co-web next) is the immediate driver, and
Automerge rich-text (CO-66) plus git-backed canonical state (CO-68) must compose
on top of this without rework. Pinning the op-log shape, HLC rules, merge
function, and recursive resolution now lets CO-62 (quilombo-blog adapter) ship a
v0 subset against a fixed contract, and keeps file-based clients (CO-51/54/58)
working as a projection rather than a fork.
