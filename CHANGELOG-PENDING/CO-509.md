## CO-509 — De-embed the tenant backend; co is the generalist software

The open `co` repo no longer ships any tenant-specific backend. CO is the
**generalist** platform: a tenant's real application lives in its own standalone
repo, and its content is served generically through the universe/content APIs —
never as bespoke Rust baked into this binary. This restores the
template = software invariant.

### What was removed

- The entire `co-web/src/universes/<tenant>/` module (routes, storage, models,
  permissions, telemetry, processos) and its `lib.rs` re-exports.
- The tenant API mount (`/api/v1/<tenant>`), its bespoke telemetry / CSRF /
  canonical-host middleware, and the `/api/v1/processos` mount in `server/router.rs`.
- The cross-account bridge layer (the tenant `storage/*_bridge.rs` and the
  `find_*` / `ensure_*` / `mirror_*` / `link_*` lookups in `storage/auth.rs`),
  plus every caller in the auth, recovery, OAuth/OIDC and onboarding handlers.
  The password-recovery flow is now a clean, generic CO flow with no bridge calls.
- Tenant seeding (`seed_*_universe`, content import, public stats endpoint +
  model), the boot-time backfill/integrity passes, the one-shot migration
  binaries, and the hardcoded tenant entry in the deployment-snapshot registry.
- The hardcoded tenant config (`*_legacy_login`, vault-dir fields), the
  hardcoded tenant theme preset, and the tenant-specific notification templates.

### Made generalist (not removed)

- Notification templates are now fully env-driven (`CO_TPL_<EVENT>_<SLOT>`) with
  no tenant-specific defaults compiled into the binary.
- The webhook event-matching engine, JWT `usuario`/`papel` claims, and the
  universe member-metadata API are kept but documented as tenant-agnostic.
- The canonical-host / `return_to` safelist no longer special-cases any tenant
  domain; only `*.artelonga.com.br` (and localhost) are allowed.

### Migrations

The chain stays valid and self-contained. The historical migration that created
the tenant tables is now a no-op-on-fresh that only **reserves** its version
numbers, and later `ALTER`s of those tables are guarded by a new `table_exists`
helper so they apply only on legacy databases and never panic on a fresh one.
`fresh_db_reaches_latest_version` passes.

### Why

Tenant code in the generalist binary couples every release to one customer and
contradicts the template = software invariant. With it gone, `co` compiles and
`cargo test --workspace` is green with zero tenant backend code; onboarding a
new content surface needs no deploy of this repo.
