## CO-510 — Scrub tenant references from module map and published docs

Follow-up to CO-509: the published documentation no longer presents any tenant
as embedded CO functionality. Private repos are data, not docs.

- `co-web/src/MODULES.md` — dropped the tenant row from the universes table and
  the tenant re-export note; added a one-line statement that CO is the generalist
  software and tenant backends do not ship in this repo.
- `docs/UNIVERSES.md` — removed the tenant system-universe row, the deprecated
  tenant-variant deletion rows, and the references to the removed seed/cleanup
  functions.
- `docs/webhooks.md` — the worked examples now use a neutral `app.*` event
  namespace instead of a tenant-named one (matching the code).
- `docs/universe-public-site.md` — removed the tenant rows/examples; the
  standalone-app point now stands on the remaining generic example.

### Why

Keeping a single customer's name threaded through the platform's module map and
user-facing docs re-creates the coupling CO-509 removed. The generalist software
documents generic capabilities; tenant specifics live in the tenant's own repo.
