## CO-492 — LGPD data-rights endpoints (WhatsApp companion)

Add three caller-scoped LGPD (Art. 18) data-rights endpoints for the WhatsApp
companion, all bound to the authenticated caller (`Scoped<EntriesRead>` /
`Scoped<EntriesWrite>`, mirroring the CO-499 lead-digest fix) so a user can only
ever touch their own data:

- `GET  /api/v1/whatsapp/me/export` — Art. 18 V (portabilidade): the caller's
  curated content (entries in the universes they own, where the bot writes on
  their behalf) plus their consent record and profile, as a portable JSON bundle
  that also carries a markdown rendering.
- `POST /api/v1/whatsapp/me/erase`  — Art. 18 VI (eliminação): erase the caller's
  curated content. Requires the explicit confirmation phrase `"apagar tudo"` in
  the body (mirrors `commands.erase_confirm` in the consent YAML) — there is no
  single-call destructive erase.
- `POST /api/v1/whatsapp/me/forget` — Art. 18 + revogação do consentimento: erase
  curated content, clear the WhatsApp link (`users.whatsapp*`) and the consent
  record, and return `clear_local_identity: true` so the bot also wipes its local
  identity store. Requires the confirmation phrase `"esquece de mim"`. Idempotent.

### Why
Closes the LGPD data-subject rights loop for the bot: portabilidade, eliminação,
and consent revocation, with the sacred destructive-ops boundary held — erase and
forget are never automatic and never one-step, and the bot only ever writes/erases
the user's own data on explicit request.

### Notes
- No new migration: "curated content" is defined as every entry in the universes
  the caller owns (`Storage::list_owned_universes`), removed via
  `SqliteEntryRepository::unindex_entry` (entries row + all projections). Forget
  NULLs the existing `users.whatsapp*` / `whatsapp_consent_*` columns via a new
  `Storage::clear_whatsapp_identity` helper.
