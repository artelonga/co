## CO-516 — co-auto must ALWAYS isolate (P0 safety net)

co-auto now isolates **every** task in a per-task git worktree and refuses to
start on top of a dirty tree or a feature branch — closing the collision where a
`--headless` run intermingled with a concurrent Workflow in one live checkout
(2026-06-28; see `feedback_coauto_workflow_tree_collision`).

- **Unconditional isolation.** The worktree gate in `dev/co-auto/src/auto.rs` was
  `config.cycle || config.teams`, so a single/`--headless` run checked out the
  task branch IN-PLACE on the CWD checkout. It is now `use_worktree = true`
  always — there is no in-place execution path; isolation is unconditional even
  for one task in headless mode.
- **Preflight guard.** Before any branch/worktree is created, co-auto inspects the
  target repo and refuses to run (clear, actionable error, exit 1) unless it is on
  a clean `main`. A dirty working tree, a feature branch, or a `main` tracking the
  wrong remote each abort the run. `--dry-run` is exempt (never mutates the tree).
- **Unit-testable decision.** The branch/dirty/upstream rule is a pure function
  `preflight_decision(&RepoState)` with no I/O; the git-shelling `gather_repo_state`
  wraps it. Six unit tests cover clean-main (with/without upstream), dirty,
  feature branch, dirty+feature precedence, and wrong-remote.

### Why
Two writers on one tree silently merge unrelated workstreams into a single
uncommitted branch. Guaranteeing an isolated worktree plus a pristine-`main`
preflight makes that class of collision impossible by construction, not by
operator discipline.
