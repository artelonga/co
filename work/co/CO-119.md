## As

a CO operator

## I Need

a `tools/restore-drill.sh` that picks a random recent snapshot, restores it into a scratch Fly app, runs a smoke check against the restored data, records a pass/fail row, and tears the scratch app down — runnable on demand and quarterly via a scheduled agent

## To

prove that the backup story (CO-104) is **actually recoverable**, not just that snapshots exist; surface restore-time regressions early; satisfy the §C.5 missing-piece flagged in the platform roadmap review

## Given / When / Then

GIVEN backups land daily in `s3://artelonga-co-backups/` per CO-104,
WHEN we run `tools/restore-drill.sh [<snapshot-date>]` (defaults to yesterday),
THEN the script provisions a scratch Fly app named `co-drill-<utc-timestamp>`, restores the snapshot into it, verifies the same universe count + content_count as a recorded baseline, appends a result row to `tools/restore-drill.log` (committed via the cron), and destroys the scratch app — succeeding or failing loudly within 10 min total.

## Script outline

```bash
#!/usr/bin/env bash
set -euo pipefail
DATE=${1:-$(date -u -v-1d +%Y%m%d-%H%M%S || date -u -d 'yesterday' +%Y%m%d-%H%M%S)}
DRILL_APP="co-drill-$(date -u +%Y%m%d-%H%M%S)"

flyctl apps create "$DRILL_APP" --org personal
flyctl secrets set JWT_SECRET=drill -a "$DRILL_APP"
flyctl deploy --config fly.uat.toml -a "$DRILL_APP"

scripts/restore.sh "$DATE" "$DRILL_APP"   # CO-104 helper

UNIV_COUNT=$(curl -s "https://${DRILL_APP}.fly.dev/api/v1/universes" | jq 'length')
CONTENT_COUNT=$(curl -s "https://${DRILL_APP}.fly.dev/api/v1/universes/template" | jq '.content_count')

if [ "$UNIV_COUNT" -lt 1 ] || [ -z "$CONTENT_COUNT" ]; then
    echo "FAIL drill=$DRILL_APP date=$DATE univ=$UNIV_COUNT content=$CONTENT_COUNT" \
         | tee -a tools/restore-drill.log
    flyctl apps destroy "$DRILL_APP" --yes
    exit 1
fi

echo "OK drill=$DRILL_APP date=$DATE univ=$UNIV_COUNT content=$CONTENT_COUNT \
     time_to_restore=${SECONDS}s" \
     | tee -a tools/restore-drill.log
flyctl apps destroy "$DRILL_APP" --yes
```

## Acceptance

- [ ] `tools/restore-drill.sh` exists, executable, idempotent
- [ ] Scratch-app naming uses UTC timestamp; never collides
- [ ] Tear-down runs in `trap` so a failure mid-drill still destroys the scratch app
- [ ] One manual run logged success in `tools/restore-drill.log`
- [ ] Quarterly cron scheduled (Fly Machine cron, or `schedule` agent — owner's call)
- [ ] `docs/OPERATIONS.md` "Backup & restore" section links to this script and notes the quarterly cadence

## Out of scope

- Cross-region drills (single-region drill is enough for v1)
- PITR / WAL-streaming restore — CO-104 out-of-scope still applies
- Encrypted-backup drill — Phase 4

## Risks

- **Fly free-tier scratch-app caps.** Mitigation: drill app destroys itself; never leave more than one drill running.
- **Backup file rot (corrupt object).** Mitigation: drill exits non-zero, log captures it, the operator gets paged on the next-day failure.
