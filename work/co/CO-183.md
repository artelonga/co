## As

operator do `rede@artelonga.com.br` que recebe leads do form `/contato/`
em artelonga.com.br

## I Need

(a) endpoint público `POST /api/v1/leads` que aceita submissões do form
artelonga e persiste em SQLite, (b) admin endpoints `GET /api/v1/admin/leads`
e `PATCH /api/v1/admin/leads/:id` pra triage, (c) admin page estática
`/admin/leads.html` que consome esses endpoints, (d) email notification
disparado em cada submissão

## So That

leads não são perdidos (mailto falha em mobile sem cliente de email),
viram queryable (status, assignee, data), e podem ser **promoted**
pra AL-tasks quando viram projetos. Ver AL-4 (artelonga repo) — esse
ticket é o backend, AL-4 é o frontend.

## Estado atual

- Form `/contato/` em artelonga.com.br usa `mailto:` (`contato/index.html:335-368`).
- Sem endpoint pra leads em `co-web`.
- Email pipeline já existe (recovery codes via `mail::MailProvider`).

## Schema

Migration v18 (após CO-178 v17 land):

```sql
CREATE TABLE leads (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    nome TEXT,
    email TEXT,
    telefone TEXT,
    mensagem TEXT NOT NULL,
    servico_titulo TEXT,
    parceiro_handle TEXT,
    status TEXT NOT NULL DEFAULT 'new',
    priority TEXT DEFAULT 'normal',
    assignee_handle TEXT,
    notes TEXT,
    closed_reason TEXT,
    promoted_to_al INTEGER,
    ip_hash TEXT,
    user_agent TEXT
);
CREATE INDEX idx_leads_status ON leads(status);
CREATE INDEX idx_leads_created_at ON leads(created_at);
CREATE INDEX idx_leads_assignee ON leads(assignee_handle);
```

Status state machine: `new → triaged → in_progress → closed`.
`closed_reason ∈ {won, lost, spam, duplicate}`.

## Endpoints

### `POST /api/v1/leads` (público)

Body:
```json
{
  "nome": "Maria Silva",
  "email": "maria@example.com",
  "telefone": "+5511999999999",
  "mensagem": "Preciso de assistência técnica...",
  "servico_titulo": "Assistência Técnica",
  "parceiro_handle": "matheus"
}
```

- Validação: `mensagem` obrigatório (max 4000 chars), demais opcionais.
- IP hash via `hash_ip_daily()` (CO-46 helper existente).
- User agent armazenado raw (trim 256 chars).
- Bot filter (`is_bot(&ua)`) rejeita silenciosamente (return 200, sem persistir).
- Rate limit por IP-hash (5 leads / 24h) — primeiro alavanca, depois 429.
- Email notification pra `rede@artelonga.com.br` com lead body + admin link.
- CORS: same allowlist de CO-177 (artelonga.com.br).

Response: `201 Created` com `{ "id": N }` (não revelar mais detalhes).

### `GET /api/v1/admin/leads?status=&since=&limit=` (admin)

Mesmo gate de CO-105 admin dashboard (JWT + `CO_SEED_ADMIN_EMAIL`).
Default order: `created_at DESC`. Pagination via `limit` (default 50, max 200).

Response:
```json
{
  "leads": [
    {
      "id": 42, "created_at": "...", "updated_at": "...",
      "nome": "...", "email": "...", "telefone": "...",
      "mensagem": "...",
      "servico_titulo": "...", "parceiro_handle": "...",
      "status": "new", "priority": "normal",
      "assignee_handle": null, "notes": null,
      "closed_reason": null, "promoted_to_al": null
    }
  ],
  "total": 42
}
```

### `PATCH /api/v1/admin/leads/:id` (admin)

Body parcial:
```json
{
  "status": "triaged",
  "priority": "high",
  "assignee_handle": "yuri",
  "notes": "Cliente quer site novo, budget 8k.",
  "closed_reason": null,
  "promoted_to_al": null
}
```

State transitions validadas (não pode pular new→closed sem passar por triaged se quiser).

`updated_at` auto-bumped.

### `GET /admin/leads.html` (admin static page)

Mesmo padrão de CO-105 admin dashboard:
- Cookie auth, redirect to login se não auth.
- Inline HTML+CSS+JS, ≤ 50 KB.
- Fila em tabela: id, created, nome, email, status (chip colorido), priority, assignee, mensagem (truncate).
- Detail panel ao clicar lead: form pra PATCH (status, priority, assignee, notes, closed_reason).
- Filtros: status (multi-select), since (date range), assignee.
- Auto-refresh 60s.

## Email notification

Reuse `mail::MailProvider`:
- Subject: `[Lead #N] {nome ?? "Anônimo"} via {servico_titulo ?? "form geral"}`
- Body: lead fields + link admin (`https://co.artelonga.com.br/admin/leads.html#lead-N`).
- `to: rede@artelonga.com.br` (configurable via env `LEADS_NOTIFY_TO`).

Failure modes:
- Mail send falha → log error, **NÃO falha o POST do lead** (lead persistido > notif perfeita).
- Rate limit no email provider → buffer/retry futuro (não pra v1).

## Privacy / LGPD

- IP raw nunca persistido (só `ip_hash` daily-salted).
- Email opt-in implícito (usuário enviou form). Opt-out: deletar via support.
- Retenção: 24 meses default. Background task `purge_old_leads_task` roda
  daily, deleta `leads WHERE created_at < now - interval '24 months' AND status='closed'`.
- Privacy notice no form (responsabilidade do AL-4, não desse ticket).

## CORS

Adicionar `/api/v1/leads` à allowlist de CORS já configurada por CO-177.

## Tests

- POST com payload válido → 201 + row inserida + email enviado.
- POST sem `mensagem` → 400.
- POST com bot UA → 200 sem persistir.
- POST 6× do mesmo IP em 24h → 6º retorna 429.
- GET admin sem JWT → 401.
- GET admin com email não-admin → 403.
- PATCH com state transition inválida → 400.
- Email send falha → POST ainda retorna 201, lead persistido.
