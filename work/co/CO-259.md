## As

A developer running multiple co-auto runs in parallel on SPA work

## I Need

The three SPA "central" modules (`sidebar.js`, `state.js`, `api.js`) split into smaller files so that parallel tasks touch **disjoint** files instead of overlapping regions of monolithic modules.

## So That

The file-overlap analysis I do before kicking parallel tasks (CO-252/253, CO-254/255, etc.) reliably finds zero shared files. Today: a task touching "the sidebar" inevitably modifies the same 470-LOC `sidebar.js` that a sibling task also needs to modify — rebase conflicts even when the engineering intent is unrelated.

## Context

Repeat offenders this session:

| File | LOC | Tasks that touched it | Conflict count |
|---|---|---|---|
| `co-web/static/variants/a/modules/sidebar.js` | ~470 | CO-238, CO-252, CO-253 | 2× rebase failures |
| `co-web/static/variants/a/modules/state.js` | ~70 | CO-221, CO-253, CO-258 | 1× rebase failure |
| `co-web/static/variants/a/modules/api.js` | ~250 | CO-232, CO-233 helpers, CO-253 | small overlaps |
| `co-web/static/variants/a/modules/modals.js` | ~600 | CO-253 only this session, but it's the next hot zone | future risk |

Mirrors what CO-219 did for `chat_routes.rs` (2063 LOC → `chat/` folder with 7 files <500 LOC each).

## Decision — split + folder pattern

### `sidebar/`

```
co-web/static/variants/a/modules/sidebar/
├── index.js         (re-exports — preserves existing `from './sidebar.js'` imports)
├── render.js        (renderSidebar core)
├── sections.js      (renderSectionHtml, renderUniverseItemHtml, buildChildMap)
├── header.js        (renderHeader, renderHeaderUserArea, renderUsageCount)
├── badge.js         (renderUserBadge)
├── mini-calendar.js (renderMiniCalendar)
└── wire.js          (event handlers, hamburger, chevron toggles)
```

### `state/`

```
co-web/static/variants/a/modules/state/
├── index.js         (re-exports — preserves `import { state } from './state.js'`)
├── shape.js         (the `state` object — fields, defaults)
├── universes.js     (canEditCurrentUniverse, userUniverses helpers — CO-253)
└── views.js         (view-specific state: collapsedGroups, sortColumn, etc.)
```

### `api/`

```
co-web/static/variants/a/modules/api/
├── index.js         (re-exports — preserves `import { api, apiFetch } from './api.js'`)
├── client.js        (apiFetch, error handling, 401 modal trigger)
├── universes.js     (getUniverses, getUniverseInfo, getUniverseProjects, cloneUniverse, subscribe)
├── tasks.js         (getTasks, createTask, updateTask, bulkDelete)
├── entries.js       (getEntries, getEntry, vault PUT)
└── auth.js          (me, login, logout, loginWithPassword)
```

The `.js` files at the old paths become `index.js` inside their folder, re-exporting from the new submodules. Zero breaking imports — every existing `import { renderSidebar } from './sidebar.js'` keeps working.

## Acceptance

- Each new submodule ≤ 250 LOC.
- Existing imports unchanged — `import { renderSidebar } from './modules/sidebar.js'` still works (resolved via `sidebar/index.js`).
- `cargo test -p co-web` + `npx playwright test` both green.
- Documentation in `co-web/src/MODULES.md` (CO-225 territory) extended with the new SPA module map.

## Blast radius

Pure refactor — no behavior change. ~1500 LOC of cuts/moves across SPA modules, but **no semantic edits**.

## Why now (vs deferring)

Every co-auto wave from here forward will continue to bottleneck on these three files until they're split. CO-258 (no Cargo.toml/CHANGELOG mutations) closes the *procedural* parallel-conflict source; CO-259 closes the *structural* source.
