GIVEN the changelog is reachable through two separate surfaces that drift apart:
  1. the **board view-tab** `data-view="changelog"` (labeled "Histórico", icon
     `history`) inside the project header in `co-web/static/variants/a/index.html`,
     which renders an embedded view (see `changelog-embed.html`), and
  2. the **standalone page** `co-web/static/variants/a/changelog.html` served at
     `/changelog`,
WHEN a reader wants the release history,
THEN there should be ONE canonical changelog surface, so the two never disagree
on content, formatting, or freshness, and so we maintain a single render path.

## Acceptance

- [ ] Decide the single canonical surface (embed the standalone view inside the
      board tab, OR make the board tab deep-link to `/changelog`) — pick one and
      remove the duplicate render logic.
- [ ] The board "Histórico" tab and any `/changelog` entry point reach the same
      content with identical formatting (no second copy of the markup/parser).
- [ ] No dead route/tab left behind: whichever surface is dropped redirects or is
      removed cleanly (no orphan `changelog.html` or unreferenced view-tab).
- [ ] Language toggle (CO-555/556) keeps working on the surviving surface.

## Notes
- Surfaces today: `index.html` view-tab `data-view="changelog"` (label
  "Histórico") + `changelog-embed.html` (embedded render) + `changelog.html`
  (standalone `/changelog`). The duplication is the root of the drift.
- Pairs with CO-559 (sidebar mislabels "Histórico"/deploy as Ferramentas) —
  consolidating the changelog surface clarifies where the single entry point lives.
