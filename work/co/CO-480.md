GIVEN CO-479 landed the compliant WhatsApp Cloud API webhook but only verified +
logged inbound messages (the reply path was a TODO),
WHEN an inbound text arrives, we forward it to the bot brain (`CO_BOT_BRAIN_URL`,
default the `whatsapp-bot` bridge `/api/chat` — the same brain the companion app
uses) and send the reply via `CloudApiProvider`, doing so **asynchronously** so
Meta still receives its required fast 200 ack while the model call runs,
THEN a WhatsApp user gets a CO-aware auto-reply over the official compliant
transport — closing the loop (same brain, two front-ends: app + WhatsApp).

## Acceptance

- [x] `event_handler` parses inbound, then `tokio::spawn`s the reply loop and
  returns `200` immediately (never blocks Meta's ack on the model call).
- [x] `reply_to` → brain (`fetch_brain_reply`) → `CloudApiProvider::send`; falls
  back to a fixed ack if the brain is unreachable, no-ops (logged) if the Cloud
  API isn't configured.
- [x] `parse_brain_reply` (pure) extracts the `reply` string; unit-tested
  (present / empty / missing / non-JSON).
- [x] `CO_BOT_BRAIN_URL` config (default `http://localhost:8765/api/chat`).
- [x] `cargo test` + `cargo clippy -- -D warnings` + `cargo fmt` clean.
