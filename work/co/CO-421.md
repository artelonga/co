## As
O operador liberando uma release, QUERO um gate e2e que valide a **usabilidade
real em produção** (não só health 200), PARA não shippar uma regressão de UX
que o smoke de health não pega.

## Contexto
Hoje ~12 das specs Playwright dependem do fixture `uat-login` (`CO_ENV=test`),
que retorna **404 em prod** — não rodam contra o site ao vivo. Só
`anonymous-bootstrap`/`co-landing` são prod-safe. Falta um conjunto curado,
**anônimo e read-only**, que rode contra `https://co.artelonga.com.br` como
gate antes (ou logo depois) do deploy de prod. Sem staging por ora (decisão
2026-06-12) — o alvo é prod direto.

## Acceptance
- [x] Uma suite `e2e/prod-usability.spec.ts` (tag `@prod`) que roda contra
      `BASE_URL=https://co.artelonga.com.br` SEM nenhum login/fixture de auth
      (puramente anônimo, read-only — nunca cria/edita dados em prod).
- [x] Cobre o caminho de usabilidade que o health não pega: board do template
      carrega com as tarefas tutorial visíveis; troca de tema aplica; toggle
      pt/en muda os rótulos; um deep-link de entrada renderiza o markdown
      (não cai no 404/home); o grafo/lente abre.
- [x] É read-only por construção: asserts só de leitura/render; um guard falha
      a suite se qualquer request for POST/PUT/PATCH/DELETE.
- [x] Roda como passo nomeado no fluxo de release (script ou workflow) e
      **bloqueia** a promoção se vermelho; tempo total < ~2 min.
- [x] Documentado em `docs/release-checklist.md` como o gate de usabilidade
      prod (substitui o smoke manual de UAT).

## Notas de implementação (CO-421)
- Deep-link usa `/template/projects/CO/1` (tarefa tutorial garantida no seed do
  template, self-contained) em vez de `/nlp/aresta` (acoplado a um universo de
  conteúdo). Ambos renderizam o mesmo zoom-modal de markdown.
- "Grafo/lente" = lente de conteúdo (`.conteudo-stat`, breakdown por tipo/tag),
  com fallback opportunista para o dashboard quando ativável (a aba dashboard é
  project-scoped e não ativa no template prod sem projeto selecionado).
- Verificado verde local (`co serve` em :3000, ~2.7s) e contra prod v3.4.0
  ao vivo (~40s); guard read-only confirmado falhando uma sonda que emite POST.

Complementa (não substitui) a suite com auth-fixture do CO-374, que continua
rodando em test/localhost. Este é o conjunto que pode tocar prod com segurança.
