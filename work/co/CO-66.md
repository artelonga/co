GIVEN three small bugs surfaced during the 2026-04-26 universe-seed exercise, each a sharp edge that will cost time at scale,
WHEN we fix all three together,
THEN the API behaves predictably under concurrent load and UAT testing isn't blocked by cold-start delays.

## Bugs

1. **Duplicate universe key returns HTTP 500.** `POST /api/v1/universes` with an existing key surfaces a SQLite UNIQUE constraint violation as Internal Server Error. Should be 409 Conflict. At scale this matters: clients see 500 and retry on a transient-error assumption, amplifying load.
2. **`quilomboaraucaria` seed clobbers user description.** `storage.rs` runs the seed on every server startup with a hardcoded description. Seed should INSERT-OR-IGNORE on existing rows; never UPDATE user-edited fields.
3. **Fly auto-stop disrupts testing.** UAT machine auto-stops after ~5 min idle; cold-start latency 5-10s. Set `auto_stop_machines = false` in `fly.uat.toml` (UAT only — prod auto-stop is a cost feature, leave it).

## Scale notes

- 500 errors should be reserved for actual server failures so monitoring/alerting works at scale
- Seed idempotency matters once seed tables grow (e.g., when manifest epic ships, seeds may include schema definitions)

## Acceptance

- `curl -X POST .../universes -d '{"key":"existing"}'` returns 409 with explanatory body
- Restarting the server preserves user-edited universe descriptions
- UAT machine stays running across `flyctl status` polls over 30 min idle
