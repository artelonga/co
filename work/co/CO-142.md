## As

a CO operator who watched user-facing universes return 404 inconsistently and got confused by overlapping universe keys

## I Need

a single coordinated cleanup of the public-universe surface so that (a) every registered universe is reachable at `co.artelonga.com.br/co/<key>` with the correct visibility behavior, (b) the `co-dev` / `co-experience` deprecation actually happens, (c) the multiple quilombo variants are unified, and (d) `content_count` reflects reality

## To

close the four-headed bug surface the user named on 2026-05-02: "universe loading is still spotty," "Co platform has 0 entries," "quilombo-blog/qb test 2/qa-dev/quilombo araucaria — confusing, all should seed the same at least," "Co (desenvolvimento / experiencia) deprecated for epic / subuniverse organization."

## Given / When / Then

GIVEN four distinct issues today on `co.artelonga.com.br`:
1. `/api/v1/universes/co-dev` returns plain-text 404 to anonymous users — `dev_board.rs::router()` is mounted at `/api/v1/universes` BEFORE `universe_api` and its admin-only middleware shadows the public-subscribable `co-dev` universe seeded by CO-140.
2. The `template` universe shows `content_count=0` in the API even though it has 6+ seeded entries (sobre, termos, privacidade, dados-rastreados, linhas-do-tempo, index — added by CO-107 in 1.22.0).
3. Multiple quilombo-related universes (`quilombo-blog`, `quilombo-blog-2`, `quilombo-blog-3`, `qa-dev`, `quilomboaraucaria`) seed inconsistently — some via prod manual API calls, some via `seed_quilombo_universe` in storage, some left over from migrations.
4. `co-dev` and `co-experience` are public-subscribable universes meant to "subscribe to follow CO development" but the user has decided to deprecate this in favor of **epic / sub-universe organization** (e.g., a single `co` universe with epics nested via `parent_key`).

WHEN we run a coordinated cleanup pass:

### Phase A — Routing + visibility (the bleeding bug)

- **Disambiguate the `co-dev` key.** Either:
  - Move `dev_board.rs` routes from `/api/v1/universes/co-dev` to `/api/v1/admin/co-dev` (no client uses the existing path per grep); the public co-dev universe then resolves correctly via `universe_api`. **Recommended.**
  - OR remove the public `co-dev` seeding (per the deprecation in Phase C) and let `dev_board` keep ownership of the key. Acceptable but couples Phase A to Phase C.
- **Audit every public-subscribable universe**: `for u in $(query); do curl /api/v1/universes/$u; done` — must return 200 with metadata for each. UAT-side test in `scripts/smoke-uat.sh`.
- **Verify private universes return 404 to anonymous**, not 403 (existence-hiding).
- **Verify the SPA `/co/<key>` route** loads the universe board for any visibility class:
  - public-static / public-subscribable → board renders for anonymous
  - requires_login → SPA shows the login modal
  - private (anonymous user not the owner) → SPA shows "universe not found" page (not a hard 404 from the static handler)

### Phase B — `content_count` reconciliation

- **Investigate why template's `content_count = 0`**. The seed loop in `reseed_template_content_pages` upserts entries but doesn't bump `universes.content_count`. Confirm via SQL on prod.
- **One-shot recompute** at startup: `UPDATE universes SET content_count = (SELECT COUNT(*) FROM entries WHERE universe_key = universes.key)`. Or wire `upsert_entry_row` to maintain count atomically (preferred long-term).
- **Acceptance**: `GET /api/v1/universes/template` returns `content_count >= 6` post-deploy.

### Phase C — co-dev / co-experience deprecation + epic/sub-universe model

- **Remove CO-140 seeding** of public `co-dev` and `co-experience` universes from `server.rs`. They're stale concepts.
- **Migrate the spirit of the feature** to: a single `co` work-tracking universe (the existing one at the work/co/ filesystem root) with epics as `parent_key`-linked sub-universes. The hierarchical-universe machinery from CO-98 is the right shape.
- **Define the epic ↔ sub-universe mapping**: each `epic` content type can either stay an entry in `co` (current model — see CO-111…116) OR be promoted to a child universe. **Decision to make in this ticket.**
- **Provide a one-shot migration** that creates child universes for each epic if the promote-to-universe path is chosen. If not, simply delete `co-dev` / `co-experience` rows.

### Phase D — Quilombo reconciliation

- **Inventory** every `quilombo*` and `qa-*` universe currently on prod (via `flyctl ssh` if needed):
  - `quilomboaraucaria` — the canonical public-subscribable one (system-owned, content_count=161)
  - `quilombo-blog`, `quilombo-blog-2`, `quilombo-blog-3` — blog variants from manual experiments
  - `qa-dev` — possibly a QA dev clone
- **Decide one canonical universe** and what each variant is for. Document in `docs/ARCHITECTURE.md`.
- **Idempotent seed** for variants that should keep existing — they share the same content tree initially, then diverge per intent. If three of them are pure noise, delete via admin tool.
- **Acceptance**: only the universes that have a documented purpose remain; their seed paths are reproducible (re-run `co-web` startup → same content).

### Phase E — Co dev board task display

- **Make the dev board show this session's completed tasks** (CO-100/103/104/105/106/107/137/138/139/69/71/74/77 etc.) as `done`. Today the dev board reads `data/co/CO-*.md` from the runtime data dir, NOT `work/co/CO-*.md` from the repo. Either:
  - Mount/symlink `work/co/` into the runtime `data/co/` (CI step on deploy)
  - Or change `dev_board::router()` to read from a config-driven path that points at `work/co/` in dev and `/data/co/` in prod
  - **Recommended**: have CI copy `work/co/*.md` into the Docker image at `/data/co/` during build. Keeps the runtime path clean and the source of truth in the repo.

THEN every public universe is reachable at a stable URL with the correct visibility semantics, the deprecated co-dev/co-experience are gone, the quilombo variants are reconciled to documented purpose, and the dev board mirrors the actual state of work.
