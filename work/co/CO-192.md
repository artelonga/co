## As

a logged-in user looking at the sidebar

## I Need

the sidebar to render universes in semantic sections — owned, member,
subscribed, **invited (with a 🎁 badge and accept-link)**, and a
collapsible "Descobrir" section with public universes I can subscribe
to — sourcing all of this from the single `GET /api/v1/me/universes`
call shipped in CO-191

## So That

- pending invitations are visible without me opening a separate inbox
  modal
- I can discover other public universes inline rather than via a
  separate "Universos públicos" page
- the sidebar visually communicates my relationship with each universe
  (owner vs. member vs. invited) instead of treating them as a flat list

---

## Precondition

CO-191 must be live (`/api/v1/me/universes` returns the bucketed shape).
This ticket is pure frontend.

## File-level changes

### `co-web/static/variants/a/modules/sidebar.js`

Replace the current `renderSidebar()` body. Today it reads
`state.userUniverses` (a flat array). Switch to `state.meUniverses`
(the bucketed object from CO-191).

Pseudocode:

```js
function renderSidebar() {
    const me = state.meUniverses;  // { owned, member, subscribed, invited, discoverable, counts }
    if (!me) return; // anonymous fallback

    const sections = [
        { key: 'owned',    label: 'sidebar.section.owned',    items: me.owned },
        { key: 'member',   label: 'sidebar.section.member',   items: me.member },
        { key: 'subscribed', label: 'sidebar.section.subscribed', items: me.subscribed },
    ];

    // Render the universe sections (existing item template, but show role
    // chip when present and non-owner).
    let html = sections
        .filter(s => s.items.length > 0)
        .map(s => `
          <div class="sidebar-section">
            <div class="sidebar-section-label">${t(s.label)}</div>
            ${s.items.map(renderUniverseItem).join('')}
          </div>`)
        .join('');

    // Invited section — conspicuous badge + per-row actions.
    if (me.invited.length > 0) {
        html += `<div class="sidebar-section invited">
            <div class="sidebar-section-label">🎁 ${t('sidebar.section.invited')} (${me.invited.length})</div>
            ${me.invited.map(renderInviteRow).join('')}
        </div>`;
    }

    // Discoverable — collapsible, default closed.
    if (me.discoverable.length > 0) {
        const open = localStorage.getItem('co_sidebar_discover') === '1';
        html += `<div class="sidebar-section discoverable">
            <div class="sidebar-section-label" data-toggle="discover" style="cursor:pointer">
                ${open ? '▾' : '▸'} ${t('sidebar.section.discoverable')}
            </div>
            ${open ? me.discoverable.map(renderDiscoverableItem).join('') : ''}
        </div>`;
    }

    list.innerHTML = html;
    wireUpHandlers();
}
```

Renderers:
- `renderUniverseItem(u)` — existing item template, plus a small role
  chip (`<span class="role-chip">admin</span>`) when `u.role !== 'owner'`.
- `renderInviteRow(inv)` — universe name + "Aceitar" / "Recusar"
  buttons inline. Click → call accept endpoint (already exposed by
  CO-188), then refresh `state.meUniverses` and re-render.
- `renderDiscoverableItem(u)` — universe name + "Inscrever-se" link.
  Click → `POST /api/v1/universes/:slug/subscribe` (existing endpoint),
  then refresh.

### `co-web/static/variants/a/app.js` (state plumbing)

Add a fetch helper and refresh on login / membership changes:

```js
async function loadMeUniverses() {
    state.meUniverses = await apiFetch('/api/v1/me/universes', {}, true);
    if (!state.meUniverses) return;
    // Backward compat: keep state.userUniverses for any code still
    // reading it (existing renderUniverseItem chevron toggle reads
    // state.userUniverses for has-children).
    state.userUniverses = [
        ...state.meUniverses.owned,
        ...state.meUniverses.member,
        ...state.meUniverses.subscribed,
    ];
}
```

Call `loadMeUniverses()` after:
- successful login (any of: password, Google, onboard-with-email verify)
- successful invitation accept
- successful subscribe / unsubscribe
- successful clone
- explicit "refresh" affordance (already exists somewhere — verify)

## Acceptance

- [ ] After login, sidebar fetches `/api/v1/me/universes` and renders
      sections in fixed order: owned → member → subscribed → invited →
      discoverable.
- [ ] Empty buckets are not rendered (no dangling section header).
- [ ] Each non-owned item shows a small role chip.
- [ ] Invited section has the 🎁 emoji + count in label, and each row
      has functional Accept/Decline buttons.
- [ ] Accepting an invite optimistically removes the row, calls the API,
      refreshes `meUniverses`, and the universe appears in `member`.
- [ ] Discoverable section is collapsible; state persists in localStorage.
- [ ] Anonymous users see the existing public-catalog sidebar (no
      regression).
- [ ] After clone / subscribe / accept / unsubscribe, sidebar refreshes
      automatically.
- [ ] All i18n strings PT + EN.
- [ ] Universe-tree chevron toggle (existing parent_key nesting) still
      works inside the `owned` and `member` sections.

## Out of scope

- **Drag-to-reorder** universes within sections.
- **Per-section search filter** — sidebar stays simple.
- **Notifications** for new invites (toast / WebSocket push).
- **Sidebar collapse on small screens** — already handled by existing
  responsive CSS.
