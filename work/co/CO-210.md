## As

a visitor curious about CO's security model, dependencies, license,
or how to render universe content

## I Need

`co.artelonga.com.br/seguranca`, `/dependencias`, `/licensa`, and
`/renderers` to be browsable pages with dropdown menu navigation,
backed by the markdown docs already in `docs/` — with telemetry
embedded so we catch user issues without them needing to raise a flag

## So That

security docs are findable + indexable for trust, and we can iterate
on the experience based on actual user behavior (which pages hit
404s, which links break, which pages load slowly).

## Technical bits

1. **Renderer**: minimal markdown → HTML conversion. Reuse the existing
   parser from `modules/views/conteudo.js` or write a tiny CommonMark
   subset. CSP-safe (no inline scripts in user content).

2. **Routing**: client-side SPA router (existing pattern). Reserved
   paths added to `server.rs` so backend doesn't intercept them as
   universe slugs.

3. **Caching**: 5-min in-memory cache per page; static `.md` files served
   from `static/docs/` (built at startup by copying `docs/`).

4. **Telemetry**: every page view fires a `page_view` event to
   `/api/v1/telemetry/events` with:
   - `path` = `/seguranca/...`
   - `referrer` = stripped of query params
   - No user PII (visitor_token only)

5. **404 tracing**: when SPA route doesn't match, emit `404_route` event
   with the attempted path. Allows us to see "user tried `/seguranca/x`
   and got nothing" and ship the missing doc.

6. **Performance tracing**: emit `page_render` event with `duration_ms`
   for each page. Detect slow pages.

7. **Privacy**: telemetry respects `localStorage["co_viewer_telemetry"]
   = "0"` opt-out (per `docs/markdown-renderers.md`).

## Acceptance

- [ ] All 9 routes serve their respective markdown content
- [ ] Dropdown navigation works mobile + desktop
- [ ] Telemetry fires `page_view` for each render (verify in
      `telemetry_events` table)
- [ ] 404 attempts emit `404_route` event
- [ ] Slow pages (>500ms) detectable via `duration_ms` field
- [ ] Opt-out toggle in settings respects user choice
- [ ] No CSP violations (test rendered HTML doesn't break inline-script
      blocking)
- [ ] Cross-link between docs works (e.g., `[ver vapid](vapid-security.md)`
      becomes `/seguranca/vapid` properly)
- [ ] Tests: 5+ covering route resolution, markdown rendering of
      sample doc, telemetry emission, 404 path
