GIVEN Fly is being deprecated and the Mac M4 becomes the SOLE prod (self-host),
reached over a Cloudflare Tunnel, and co is now tenant-free (de-embed merged) so
prod is content-agnostic — the same `target/release/co-web` binary, just run on
our own box with `$CO_WEB_DATA` on local disk (CO-497 parallel-path invariant),
WHEN we cut production over from the managed Fly app to the M4,
THEN it must happen on a TEST host first, with the live data migrated and PROVEN,
hardened, soaked, and only then have DNS cut and Fly retired — using the
content-agnostic smoke + local disk gate + one-time data migration tooling below,
never the estate-pinned `smoke-prod.sh`.

## Acceptance

This task ships the **cutover tooling + runbook**; executing the runbook is the
operator's act (it touches prod DNS, a physical UPS, and the Fly account). The
shipped deliverables:

- [x] `scripts/migrate-fly-to-m4.sh` — one-time Fly→M4 data move (dry-run default,
  `--apply`): tars `/data` (meta.db + universes/*.db) on the Fly app, downloads, backs
  up the existing target, restores into `~/.co/data`, and proves it with

- [x] The cutover documented as the ordered **operator runbook** below (test-host
  first → migrate+prove → harden → cut DNS → soak → retire Fly).
- [x] Telemetry & observability config for the M4 documented (cold-tier archival,
  GeoLite2, optional OTLP, post-cutover verification) — see the section below.
- [x] Availability profile documented (anti-sleep, UPS, auto-restart, keep-alive).
- [x] Disk pre-flight wired into `scripts/selfhost/run.sh` (CO-537) + references the

## Runbook — operator cutover sequence (do in order)

1. **Merge de-embed.** Confirm prod is tenant-free: no universe content is required to
   build/boot/e2e the binary. This precondition lets a content-agnostic smoke replace
   the seed-pinned one.
2. **Build + boot the M4 on loopback.** `JWT_SECRET=… scripts/selfhost/run.sh --localhost`
   (stable secret from a 0600 file). Verify `GET /api/health` → ok and version ==
   workspace version, serve-allowlist clean — all asserted by `smoke-selfhost.sh`
   (CO-536). `disk-gate-selfhost.sh` (CO-537) now runs in `run.sh` automatically.
3. **Cloudflare Tunnel on a TEST hostname.** Bring up `cloudflared` per
   `scripts/selfhost/cloudflared-config.example.yml` pointing a **test** subdomain
   (e.g. `m4-test.artelonga.com.br`) at `localhost:8742`. Re-run
   `smoke-selfhost.sh https://m4-test.…` to prove reachability. Do NOT touch the prod
   hostname yet.
4. **Migrate the data.** During a quiet window (Fly app quiesced for a consistent
   snapshot), run `migrate-fly-to-m4.sh` dry-run, then `--apply`.
5. **Harden.** Firewall (`infra/SELF-HOST-SECURITY.md`: pf, kill-switch, exposure-scan).
   Stable `JWT_SECRET` in a 0600 file. Local Ollama loopback-only (no auth). Backups live
   (Litestream on `meta.db` + companion `universes/` snapshot + scheduled
   `verify-restore.sh`). Anti-sleep + auto-restart (see Notes). Prefer co-web on
   **loopback** behind the tunnel (`run.sh --localhost`) so it never appears on the LAN.
6. **Cut DNS.** Re-point `co.artelonga.com.br` to the M4 tunnel. Re-run
   `smoke-selfhost.sh https://co.artelonga.com.br` (read-only + opt-in round-trip) — green.
7. **Soak, then retire Fly.** Watch health/logs/disk for a soak window. Once stable,
   destroy the Fly app and remove it from the deploy docs. Keep the last Fly `/data`
   snapshot as a cold archive.

## Telemetry & observability (M4)

The de-embed left telemetry intact (`telemetry_middleware` wired in
`co-web/src/server/router.rs`; `telemetry_events` lives in `meta.db`, so it rides the
`/data` tar in step 4). Self-host must keep **full** observability — configure and
verify it as part of the cutover:

- **Cold-tier archival ON (ties to CO-537 disk gate / 94%-full concern).** Set
  `CO_TELEMETRY_ARCHIVE_ENABLED=true` + a sane `CO_TELEMETRY_HOT_DAYS` (default `90`).
  Archival (CO-449) moves whole cold months to Parquet under
  `$CO_WEB_DATA/telemetry-archive/` and reclaims pages so the volume doesn't bloat back
  over the gate. First run is delicate on a near-full disk — enable deliberately and
  watch `disk-gate-selfhost.sh`. Tune with `CO_TELEMETRY_ARCHIVE_INTERVAL_SECS`.
- **GeoLite2 present (else geo enrichment is silently OFF).** `geo.rs` loads a MaxMind
  GeoLite2 DB from `GEOIP_DB_PATH` (default `/data/GeoLite2-City.mmdb`); absent → NULL
  country/city. Download `GeoLite2-City.mmdb` onto the M4 and set `GEOIP_DB_PATH`.
- **(Optional) external traces/metrics.** `CO_TELEMETRY_OTLP_ENDPOINT` ships OTLP off-box;
  `CO_TELEMETRY_SERVICE_NAME` / `CO_TELEMETRY_SAMPLING_RATIO` tune it.
- **Verify post-cutover.** `smoke-selfhost.sh [04]` proves the analytics surface answers
  + reports the migrated `telemetry_events` count; then confirm recording (count, fresh
  GET, count incremented). `migrate-fly-to-m4.sh` checks BEFORE/AFTER counts +
  `telemetry_archives` rows + `telemetry-archive/` presence.

> **Off-box telemetry backup.** `meta.db` (incl. `telemetry_events`) is covered by
> Litestream and `telemetry-archive/` by the companion snapshot. A durable off-box
> replica until the CO-81 S3 offload exists is tracked in **CO-539**.

## Notes — availability profile (single box)

The M4 is a single point of failure; the accepted near-term profile is keep-it-up, not
cloud HA (cloud failover is the deferred CO-539):

- **Anti-sleep:** `sudo pmset -c disablesleep 1` (+ `pmset -c sleep 0`); lid-closed needs
  `caffeinate -dimsu`. The Mac must stay awake to serve.
- **UPS:** SQLite + a yanked cord is the classic corruption path; a UPS turns a power cut
  into a clean shutdown.
- **Auto-restart after power return:** `sudo pmset -a autorestart 1`.
- **Process keep-alive:** the `com.artelonga.co.plist` LaunchAgent with `KeepAlive=true`;
  for headless 24/7 prefer a LaunchDaemon (or auto-login) + `pmset autorestart`.
- **Backups are the real DR:** off-box Litestream + `universes/` snapshot, proven by
  `verify-restore.sh` — a dead box restores onto any machine.
