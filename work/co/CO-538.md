GIVEN Fly is being deprecated and the Mac M4 becomes the SOLE prod (self-host),
reached over a Cloudflare Tunnel, and co is now tenant-free (de-embed merged) so
prod is content-agnostic — the same `target/release/co-web` binary, just run on
our own box with `$CO_WEB_DATA` on local disk (CO-497 parallel-path invariant),
WHEN we cut production over from the managed Fly app to the M4,
THEN it must happen on a TEST host first, with the live data migrated and PROVEN,
hardened, soaked, and only then have DNS cut and Fly retired — using the
content-agnostic smoke + local disk gate + one-time data migration tooling below,
never the estate-pinned `smoke-prod.sh`.

## Acceptance

The checklist IS the 7-step runbook; do them in order.

- [ ] **1. Merge de-embed.** Confirm prod is tenant-free: no universe content is
  required to build/boot/e2e the binary (a clean-env build + boot serves zero
  universes happily). This is the precondition that lets a content-agnostic smoke
  replace the seed-pinned one.
- [ ] **2. Build + boot the M4 on loopback.** `JWT_SECRET=… scripts/selfhost/run.sh
  --localhost` (stable secret from a 0600 file). Verify `GET /api/health` → ok and
  the reported version == workspace version, and the serve-allowlist is clean —
  both asserted by `scripts/smoke-selfhost.sh` (CO-536). Confirm `scripts/disk-gate-selfhost.sh`
  (CO-537) passes on `$CO_WEB_DATA`.
- [ ] **3. Cloudflare Tunnel on a TEST hostname.** Bring up `cloudflared` per
  `scripts/selfhost/cloudflared-config.example.yml` pointing a **test** subdomain
  (e.g. `m4-test.artelonga.com.br`) at `localhost:8742` — public HTTPS, zero inbound
  ports. Re-run `smoke-selfhost.sh https://m4-test.…` to prove reachability through
  the tunnel. Do NOT touch the prod hostname yet.
- [ ] **4. Migrate the data.** During a quiet window (ideally Fly app quiesced for
  a consistent SQLite snapshot), run `scripts/migrate-fly-to-m4.sh` — dry-run first
  to read the plan, then `--apply`. It tars `/data` (meta.db + universes/*.db) on
  the Fly app, downloads it, backs up any existing target, restores into
  `~/.co/data`, and proves it with `smoke-selfhost.sh` + `selfhost/verify-restore.sh`.
- [ ] **5. Harden.** Firewall (`infra/SELF-HOST-SECURITY.md`: pf rules, kill-switch,
  exposure-scan e2e guard — co-web binding `0.0.0.0` is reachability, not a security
  boundary). Stable `JWT_SECRET` in a 0600 sourced file (never in the plist/repo).
  Local Ollama bound to loopback (no auth → never expose; reach via tunnel/proxy
  only). Backups live: Litestream on `meta.db` + the companion `universes/` snapshot,
  with `verify-restore.sh` on a schedule. Anti-sleep + auto-restart (see Notes).
- [ ] **6. Cut DNS.** Re-point the prod hostname (`co.artelonga.com.br`) tunnel
  route to the M4. Re-run `smoke-selfhost.sh https://co.artelonga.com.br` (read-only,
  plus the opt-in round-trip with admin creds) — all green.
- [ ] **7. Soak, then retire Fly.** Watch health/logs/disk for a soak window
  (`disk-gate-selfhost.sh` in the upgrade loop, `smoke-selfhost.sh` post-restart).
  Once stable, scale the Fly app to zero / destroy it and remove it from the deploy
  docs. Keep the last Fly `/data` snapshot tarball as a cold archive.

## Notes — availability profile (single box)

The M4 is a single point of failure; the accepted near-term profile is keep-it-up,
not cloud HA (cloud failover is the deferred CO-539):

- **Anti-sleep:** `sudo pmset -c disablesleep 1` (and `pmset -c sleep 0`); on a
  laptop lid-closed-running needs `caffeinate -dimsu` or `disablesleep`. The Mac
  must stay awake to serve.
- **UPS:** SQLite + a yanked cord is the classic corruption path. A UPS turns a
  power cut into a clean shutdown; also enables `pmset -a haltlevel`/graceful halt.
- **Auto-restart after power return:** `sudo pmset -a autorestart 1` (boot when
  power is restored) so an outage self-heals.
- **Process keep-alive:** the `com.artelonga.co.plist` LaunchAgent with
  `KeepAlive=true` restarts co-web on crash. A LaunchAgent only runs while the
  user is logged in — for headless 24/7 prefer a LaunchDaemon or keep an auto-login
  session, plus `pmset autorestart`.
- **Backups are the real DR:** off-box Litestream + `universes/` snapshot, proven by
  `verify-restore.sh`. A dead box is recoverable from the replica onto any machine.
