## Contexto
CO-278-E do épico da API pública: expor, sob **contrato documentado**, dados de
telemetria/analytics que hoje só vivem em tabelas (`agent_sessions` CO-275,
`deployment_snapshots` CO-273) ou em agregações ad-hoc do `/gestao/resumo`. Tudo
**read-only**. Reusa as queries existentes; nada de tabela nova.

## Endpoints (todos read-only, versionados em `/api/v1`)
| Endpoint | Fonte | Notas |
|---|---|---|
| `GET /api/v1/agent/sessions` | `agent_sessions` (CO-275) | paginado; filtros `?model=&since=` |
| `GET /api/v1/agent/sessions/{id}` | idem | uma sessão |
| `GET /api/v1/deployments` | `deployment_snapshots` (CO-273) | últimos N por app |
| `GET /api/v1/metrics/throughput` | agregação sobre agent_sessions | tokens/tempo por janela |
| `GET /api/v1/metrics/token-budget` | idem | gasto vs orçamento |
| `GET /api/v1/metrics/release-cadence` | git/CHANGELOG | versões por período |

## Auth — least-privilege via CO-448
- Gate com o extractor **`Scoped<TelemetryRead>`** (capacidade `telemetry:read` do
  CO-448): um token escopado lê telemetria **sem** ser admin pleno. Sessão admin
  também passa (o gate já trata JWT). Não admin sem o escopo → **403**.

## Acceptance
- [ ] 6 endpoints acima, read-only, sob `/api/v1`, **gated por `telemetry:read`** (CO-448).
- [ ] Reusar queries/agregações existentes (CO-273/275/360) — sem tabela/migração nova.
- [ ] Paginação + filtros básicos (`?model=`, `?since=`, `?limit=`) onde fizer sentido.
- [ ] Rotas no `api-catalog.md` + `openapi:check` sem drift (aparecem no Swagger do CO-452).
- [ ] Token só com `entries:read` (sem `telemetry:read`) → **403**; token com `telemetry:read` → **200**.
- [ ] Testes de integração (tower::ServiceExt) por rota + o caso 403/200 de escopo.
- [ ] Sem migração; sem MCP.

## So that
A API pública (CO-278) ganha o "panel-of-glass" de telemetria que o north star pede,
consumível por dashboards/sister-repos com um token `telemetry:read` — e exercita
o modelo de escopo do CO-448 numa superfície real.

## Não no escopo
- Agent dispatch (CO-278-D) · versioning/envelope (CO-278-A) · SDK (CO-278-F).
- Escrever telemetria (já existe via o pipeline CO-46).
