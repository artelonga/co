## As

The CO platform operator, I need the backup worker to refuse to snapshot when
disk headroom is insufficient and to retain by count/size instead of days, so
that backups can never again take production down.

## Context — 2026-06-11 outage (~08:26–11:30 BRT)

The CO-365 LocalFsBackend snapshots on **machine start** to `/data/backups/`.
With universes at ~409 MB on a 1 GB volume, the ~263 MB tarball overflowed the
disk → SQLite `SQLITE_IOERR_SHMSIZE` (4874) → startup panic → crash loop →
Fly max-restart cap → site dark ~3 h. Each restart re-attempted the snapshot:
self-amplifying. Recovered live via `flyctl volumes extend` 1→3 GB + prune.

The math is still broken: snapshots are ~263 MB *per machine start* and grow
with `/data/universes`; 30-day retention on 3 GB fills in ~days.

## GIVEN / WHEN / THEN

- GIVEN free space < 2× the last snapshot size (or < a configurable floor),
  WHEN the backup worker fires, THEN it SKIPS the snapshot, emits a
  `backup.skipped_low_disk` event on the CO-380 bus, and logs at WARN —
  it never brings down the app.
- GIVEN `CO_BACKUP_RETAIN_COUNT` (default e.g. 3) and/or
  `CO_BACKUP_RETAIN_MAX_BYTES`, WHEN a snapshot completes, THEN oldest
  snapshots are pruned until both limits hold (days-based retention becomes
  secondary).
- GIVEN repeated machine restarts within a short window, WHEN the worker
  fires, THEN it debounces (no new snapshot if the newest is < N hours old)
  — restarts must not multiply snapshots.
- Metrics/visibility: snapshot size, free space, and skip events appear in
  the atividades log.
- GIVEN server boot, WHEN the snapshot fires, THEN it runs AFTER the HTTP
  listener binds (async, low-priority) — 2026-06-11 21:21 restart: boot
  blocked >6 min on compressing 2.8 GB while health checks failed
  (connection refused). The snapshot must never sit in the boot path.
- Retention must also cover restart bursts: 4 snapshots accumulated in ONE
  day (one per deploy/restart) — 264+266+280+299 MB — and re-filled the
  freshly extended volume to 100% within hours (second outage same day).
