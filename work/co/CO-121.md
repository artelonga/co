## As

a CO operator

## I Need

three new SQLite tables (`feature_flags`, `ab_assignments`, `ab_exposures`), a stable assignment helper (`hash(user_id || flag_key) → variant`), and an exposure logger that emits to WAE (CO-118)

## To

run A/B tests **today** on the existing OLTP without waiting for the streaming bus, satisfying the user's "real-time analytics (e.g. a/b testing)" requirement at Phase 1 cost

## Given / When / Then

GIVEN we have OLTP + WAE (CO-118) but no A/B primitives yet,
WHEN we add three tables + an assignment helper + an exposure logger,
THEN any product surface can declare a flag, get a stable variant for a user, and emit exposures that are queryable in WAE within 60s.

## Schema

```sql
CREATE TABLE feature_flags (
    flag_key TEXT PRIMARY KEY,
    description TEXT NOT NULL,
    variants TEXT NOT NULL,   -- JSON: ["control","treatment"] or weighted: [{"v":"a","w":50}, ...]
    salt TEXT NOT NULL,       -- per-flag salt; rotating it re-randomizes assignments
    enabled INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE ab_assignments (
    user_id TEXT NOT NULL,
    flag_key TEXT NOT NULL,
    variant TEXT NOT NULL,
    assigned_at TEXT NOT NULL,
    PRIMARY KEY (user_id, flag_key)
);

CREATE TABLE ab_exposures (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,
    flag_key TEXT NOT NULL,
    variant TEXT NOT NULL,
    universe_id TEXT,
    exposed_at TEXT NOT NULL
);
CREATE INDEX idx_exposures_flag_time ON ab_exposures(flag_key, exposed_at);
```

## Assignment algorithm

```rust
fn assign(user_id: &str, flag: &Flag) -> &str {
    let h = blake3::hash(format!("{}::{}::{}", flag.salt, flag.flag_key, user_id).as_bytes());
    let bucket = u64::from_le_bytes(h.as_bytes()[..8].try_into().unwrap()) % 100;
    flag.variant_for_bucket(bucket)
}
```

Persist on first call (`INSERT OR IGNORE INTO ab_assignments`). Subsequent reads for the same `(user, flag)` are stable until either (a) the flag's `salt` rotates, or (b) the assignment row is deleted.

## API surface

```rust
let variant = co_ab::assign(user_id, "home_v2").await?;        // stable
co_ab::expose(user_id, "home_v2", variant, universe_id).await?; // logs to OLTP + WAE
```

## Acceptance

- [ ] Migration adds the three tables; rolls back cleanly
- [ ] `co_ab::assign` returns the same variant for 1000 consecutive calls with the same input
- [ ] `co_ab::expose` writes to OLTP **and** emits a WAE row within 60s
- [ ] Flag definitions seedable from `data/seed/feature_flags.yaml`
- [ ] Admin endpoint `POST /api/v1/admin/flags` to create/toggle flags
- [ ] One real flag wired up end-to-end (e.g., `home_v2_layout`) and exposed events visible in WAE

## Out of scope

- Causal-impact analysis tooling — that's the analyst's job, not the platform's
- Multi-armed bandits — separate ticket if/when warranted
- Sticky-by-cookie for anonymous users — works through `visitante_id` already; CO-97 dependency

## Risks

- **Hot writes on `ab_exposures`.** Mitigation: emit only once per session per flag (in-memory dedupe in `co-web`); the table is a backstop, WAE is the primary query surface.
- **Salt rotation surprise.** Mitigation: rotation requires a deliberate admin action and emits a deploy marker.
