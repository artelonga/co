GIVEN Phase 1 (CO-51 CLI sync) provides the sync protocol and Vault API integration,
WHEN I build the desktop tray app and PWA offline support,
THEN these are bundled as a single task for planning (implement sequentially):

## Desktop Tray App (Phase 2)

- [ ] Electron or Tauri app (decision: Tauri for smaller binary)
- [ ] System tray icon: green (synced), yellow (syncing), red (error)
- [ ] Background file watcher (reuses `co sync watch` logic)
- [ ] Native notifications: "3 files synced", "Conflict in sobre.md"
- [ ] Settings: which universes to sync, interval (1s/5s/30s/manual), conflict strategy
- [ ] Auto-start on OS login (configurable)
- [ ] Installers: `.dmg`, `.AppImage`, `.exe`
- [ ] CI: GitHub Actions builds all 3 platforms on tag

## PWA Offline (Phase 4)

- [ ] IndexedDB store: cache entries locally in browser
- [ ] Write queue: save changes to IndexedDB when offline
- [ ] Background sync: use Service Worker Background Sync API when online
- [ ] Offline indicator in header: "Offline — changes saved locally"
- [ ] Sync banner: "3 changes pending — sync now?" when reconnected
- [ ] Conflict resolution in browser (show diff modal)

## Depends On

- CO-51 (CLI sync protocol — shared by all clients)
- CO-54 (conflict resolution — defines strategies)
- CO-50 (universe-as-repo — for repo-backed universes)

## Acceptance Criteria

### Desktop
- [ ] App installs and runs on macOS, Linux, Windows
- [ ] Tray icon shows correct sync status
- [ ] File changes detected within 2 seconds
- [ ] Conflicts handled per configured strategy
- [ ] Settings persist across app restarts

### PWA
- [ ] App works offline (cached pages load, edits saved locally)
- [ ] Changes sync when back online
- [ ] No data loss on network interruption
- [ ] Install prompt works on Chrome/Safari mobile
