GIVEN CO will be released as an open-source project,
WHEN I prepare the repository for public consumption,
THEN:

- [ ] LICENSE file: MIT (already exists in core, verify workspace-level)
- [ ] README.md rewrite for public audience:
  - What CO is (one paragraph)
  - Screenshot of template board
  - Quick start: `cargo install co-cli` or Docker
  - Self-hosting: one-liner `docker run` or Fly.io deploy button
  - Link to artelonga.com.br/co for hosted version
  - Architecture diagram (simple: CLI ↔ core ↔ web)
  - Contributing section
- [ ] CONTRIBUTING.md: development setup, PR process, issue labels, code style
- [ ] .github/ISSUE_TEMPLATE/ — bug report and feature request templates
- [ ] .github/workflows/ci.yml — cargo test + clippy + fmt check on PR
- [ ] Verify no secrets in source: grep for API keys, tokens, hardcoded passwords
- [ ] Remove or .gitignore development databases (co.db, auth.redb, *.db files)
- [ ] Verify .gitignore covers: data/, *.db, *.redb, .env, node_modules/
- [ ] Docker image: verify Dockerfile builds clean, push instructions in README
- [ ] crates.io readiness: verify Cargo.toml metadata (description, repository, license, keywords)
- [ ] CHANGELOG.md up to date through current version
