## As

an author (or surface) linking across the recursive universe tree — where a node may be a root universe (`yggdrasil`), a nested sub-universe (`comunicacao` under `yggdrasil`, `mbya` under `comunicacao`), or a promoted surface with its own DNS (`yuri`, `retro-umarizal`)

## I Need

a stable **surface-key reference** `<key>::<path>` that resolves to the node's **live deployment URL** no matter where it sits in the tree, and no matter whether the node is itself a deployable unit or inherits a deploying ancestor's DNS — so links never break when a universe is promoted, demoted, or remounted.

## So That

content and surfaces address each other by *logical identity*, not by physical URL. `yggdrasil::comunicacao/mbya` and `mbya::` both point at `https://yggdrasil.artelonga.com.br/comunicacao/mbya` today; if `comunicacao` is later promoted to its own surface, the same refs follow it to `https://comunicacao.artelonga.com.br/mbya` with **zero link edits**. This is the addressing half of the recursive sub-universe ⇄ universe ⇄ deployable-unit model (the resolver that makes promotion seamless).

## Context

### Relationship to what exists

| Scheme | Status | Resolves to | Use |
|---|---|---|---|
| `co://<universe>/<path>` | exists (CO-153, `co-web/src/content/relation_index.rs`) | `{universe, path}` — logical, CO-internal | frontmatter relations, portable refs |
| `<PREFIX>-N` task IDs | exists (CO-276/CO-277) | a task file via tree-walk + uniqueness | `co-auto` CLI |
| **`<key>::<path>`** | **this ticket** | a **physical deployment URL** | content links, surface↔surface links, render-time |

`::` is the **deployment-resolving render** of the same key-tree-walk CO-277 already does for task IDs. It reuses CO-277's resolution semantics (uniqueness wins; ambiguity must be qualified) and CO-153's universe/path split; the new part is mapping a resolved node → `https://<dns>/<path-from-deployable-ancestor>`.

### Resolution algorithm

`resolve_surface_ref(key, subpath) -> Url`:

1. **Find the node** whose surface-key == `key`. (Key source: the universe `handle`/`slug`.)
   - If exactly one → use it.
   - If several at different depths → the **outermost (highest) wins** (a bare key is the top-level reading). To target a shadowed nested node, qualify through an ancestor: `yggdrasil::comunicacao/mbya`.
   - If several at the *same* depth → ambiguous → error `"qualify <key>: ancestor::key"`. (Same failure mode as CO-277.)
2. **Walk up `parent` links** from the node to the **nearest deployable ancestor** (a universe with `surface_dns` set). The node itself counts if it is deployable.
3. **Base** = `https://<that ancestor's surface_dns>`.
4. **Path prefix** = the chain of handles from the deployable ancestor (exclusive) down to the node, joined by `/`.
5. **Result** = `<base>/<path prefix>/<subpath>` (empty `subpath` or `index` → the base index).

### Worked examples (target behaviour)

| Ref | Node found | Deployable ancestor (dns) | Path prefix | Resolves to |
|---|---|---|---|---|
| `yggdrasil::index` | yggdrasil | yggdrasil (`yggdrasil.artelonga.com.br`) | — | `https://yggdrasil.artelonga.com.br/` |
| `yggdrasil::comunicacao/mbya` | yggdrasil | yggdrasil | (explicit) | `https://yggdrasil.artelonga.com.br/comunicacao/mbya` |
| `mbya::` | mbya | yggdrasil (walk mbya→comunicacao→yggdrasil) | `comunicacao/mbya` | `https://yggdrasil.artelonga.com.br/comunicacao/mbya` |
| `yuri::` | yuri | yuri (`yuri.artelonga.com.br`, own surface) | — | `https://yuri.artelonga.com.br/` |
| `comunicacao::` (pre-promotion) | comunicacao | co (`co.artelonga.com.br`) | `co/comunicacao` | `https://co.artelonga.com.br/co/comunicacao` |
| `comunicacao::` (post-promotion) | comunicacao | comunicacao (`comunicacao.artelonga.com.br`) | — | `https://comunicacao.artelonga.com.br/` |

The last two rows are the whole point: **the ref is identical; only the data (deployable flag + dns) changes on promotion**, and the link follows.

## Given / When / Then

GIVEN universes carry lineage (`parent`) and deployable surfaces carry a `surface_dns` (today: flat `co-universes.yaml` + hardcoded units in `deployment_snapshot_worker.rs`),

WHEN a `<key>::<subpath>` reference is resolved (in markdown render, in an API call, or in a surface's link-rewrite),

THEN it returns the live deployment URL computed by walking the key to its node and up to the nearest deploying ancestor — and a bare unique key (`mbya::`) resolves the same as its fully-qualified form (`yggdrasil::comunicacao/mbya`), while a shadowed key requires qualification.

## Decision / scope (confirm before build)

1. **Key = universe `handle`/`slug`** (reuse, not a new field). `yuri`, `yggdrasil`, `comunicacao`, `mbya`, `yoruba`.
2. **Add two fields to the universe model + `co-universes.yaml` + the DB row:** `parent: <key>` (lineage) and `surface_dns: <host>` (set only on deployable units). `deployment_snapshot_worker.rs`'s hardcoded unit list becomes a generated view of these (kills the duplication — ties to CO-280).
3. **Shadowing:** outermost-wins for bare keys; same-depth collision → error requiring an ancestor qualifier (mirror CO-277).
4. **Resolver lives in `core`** (`resolve_surface_ref`) so the CLI, co-web, and standalone surfaces share one implementation. Expose via:
   - `GET /api/v1/resolve?ref=<key>::<path>` → `{ url, universe, deployable_ancestor }`
   - render-time rewrite of `key::path` in markdown/wikilinks → `<a href="…">`.
5. **`::` complements `co://`** — same resolver core; `co://` returns the logical `{universe,path}`, `::` returns the physical URL. A `co://` ref can be rendered to a `::` URL when a live link is needed.
