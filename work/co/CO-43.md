GIVEN the CO project itself manages its development tasks as markdown files in `data/co/CO-*.md` (read by `co auto`), and these tasks have rich metadata (id, title, status, priority, parent, labels, module, created/updated),
WHEN I expose the CO development board as a private universe inside the deployed Co platform, accessible only to logged-in admin (Yuri),
THEN:

## Universe Setup

- [ ] Special universe `co-dev` (private, not public)
- [ ] Owner: Yuri's user_id
- [ ] Hidden from `GET /api/v1/universes` listings (only owner sees it)
- [ ] Accessible at `/co/co-dev` only when authenticated as admin
- [ ] Visiting unauthenticated → 404 (not 403 — don't reveal existence)

## Data Source

- [ ] Read tasks from filesystem path `data/co/CO-*.md` at runtime (not seeded into DB)
- [ ] OR import once + watch for file changes (inotify/fsnotify)
- [ ] Each markdown file → entry with full frontmatter exposed
- [ ] ROADMAP.md → page entry
- [ ] project.yaml → universe metadata source

## Task Metadata Display

Developer needs ALL metadata visible in the UI. Card should show:

- [ ] **ID**: `CO-21` (clickable to copy)
- [ ] **Title**: full task title
- [ ] **Status**: badge (todo, in_progress, done, review)
- [ ] **Priority**: colored pill
- [ ] **Parent**: link to parent task (e.g. epic)
- [ ] **Labels**: chips
- [ ] **Module**: text (e.g. `co-web`, `core`)
- [ ] **Created/Updated**: relative timestamps
- [ ] **Body preview**: GIVEN/WHEN/THEN sections rendered
- [ ] Click → opens viewer with full task body + checklist
- [ ] Checklists (- [ ] / - [x]) interactive (click to toggle, saves to file)

## Filtering

- [ ] Filter by status (in_progress is the natural default for active dev)
- [ ] Filter by priority
- [ ] Filter by module
- [ ] Filter by label (combinable)
- [ ] Search by title/id

## Admin Access

- [ ] Only users with `tier = admin` OR matching `CO_DEV_OWNER` env var see this universe
- [ ] Yuri's user_id will be set as `CO_DEV_OWNER` on prod
- [ ] Middleware check on `/api/v1/universes/co-dev/*` routes

## Read/Write Capability

- [ ] Read-only initially (safer)
- [ ] Phase 2: write back to markdown files when status changes (PUT updates frontmatter `status` field)
- [ ] Git commit hint shown on save (don't auto-commit, leave to dev)

## Acceptance

- [ ] `/co/co-dev` accessible only to admin
- [ ] All CO-* tasks visible with full metadata
- [ ] Anonymous/non-admin gets 404
- [ ] Filters work
- [ ] Task body renders with checklists
- [ ] `cargo test` passes
