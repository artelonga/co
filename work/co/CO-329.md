## As
Yuri running CO and wanting to see what's happening in real-time

## I Need
A non-indexed route `/analytics` that shows live telemetry + background process status

## So That
I always know what CO is doing on my machine (or on a deployed server) — what queries are happening, what workers are running, what AI sessions are active, error rates, etc.

## Scope

### Route
- `GET /analytics` — HTML page, non-indexed (`<meta name="robots" content="noindex">` + `X-Robots-Tag: noindex` header)
- Behind auth: only universe owners (or admin) can view
- For yuri.artelonga.com.br: only yuri

### Real-time data via WebSocket
- New endpoint `WS /api/v1/analytics/stream`
- Pushes events as they happen:
  - Request started/finished (path, status, duration)
  - Background worker started/finished (CO-292 InProcessExecutor)
  - AI query started/finished (CO-328)
  - Subscription/login/logout events
  - Errors with stack trace excerpt

### Panel layout
- **Live requests** — scrolling list, color-coded by status
- **Background processes** — table of active jobs (worker id, status, started_at)
- **AI sessions** — active Ollama + Claude Code processes
- **Stats** — rolling 1m/5m/1h request count, p50/p95 latency, error rate
- **Recent errors** — last 10 with timestamp + brief

### Telemetry retention
- Last 1000 events in a ring buffer (in-memory, not persisted)
- Optional: write to a `telemetry_events` SQLite table for longer retention (configurable)

### Build on existing
- CO-118 added WAE worker proxy (analytics export) — that's prod-side
- CO-292 InProcessExecutor already tracks running jobs — expose `list_active()`
- CO-300 TestServer for testing
- Event bus from CO-279 already publishes events

## Acceptance
- [ ] `GET /analytics` returns HTML page (auth-gated, noindex)
- [ ] `WS /api/v1/analytics/stream` pushes events in real-time
- [ ] Live request log scrolls with each request
- [ ] Background process table updates as workers start/finish
- [ ] Active AI sessions visible
- [ ] Error count + recent error list

## Blast radius
- 1 new route handler
- 1 WS endpoint
- ~200 lines SPA dashboard
- ~100 lines event-bus subscriber wiring
- Optional 1 new SQLite table for retention

## Why now
Yuri wants to see "what's running in the background and where". This is the canonical surface for that. Plays into CO-327 (notifications) and CO-328 (AI sessions).
