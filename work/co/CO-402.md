## As

Wave 6 (the security epic — slotted after v3.5.0 per `docs/roadmap.md`), I need
one architecture document — the `sala-surface.md` of the security epic — agreed
BEFORE any implementation agent touches `.co` format, fs-as-web, or encryption,
because these are architecture decisions, not features.

## I Need

`docs/architecture/wave6-security-epic.md` covering: the `.co` container format
(cleartext header, typed frontmatter, body `oneof`, attachment graph), how `.co`
wraps markdown + assets, the composable protocol-stack layering (CO-87
composition order), fs-as-web flow + pairing ceremony (CO-110), the per-universe
encryption envelope (Argon2id KEK → per-universe DEK → blob ciphertext, what
stays plaintext for search), the migration path for existing universes, and the
explicit precondition that CO-104/119 (S3 backup + restore drill) is DONE before
encryption-at-rest ships — never encrypt what you cannot restore.

## So That

every downstream implementation ticket (CO-86 format, CO-87 stack, CO-110
fs-as-web, CO-145/148 envelope) lands in a shape that does not have to be redone,
and the plaintext-for-search boundary + the restore-drill gate are decided once,
in writing, rather than rediscovered per ticket.
