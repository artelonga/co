GIVEN CO universes store content as structured data in SQLite and Obsidian expects a directory of `.md` files with YAML frontmatter and `[[wikilinks]]`,
WHEN I publish a genuine Obsidian community plugin that syncs a CO universe to/from an Obsidian vault,
THEN:

## Plugin Setup (from obsidian-sample-plugin template)

- [ ] New repo `co-obsidian/` scaffolded from https://github.com/obsidianmd/obsidian-sample-plugin
- [ ] `manifest.json`: id `co-universe-sync`, name "CO Universe Sync", minAppVersion per current stable
- [ ] `package.json` with esbuild build system (from template)
- [ ] Plugin settings: CO instance URL (default: `https://artelonga.com.br`), API token (from CO login), universe slug, sync direction (pull/push/bidirectional), sync interval
- [ ] Settings tab in Obsidian: configure instance, authenticate (OAuth or token paste), select universe

## Core Sync Engine

- [ ] `pull()`: GET `/api/v1/universes/:slug/vault/` (file listing) → compare with local vault files → download changed/new files → write to vault
- [ ] `push()`: scan vault `.md` files → compare hashes with remote → upload changed/new files → POST/PUT to vault API
- [ ] `sync()`: bidirectional — pull remote changes first, then push local changes, last-write-wins on conflict (with conflict marker option)
- [ ] Sync triggers: on Obsidian startup, on file save (debounced 5s), manual button, configurable interval (off/5min/15min/1hr)
- [ ] Status bar indicator: "CO: synced ✓" / "CO: syncing..." / "CO: offline" / "CO: 3 conflicts"

## Frontmatter Mapping

- [ ] CO → Obsidian: `labels` → `tags`, `created_at` → `created`, `updated_at` → `modified`, `title` stays, `status`/`priority` preserved as-is
- [ ] Obsidian → CO: `tags` → `labels`, `created` → `created_at`, `aliases` preserved in metadata JSON
- [ ] Bidirectional: `id` field preserved, `type` field mapped to CO content type
- [ ] Unknown frontmatter fields: preserved in both directions (round-trip safe)

## Wikilink Support

- [ ] CO content references rendered as `[[CO-21|Universe CRUD API]]` wikilinks in exported `.md`
- [ ] `parent: 21` field generates `parent:: [[CO-21]]` inline dataview field
- [ ] On import: `[[CO-21]]` resolved back to `parent: 21` numeric reference
- [ ] Backlinks: Obsidian's graph view shows CO task/content relationships naturally
- [ ] Link resolution: plugin registers link handler so clicking `[[CO-21]]` opens the synced file

## File Organization

- [ ] Universe vault structure:
  ```
  <vault>/
  ├── .obsidian/          # Obsidian config (auto-generated on first sync)
  ├── .co/                # CO sync metadata (hashes, last sync timestamp)
  ├── projects/
  │   └── <project-key>/
  │       ├── _project.md       # Project metadata
  │       ├── <task-id>.md      # Tasks
  │       └── comments/         # Comments as sub-files (optional)
  ├── content/                  # Free-form content (jardim, relatos, etc.)
  └── README.md                 # Universe description
  ```
- [ ] Folder structure mirrors CO project/task hierarchy
- [ ] `.co/sync.json`: `{ lastSync, fileHashes, remoteVersion }` for incremental sync

## Obsidian Commands

- [ ] "CO: Sync now" — manual full sync
- [ ] "CO: Pull from CO" — one-way pull
- [ ] "CO: Push to CO" — one-way push
- [ ] "CO: Open in CO" — opens current file's universe page in browser
- [ ] "CO: Create task" — quick-add task from current note (extracts title from heading)
- [ ] "CO: Link to CO" — insert `[[CO-XX]]` reference picker
