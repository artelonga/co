## As

an author tracking that "Ayvu Rapyta — Cadogan 1959" exists as four scans, two reprints with different editorial notes, and one OCR'd transcription

## I Need

reference cards to carry a **conceptual identity** (`work_id`) separate from each concrete file's identity (`sha256`), with an `editions[]` array listing every artifact, and a `primary_source_chain` documenting the layers of mediation between the original phenomenon and the cited document

## To

stop pretending two scans of the same book are interchangeable references; surface what's actually known (Cadogan transcribed; the publisher edited; we OCR'd) so authority weighting is honest

---

## Schema

```yaml
---
type: reference

# Conceptual identity — same value across every concrete file of the same work.
work_id: ayvu-rapyta-cadogan-1959

# What kind of source this is in the chain.
primary_source_chain:
  - layer: 0
    role: phenomenon
    description: "Mbyá knowledge-keepers' oral cosmogonic narratives (Guairá, Paraguay, ~1940s–1959)"
  - layer: 1
    role: transcription
    description: "León Cadogan transcribes from speakers in Mbyá and Spanish"
    actor: "León Cadogan"
    date_year: 1959
  - layer: 2
    role: publication
    description: "Universidade de São Paulo first edition"
    actor: "USP"
    date_year: 1959
  - layer: 3
    role: digital_scan
    description: "Acervo Socioambiental scan + indexing"
    actor: "Instituto Socioambiental"
    source_url: https://acervo.socioambiental.org/...

# Concrete artifacts of this work — each is one row.
editions:
  - edition_id: usp-1959
    file: ayvu-rapyta-1959-usp.pdf
    sha256: <hex>
    pages: 224
    language: es
    published_at: 1959-01-01
    editor_notes: "Original Cadogan edition; no scholarly apparatus."
    seed_status: native-confirmed
  - edition_id: ucsa-1992-corregida
    file: ayvu-rapyta-1992-ucsa.pdf
    sha256: <hex>
    pages: 248
    language: es
    published_at: 1992-06-01
    editor_notes: "Edición corregida — UCSA 1992 with corrections from posthumous Cadogan archive."
    seed_status: reviewed
  - edition_id: socioambiental-2010-ocr
    file: null
    url: https://acervo.socioambiental.org/...
    sha256: null
    language: es
    published_at: 2010-01-01
    editor_notes: "Web-readable scan; OCR'd; line breaks unreliable."
    seed_status: stub

# Default edition for citation when the human says "Ayvu Rapyta" without specifying.
canonical_edition: ucsa-1992-corregida
---
```

## Why `primary_source_chain` matters

When two references contradict each other, authority weighting can't just say "the older one wins" or "the more academic one wins." The chain says **how mediated** each claim is:

- `layer: 0` — direct phenomenon (a moon phase, a speaker's utterance, an event observed)
- `layer: 1` — first-person account / transcription
- `layer: 2` — published interpretation
- `layer: 3+` — re-print, scan, digitization, OCR, secondary commentary

A topologia term backed by `primary_source_chain.layer == 1` (a Mbyá speaker today, recorded last week) supersedes one backed by `primary_source_chain.layer == 4` (an OCR of a scan of a reprint). The schema makes that explicit; the UI can render it as a chain-of-custody diagram.

## API

```
GET /api/v1/universes/{u}/references?work_id=<id>     → all editions of a work
GET /api/v1/universes/{u}/references/works            → distinct work_ids in the universe
GET /api/v1/universes/{u}/references?primary_layer=1  → all references claiming first-person sourcing
```

## Migration

Existing reference cards (e.g. `mbya/refs/GNDicLex.md`) get a `work_id` (auto-derived from filename if reasonable, otherwise authored) and a one-row `editions[]` containing what's already in their frontmatter. Backfill is one-shot on first boot after this deploy.

## Acceptance

- [ ] Manifest accepts `work_id`, `editions`, `primary_source_chain`, `canonical_edition` on the `reference` type
- [ ] `references_meta` table gains `work_id`, `edition_id`, `primary_layer` columns; existing rows backfilled with `work_id = <slug-of-card-key>`, `edition_id = "default"`, `primary_layer = null` (until authored)
- [ ] `GET /references?work_id=<id>` returns every edition row matching the work
- [ ] Re-uploading the same PDF (same sha256) under a different filename detects the duplicate and merges into the existing edition row instead of creating a new one
- [ ] Test: round-trip a card with 3 editions through write → read → assert all 3 appear in `references_meta`

## Out of scope

- A "render the chain of custody as a graph" UI. Schema first; render later.
- Resolving `work_id` collisions across universes (two different works happen to use the same slug). Universes are local namespaces; cross-universe `work_id` joins are CO-153 territory.
- Importing existing scholarly metadata (CrossRef, OpenLibrary). CO-157 may stub it; this ticket scopes to schema + API.
