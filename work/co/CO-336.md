## As
Yuri receiving feedback on an entry (yuri.artelonga.com.br, artelonga.com.br, sister sites via Yggdrasil's Fale Conosco)

## I Need
Each feedback entry to function like a lightweight GitHub issue — open-source traceable, with explicit linkage to the fix/PR that resolved it, and a public trail of how it was addressed

## So That
- Visitors can see "this feedback led to commit X / PR Y" — the platform is auditable
- Yuri builds a public record of corrections + contributions, not a private inbox
- The feedback log becomes a discovery surface ("look at the things people corrected")

## Builds on

- **CO-333** ✓ shipped — feedback table with `status: open|reviewed|addressed`, per-entry locus
- **Yggdrasil's Fale Conosco** — already universal across sister sites
- **CO-329** ✓ shipped — analytics surfaces every feedback submission

## Design

### Schema additions

Extend the `feedback` table (additive):

```sql
ALTER TABLE feedback ADD COLUMN linked_ref TEXT;           -- "https://github.com/owner/repo/pull/123" or "commit:abc1234"
ALTER TABLE feedback ADD COLUMN linked_summary TEXT;       -- one-line description of what changed
ALTER TABLE feedback ADD COLUMN owner_response TEXT;       -- public-facing reply from owner
ALTER TABLE feedback ADD COLUMN public_visible INTEGER NOT NULL DEFAULT 0;
                                                            -- 0: private (only owner sees); 1: public mural
```

### Status state machine (extends CO-333's enum)

| Status | Owner action | Public visibility default |
|---|---|---|
| `open` | initial state on submission | private (owner-only) |
| `reviewed` | owner read it | private |
| `addressed` | owner committed a fix; `linked_ref` set | **public** (auto-flip) |
| `wont-fix` | owner declined; `owner_response` required | public (with reason) |
| `duplicate` | same as another; `linked_ref` points to original feedback ID | public |

`addressed` and `wont-fix` are terminal states; the public visibility auto-flips so the trail is built.

### API extensions

```
PATCH /api/v1/feedback/<id>
  { status?, linked_ref?, linked_summary?, owner_response?, public_visible? }

GET /api/v1/feedback/<universe>/public            -- public-traceable feedback only
GET /api/v1/feedback/<universe>/entry/<path>      -- per-entry feedback (owner sees all; anon sees public)

GET /api/v1/feedback/<universe>/<id>              -- single feedback + linked context
```

When `linked_ref` looks like a GitHub PR/commit URL, CO can fetch the title + state via `gh api` and cache in `linked_summary` (best-effort).

### "Like GitHub issues" UX

#### Public mural per universe
`/universe/<key>/feedback` extends CO-333's mural:
- Shows `addressed` + `wont-fix` items publicly by default (anonymous-visible)
- Each item: original message + owner_response + link to fix (PR/commit)
- Threaded layout: feedback → response → linked PR
- Search by entry, by status, by date

#### Per-entry inline
On any entry view:
- Open feedback badge (owner-only)
- "Reviewed" history strip (public): "3 visitors flagged this; corrected in PR #128"
- Visitors clicking the strip see the public trail

#### Owner workflow (in-locus, extends CO-333)
- Side panel adds a "Link fix" button → text input for PR URL or commit SHA
- Submitting auto-flips status to `addressed` + `public_visible=1`
- "Wont-fix" option requires `owner_response` (no silent dismissals)

### Integration with CO-333 chat (CO-332)

The chat assistant gets a new tool:
```
get_feedback_status(entry_path?)
  → { open: N, addressed: M, recent_fixes: [...] }
```

So when a visitor asks "what's recent activity here?", the LLM can surface "12 issues addressed in the last month, 3 open" — making the platform's responsiveness visible.

### Integration with CO-334 (changelog aggregator)

When `linked_ref` is a commit SHA in a repo CO knows about (via CO-330's `local_repo_path`), the changelog feed cross-links: "the 2.35.0 release addressed feedback #abc123 from yuri.artelonga.com.br". Two-way linkage.

### Yggdrasil compatibility preserved

Existing Yggdrasil Fale Conosco submissions still work — they post to the same endpoint. The traceability fields are additive; old rows have NULL `linked_ref` and `public_visible=0` (private = preserves existing privacy expectation).

### Open-source surface

`GET /api/v1/feedback/all/public` (no universe filter) — returns all public-visible feedback across all universes the caller can read. This is the "GitHub issues across the org" view.

Optionally exportable as RSS/Atom feed for those who want to follow.

## Not in scope

- Reply threads (feedback → owner reply → visitor reply) — could come in v3 if needed
- Voting/reactions on feedback ("agree" / "me too") — speculative; defer
- Cross-platform GitHub integration (auto-create real GitHub issues) — out of scope; CO is the canonical surface
- Feedback search (full-text) — `body_text` ready but UI defers
- Bounty / pay-per-fix mechanics — way out of scope

## Why now

- CO-333 just shipped — adding traceability now keeps the model coherent before patterns calcify
- Yuri's vision: yuri.artelonga.com.br is a public-curated portfolio; visitor feedback that visibly leads to fixes builds trust + a discovery surface
- Open-source ethos: corrections + their resolutions should be public when they're behavior-affecting (mirroring how GitHub issues + PRs work)
- Pairs with CO-334 (changelog) to build a complete "what visitors said + what got done about it" public record
