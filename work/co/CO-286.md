## What this slice does

Splits the embedding worker out of `co-artelonga` into a sibling Fly app `co-embedding` that suspends when idle. Today the embedding model (400-1500MB depending on which model is selected) lives in-process and forces co-artelonga to a 1GB+ tier even when nobody is embedding. Extracting it lets co-artelonga drop to 256-512MB and the embedding sidecar pays its 1GB rent only during active embedding (~5% of the time).

## Scope

1. New crate `co-embedding-server/` at repo root with `Cargo.toml` + single binary
   - Axum server, single endpoint: `POST /embed` body `{ texts: [String] }` → `{ vectors: [[f32]] }`
   - Auth: shared secret in env var `CO_EMBEDDING_TOKEN`
   - Bind to `[::]:8080` (internal `.flycast` only — no public IP)
2. Move the embedding worker code from `co-web/src/platform/embedding.rs` (model load + inference) into the new crate
3. New Fly config `fly.embedding.toml` at repo root:
   - shared-1x 1GB
   - `auto_stop_machines = "suspend"`, `min_machines_running = 0`
   - `[mounts]` for the model cache volume
4. Refactor `co-artelonga`:
   - Replace in-process embedding worker with an HTTP client calling `http://co-embedding.flycast/embed`
   - Env var `CO_EMBEDDING_URL` (default `http://co-embedding.flycast`)
   - **Fallback**: when sidecar is unreachable, log a warning and emit zero-vector (don't panic, don't block the request)
5. Deploy order documented in PR: `co-embedding` first, verify health, then `co-artelonga` repointed

## Acceptance

- [ ] `co-embedding` Fly app exists, listens on internal `.flycast` only
- [ ] `co-artelonga` no longer loads the embedding model in-process (verify: `flyctl ssh console -a co-artelonga -C "ps aux | grep embed"` shows no model thread)
- [ ] Embedding a doc end-to-end works: write to co-artelonga → embedding sidecar wakes → vector stored
- [ ] When co-embedding is down, co-artelonga writes still succeed (graceful degradation)
