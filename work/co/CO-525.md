GIVEN composability should be provable with a real external add-on — the open-source
**production-agentic-rag** framework wired as an optional retrieval tool an agent can
call **with zero change to the CO binary** — via a single manifest entry consumed by
the HTTP invoker (CO-523) under the canonical contract (CO-503),
WHEN we add a manifest entry
`{ url, input_schema: { query }, tool_type: predictive }` pointing at a running
production-agentic-rag service,
THEN an agent can invoke RAG retrieval as just another tool in the tool-calling loop —
recompiling nothing — making this the **reference external add-on** for CO's
composability engine.

## Acceptance

- [ ] **Manifest entry** for production-agentic-rag: `name`, `description`,
  `input_schema: { query }`, `url` (the running RAG service), `tool_type: predictive`
  — dropped into the trusted `tools/` catalog / `tools.d/`, no code change.
- [ ] **Callable via the HTTP invoker (CO-523)** — the agent invokes it through the
  canonical contract (CO-503); a `query` goes out, retrieved context comes back as the
  tool `result`.
- [ ] **Zero binary change demonstrated** — adding/removing this tool is purely a
  manifest + service-availability change; the CO binary is untouched.
- [ ] **Opt-in, default OFF** — registered only when external tools are enabled
  (CO-523 gating); absent service degrades gracefully (tool unavailable, not a crash).
- [ ] **Reference docs** — document this as the canonical pattern for wiring any
  external OSS HTTP tool as a CO add-on (the front-door shape new HTTP add-ons copy).

## Notes
- Depends on CO-503 (canonical contract, `predictive` `tool_type`) + CO-523 (HTTP
  invoker, manifest discovery, opt-in/trust). This is the **reference external add-on**
  that exercises the whole composability engine end-to-end.
- NOT MCP (`feedback_no_mcp.md`) — production-agentic-rag is reached as a plain HTTP
  service through CO's native external-tool adapter.
- Term is **tool/ferramenta** and **agent/agente** — never "bot".
