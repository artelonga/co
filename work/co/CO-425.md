## As
Operador de launchers co-auto em várias máquinas, QUERO que cada sessão
headless capture seu consumo de tokens e o reporte ao CO central, PARA que o
dashboard (CO-426) mostre usage real por task/universo/modelo/máquina sem
nenhum polling.

## Contexto técnico
`launch_claude` em `dev/co-auto/src/auto.rs` roda `claude -p <prompt>` e só
guarda exit code + stdout. O modo headless do Claude Code suporta
`--output-format stream-json`, que emite NDJSON com `usage` por mensagem
(input_tokens, output_tokens, cache_creation_input_tokens,
cache_read_input_tokens, modelo) e um evento final `result` com totais e
duração. É a fonte primária. Fallback (modo interactive, onde stdout é do
usuário): ler o `.jsonl` da sessão em `~/.claude/projects/<dir>/` ao final
(mesma fonte do `co-mine-claude-sessions.py`).

## Acceptance Criteria
- [ ] Headless: co-auto passa `--output-format stream-json --verbose`, parseia
      o NDJSON e acumula por sessão: tokens in/out, cache read/write, modelo(s),
      duração, num_turns, exit status. Stdout "humano" continua visível no log
      do launcher (re-emitir o texto dos eventos `assistant`).
- [ ] Novo struct `SessionUsage` serializável; ao fim da task (sucesso OU
      falha), co-auto faz POST `/api/v1/usage/sessions` (CO-426) com:
      `{task_key, universe_key, machine (hostname), model, usage{...},
      started_at, ended_at, outcome}`. Auth via token existente (mesmo esquema
      do co-sync). Falha de POST não falha a task — loga e segue (best-effort,
      com retry único).
- [ ] Interactive: ao final da sessão, localizar o `.jsonl` mais recente da
      sessão `co-auto-<task>` e extrair o mesmo `SessionUsage` (best-effort).
- [ ] `--no-usage-report` desliga o report (offline/dev).
- [ ] Endpoint de destino configurável (`CO_USAGE_URL` ou config do co-auto) —
      nada hardcoded; default = deployment configurado do launcher.
- [ ] Resumo impresso no terminal ao fim de cada task:
      `usage: 12.3k in (84% cached) / 4.1k out — sonnet — 6m12s`.
- [ ] Testes: parser do stream-json com fixtures (mensagens usage + result);
      montagem do payload; flag off.

## Notas
- Não bloquear nem atrasar o fluxo da task por causa de telemetry.
- Não inventar custo em USD quando a auth é assinatura (keychain): reportar
  tokens; custo só quando o evento `result` trouxer `total_cost_usd`.
