GIVEN CO-472 generalized chat into a unified **thread** model (migration v092 —
anchored / recursive / scoped threads on `chat_rooms`) and shipped the
entry-anchored `comments` view plus the storage primitives for scoped threads
(`create_scoped_thread`, `create_reply_thread`, `can_access_thread`), but
DEFERRED the **standalone** scoped-thread REST surface,
WHEN we expose those primitives over HTTP — create / list / post / reply /
archive — on the visibility-gated router, reusing the same `ChatEvent` broadcast
for live delivery,
THEN a *message is still a comment in a thread*: members can open a thread for
everyone (`all`), a subset of members, or just themselves (`self`), post and
reply (recursive child threads), and archive it — with connected members
receiving each post live exactly as a chat message.

## Design

No new schema — the v092 thread columns (`anchor_entry_path`, `anchor_block_id`,
`parent_thread_id`, `scope`) and the legacy `archived_at` column already exist.
Routes register on the `entry` router, inheriting the CO-161 visibility +
writer gates. Standalone threads are those with `anchor_entry_path IS NULL AND
parent_thread_id IS NULL` — distinct from the entry-anchored `comments` view.

| Route | Purpose |
|-------|---------|
| `GET /{slug}/threads` | List standalone threads the caller can access (`?include_archived`). |
| `POST /{slug}/threads` | Create a thread — `scope: all\|subset\|self` (`+ members` for subset). |
| `GET /{slug}/threads/{thread_id}` | Read messages + recursive child threads (replies). |
| `POST /{slug}/threads/{thread_id}/messages` | Post a message; `parent_id` ⇒ recursive reply. |
| `POST /{slug}/threads/{thread_id}/archive` | Archive / un-archive (`{archived}`). |

- `scope: all` maps to the storage scope `universe`; `subset`/`self` are gated by
  `chat_room_members` via `can_access_thread` (subset non-member → 403; self →
  private to the creator).
- Live delivery reuses `broadcast_event(&ChatBroadcast, &ChatEvent)` (CO-468
  serialize-once) — every post publishes `ChatEvent::MessageCreated`.
- Existence checks run before taking the storage lock (CO-472 re-entrant-deadlock
  hazard: `storage_trait` and `storage` share one `parking_lot::Mutex`).

## Acceptance

- [x] `POST /{slug}/threads` creates a thread for scope `all` / `subset` / `self`
  (201); `subset` admits the listed members, `self` is creator-only.
- [x] `GET /{slug}/threads` lists the standalone threads the caller can access,
  filtering anchored/child threads out and archived threads (unless
  `?include_archived=true`); scope gating enforced via `can_access_thread`.
- [x] `GET /{slug}/threads/{thread_id}` returns the thread, its messages, and its
  recursive child threads (nested replies).
- [x] `POST /{slug}/threads/{thread_id}/messages` posts a message; `parent_id`
  spawns a recursive child thread (nested replies).
- [x] Subset thread: a non-member (even a universe member) is rejected (403) on
  GET and POST; a subset member is accepted.
- [x] Self thread: private to the creator (other universe members get 403).
- [x] `POST /{slug}/threads/{thread_id}/archive` archives / un-archives a thread
  (creator or universe manager only); archived threads drop out of the default
  list.
- [x] Live delivery: posting into a thread publishes a `ChatEvent` over the chat
  broadcast bus (asserted via a broadcast subscriber), reusing the CO-468
  serialize-once `broadcast_event` path — no regression.
- [x] Integration tests (`tower::ServiceExt::oneshot`, in-process) cover every
  route above; storage unit tests cover list-by-scope/archive + standalone vs
  anchored filtering.
- [x] `docs/architecture/api-catalog.md` documents the `threads` routes;
  `openapi.yaml` regenerated with no drift (`npm run openapi:check`).
- [x] `cargo test` green; `cargo clippy --workspace -- -D warnings` clean; `cargo fmt`.

## Implemented now

The standalone scoped-thread REST surface CO-472 deferred, end-to-end with tests,
reusing the existing v092 storage + the chat `ChatEvent` bus:

- Storage: `list_threads_for_user` (scope- + archive-filtered standalone list)
  and `set_thread_archived`; `Thread` now carries `archived_at`.
- Routes (`/{slug}/threads…`) on the visibility-gated entry router with live
  `ChatEvent` delivery on every post.

## Deferred follow-ups

- **Resolve / unresolve** as a first-class, *separate* thread state. This needs a
  net-new `resolved_at` column on `chat_rooms`, i.e. a numbered migration beyond
  v092 — out of scope for this task (which is explicitly no-migration). Archive
  (this task) covers the "close a thread" need via the existing `archived_at`
  column; a distinct resolved state is tracked separately.
- **Migrating task comments** (`/projects/{key}/tasks/{id}/comments`) onto the
  unified thread model — still tracked under CO-472's deferred list.
