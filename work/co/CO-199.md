## As

a user who isn't always logged in

## I Need

a notification engine that records important events for me — new chat
messages in rooms I belong to, new DMs, universe invitations I receive,
and mentions of my name — plus per-user preferences for which events
I want to be notified about

## So That

the rest of Phase 5 (email digests in CO-200, web push in CO-201,
in-app notification center in CO-202) all consume from a single
unified `notifications` table with consistent event semantics.

---

## Why a separate ticket from the delivery channels

Phase 5 is split so each delivery channel is independently shippable:

| Slice | Ticket | What | Estimate |
|---|---|---|---|
| 1 | **CO-199 (this)** | Backend engine — schema, event capture, preferences | ~½ day |
| 2 | CO-200 | Email digest delivery (daily/hourly) | ~½ day |
| 3 | CO-201 | Web push (browser Push API + service worker) | ~1 day |
| 4 | CO-202 | In-app notification center UI (🔔 dropdown) | ~½ day |

No delivery yet — that comes in CO-200/201/202. Each subsequent ticket
just reads from `notifications` table.

## Schema

```sql
-- Per-user notification log. Append-only; UI reads + marks read.
CREATE TABLE IF NOT EXISTS notifications (
    id              TEXT PRIMARY KEY,        -- notif_xxxxx
    user_id         TEXT NOT NULL,           -- recipient
    event_type      TEXT NOT NULL,           -- 'chat.message' | 'chat.dm' | 'universe.invitation' | 'chat.mention'
    universe_key    TEXT,                    -- nullable; for universe-scoped events
    room_id         TEXT,                    -- nullable; for chat events
    actor_id        TEXT,                    -- who triggered the event (author/inviter)
    object_id       TEXT,                    -- the target object id (message_id, invitation_id)
    summary         TEXT NOT NULL,           -- short i18n key + params JSON for rendering
    created_at      TEXT NOT NULL,
    read_at         TEXT,                    -- nullable; set on mark-read
    delivered_email_at TEXT,                  -- CO-200 sets this
    delivered_push_at  TEXT,                  -- CO-201 sets this
    FOREIGN KEY (user_id) REFERENCES users(id)
);
CREATE INDEX IF NOT EXISTS idx_notifications_user_unread
    ON notifications(user_id, read_at);
CREATE INDEX IF NOT EXISTS idx_notifications_user_created
    ON notifications(user_id, created_at DESC);
CREATE INDEX IF NOT EXISTS idx_notifications_pending_email
    ON notifications(delivered_email_at) WHERE delivered_email_at IS NULL;

-- Per-user notification preferences. Defaults to "all email + all push".
CREATE TABLE IF NOT EXISTS notification_preferences (
    user_id              TEXT PRIMARY KEY,
    email_chat_message   INTEGER NOT NULL DEFAULT 0,  -- chat in universe rooms — default OFF (noisy)
    email_chat_dm        INTEGER NOT NULL DEFAULT 1,  -- DMs — default ON
    email_invitation     INTEGER NOT NULL DEFAULT 1,  -- universe invites — default ON
    email_mention        INTEGER NOT NULL DEFAULT 1,  -- mentions — default ON
    email_digest_freq    TEXT NOT NULL DEFAULT 'daily',  -- 'instant' | 'hourly' | 'daily' | 'weekly' | 'never'
    push_chat_message    INTEGER NOT NULL DEFAULT 1,
    push_chat_dm         INTEGER NOT NULL DEFAULT 1,
    push_invitation      INTEGER NOT NULL DEFAULT 1,
    push_mention         INTEGER NOT NULL DEFAULT 1,
    in_app_chat_message  INTEGER NOT NULL DEFAULT 1,
    in_app_chat_dm       INTEGER NOT NULL DEFAULT 1,
    in_app_invitation    INTEGER NOT NULL DEFAULT 1,
    in_app_mention       INTEGER NOT NULL DEFAULT 1,
    quiet_hours_start    TEXT,                          -- 'HH:MM' local time; nullable
    quiet_hours_end      TEXT,                          -- 'HH:MM' local time; nullable
    quiet_hours_tz       TEXT NOT NULL DEFAULT 'America/Sao_Paulo',
    updated_at           TEXT NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

Backfill on boot: every existing user gets a default `notification_preferences`
row via `INSERT OR IGNORE`.

## Event capture — wire into existing producers

CO-199 doesn't introduce new endpoints for *triggering* events — it
wires into existing emit-sites:

| Event | Hook point | Recipients |
|---|---|---|
| `chat.message` | `chat_routes::post_message_handler` (CO-193) after WS broadcast | All `chat_room_members` for the room except the author, where `in_app_chat_message=1` |
| `chat.dm` | Same handler, when `chat_rooms.kind='dm'` (CO-198) | Just the other DM member |
| `universe.invitation` | `invitation_routes::create_invitation` (CO-188) | The invited user (if they have a CO account; else just stays as email recovery channel) |
| `chat.mention` | `chat_routes::post_message_handler` — parse `@usuario` from body | The mentioned user, if they're a member of the room |

The capture step is one storage method called from each hook:

```rust
storage.create_notification(
    user_id: &str,
    event_type: &str,
    universe_key: Option<&str>,
    room_id: Option<&str>,
    actor_id: &str,
    object_id: &str,
    summary_key: &str,           // i18n key e.g. "notif.chat.message"
    summary_params: serde_json::Value,
)?;
```

Idempotent for `chat.message`: don't create a duplicate if the same
`(user_id, event_type, object_id)` row already exists within the last
5 seconds (handles race conditions on retransmit).

## Endpoints

### `GET /api/v1/me/notifications?since=<ISO>&limit=<n>` (auth)

Returns recent notifications for the caller. `since` is optional
cursor; `limit` default 50, max 200.

```jsonc
{
  "notifications": [
    {
      "id": "notif_abc",
      "event_type": "chat.dm",
      "actor": { "user_id": "...", "display_name": "Maria", "usuario": "maria" },
      "summary": { "key": "notif.chat.dm", "params": {"name": "Maria"} },
      "context": {
        "universe_key": "dm",
        "room_id": "room_dm_xyz",
        "object_id": "msg_..."
      },
      "created_at": "...",
      "read_at": null
    }
  ],
  "unread_count": 7,
  "has_more": false
}
```

### `POST /api/v1/me/notifications/:id/read` (auth)

Mark single notification as read. Returns 200 with updated row.

### `POST /api/v1/me/notifications/read-all` (auth)

Mark all my unread notifications as read. Returns `{ count: N }`.

### `GET /api/v1/me/notification-preferences` (auth)

Returns the caller's prefs row (creating defaults if not exist).

### `PUT /api/v1/me/notification-preferences` (auth)

Body is a partial update — only sent keys are touched. Validates
enum values for `email_digest_freq` and time format for `quiet_hours_*`.

```jsonc
{
  "email_chat_dm": false,
  "email_digest_freq": "hourly",
  "quiet_hours_start": "22:00",
  "quiet_hours_end": "07:00"
}
```

## Quiet hours enforcement

When `create_notification` is called, the row is INSERTED unconditionally
(so the user can see it later). But push (CO-201) checks quiet hours
before delivery, and email (CO-200) batches per the user's frequency
preference.

## Backfill safety

Existing universe members + DM members + open invitations don't get
backfilled notifications — only events from now-forward generate rows.
Rationale: we can't reconstruct "what was unread when the user last
logged in" without snapshotting state in CO-199; that's deferred work.

      idempotently.
- [ ] Boot-time backfill inserts default preferences for every existing
      user.
- [ ] Chat message → notification row for every other room member.
- [ ] DM message → notification row for the other party only.
- [ ] Invitation create → notification row for invited user (when they

- [ ] Preferences GET/PUT work with partial-update semantics.
