## Contexto
Precisamos de um **backup local confiável** + uma **varredura de lixo** que reduza o
`/data` sem perder a capacidade de **reconstruir**, e que escale quando virarmos StaaS.
Reusa o guard/retention do CO-405 e (se mergeado) escreve via o `LocalFsBackend` (CO-458).

## Escopo
### 1. Backup local reconstrutável
- Snapshot consistente de `meta.db` (`VACUUM INTO`/backup API, não cópia a quente) +
  diretórios de `universes/` essenciais → `/data/backups/<ts>/` com **manifesto
  sha256** por arquivo (reconstrução verificável). Via CO-458 backend se disponível.
- Comando/endpoint admin `POST /api/v1/admin/backup` (admin-gated) que dispara e
  retorna o manifesto; reusa o caminho de snapshot existente onde houver.

### 2. Junk sweep (remover desnecessário — com guarda de reconstrução)
- Identificar e remover com segurança: diretórios de **universos anônimos órfãos**
  (sem dono, expirados), **temporários/locks** velhos, **logs** rotacionáveis,
  **blobs órfãos** (refcount 0 em `blob_refs` do CO-458, se existir), snapshots de
  backup além da retenção (CO-405). **NUNCA** apagar sem checar referência/owner.
- Modo **dry-run por default** + relatório (o que apagaria, quanto liberaria);
  `--apply` (ou flag) pra efetivar. Logar tudo (sem deleção silenciosa — feedback_serve_only).

### 3. Otimização de retenção (scale-ready)
- Retenção por **contagem + espaço** (CO-405) parametrizável; documentar a matemática
  de retenção e o ponto em que S3/StaaS assume (CO-458/81).

## Acceptance
- [ ] Backup local consistente (`VACUUM INTO`/backup API) de meta.db + universes → `/data/backups/<ts>/` com **manifesto sha256**.
- [ ] Verificação: re-hash do snapshot == manifesto (prova de reconstrução).
- [ ] Endpoint admin `POST /api/v1/admin/backup` (admin-gated) dispara + retorna manifesto; rota no `api-catalog.md`, `openapi:check` sem drift.
- [ ] Junk sweep: identifica universos anônimos órfãos, temporários, logs, blobs órfãos, backups além da retenção — **dry-run default** + relatório de espaço.
- [ ] `--apply` remove só o seguro (checa owner/refcount); tudo logado; nada apagado sem referência.
- [ ] Retenção por contagem+espaço parametrizável (reusa CO-405); doc da matemática.
- [ ] Testes: backup→verify manifesto; sweep dry-run não apaga; sweep apply remove só órfão; retenção respeita limites. `tempfile`.
- [ ] `cargo test` + `clippy -D warnings` + `fmt` limpos; **sem migração** (reusa tabelas existentes); sem MCP.

## So that
`/data` para de inchar com lixo, o backup é **reconstrutável e verificável**, e a
lógica está pronta pra escalar pro modelo StaaS (CO-458/460) — "local backup for now".

## Não no escopo
- Upload de backup pro S3 (depois de CO-81) · arquivamento de telemetria (CO-449) ·
  cobrança StaaS (CO-460).
