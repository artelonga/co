## As

Any logged-in user opening the chat panel in any CO universe (artelonga, yggdrasil, comunicacao, rfq, qb)

## I Need

The chat composer to be enabled and the "Entre para participar do chat" banner to NOT appear

## So That

I can actually post messages instead of being told I need to log in — even though I am.

## Context

Bug confirmed in `co-web/static/variants/a/modules/chat.js:486-495`. The function `_hasSessionCookie()` does:

```js
return /(^|;\s*)session=/.test(document.cookie || '');
```

…trying to detect the session cookie by regex-matching `document.cookie`. But the session cookie is set with `HttpOnly` at `co-web/src/auth.rs:271`:

```rust
let mut cookie = format!("session={token}; Path=/; HttpOnly; SameSite=Lax; Max-Age={max_age}");
```

The `HttpOnly` flag hides the cookie from JavaScript by design (CSRF/XSS protection). So `_hasSessionCookie()` returns `false` even for authenticated users → `_showAuthHint()` runs (chat.js:505) → user sees "Entre para participar do chat" (chat.js:649).

This affects **every** universe — the chat module is universe-agnostic, the bug is in the auth-detection layer.

## Acceptance

- `_hasSessionCookie()` (or its replacement) returns `true` for authenticated users.
- Recommended fix: rely on the `me` argument already passed to `mountChat()` instead of inspecting `document.cookie`:
  ```js
  function _isAuthenticated() {
      return !!_state?.me;
  }
  // and at line 499:
  if (!_isAuthenticated()) { … }
  ```
- The composer is enabled for logged-in users with roles `owner`/`admin`/`member` (existing `_renderComposer` logic unchanged).
- Anonymous visitors still see the auth hint (no regression).
- Playwright test: log in as yuri, mount chat, assert composer is not disabled and banner is hidden.
- Test across at least 2 universes (template + artelonga or yggdrasil).

## Blast radius

Tiny — single function in a single module. The WS server-side flow is unchanged; this only fixes the client-side gating that incorrectly blocked authenticated users.
