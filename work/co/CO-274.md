## As

A developer kicking co-auto runs (and the user paying for tokens)

## I Need

Each co-auto invocation to load **only what's necessary and sufficient** for the specific task — not 5 layers × ~30k chars = 150k+ tokens of always-loaded context.

## So That

- Hallucination rate drops (less stale/irrelevant context = sharper task focus)
- Usage limits hit later (token budget per task slashed 80%)
- Context rotting (the relevant signal getting buried in deeply-loaded noise) stops being a failure mode

## Context

### What's loaded today

Recent agent kicks logged:

```
◆ Context: 5 layers, 51699 chars   (CO-260)
◆ Context: 5 layers, 55441 chars   (CO-264)
◆ Context: 5 layers, 51092 chars   (CO-265)
◆ Context: 5 layers, 45822 chars   (CO-254)
◆ Context: 5 layers, 44389 chars   (CO-251)
```

Roughly **45k–55k chars per task** in the "layers" alone, plus the task spec body (~5k), plus tool/system prompts.  At Claude's ~4 chars/token, that's **~12k–15k tokens per layer × 5 = 60k–75k tokens just for "context"**, which the user reports comes to **150k+ tokens per session** including system + tools + actual reasoning.

### What the 5 layers likely contain (need to confirm by reading dev/co-auto/src/)

1. **Root `CLAUDE.md`** — workspace-global instructions (versioning policy, branch naming, etc.)
2. **Co-auto-context.md** — copied per-task into the worktree, describes the task system
3. **MODULES.md / architecture map** — file structure + module ownership
4. **Recent git log + open issues** — historical context
5. **Task spec body** — the actual ticket (`work/co/CO-N.md`)

Of these, only #5 changes per-task. The other 4 are largely static across the entire repo.

### What's wasteful

- The MODULES.md gets reloaded every task even when the task only touches `co-web/src/auth/`
- The full CLAUDE.md (versioning, deployment, branch naming) is loaded even for a simple SPA-only fix that won't push or branch
- Recent git log is appended even for refactors that don't care about recent history
- The co-auto-context.md describes the **whole platform** when the task is e.g. "fix a CSS bug in conteudo.js"

## Decision — three tools to cut, in order of leverage

### A. Per-universe / per-space CLAUDE.md (highest leverage)

Each `work/<space>/` already has its own CLAUDE.md (e.g., `work/co/CLAUDE.md`). Extend the pattern:

- A task in `work/co/` ONLY loads `work/co/CLAUDE.md`, not root `CLAUDE.md`
- A task in `work/yggdrasil/` ONLY loads `work/yggdrasil/CLAUDE.md`
- Each per-space CLAUDE.md is < 5k chars (vs root ~15k)
- Root CLAUDE.md becomes "the index of CLAUDE.mds" — references the specific ones

### B. Skills (load on-demand) (medium leverage)

For knowledge that's task-type-specific (not universe-specific):

| Skill | Loaded when |
|---|---|
| `rust-architecture.md` | Task touches `*.rs` files |
| `spa-conventions.md` | Task touches `co-web/static/variants/a/` |
| `deploy-runbook.md` | Task touches `Dockerfile`, `fly.toml`, or `scripts/release-*` |
| `migration-template.md` | Task adds a migration |
| `playwright-pattern.md` | Task adds an e2e test |

The agent's launcher (`dev/co-auto/src/`) inspects the spec's `labels` and `module:` field, then loads only the relevant skills. Each skill is ~2k chars.

### C. Hash-based context cache (low leverage, optional)

The static context layers (CLAUDE.md, MODULES.md) rarely change. Hash them on session start; if unchanged from the last session, reference by ID instead of re-loading the full body. This needs Claude API tool support — likely not feasible today, but worth specifying for future.

### Step 2 — Per-space CLAUDE.md routing

In `dev/co-auto/src/auto.rs`:

```rust
// Before:
let context = build_context(workspace_root)?;  // Loads root CLAUDE.md + universal docs

// After:
let space_claude = task_workdir.join("CLAUDE.md");
let context = if space_claude.exists() {
    build_context_minimal(workspace_root, &space_claude)?
} else {
    build_context_legacy(workspace_root)?  // fallback
};
```

Backwards-compatible — only kicks in when the space has its own CLAUDE.md (and we author one for each).

### Step 4 — Skill loader by label

```rust
fn skills_for_task(spec: &TaskSpec) -> Vec<PathBuf> {
    let mut out = vec![];
    for label in &spec.labels {
        match label.as_str() {
            "module:rust" | "module:storage" => out.push("skills/rust-architecture.md".into()),
            "module:spa" | "module:editor" => out.push("skills/spa-conventions.md".into()),
            "module:deploy" => out.push("skills/deploy-runbook.md".into()),
            "type:test" => out.push("skills/playwright-pattern.md".into()),
            _ => {}
        }
    }
    out.dedup();
    out
}
```

### Step 5 — Token-budget assertion

The launcher logs the assembled prompt's final size. CI test:

```
co-auto context budget per task < 30k chars
```

Fail-fast if a regression bloats context above the budget.

## Acceptance

- A co-auto run for a CO-N task loads: per-space CLAUDE.md (≤3k chars) + 1-2 skills (≤4k chars) + task spec (≤5k chars) = **~12k chars total**, down from 45k+
- Token count per task drops to **~3k tokens of context** (from ~12k)
- Hallucination spot-check: kick 3 tasks; confirm none of them invent files / functions that don't exist due to over-loaded irrelevant context
- New skills directory: `skills/<topic>.md`
- New per-space CLAUDE.mds for each work/<space>/
- `dev/co-auto/src/` learns to assemble minimal context based on task spec's labels/module

## Blast radius

- ~80 LOC in `dev/co-auto/src/` (context assembly + skill loader)
- 5 new per-space CLAUDE.mds (~3k each = 15k chars total, replacing the ~45k currently loaded)
- 5 new skills/*.md files (~2k each)
- 1 new CI test asserting token budget
- Backwards-compatible — old behavior is fallback if per-space CLAUDE.md missing

## Why now

User's exact words: *"we are generating 150k tokens for each session at least, too much for hallucination / usage limits / context rotting etc. cut significantly by keeping only whats necessary and sufficient, use skills and claude.md for efficient universe specific context"*. 

The session has run ~30 co-auto invocations. At 150k tokens each that's 4.5M tokens. With this fix, future sessions hit ~30k per task = 900k for the same throughput. **80% token reduction**, on top of the hallucination + context-rotting wins.
