## GIVEN / WHEN / THEN

- GIVEN `co auth` (any subcommand) against prod, WHEN it calls the API, THEN
  requests carry `User-Agent: co-cli/<version>` and are not rejected with
  `400 missing_user_agent` (regression test: ua_tests in auth.rs binds a
  local socket and asserts the header).
- GIVEN a newcomer reading docs/, WHEN they need the CLI, THEN docs/CLI.md
  documents the real command surface (generated against `co --help` 3.2.x):
  the five daily verbs (auth/push/construir/updates/serve) with examples +
  full command tables; linked from docs/README.md.

## Context

Found live 2026-06-11: owner ran `co auth reset-password` against prod and
was rejected by CO's own CO-397 abuse heuristics — the auth ApiClient builder
never set a UA (push.rs already did). One-line fix + test + docs.
