## What this slice does

Extracts the JWT auth flow (CO-85 password-login, CO-44 UAT-login, magic-code email login) behind an `AuthProvider` trait. Default impl is the current local JWT; future OAuth/SAML/Magic-link providers plug in.

## Scope

1. New trait in `co-web/src/infra/auth.rs`:
   ```
   #[async_trait]
   trait AuthProvider: Send + Sync {
       async fn verify_credentials(&self, creds: Credentials) -> Result<UserClaims>;
       async fn issue_token(&self, claims: UserClaims, ttl: Duration) -> Result<Token>;
       async fn verify_token(&self, token: &Token) -> Result<UserClaims>;
       async fn revoke(&self, token: &Token) -> Result<()>;
   }
   ```
2. Default impl `LocalJwtProvider` wrapping the current `auth::sign_jwt` / `auth::verify_jwt` (uses CO-295's `SecretsProvider` for the signing key)
3. Migrate all auth call sites (login routes, middleware) to use the trait
4. `Credentials` enum supports Password, EmailMagicCode, UatLogin, ApiToken
5. Foundation for adding `OAuthProvider` (Google, GitHub) without touching routes

## Acceptance

- [ ] Trait `AuthProvider` exists; `LocalJwtProvider` implements it
- [ ] All current login flows (password, magic-code, UAT) work through the trait
- [ ] No regressions in `cargo test --test auth_*`
- [ ] Adding a hypothetical OAuth provider would touch only `infra/auth.rs`, not route handlers

## Not in this phase

- Actual OAuth integration (deferred; concrete provider when needed)
- SAML
- Passkeys / WebAuthn
