## As

A user browsing **any** universe (`/co`, `/artelonga`, `/rfq`, `/yggdrasil`, `/quilomboaraucaria`, or any sub-folder within them)

## I Need

The universe (and every sub-folder of it) to behave like a **filesystem-shaped wiki**, where well-known filenames at each level have special rendering:

| File at any folder level | Renders as |
|---|---|
| `index.md` | Folder home page |
| `CHANGELOG.md` | Folder-scoped changelog view |
| `README.md` | Folder-scoped documentation |
| `LICENSE.md` | Folder-scoped license display |

And folder-prefix filtering is a first-class operation — `/co/work/co/` lists entries under `work/co/`, `/co/public/` lists under `public/`, etc.

## So That

The recursive-universe mental model the user laid out (*"nested, hierarchical, recursive universes should guarantee file compatibility at any level"*) is actually true in the data model AND the URLs. Every level looks like every other level. Filtering subsets is just filtering by folder.

Right now (v2.23.0):

- `/changelog` reads the GLOBAL `CHANGELOG.md` only — not the current universe's
- `/sobre` etc. are special-cased per-page slugs (CO-251 wiki)
- There's no consistent "look for index.md / CHANGELOG.md at folder X" abstraction
- Sub-folders don't have their own home pages

## Context

### Today's data shape (good news — already mostly there)

- Every universe has a per-universe SQLite DB
- Entries have a `path` column: `'tasks/CO-261.md'`, `'public/seguranca.md'`, `'index.md'`
- Universes can have `parent_key` referencing another universe → recursive tree (CO-141)
- `serve_deep_link` (CO-232) routes `/<universe>/<subpath>` to entry rendering

### What's missing — the file-compat layer

1. **Universe-scoped CHANGELOG**:
   - `/co/changelog` should render the entry at `path='CHANGELOG.md'` in the `co` universe
   - Today's `/changelog` route is global to the CO platform, not per-universe
   - For sister repos (artelonga/rfq/yggdrasil/quilomboaraucaria), each repo's `CHANGELOG.md` should be the entry at `path='CHANGELOG.md'` in that universe
2. **Folder-level index.md** (partially done for universe root via CO-251):
   - Visit `/co/public/` → render entry at `path='public/index.md'` if it exists, fallback to folder listing
   - Visit `/co/work/co/` → same logic
   - Each folder is its own "mini home page"
3. **Folder-prefix entry list endpoint**:
   - `GET /api/v1/universes/co/entries?path_prefix=public/` → all entries with paths starting with `public/`
   - Already partially possible via existing filters; needs explicit `path_prefix` query param
4. **README.md / LICENSE.md rendering** (low priority — same pattern):
   - Same lookup rules applied at any folder level

### Compatibility across the 5 example universes

The CO universe is built locally (CO-261 walks `work/co/`). For sister repos, the CHANGELOG.md + index.md + README.md of each repo must end up as entries in the corresponding CO universe:

| Universe | Source repo file → entry path | Status today |
|---|---|---|
| `co` | `co/CHANGELOG.md` → `CHANGELOG.md` | needs explicit sync (CO-261 walks `work/` only) |
| `co` | `co/README.md` → `README.md` | needs sync |
| `artelonga` | `artelonga/CHANGELOG.md` → `CHANGELOG.md` | needs cross-repo sync (CO-261 phase B) |
| `rfq` | same | same |
| `yggdrasil` | same | same |
| `quilomboaraucaria` | same | same |

So CO-264 covers BOTH the **routing/rendering** layer AND extends **CO-261's seeder** to pick up these well-known top-of-repo files (CHANGELOG, README, LICENSE) in addition to the `work/<space>/` folder.

## Scope

### Backend — file-compat seeder extension

In `co-web/src/storage/seed.rs` (extending CO-261):

- For the local `co` universe, in addition to walking `work/co/`:
  - Read `<repo-root>/CHANGELOG.md` → upsert as entry path `CHANGELOG.md` type `page`
  - Read `<repo-root>/README.md` → upsert as `README.md` type `page`
  - Read `<repo-root>/LICENSE` (any extension) → `LICENSE.md` type `page`
- For sister-repo universes, when CO-261 phase B (file-watcher / co-sync) lands, the same set of files transfers
- Frontmatter not required — if absent, infer title from H1 or filename

### Backend — folder-level resolution

In `co-web/src/server/static_files.rs` `serve_deep_link` (or a new helper):

- When the user visits `/<universe>/<subpath>/` (trailing slash, no specific entry):
  - Try `entries WHERE path = '<subpath>/index.md'` — if found, render it
  - Else render a folder-listing view (entries with `path_prefix = '<subpath>/'`)
- When the user visits `/<universe>/changelog` (no .md suffix):
  - First try `entries WHERE path = 'CHANGELOG.md'` (universe-root changelog)
  - Else if `<universe>` resolves to a sub-folder, look at parent: `entries WHERE path = '<parent>/CHANGELOG.md'`
  - Else "not found" view
- New endpoint: `GET /api/v1/universes/<slug>/entries?path_prefix=<prefix>` for the SPA's folder navigator

### Frontend — folder-aware navigation

- Sidebar's project list can be replaced by (or supplemented with) a folder tree of the current universe
- "Conteúdo" view: when on `/<universe>/<folder>/`, render that folder's `index.md` (if present) + a sub-listing of files in that folder
- `/<universe>/changelog`: render the universe's `CHANGELOG.md` entry (same rendering pipeline as any other markdown entry); empty state = "Esta universo ainda não tem um CHANGELOG. Crie um arquivo `CHANGELOG.md` no nível raiz."

### Acceptance — verify across all 5 universes

After CO-264 lands + seeders re-run:

| URL | Expected | Today |
|---|---|---|
| `/co/changelog` | renders CO's CHANGELOG.md (v2.23.0 → v2.13.x history) | ⚠ shows global registry-style view from CO-260 backend |
| `/artelonga/changelog` | renders artelonga's CHANGELOG (0.13.0 → 0.14.0) | ❌ not seeded yet |
| `/rfq/changelog` | renders RFQ's CHANGELOG | ❌ not seeded |
| `/yggdrasil/changelog` | renders Yggdrasil's CHANGELOG (with v1.0.0 epic notes) | ❌ not seeded |
| `/quilomboaraucaria/changelog` | renders QB's CHANGELOG | ❌ not seeded |
| `/co/public/` | renders `public/index.md` if present, else folder listing | ❌ no folder-resolution today |
| `/co/work/co/` | folder listing of CO-N tasks | ⚠ rendered as deep-link to a single entry today |

### Edge cases

- Trailing-slash vs no-slash routing (CO-232/2.12.3 hotfix territory)
- Folder containing both `index.md` AND child entries → index.md is rendered + a "Files in this folder" section below
- Empty folders (no index.md, no children) → 404 with helpful "Crie um arquivo nesta pasta" message
- Case-insensitivity (CHANGELOG.md vs Changelog.md vs changelog.md) — accept all, prefer uppercase
- Sub-universe rendering: today `template` is parent_key=co. When user visits `/co/template`, should we treat that as a sub-universe (full render) or as a folder (folder listing)? Decision: prefer sub-universe rendering when there's a row in `universes` with `parent_key=co AND key=template`; fall through to folder-listing otherwise.

- `/artelonga/changelog`, `/rfq/changelog`, `/yggdrasil/changelog`, `/quilomboaraucaria/changelog` all return either:
  - 200 with rendered universe-specific CHANGELOG if seeded, OR
  - 404 with "not found" view (graceful) until cross-repo sync lands

- The same pattern works for any other universe — no special-casing per universe
- New Playwright spec `co-web/e2e/recursive-universe.spec.ts` asserts:
  - `/co/changelog` and `/artelonga/changelog` (the live ones) both work
  - `/co/public/` folder rendering
  - `path_prefix` filter API
- Documentation in MODULES.md (CO-225 territory) describes the file-compat conventions

## Blast radius

- ~200 LOC backend: extend seeder for top-of-repo files (~50), add folder resolution in serve_deep_link (~80), add `path_prefix` query param (~30), changelog-from-universe route (~40)
- ~150 LOC frontend: folder breadcrumbs, folder-listing view, "this universe has no CHANGELOG" empty state
- New migration: optional `is_folder_index` boolean on entries to speed up `index.md` lookups

## Why now

The user's session-end report: "*changelog not showing up in universes, should read from CHANGELOG or not found, just like home should read from index.md and subsequent folders as well, nested, hierarchical, recursive universes should guarantee file compatibility at any level*". This is the architecture vision that's been implicit in CO-141 (sub-universes), CO-251 (wiki landing), CO-252 (co dev surface), CO-261 (work/*.md sync) — but never explicit as a unified file-compat contract.

Once CO-264 lands, every CO universe IS a wiki + dev-board + docs site with the same shape, and adding a new repo is just "make sure its CHANGELOG.md + index.md ride along with the existing sync".
