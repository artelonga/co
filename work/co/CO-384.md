## As
Yuri running CO + Yggdrasil + multiple devices (laptop, mobile, friend's machine)

## I Need
A federated event bus bridge: persistent bidirectional WS connections between deployments (CO ↔ Yggdrasil) and between deployments and devices (cloud bus ↔ local CO instance). Events publish via local bus (CO-380), traverse the bridge, land on remote subscribers within ms. No polling, no fetch loops, no scheduled jobs.

## So That
- The IaaS service primitive is the **bounded event stream**, not request/response polling.
- A note edited in Yggdrasil appears in CO's live timeline (`/agora`) within 300ms — visible to every connected device.
- An edit on mobile reaches the laptop the moment the laptop's bus reconnects (replay queue).
- The brain (user) experiences sync as continuous, never as a 5-minute lag.
- CO-383 (Yggdrasil ingest) becomes a thin subscriber on top of this primitive; future integrations (other deployments, other services) reuse the bridge.

## Context

CO-380 ships the in-deployment event bus (tokio broadcast). What it lacks: cross-deployment + cross-device fanout. This spec adds that as a new transport layer.

The user model (decided 2026-06-06):
1. User views production (yggdrasil)
2. User opens CO's latest snapshot (which CO holds locally from prior subscription)
3. User modifies locally
4. Modifications approved (local-host + staging gates per CO-382 DoD CI)
5. Approved changes publish proactively: CRUD request to source → changelog mod → auto conflict resolve → CI/CD verifications → live version online
6. Cross-device sync: if user modifies same thing on mobile, PC notices via bus events (NOT polling); jujutsu-style conflict resolution applies

The "jujutsu-style" piece is CO-385 (v3.1). This spec ships the transport.

## Design

### Bridge protocol

WebSocket-based. One persistent connection per (source, target) deployment pair. Heartbeat every 30s. Reconnect with exponential backoff (1s, 2s, 4s, 8s, max 30s).

```
GET /api/v1/events/bridge?source=co.artelonga.com.br&token=<jwt>
Upgrade: websocket
Sec-WebSocket-Protocol: co.eda.bridge.v1
```

Server validates token (must be issued by source deployment AND trusted by target). After handshake, bidirectional Event messages flow.

### Event envelope (federated extension of CO-380's Event)

```rust
#[derive(Clone, Debug, Serialize)]
pub struct FederatedEvent {
    pub event: Event,              // CO-380's Event
    pub origin_deployment: String, // e.g. "yggdrasil.artelonga.com.br"
    pub signed_by: String,         // JWT-signed origin's identity
    pub bridge_received_at: DateTime<Utc>,
    pub hop_count: u8,             // prevents infinite federation loops
}
```

Events with `hop_count > 3` are dropped (loop guard).

### Topology

| Connection | Role |
|---|---|
| CO ↔ Yggdrasil (bidirectional WS) | Both publish, both subscribe; bidirectional |
| CO Fly ↔ Mobile device (per-user WS) | Device subscribes to user's scoped events; publishes its edits back |
| Yggdrasil Fly ↔ Yggdrasil-side device | Same pattern, separate bus |
| Future: CO ↔ Quilombo, CO ↔ ArteLonga static | When those deployments add EDA support |

Bus topology is **star-with-bridges**, not full mesh:
- Each deployment has its own bus (CO-380 instance)
- Bridges connect pairs of deployments
- Devices connect to one bus (their primary deployment)
- No N×N mesh; scales as deployments + devices grow linearly

### Subscriber model

A subscriber (e.g. CO-383 Yggdrasil-notes handler, CO-381 live timeline) registers a Filter against its LOCAL bus. The bridge:
1. Receives a FederatedEvent from the remote bus
2. Republishes locally with `event.origin_deployment` tagged
3. Local subscribers' Filters fire normally

Subscribers don't know or care if the event came from local or remote — uniform interface.

### Backpressure + queueing

If a bridge is disconnected (network drop, remote deployment restart):
- Sender's bus buffers undelivered events to `event_log` table (CO-380 schema)
- On reconnect, sender replays events since last delivered (tracked per bridge in `bridge_state` table)
- Receiver acks `last_event_id` on reconnect
- Replay is idempotent (events keyed by ULID; receivers dedupe)

```sql
CREATE TABLE bridge_state (
    id TEXT PRIMARY KEY,             -- '<source>:<target>'
    source_deployment TEXT NOT NULL,
    target_deployment TEXT NOT NULL,
    last_delivered_event_id TEXT,    -- ULID of last ACK'd event
    last_connected_at TEXT,
    last_disconnected_at TEXT,
    state TEXT NOT NULL CHECK (state IN ('connected','disconnected','degraded'))
);
```

Migration v65.

### Auth + trust

Bridge auth = JWT signed by source's identity. Target validates against source's `/.well-known/jwks.json` (existing OIDC endpoint per CO-211 catalog).

Trust list: env var `CO_BRIDGE_TRUSTED_SOURCES` (CSV of deployments). Default: empty (rejects all). Operator opts in per integration.

### Privacy filter (federation rules)

Bridge enforces CO-380's Visibility rules at the BRIDGE level — events tagged `Visibility::UniverseOwner` or `Visibility::UserOnly` are NEVER federated unless the target has the relevant credential. Public + UniverseMembers events flow. Private events stay local.

### Devices (mobile, laptop) — the local-first piece

For v3.0 scope: device = a WebSocket client subscribed to its user's event scope on the cloud bus. Stored state is the cached event_log replay.

Local-first edit (offline → reconnect → publish) is a **v3.1 deepening** (CO-386 — full local-first snapshot model). For v3.0:
- Device shows last-cached state when offline
- On reconnect, drains pending publishes
- Conflict resolution = "remote wins" (CO-385 enriches this in v3.1)

### Bootstrap (config)

```bash
# CO Fly secrets
flyctl secrets set CO_BRIDGE_TRUSTED_SOURCES="yggdrasil.artelonga.com.br" -a co-artelonga
flyctl secrets set CO_BRIDGE_OUTBOUND_TOKENS_JSON='{"yggdrasil.artelonga.com.br":"<jwt>"}' -a co-artelonga

# Yggdrasil Fly secrets (matching pair)
flyctl secrets set YGG_BRIDGE_TRUSTED_SOURCES="co.artelonga.com.br" -a yggdrasil-artelonga
```

### Telemetry (via CO-380 bus)

- `bridge.connected{source,target}` per WS open
- `bridge.disconnected{source,target,reason}` per drop
- `bridge.event_received{source}` per inbound event (sampled at 1%)
- `bridge.event_sent{target}` per outbound (sampled at 1%)
- `bridge.replay_completed{source,events_count}` per reconnect drain

All visible in `/agora` live timeline.

### Failure modes (explicit)

| Mode | Behavior |
|---|---|
| Remote deployment down | Bridge marks `disconnected`; local subscribers don't see remote events; events accumulate in remote's `event_log` for eventual replay |
| Network partition | Same as remote down |
| Slow consumer | Bus uses bounded broadcast channel (1024 events); slow consumer drops events with metric; reconnect triggers replay |
| Auth token expired | Bridge marks `degraded`; logs error; retries with refresh (operator alert) |
| Loop (A → B → A) | Hop count > 3 drops event |
| Malicious source | Trust list rejects unknown sources at handshake |
