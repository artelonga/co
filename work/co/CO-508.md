GIVEN the term across the codebase is "bot" (~308 occurrences in the co repo + 18
files in `tools/whatsapp-bot`) but the architecture direction is **agents, not bot** —
CO is a general agent platform — and the word should be `agent` (en) / `agente` (pt-BR)
everywhere,
WHEN we rename "bot" → agent/agente, treating docs/tasks/changelogs as a free cosmetic
sweep but the **wire contract** (env vars, headers, routes, Rust module) as a
coordinated migration with aliases,
THEN the platform speaks "agent" consistently, without breaking any live deploy.

## Acceptance

- [ ] **Cosmetic sweep** (no behavior change): docs, task files, changelog-pending,
  comments, internal identifiers → `agent` (en) / `agente` (pt-BR).
- [ ] **Wire contract migrated WITH back-compat aliases** (don't break deploys):
  `CO_BOT_BRAIN_URL`/`CO_BOT_*` env vars, `X-Bot-Secret` header, `/bot/chat` route,
  `bot_proxy_routes.rs` module → agent-named equivalents; old names continue to work.
- [ ] `tools/whatsapp-bot` internals renamed where safe; the directory rename (if any)
  is called out separately and aliased so launch scripts/ops don't break.
- [ ] **pt-BR uses "agente"** (not "robô", not "bot") consistent with the domain glossary.
- [ ] Build/tests/CI green after the rename; no dangling references to removed names
  except the intentional aliases.
- [ ] No tenant-specific names introduced during the sweep (stays generalist).

## Notes
- Pairs with CO-507, which migrates the *same* wire contract for the thin-client work;
  keep the alias set consistent between the two tasks (single source of alias truth).
- The risky part is the wire contract — env/header/route/module names that other
  processes and deploys depend on. Everything else is a find-and-replace.
- Confirms the project's voice: **agent/agente**, never "bot".
