GIVEN similarity, topology, and search all need vectors but disagree on HOW a vector
is produced — neural embeddings (Ollama nomic/mxbai), statistical co-occurrence
(PMI/TF-IDF, no model), or raw numeric passthrough — and topologia already has an
ad-hoc `Embedder` trait with a "3.5 interim" PMI path,
WHEN we define **one `Vectorizer` trait** whose contract is `input → Vec<f32>`
regardless of the production method,
THEN every downstream (similarity/topology/search) depends only on `Vec<f32>` + a
`Metric`, never on the source, and swapping the vector source is a flag, not a refactor.

## Acceptance

- [ ] **One trait, representation-agnostic**: `kind() → Repr {Neural|Statistical|Numeric|Hashed}`,
  `dim()`, `embed(items) → Vec<Vec<f32>>`, plus a `Metric` (cosine/dot) the downstream uses.
- [ ] **Neural impl**: Ollama-backed (nomic/mxbai), local-first default.
- [ ] **Statistical impl**: PMI / co-occurrence / TF-IDF with NO model — pure computation.
- [ ] **Raw-numeric impl**: passthrough for vectors that are already numeric.
- [ ] **Downstream depends only on `Vec<f32>` + `Metric`** — similarity/topology/search
  never reference which `Vectorizer` produced the vector.
- [ ] **Subsumes topologia's `Embedder`** trait and its PMI "3.5 interim" path: topologia
  becomes one `Vectorizer` impl, not a parallel abstraction.
- [ ] **Generalist**: no tenant names; the source is DB/config-driven. "swap = a flag."

## Notes
- Sibling to CO-504's `Backend` trait (model-agnostic agent runtime): `Vectorizer` is the
  representation-agnostic counterpart. Same principle — the consumer depends on the contract,
  not the implementation.
- Local-first: neural impl defaults to local Ollama; statistical/numeric impls run on-box
  with no model at all, keeping the self-host invariant (CO-497) intact.
- Term is **vetor/Vectorizer**; the trait carries no "embedding == neural" assumption.
