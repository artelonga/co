GIVEN co-web already has a `universes` table (key, name, owner_id) and universe_members join table,
WHEN I extend it to support public universe creation with slug-based routing,
THEN:

- [ ] Add columns to `universes` table: `slug TEXT UNIQUE`, `description TEXT`, `theme_preset TEXT DEFAULT 'scholarly'`, `content_count INTEGER DEFAULT 0`, `is_template BOOLEAN DEFAULT false`, `is_public BOOLEAN DEFAULT true`
- [ ] Migration: ALTER TABLE universes ADD COLUMN for each new field, seed template universe with `is_template=true, slug='template'`
- [ ] `POST /api/v1/universes` — create universe (accepts: name, slug, description). No auth required. Generates unique slug if collision. Sets owner_id if authenticated, NULL if anonymous. Returns universe object with slug
- [ ] `GET /api/v1/universes` — list public universes (paginated, 20/page)
- [ ] `GET /api/v1/universes/:slug` — get universe by slug (public info)
- [ ] `DELETE /api/v1/universes/:slug` — delete universe (owner or admin only, auth required)
- [ ] `PUT /api/v1/universes/:slug` — update name, description, theme_preset (owner only)
- [ ] `POST /api/v1/universes/:slug/clone` — clone template: copies all content entries from source universe into new universe with caller's slug/name
- [ ] Slug validation: lowercase alphanumeric + hyphens, 3-48 chars, no reserved words (template, api, auth, admin, static)
- [ ] Anonymous universe tracking: set `co_universe_owner` cookie (nanoid) so anonymous users can edit their universe across sessions
- [ ] Route mounting: `/co/:slug` serves the board UI scoped to that universe
- [ ] `/co` (no slug) serves the template universe (read-only)
- [ ] Board API (`/api/projects/*`) respects universe scope from URL context
- [ ] Unit test: create universe, get by slug, clone template, delete
- [ ] Integration test: anonymous create → edit → hit limit flow
- [ ] `cargo test` passes, `cargo clippy -- -D warnings` clean
