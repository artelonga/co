GIVEN today the only persistent copy of all four content sources (`~/projects/quilomboaraucaria`, `~/projects/ArteLonga`, `~/projects/rfq-gateway`, and the future `~/projects/mbya`) lives on a single laptop disk + their respective `co.fly.io` deployments, AND the only "backup" of the *deployed* state is the Fly volume snapshot (operator-managed, not user-driven, single-region), AND CO-104 covers prod-side daily snapshots to S3 but does NOT cover the local-source ground truth that yuri authors against,
WHEN we define a **co-compatible archive format** (a Co-shaped state dir per universe — `co.db` + `universes/<key>/` markdown — wrapped in a deterministic, storage-optimized bundle) AND a `scripts/backup-to-disk.sh` that produces one such archive per source repo onto an external HD,
THEN the four content sources have a portable cold-storage representation that any Co instance can boot from (no migration needed — drop the archive's `co.db` and `universes/` into a fresh `data_dir`), the bundle deduplicates and compresses to ≈ 10× smaller than the raw markdown tree, and yuri's external HD becomes the single-source-of-truth for "what was the world like at time T."

## Format spec

A universe archive is a single `.tar.zst` file with the following internal layout:

```
<universe_key>/
├── manifest.json                — universe metadata
├── co.db                        — SQLite extract: rows for THIS universe only
│                                  (universes, universe_members, entries, ops, …)
├── entries/                     — full markdown tree
│   ├── projects/<key>/_project.md
│   ├── content/*.md
│   ├── events/*.md
│   └── …                        (mirror of /data/universes/<key>/)
└── README.md                    — human-readable provenance: source path, jj
                                  commit, deployment, archived_at, hash
```

`manifest.json` shape:

```json
{
  "format_version": 1,
  "universe_key": "qa",
  "name": "Quilombo Araucária",
  "description": "...",
  "owner_email": "yuri@artelonga.com.br",
  "visibility": "public-subscribable",
  "theme_preset": "quilombo",
  "layout": "board",
  "parent_key": null,
  "source_repo": "/Users/artelonga/projects/quilomboaraucaria",
  "source_commit": "d44ff5c1b…",
  "source_jj_commit": "kqzzlwxuvkr…",
  "deployment_snapshot": "https://co-artelonga.fly.dev",
  "archived_at": "2026-04-30T12:34:56Z",
  "entry_count": 95,
  "tar_zst_sha256": "ab12cd…",
  "co_db_schema_version": 13
}
```

`co.db` is produced via `sqlite3 .backup` against the **target** machine after `seed-prod-universes.sh` has finished — so the archive captures the deployed state, not just the local source. (For local-only archives — e.g., before first deploy — generate a fresh in-memory `co.db` by running the seed script's logic against an empty `data_dir`.)

## Bundle layout on external HD

```
/Volumes/<drive>/co-archive/
├── README.md                                  — restore instructions
├── 2026-04-30/                                — date of archive run
│   ├── manifest.json                          — global manifest: archive run metadata
│   ├── quilomboaraucaria.tar.zst              — 70-entry public, legacy-migrated
│   ├── qa.tar.zst                             — 95-entry working files (was qa-dev)
│   ├── artelonga.tar.zst                      — 146-entry private dev content
│   ├── rfq.tar.zst                            — 14-entry private trading notes
│   └── mbya.tar.zst                           — N-entry stress-test corpus (CO-109)
└── 2026-05-07/                                — next weekly run
    └── …
```

Compression target: zstd level 19 (or 22 for archive runs that don't need to be fast). Markdown-heavy content compresses to ≈ 8-12× smaller. SQLite extracts compress similarly well.

## Script — `scripts/backup-to-disk.sh`

```bash
#!/usr/bin/env bash
# Usage: bash scripts/backup-to-disk.sh /Volumes/Backup [--from prod|uat|local]
set -euo pipefail
TARGET_DIR="${1:?usage: backup-to-disk.sh <mount-path> [--from <deployment>]}"
SOURCE="${2:---from local}"; SOURCE="${SOURCE#--from }"; SOURCE="${SOURCE:-local}"

DATE=$(date -u +%Y-%m-%d)
OUT="$TARGET_DIR/co-archive/$DATE"
mkdir -p "$OUT"

# Map: universe_key → source_local_path
declare -A SOURCES=(
    [quilomboaraucaria]="/Users/artelonga/projects/quilomboaraucaria"
    [qa]="/Users/artelonga/projects/quilomboaraucaria"   # same source, different framing
    [artelonga]="/Users/artelonga/projects/ArteLonga"
    [rfq]="/Users/artelonga/projects/rfq-gateway"
    [mbya]="/Users/artelonga/projects/mbya"
)

for key in "${!SOURCES[@]}"; do
    src="${SOURCES[$key]}"
    [ -d "$src" ] || { echo "skip $key — source $src missing"; continue; }
    bash "$(dirname "$0")/_archive-one.sh" "$key" "$src" "$OUT" "$SOURCE"
done

# Global manifest
python3 "$(dirname "$0")/_archive-manifest.py" "$OUT" > "$OUT/manifest.json"

echo "Archive complete: $OUT"
du -sh "$OUT"/*.tar.zst
```

`_archive-one.sh` per-universe steps:

1. `co sync status --to <deployment> --universe <key>` (or fall back to local-only inventory if `--from local`)
2. `sqlite3 /data/co.db ".backup /tmp/<key>.db"` extracted via `flyctl ssh console -C` if remote, or local data_dir if local-only
3. `tar cf - <key>/entries <key>/manifest.json <key>/co.db | zstd -19 > <out>/<key>.tar.zst`
4. SHA256 the result; write into manifest

## Restore — `scripts/restore-from-disk.sh`

```bash
bash scripts/restore-from-disk.sh /Volumes/Backup/co-archive/2026-04-30/qa.tar.zst /tmp/restored-co
```

Inverse: extract the tar.zst, drop `co.db` + `universes/qa/` into target `data_dir`. Run Co against that data_dir → it boots with the archived state intact. The manifest's `co_db_schema_version` is checked against the binary's expected version; mismatch fails loudly.

## Storage budget

Rough estimate at current corpus sizes:

| Universe | Raw .md size | Compressed (zstd-19) |
|---|---|---|
| quilomboaraucaria | ~600 KB (70 entries) | ~50 KB |
| qa | ~1.2 MB (95 entries) | ~100 KB |
| artelonga | ~3 MB (146 entries) | ~250 KB |
| rfq | ~280 KB (14 docs, mostly long-form) | ~40 KB |
| mbya | ~50-200 MB (depends on lexicon ingestion strategy, see CO-109) | ~5-25 MB |
| **Per archive run** | **~55-205 MB** | **~5.5-25.5 MB** |

A year of weekly archives = ~50 runs × 25 MB = ~1.25 GB. Comfortably fits on any external HD with room for hundreds of years.

## Source semantics: `--from local | uat | prod`

| Mode | What gets archived |
|------|---|
| `--from local` | Just the local source (`~/projects/<repo>`). No SQLite — generate a synthetic one by running seed logic in-process. Useful before first deploy. |
| `--from uat` | UAT's actual deployed state. SSH'd `co.db` extract + `universes/` rsync. |
| `--from prod` | Prod's actual deployed state. **Default.** |

## Out of scope

- Encryption of archive contents (CO-86 territory; archives currently mirror Co's plaintext-at-rest reality)
- Cross-machine restore (`scp` the .tar.zst is the workflow; no automated network transfer)
- Bitrot-resistant erasure coding (par2 or similar) — defer until first incident
- Archive search (`grep` inside archives) — out of scope; restore first, then search
