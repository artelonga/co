## As

a user trying to play a 50 MB video or load a board with 200 thumbnails on mobile

## I Need

`GET /assets/{sha256}` to honor `Range:` requests, set `Cache-Control: private, max-age=31536000, immutable` + ETag, and the SPA to cache decrypted blobs in IndexedDB keyed by sha256

## To

stream large media without buffering the whole file, and never refetch the same asset twice in a session

## Implementation

### Server: range support

```rust
async fn get_asset(...) -> Response {
    let (meta, plaintext) = state.storage.get_asset(...)?;  // full decrypt (CO-148)
    let range = headers.get(RANGE).and_then(parse_range);

    match range {
        Some((start, end)) => {
            let slice = &plaintext[start..=end];
            Response::builder()
                .status(206)
                .header(CONTENT_RANGE, format!("bytes {}-{}/{}", start, end, plaintext.len()))
                .header(CONTENT_LENGTH, slice.len())
                .header(ACCEPT_RANGES, "bytes")
                .header(CACHE_CONTROL, "private, max-age=31536000, immutable")
                .header(ETAG, format!("\"{}\"", sha256))
                .body(slice.into())
        }
        None => Response::builder()
            .status(200)
            .header(CONTENT_LENGTH, plaintext.len())
            .header(ACCEPT_RANGES, "bytes")
            // ... same cache + etag
            .body(plaintext.into()),
    }
}
```

Phase 4 keeps full-decrypt-then-slice (CO-148 designed for this). Phase 6 (future) adds chunked-AEAD for files > 50 MB.

### Client: IndexedDB cache

New module `co-web/static/js/asset_cache.js`:
```js
async function fetchAsset(universeKey, sha256) {
    const cached = await idbGet(`asset:${sha256}`);
    if (cached) return cached;

    const resp = await fetch(`/api/v1/universes/${universeKey}/assets/${sha256}`);
    if (!resp.ok) throw new Error(`asset ${sha256} fetch failed: ${resp.status}`);
    const blob = await resp.blob();
    await idbPut(`asset:${sha256}`, blob);
    return blob;
}
```

Eviction: LRU at 100 MB total cache; cold blobs evicted on quota pressure.

### Range coalescing for video

Browser `<video>` element issues multiple range requests. Server handles each independently (no streaming session state). IndexedDB cache stores the *full* blob once any range request fully completes — partial-range fetches don't populate cache (would corrupt subsequent reads).

## Acceptance

- [ ] `Range: bytes=0-1023` returns 206 with `Content-Range: bytes 0-1023/<size>`
- [ ] `Range: bytes=1024-` returns 206 with the rest
- [ ] Invalid range returns 416
- [ ] `If-None-Match: "<sha>"` returns 304 (already in CO-146; reaffirm)
- [ ] `<video src="...">` plays with multiple range requests visible in dev tools
- [ ] Second `<img src="...">` for same sha256 in same session: 0 server requests (IndexedDB hit)
- [ ] IndexedDB cache evicts cold blobs over 100 MB budget
- [ ] CHANGELOG entry

## Out of scope

- Chunked AEAD for files > 50 MB (Phase 6 / future)
- Service Worker for offline-first (separate ticket)
- CDN/edge caching (Cloudflare/Fly Tigris) — local-only Phase 4
