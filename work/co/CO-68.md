GIVEN CO-34 ships a basic Obsidian plugin (manual sync) and the post-GitHub roadmap (ROADMAP-SYNC.md Phase 3) calls for real-time sync, and Obsidian is the closest existing client to validate the manifest epic against,
WHEN we add auto-sync, pull-on-open, conflict UI, status bar, and vault↔universe folder mapping,
THEN Obsidian becomes the reference rich client for CO-63 manifest rendering.

## Tasks

- [ ] Auto-sync: file watcher debounces and pushes on save (configurable interval, default 5s)
- [ ] Pull on open: on Obsidian start, fetch latest from server in the background
- [ ] Conflict UI: when remote changed since last sync, show 3-way diff
- [ ] Status bar: "Co: synced ✓ | 2 pending" indicator
- [ ] Settings: vault folder ↔ universe key mapping (multi-universe in one vault)
- [ ] Read manifest from server; populate Obsidian metadata cache with declared content types

## Scale notes

- Per-vault file watcher is local; no server impact
- Auto-sync push uses Vault PUT with optimistic concurrency (`If-Match` ETag) — must coordinate with CO-54 (idempotency)
- Pull-on-open uses `If-Modified-Since` to avoid unnecessary transfers
- Per-user rate limit applies; honor `Retry-After` header (CO-80)
