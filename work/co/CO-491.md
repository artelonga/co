GIVEN consent, privacy, rights, and the sacred-command confirmations are **legal
artifacts, not conversational copy** — and LGPD (Art. 8º §2º) requires the exact
text a user agreed to be reproducible,
WHEN the bot presents any such text, it uses a **deterministic, versioned source**
verbatim (the LLM may phrase *help*, never the agreement), and the version is
recorded against the user's consent,
THEN what the user agreed to is auditable forever, and changing wording means
minting a new version — never editing a published one.

## Acceptance

- [ ] Single source of truth: `co-web/seed/legal/whatsapp-consent.<version>.yaml`
  (created — `v1`): `version`, `agreement`, `boundary`, `how_it_works`,
  `commands.*`, `rights`. General; only `{operator}` is substituted; no model output.
- [ ] `GET /api/v1/whatsapp/consent` serves the current `{version, ...texts}` so the
  bridge displays them **verbatim** (no LLM phrasing of legal text).
- [ ] `link/verify` records the **consent version** the user agreed to alongside the
  text + timestamp + source (extend the consent record; coordinate the migration
  number across branches — do NOT collide with v094).
- [ ] Bridge `bot/profile` routes the deterministic intents (consent / boundary /
  how_it_works / rights / sacred-commands) to the fixed strings **before** the model
  loop — proven by a test that the model is never asked to phrase them.
- [ ] Published versions are immutable; a new wording = a new file + bumped version;
  old versions retained for historical-consent verification.
- [ ] Tests: render with `{operator}`, version pinning, "model never sees consent
  text" guard.
