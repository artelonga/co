## As
Anyone running a universe locally via `co launch`

## I Need
The seed path to extract `[[wikilink]]` relations so the knowledge-graph view has edges,
matching what the server vault/entry write path already does.

## So That
- The grafo / garden view works for CLI-seeded universes (it was empty — nodes, 0 edges).
- The wiki we interlink renders as a graph immediately after `co launch`, with no Vault round-trip.

## Context

`seed_universe_from_local_repo` (`co-web/src/storage/seed.rs`) upserted entry bodies but
never ran relation extraction; `extract_relations`/`RelationIndex` was wired only into
`vault_routes`/`entry_routes`. Result: `entry_relations` empty → graph endpoint returns
nodes with zero edges. Discovered while rendering grcsamazonia as a wiki.

## Design

After each `upsert_entry_row`, with the per-universe connection in scope:
1. `extract_body_wikilinks(&entry.body)` → candidate relations.
2. Resolve same-universe `to_path` relative to the entry's directory via a new
   `resolve_entry_rel(from_entry, target)` helper (normalizes `.`/`..`) so the stored
   path matches entry paths (which carry the `content/` subdir prefix). Cross-universe
   (`to_universe = Some`) targets pass through unchanged.
3. `RelationIndex::replace_all(universe_key, &entry_path, &relations)`.

## Acceptance

- [x] Seed extracts wikilink relations for every seeded entry
- [x] Same-universe targets resolved to full paths matching nodes (unit test
      `test_resolve_entry_rel_co394`)
- [x] Verified on grcsamazonia: 0 → 20 relations, 0 → 18 graph edges
- [ ] `cargo test/clippy/fmt` green via CI

## Blast radius

- ~20 LOC in `seed.rs` (extraction in the seed loop + `resolve_entry_rel` helper) + 1 unit test
- 0 schema changes; 0 new deps

## Not in scope

- Frontmatter `ref`/`ref_list` extraction in the seed (body wikilinks cover the wiki case;
  add later for parity if needed)
- The `::` vs `/` cross-universe wikilink form inconsistency between extractor and SPA
  renderer (pre-existing; separate task)
