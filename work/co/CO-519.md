GIVEN `co-agent` test `tests::test_retry_then_drop_on_persistent_5xx`
(co-agent/src/lib.rs:390) asserts "exactly 2 attempts" and flakes under
`cargo test --workspace` parallel load (it passes when run in isolation) because the
assertion races a yield/flush loop,
WHEN the workspace test suite runs under contention,
THEN the test must be deterministic — it asserts the retry/drop behavior via a
deterministic signal, not by reading an exact attempt count snapshotted mid-loop.

## Acceptance

- [ ] **Remove the timing race**: do not assert an exact attempt count while a
  yield/flush loop may still be advancing the counter.
- [ ] **Deterministic signal**: the test gates on a deterministic completion condition
  (e.g. the retry budget is exhausted and the message is dropped) rather than a count
  observed at an arbitrary instant.
- [ ] **Passes under load**: green under `cargo test --workspace` with parallelism, not
  only in isolation — run it repeatedly to confirm the flake is gone.
- [ ] No change to the retry/drop behavior itself — this is a test-determinism fix only.

## Notes
- Reference [[feedback_flaky_coagent_retry_test]].
- The behavior under test (retry on persistent 5xx, then drop) is correct; only the
  assertion is racy. Keep the production code untouched.
