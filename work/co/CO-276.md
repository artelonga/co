## As

A developer kicking co-auto runs (this session has run ~30; muscle memory matters)

## I Need

A shorter, smarter CLI surface:

```
# Long form (current)
co-auto --workdir /Users/artelonga/projects/co --space co --task CO-272 --cycle --max-tasks 1 --auto-pr --timeout 1800

# Short form (proposed)
co-auto 272
```

The defaults plus auto-detection should make the long form unnecessary 90%+ of the time.

## So That

Friction to spawn a task drops by an order of magnitude. The user already established muscle memory of `co-auto --workdir … --space … --task CO-N --cycle --max-tasks 1 --auto-pr --timeout 1800` — that's 6 flags + 7 values for an operation that wants to be `co-auto N`.

## Context

### Current CLI vs minimum-necessary args

Today's `Cli` struct (`dev/co-auto/src/main.rs`):

| Flag | Default | Necessity | Verdict |
|---|---|---|---|
| `--workdir` | CWD | Auto-detected from CWD | ✅ already optional — drop from typical usage |
| `--space` | Auto-detect when only one space exists | Already auto-detects from `work/<single-dir>/` | ✅ already optional — drop |
| `--task` | None (picks next unblocked) | Required when targeting a specific task — but **prefix is redundant** with space | ⚠ shorten to just the number |
| `--cycle` | false | Only meaningful with `--max-tasks` — and even then... | ❌ redundant when specifying one task; drop |
| `--max-tasks` | None | Implicit `1` when `--task` given | ❌ redundant when --task is set; drop |
| `--auto-pr` | false | Almost always desired (we ship via ship-task.sh) | ⚠ flip default to TRUE; add `--no-pr` for opt-out |
| `--timeout` | 600s (10 min) | Tasks regularly take 15-25 min; 600s is wrong | ⚠ raise default to 1800s; add `--quick-timeout` opt-in |
| `--model` | "sonnet" | Sensible default | ✅ keep as-is |
| `--dry-run` | false | Real opt-in | ✅ keep |
| `--teams` | false | Real opt-in | ✅ keep |
| `--headless` | false | Real opt-in | ✅ keep |

### Task key prefix inference

Today: `--task CO-272`. The "CO-" prefix is **fully determined by the space** (`work/co/` → CO-N; `work/yggdrasil/` → YG-N).

A new helper `infer_prefix_from_space(space)` reads either:

1. `<workdir>/work/<space>/_universe.yaml` if it has a `task_prefix:` field, OR
2. A hardcoded fallback table (`co → CO`, `yggdrasil → YG`, `rfq → RFQ`, `qb → QB`, `artelonga → AL`), OR
3. The first existing `<workdir>/work/<space>/<PREFIX>-*.md` file's prefix

With that, `--task 272` resolves to `CO-272` when space=co.

### Positional argument

Clap supports a positional after all options:

```rust
struct Cli {
    // ...existing flags...

    /// Task to execute. Accepts either a bare number (e.g., `272`) which is
    /// expanded using the space's prefix, or a full key (e.g., `CO-272`).
    /// When omitted, the next unblocked task is picked.
    task_arg: Option<String>,
}
```

So you can write `co-auto 272` or `co-auto CO-272` or `co-auto --task CO-272` — all equivalent.

## Decision matrix — new defaults

| Behavior | Current | Proposed |
|---|---|---|
| `--workdir` | required-ish | auto-detect CWD (no change — already works) |
| `--space` | required-ish | auto-detect from single space (no change — already works) |
| `--task` | flag-only | positional OR flag, with prefix inferred from space |
| `--cycle` + `--max-tasks 1` | required pair to "run one task" | default behavior — runs the specified task once and exits |
| `--auto-pr` | opt-in | **default ON**; add `--no-pr` opt-out |
| `--timeout` | 600s | **default 1800s** (matches typical task duration); `--quick-timeout 300` opt-in for triage |
| Final invocation pattern | `co-auto --workdir … --space … --task CO-N --cycle --max-tasks 1 --auto-pr --timeout 1800` | `co-auto N` |

## Scope

### 1. clap rework

Edit `dev/co-auto/src/main.rs`:

- Add `task_arg: Option<String>` positional field
- Flip `auto_pr: bool` default to true; add `no_pr: bool` for opt-out
- Raise `timeout` default to 1800
- When `task_arg` set AND no `--cycle`: implicit max_tasks=1 and exit after
- Resolve task: `task_arg` > `--task` > pick-next-unblocked

### 2. Prefix inference

New helper in `dev/co-auto/src/`:

```rust
fn resolve_task_id(input: &str, space: &str, workdir: &Path) -> Result<String> {
    if input.contains('-') {
        return Ok(input.to_uppercase()); // already a full key
    }
    let prefix = read_universe_yaml_prefix(workdir, space)
        .or_else(|_| infer_prefix_from_existing_files(workdir, space))
        .unwrap_or_else(|| space.to_uppercase());
    Ok(format!("{}-{}", prefix, input))
}
```

### 3. Backwards compatibility

Long-form invocations remain valid. Anyone with the old muscle memory or scripts still works. New users get the short form.

### 4. Documentation

Update `dev/co-auto/README.md` (if exists) or `CLAUDE.md` section about co-auto with the new short-form examples.

## Acceptance

- `co-auto --workdir ~/projects/yggdrasil 50` executes YG-50
- `co-auto` (no task) picks the next unblocked task
- `co-auto --no-pr 272` runs but doesn't open PR

- `co-auto --version` exists and matches Cargo.toml
- Help text via `--help` is updated and concise

- No behavior change for existing invocations

## Why now

User feedback: *"rview the necessity and requirement for each of the co-auto params, some seem rdundant. see, universes have unique ids (AL, QB) so we only need to specify folder (or keep a local map) and the task number; spaces should be equivalent to the working directory etc"*. 

Every flag carries a small cognitive tax. After 30 invocations this session, the tax is visible. Simplifying the CLI is a high-ROI cleanup that doesn't change semantics — just makes the common case ergonomic.
