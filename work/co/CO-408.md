## Three small fixes, one PR

1. **`staging.co.artelonga.com.br` has no DNS record** (empty answer as of
   2026-06-11; likely lost when the staging app was recreated). Re-add the
   CNAME → `co-artelonga-staging.fly.dev` at the dns-parking nameservers +
   `flyctl certs add`. Release checklist references this URL.
2. **Google OAuth token-exchange errors are opaque**: `oauth_google.rs:221-222`
   `error_for_status()` discards Google's response body, so `invalid_grant`
   (code reuse — harmless) and `invalid_client` (rotated secret — every login
   broken) are indistinguishable in logs. Read the body on non-2xx and include
   Google's `error`/`error_description` in the 401 message + a WARN log.
   (2026-06-11: a login failure took manual curl-from-prod to diagnose.)
3. **`fatal: could not read Username for 'https://github.com'` ×2 on prod
   startup** — something still shells out to git without credentials
   (webhook/collab leg or leftover git_sync). Find it, gate it on configured
   credentials, or remove with the CO-64 dead-code cleanup.

## Resolution

- **Item 2 (OAuth error body) — code.** `oauth_google.rs` now reads the response
  body on a non-2xx token exchange, parses Google's `{error, error_description}`
  via a new `format_token_error_body` helper, surfaces it in the 401, and emits a
  `WARN` log. Six unit tests cover invalid_grant vs invalid_client, code-only,
  non-JSON fallback, empty body, and char-boundary truncation.
- **Item 3 (git-credential noise) — code.** The fatal lines came from the CO-337
  `run_remote_sister_repo_seeds` clone/pull (e.g. `mbya`'s HTTPS `remote_url`)
  running with no credential. Added `is_network_remote` / `has_git_credentials` /
  `remote_needs_credentials` to `platform/vcs.rs`; the seed orchestrator now skips
  network remotes with an `info` log when no `CO_GIT_TOKEN` / `CO_GIT_SSH_KEY_PATH`
  is set, instead of letting git emit `fatal:`. Feature intact — set the token and
  the next 15-min worker tick syncs, no redeploy. Two new unit tests.
- **Item 1 (staging DNS) — manual ops, documented.** Not fixable from code. Exact
  steps captured in `CHANGELOG-PENDING/CO-408.md`: add CNAME
  `staging.co → co-artelonga-staging.fly.dev.` at the dns-parking nameservers,
  then `flyctl certs add staging.co.artelonga.com.br -a co-artelonga-staging`.
