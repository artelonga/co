## As
Um serviço externo (Yggdrasil, e qualquer cliente com API token de um usuário),
QUERO criar um universo no CO, definir visibilidade, convidar membros e abrir
assinatura pública — **via API com token**, PARA que o "criar universo" do
Yggdrasil (YG-126) vire um universo federado no CO sem código interno de seed/clone.

## Contexto (confirmado dos dois lados, 2026-06-13)
- `POST /api/v1/universes` **existe mas é session-only**: com api-token retorna
  401 "requires a logged-in session" (mesmo bug que travou o import do
  claude-code; ver CO-438). Criação + `parent_key` hoje são código interno de
  seed/clone, sem endpoint utilizável por serviço externo.
- **Convites** e **assinatura pública** não têm endpoint user-facing.
- YG-138 deixou o spec do lado Yggdrasil pronto esperando estas rotas.

## Acceptance
- [ ] **Criar (token-auth):** `POST /api/v1/universes` aceita **api-token** (não só
      sessão) — cria o universo de posse do usuário do token. Body:
      `{ key, name, description?, visibility, parent_key? }`. `visibility` ∈
      `private | public | unlisted`. Idempotente/409 em key tomada (sem órfão —
      ver bug CO-438). Mesmo dono via token e via sessão (consertar a divergência
      token-vs-sessão do gate CO-161/CO-438).
- [ ] **Convites:** `POST /api/v1/universes/{key}/invites` (owner/admin do
      universo) — `{ email | handle, role }`; `GET/DELETE` para listar/revogar.
      Aceitar convite via `POST /api/v1/universes/{key}/invites/{token}/accept`.
- [ ] **Assinatura pública:** `POST /api/v1/universes/{key}/subscribe` /
      `DELETE …/subscribe` para universo `public` (assinante read-only); reusa o
      modelo de subscriptions existente (CO-...).
- [ ] **Visibilidade:** `PUT /api/v1/universes/{key}` já aceita `parent_key`
      (CO-423) — estender para `visibility`. Gate (CO-161) aplica consistentemente.
- [ ] Rotas no `api-catalog.md` + openapi regen (sem drift). Testes de integração
      (tower::ServiceExt) de cada rota, incl. token-auth cria + dono correto.
- [ ] Nada de MCP; sem mapeamento universo→repo hardcoded (vem do payload/DB).

## So that
O Yggdrasil (YG-126/YG-138) liga o "criar universo" à criação federada no CO +
UI de convite/público no commit, sem fazer a metade do CO às cegas.

## Notas
Habilita o padrão stakeholder↔project / bridge universes (CO-413) de forma
genérica e externa. Parte do arco aditivo de federação (não-breaking): novas
rotas, nada removido. Prioridade alta — desbloqueia integração cross-repo viva.
