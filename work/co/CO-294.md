## What this slice does

Finishes the blob-store abstraction CO-263 started (R2 adapter behind a feature flag). Defines the trait properly, default is LocalFs (`UPLOAD_DIR/blobs/`), R2 stays opt-in.

## Scope

1. New trait `BlobStore` in `co-web/src/infra/blob.rs`:
   ```
   #[async_trait]
   trait BlobStore: Send + Sync {
       async fn put(&self, key: &str, bytes: AsyncRead) -> Result<BlobMeta>;
       async fn get(&self, key: &str) -> Result<AsyncRead>;
       async fn delete(&self, key: &str) -> Result<()>;
       async fn presign_url(&self, key: &str, ttl: Duration) -> Result<String>;
       async fn exists(&self, key: &str) -> Result<bool>;
   }
   ```
2. Default impl `LocalFsBlobStore` mapping `key` → `UPLOAD_DIR/blobs/<first-2>/<key>`
3. Move existing CO-263 R2 adapter behind this trait (no behavior change)
4. Selector: `CO_BLOB_BACKEND=local` (default) or `local_then_r2_fallback` or `r2`
5. Find existing blob/file ops in co-web and migrate to the trait

## Acceptance

- [ ] Trait `BlobStore` exists; both `LocalFsBlobStore` and the R2 adapter implement it
- [ ] Behavior unchanged with default config
- [ ] Setting `CO_BLOB_BACKEND=r2` + R2 credentials switches the backend at boot, no code change
- [ ] Tests pass

## Not in this phase

- Migration of existing blobs to R2 (separate ops task, not code)
- Multi-region replication
- S3 adapter (R2 is S3-compatible; just config the endpoint)
