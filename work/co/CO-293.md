## What this slice does

Wraps the existing in-process `lru::LruCache` usage behind a `Cache<K, V>` trait. Foundation for future Redis/Memcached impls when cross-machine cache consistency starts mattering (not yet).

## Scope

1. New trait in `co-web/src/infra/cache.rs`:
   ```
   #[async_trait]
   trait Cache<K: Send + Sync, V: Send + Sync + Clone>: Send + Sync {
       async fn get(&self, key: &K) -> Option<V>;
       async fn put(&self, key: K, value: V);
       async fn invalidate(&self, key: &K);
       async fn invalidate_all(&self);
   }
   ```
2. Default impl `LruCache<K, V>` wrapping `lru::LruCache` + `tokio::sync::Mutex`
3. Find existing cache usages (`co-web/src/cache.rs` or similar) and migrate them through the trait
4. Per-cache configuration: name + max_entries via env or config

## Acceptance

- [ ] Trait `Cache` exists in `co-web/src/infra/cache.rs`
- [ ] `LruCache` default impl works identically to current cache layer
- [ ] All call sites go through the trait
- [ ] Tests pass

## Not in this phase

- Redis impl (deferred until cross-machine consistency is needed)
- Distributed invalidation protocols
