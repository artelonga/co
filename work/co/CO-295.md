## What this slice does

Centralizes scattered `std::env::var(...)` reads of secrets (JWT_SECRET, RESEND_API_KEY, VAPID_*, CO_FLY_API_TOKEN, etc.) behind a `SecretsProvider` trait. Default impl reads env vars; future impls (Vault, AWS Secrets Manager, sops) plug in.

This also resolves the JWT_SECRET parallel-test race we hit in this session: with a trait-backed provider, tests inject a `StaticSecrets` instance instead of mutating env state.

## Scope

1. New trait in `co-web/src/infra/secrets.rs`:
   ```
   trait SecretsProvider: Send + Sync {
       fn get(&self, name: &str) -> Option<String>;
       fn rotate(&self, name: &str, new_value: String) -> Result<()>;  // default: Err(NotSupported)
       fn list_audit(&self, since: DateTime<Utc>) -> Vec<SecretAccess>; // default: empty
   }
   ```
2. Default impl `EnvSecretsProvider` reading `std::env::var(name)`
3. Test impl `StaticSecretsProvider` taking a `HashMap<String, String>`
4. Find every `std::env::var("JWT_SECRET")`, `RESEND_API_KEY`, etc. — route through the provider
5. `AppState` gains `Arc<dyn SecretsProvider>`
6. Tests use `StaticSecretsProvider` injected at `build_test_router(secrets)` — no more env-var mutation between tests

## Acceptance

- [ ] All known secret reads go through the trait
- [ ] `EnvSecretsProvider` default works identically to today
- [ ] At least 5 tests are migrated from `std::env::set_var(...)` to `StaticSecretsProvider::new([("JWT_SECRET", "test-jwt-secret")])`
- [ ] No `JWT_SECRET` parallel-test race possible (the env var is no longer mutated by tests)

## Not in this phase

- Vault / AWS Secrets Manager impl (deferred until needed)
- Audit log persistence (the trait shape allows it; impl is later)
- Auto-rotation (separate ops concern)
