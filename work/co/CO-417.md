## As
Yuri (e qualquer autor), QUERO apontar o CO a um repositório GitHub e tê-lo
ingerido como conteúdo navegável, PARA testar a capacidade de *source* do CO
de ponta a ponta.

## Escopo (decisão 2026-06-12: adapter GERAL, não import pontual)
Um tipo de fonte de primeira classe `source: github` reutilizável para
qualquer repo, demonstrado com `yurisugano/SensorySpeech` em CO-419.

## Acceptance Criteria
- `co source add github <owner/repo>` (e/ou rota API) clona/baixa o repo e o
  materializa numa árvore de entradas sob o universo alvo, preservando a
  hierarquia de pastas como folders/árvore na UI.
- **Parse por arquivo**: `.md` direto; `.ipynb` → extrai JSON e renderiza
  markdown + células de código como markdown (```); outros arquivos viram
  entradas-asset com link ao original.
- Cada entrada importada carrega `source: github:<owner/repo>@<sha>` e
  `source_path: <caminho/no/repo>` — base do traceback (CO-418).
- Re-sync idempotente por `sha`/hash; remoções no repo refletem (soft) no CO.
- Árvore hierárquica clicável: pasta → arquivos; um nó "intro" pode linkar ao
  original e a versões mais específicas.
- Teste: import de um repo-fixture com .md + .ipynb produz a árvore esperada e
  o ipynb vira markdown legível.
