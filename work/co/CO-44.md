GIVEN UAT exists at co-artelonga-uat.fly.dev with the same code as prod but separate volume, and the user wants UAT to be a clean E2E testing environment that always starts at the current state,
WHEN I configure UAT-specific behavior triggered by an env var,
THEN:

## Environment Variable

- [ ] Add `CO_ENV` config option (`prod` default, `uat` for UAT)
- [ ] Set `CO_ENV=uat` in `fly.uat.toml` env section
- [ ] All UAT-specific behavior gated on `config.is_uat()`

## UAT Yuri Account

- [ ] On startup in UAT mode, seed user `yuri` with password `uat` (Argon2 hashed)
- [ ] Email: `yuri@uat.local`
- [ ] Tier: `admin`
- [ ] Idempotent: skip if user already exists
- [ ] Login flow: email + password (legacy path) — `/api/v1/auth/legacy-login`

## Auto-Reset Database

- [ ] On startup in UAT mode, check for `/data/uat-reset.flag` file
- [ ] If present: drop all tables EXCEPT users + sessions, re-run migrations, re-seed
- [ ] Delete the flag file after reset
- [ ] Manual reset: `flyctl ssh console -a co-artelonga-uat -C "touch /data/uat-reset.flag" && flyctl machine restart ...`

## Anonymous User Behavior on UAT

- [ ] Anonymous visitors always see fresh state (no persistence)
- [ ] Implementation: anonymous universes get cleaned up on each visit (cron-style on startup, or on-demand)
- [ ] OR: anonymous changes go to a session-scoped in-memory store (no DB writes)
- [ ] Decision: simpler — clean up `anon-*` owned universes on startup

## CO Board Pre-Seeded

- [ ] On UAT first boot, seed the `co-dev` universe (from CO-43) with all current CO-* tasks
- [ ] This is the primary thing E2E tests can interact with
- [ ] Yuri logs in → sees co-dev board → can run E2E tests on real task structure
