> **Done — exceeded scope.** `co-web/static/shared/timeline.html` renders events with linear-near-focus + log10-far transform. 1.21.0 added the timeline trio (`tempo` / `humanity` / `universo`) seeded out of the box; 1.21.1 added multi-universe overlay (`?u=tempo,humanity,universo`), per-universe colors and lanes, prev/next event travel with 750ms ease-in-out-cubic in pixel-space, arrow-key nav, click-to-travel. Inspired by scaleofuniverse.com/pt with emphasis on time over distance.

GIVEN entries with `type: event` and a `date_year` (or ISO `date`) frontmatter field carry temporal meaning, but the platform has no view that treats time as the primary axis,
WHEN we add a standalone timeline page (`/shared/timeline.html?u=<universe>`) that fetches events from a universe and renders them on a horizontal axis with **linear scaling near the focus and logarithmic scaling toward the edges** — so a single view spans 4.6 billion years of past and 300 thousand years of future without infinite scrolling,
THEN any universe with timestamped event entries gets an immediately usable temporal view, and the platform exercises the temporal model (CO-73) before the full manifest layer lands.

## Coordinate transform

```
       |delta| < LINEAR_HALF_SPAN  →  pixel = sign(delta) · |delta| · LINEAR_SCALE
       |delta| ≥ LINEAR_HALF_SPAN  →  pixel = sign(delta) · (linearMax + log10(|delta| - LINEAR_HALF_SPAN + 1) · LOG_SCALE)

defaults:
  LINEAR_HALF_SPAN = 100  years   (linear within ±100 years of focus)
  LINEAR_SCALE     = 4    px/year (linear region density)
  LOG_SCALE        = 90   px/decade (logarithmic outside)
```

A single 1920px-wide screen, with focus at year 2026, simultaneously shows:
- 4.6 Gya formation of Earth (left edge)
- 300 kya emergence of *Homo sapiens* (intermediate)
- ~2026 modern era (centered, with year-scale resolution)
- 300 kya from now (right edge)

## Date format support

Frontmatter convention:

| Field | Type | Used for |
|-------|------|----------|
| `date_year` | signed integer | canonical timeline position. Negative = BCE / before-now. Required for events older than ~9999 BCE or beyond ~9999 CE. |
| `date` | ISO 8601 string `YYYY-MM-DD` | optional precise date for modern events |
| `time` | `HH:MM` | optional time-of-day |

Examples:
```yaml
# Geological event
type: event
title: Formation of Earth
date_year: -4600000000

# Modern event
type: event
title: Co 1.18.5 deploy
date_year: 2026
date: 2026-04-28
time: "10:54"

# Far future
type: event
title: 300k years from now
date_year: 302026
```

## Composition with other tasks

- **CO-73** (temporal model): timeline is the most natural consumer; first concrete need for `entry_dates` indexing
- **CO-83** (Mermaid): Gantt view of tasks reuses the same date math
- **CO-89** (git-backed universes): `commit` entries on the timeline = a unified history view
- **CO-86** (`.co` format): events encoded with `frontmatter.event_at_ns` (CO-86's nanosecond field) reduce client-side parsing
- **CO-87** (composable layers): the "fetch events from universe" call goes through the same transport stack

## Tradeoffs decided

- **Standalone HTML page over SPA integration** — ships in one file with no dependencies. The board's variant-a SPA is variant-specific; making the timeline shared/standalone means it works regardless of which variant the user has set.
- **Client-side date parsing** — `frontmatter_json` is already returned by the entries endpoint. No new backend route. Cost: a bit of JS work per render. Fine at hundreds of events.
- **Linear + log over geological log everywhere** — pure log feels disorienting near the present (1 year and 10 years are at meaningfully different distances). The hybrid transform makes the recent past/future feel right and only gets compressive when distances actually matter.

## Acceptance

- Open `/shared/timeline.html?u=co-dev` (or any universe with events) → SVG renders with focus at year 2026
- 4 sample events visible: Earth formation (far left), Homo sapiens (mid-left), 2026 (center), 302,026 (mid-right)
- Drag horizontally → focus moves; events repaint smoothly
- Mouse wheel / trackpad → pans
- Hover an event dot → tooltip with title, date, description
- Reset button → focus snaps back to year 2026
- Empty universe (no events with `type: event` + `date_year`) → friendly message instead of blank page
- Logged-out user trying a private universe → "log in" prompt, not a silent failure

## Out of scope (deferred indefinitely)

- Vertical timeline orientation
- Astronomical/calendar conversions (Julian / Hebrew / Mayan / etc.) — use Gregorian Proleptic for everything
- 3D temporal visualization
- Real-time updates (live new events streaming in)
