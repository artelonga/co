## As

a user studying / composing / curating across a content universe (mbya lexicon, comunicacao sources, ArteLonga refs, my personal notes) — today I can list, kanban, or graph these entries, but I can't *arrange* them spatially, link them with my own typed edges, and revisit that arrangement later as a working surface.

## I Need

a third first-class view next to **kanban** and **conteudo** (and the existing graph): **workspace** ("Sala" in PT-BR). A workspace is a personal spatial canvas anchored to a source universe — drop entries onto it, draw typed edges, compose new entries that write back to the source, suggest changes for review, save the layout, share it.

## So That

- Yggdrasil's `/universos/comunicacao` (a spatial composer over mbya/yoruba terms) absorbs into CO as a reusable primitive — any universe gets a Sala for free.
- Game content authors get a spatial editor; study-mode users get a flashcard-like review surface; researchers get a working canvas they can return to.
- The PT-BR domain term "Sala" lands as a real workspace concept (not a meeting room metaphor), with the English label "Workspace" everywhere else.

### Workspace state ownership (Option C)

- **Default**: workspace state is per-user (rows scoped to `user_id`) — your arrangement of mbya terms doesn't affect mine.
- **Publishable**: owner can mark a workspace as `is_public` → others can clone or view read-only.
- **Shareable**: workspace URL with a token grants view/edit to collaborators.

## Design

### New entry types

| `entry_type` | Stored in | Notes |
|---|---|---|
| `workspace` | source universe (file: `_workspaces/<slug>.md` or top-level `_workspace.yaml`) | Workspace **definition** — name, description, template ref. Versioned with the universe. |
| `workspace_state` | runtime SQLite (`workspace_states` table) | Per-user canvas snapshot: node positions, custom edges, view transform, last-opened. |

Storage split: definitions live in the universe (portable, reviewable); state is local/per-user (heavy mutation, not worth versioning).

### Schema (additive migration)

```sql
CREATE TABLE workspace_states (
  id TEXT PRIMARY KEY,
  universe_key TEXT NOT NULL,
  workspace_slug TEXT NOT NULL,           -- references the workspace entry; "default" if none
  user_id TEXT NOT NULL,                  -- "anon:<session>" for unauthenticated
  layout_json TEXT NOT NULL,              -- {nodes: [{entry_path, x, y, z}], edges: [{from, to, type}], view: {tx, ty, scale}}
  is_public INTEGER NOT NULL DEFAULT 0,
  share_token TEXT,                       -- nullable; presence => shareable
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (universe_key, workspace_slug, user_id)
);
CREATE INDEX idx_workspace_states_user ON workspace_states (user_id);
CREATE INDEX idx_workspace_states_token ON workspace_states (share_token) WHERE share_token IS NOT NULL;
```

### Routes

| Route | Purpose |
|---|---|
| `GET /u/{universe}/sala` | Renders the workspace canvas (default workspace, current user's state) |
| `GET /u/{universe}/sala/{slug}` | Renders a named workspace |
| `GET /sala/{share_token}` | Public/shared workspace render |
| `GET /api/v1/universes/{key}/workspaces` | List workspaces (definitions) in the universe |
| `GET /api/v1/universes/{key}/workspaces/{slug}/state` | Get current user's state |
| `PUT /api/v1/universes/{key}/workspaces/{slug}/state` | Upsert layout (debounced from client) |
| `POST /api/v1/universes/{key}/workspaces/{slug}/state/share` | Generate share token |

- Any CRUD click (btn-add, btn-link, btn-compor, btn-publish, save-layout) on an unauthenticated session → triggers existing login modal (reuse pattern from CO-329 / board CRUD).
- `btn-sugerir` is the one CRUD action that allows anon (the suggest pipeline rate-limits + queues for owner review — CO-354).
