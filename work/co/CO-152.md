## As

a consumer of the cross-language meaning topology (Co SPA, Arandu app, future search index)

## I Need

a Rust crate `topologia-co-adapter` at `~/projects/topologia/crates/topologia-co-adapter/` that reads CO universe markdown (frontmatter + body) and exposes the entries as typed `topologia-core::Term` / `Concept` values via the `LanguagePlane` and `ConceptPlane` traits

## To

## Implementation sketch

```rust
// topologia-co-adapter/src/lib.rs
use co::entry::{read_entry, walk_entries};
use topologia_core::*;

pub struct CoLanguagePlane {
    universe_root: PathBuf,
    code: LanguageCode,
}

impl CoLanguagePlane {
    pub fn open(universe_root: impl Into<PathBuf>, code: LanguageCode) -> anyhow::Result<Self> { ... }
}

impl LanguagePlane for CoLanguagePlane {
    fn code(&self) -> &LanguageCode { &self.code }

    fn get_term(&self, key: &str) -> Option<Term> {
        let path = self.universe_root.join("terms").join(format!("{key}.md"));
        let entry = co::entry::read_entry(&path).ok()?;
        deserialize_term(&entry, &self.code).ok()
    }

    fn iter_terms<'a>(&'a self) -> Box<dyn Iterator<Item = Term> + 'a> {
        let root = self.universe_root.join("terms");
        let lang = self.code.clone();
        Box::new(
            walkdir::WalkDir::new(&root)
                .into_iter()
                .filter_map(|e| e.ok())
                .filter(|e| e.path().extension().map(|x| x == "md").unwrap_or(false))
                .filter_map(move |e| {
                    let entry = co::entry::read_entry(e.path()).ok()?;
                    deserialize_term(&entry, &lang).ok()
                }),
        )
    }
}
```

Plus `CoConceptPlane` for the meta `concepts/` universe with the same shape but reading `Concept`.

## Out of scope

- Writing back into the universe — adapter is read-only.
- Server-side caching (e.g. memo-ize parsed terms). Caller's concern.
- Resolution of cross-universe `co://` URIs into actual `Term` values from another plane — that's CO-153 territory.
