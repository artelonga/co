## As

a universe owner (mbya curator, comunicacao editor, ArteLonga publisher) — I want to offer **opinionated starting layouts** for the Sala canvas: a "basics" workspace seeded with the foundational terms, an "advanced" one with deeper relations, a "blank" one for free composition.

## I Need

a per-universe template file (`_workspace.yaml`, or multiple under `_workspaces/`) that defines a starting set of nodes, edges, and study-mode config — so creating a new Sala starts from "mbya-basics with 12 seed terms already placed" instead of "empty canvas, figure it out."

## So That

- Newcomers to a universe get a useful surface immediately.
- Curators can codify canonical "starting points" for study or composition.
- Yggdrasil's `data-tpl="blank|mbya|yoruba"` attribute (today a hardcoded HTML switch) generalizes into a versioned, content-side construct.
- Templates ship with the universe repo, so they version + travel with the content.

## Context

### Today

- CO-352 ships the Sala canvas; opening one gets you an empty layout per user.
- Yggdrasil's `/universos/comunicacao.html` has a hardcoded `data-tpl` attribute switching between three baked-in starting layouts — not extensible, not curator-editable.
- CO universes already support arbitrary YAML/MD files in their root (templates land naturally as content).

## Design

### Template file location

Two supported shapes:

1. **Single default**: `<universe-root>/_workspace.yaml` — used when opening `/u/{key}/sala` with no slug.
2. **Named templates**: `<universe-root>/_workspaces/<slug>.yaml` — picker dropdown when creating a new Sala.

### Schema

```yaml
# _workspaces/mbya-basics.yaml
name: "Mbya — Básico"
description: "12 termos fundamentais do guarani mbya com relações de afinidade."
default_layout:
  nodes:
    - entry_path: "termos/nhandereko.md"
      x: 200
      y: 150
    - entry_path: "termos/ayvu-rapyta.md"
      x: 400
      y: 150
    # ... 10 more
  edges:
    - from: "termos/nhandereko.md"
      to: "termos/ayvu-rapyta.md"
      type: "afinidade"
    - from: "termos/ayvu-rapyta.md"
      to: "termos/tekoa.md"
      type: "deriva"
study_mode:
  algorithm: "spaced-repetition"        # spaced-repetition | review-queue | free
  initial_interval_hours: 24
  ease_factor: 2.5
allowed_entry_types:                     # restricts btn-add picker
  - term
  - concept
metadata:
  difficulty: beginner
  estimated_minutes: 20
```

All fields optional except `name`. Missing `default_layout` → empty canvas (still a valid template — it just sets metadata + study config).

### Loader

- New module `/Users/artelonga/projects/co/co-web/src/workspace/templates.rs`:
  - `list_templates(universe_key) -> Vec<WorkspaceTemplate>`
  - `load_template(universe_key, slug) -> WorkspaceTemplate`
- Reads files from the universe's resolved content path (CO-330 + CO-337 logic) — works for local + remote-synced universes.
- Validation: rejects template with unknown `entry_path` (log warning, drop node) or unknown `allowed_entry_types` (log warning, ignore).
- Caching: parsed templates cached in memory; invalidated on universe re-sync.

### Endpoints

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/api/v1/universes/{key}/workspace-templates` | List available templates |
| `GET` | `/api/v1/universes/{key}/workspace-templates/{slug}` | Get one template |
| `POST` | `/api/v1/universes/{key}/workspaces/{state_slug}/from-template/{template_slug}` | Create a new workspace state seeded from template |

### UI integration (Sala — CO-352)

- "Nova Sala" / "New workspace" button → opens picker modal:
  - Dropdown: `Pick a template: blank | mbya-basics | mbya-advanced | <other names from registry>`
  - On select → POST to `/from-template/{slug}` → redirects to new Sala URL with seeded layout
- `data-tpl` attribute removed from any inherited yggdrasil markup — replaced by registry lookup.
- Study-mode toggle uses the template's `study_mode` config when active.

### Edge case: missing source entries

- Template references `termos/nhandereko.md` but the file doesn't exist (universe pre-seed, partial sync) → drop that node silently; emit a warning to the log. Don't fail the whole template.

### Authoring workflow

- Curator edits `_workspaces/<slug>.yaml` in the universe repo.
- Next universe sync (CO-337 cadence) picks it up.
- Available in the picker on next page load.

## Not in scope

- Template inheritance / composition (one template extending another) — flat for v1
- Per-user template overrides — templates are universe-scoped
- Marketplace / cross-universe template sharing — Phase 2
- Visual template editor (WYSIWYG) — authors write YAML; UI editor later
- Migrating Yggdrasil's `data-tpl` HTML attribute automatically — yggdrasil shims to call the new API
- Spaced-repetition runtime — `study_mode` config is stored + exposed; actual algorithm is a separate ticket
