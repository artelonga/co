## As

Owner of the language-lexicon content across three repos (`mbya`, `comunicacao`, `topologia`) that currently duplicate or fragment the same data.

## I Need

(a) The standalone `~/projects/mbya/` repo formatted as a first-class CO universe; (b) the embedded `~/projects/comunicacao/mbya/` copy removed (or symlinked); (c) `~/projects/topologia/yoruba/terms/` merged into `~/projects/comunicacao/yoruba/terms/` with manual diff review.

## So That

- A single canonical source for each lexicon (mbya, yoruba) instead of three drifting copies.
- The mbya repo becomes addressable by CO-337 sync (one repo, one universe — no subfolder gymnastics).
- The topologia repo stays as the **lexicon-shape exemplar** (`_template-language` + `_universe.yaml` skeleton) without continuing to host live data.

## Context

Current state:

- `~/projects/mbya/` — standalone Rust repo with `content/`, `refs/`, lexicon DB; **no `_universe.yaml`** at root.
- `~/projects/comunicacao/mbya/` — copy of the same content (embedded as a subfolder of comunicacao).
- `~/projects/topologia/guarani-mbya/` — third copy with a `_universe.yaml` (the schema model for CO-141).
- `~/projects/topologia/yoruba/terms/` — 8 terms: `ede, iemanja, iya, ogum, ogunte, olokun, orixa, oro`.
- `~/projects/comunicacao/yoruba/terms/` — 16 terms (superset): adds `ase, egbe-orun, esu, ifa, odu, olodumare, ori, orunmila`.

Per CO-141 the schema living in topologia is the canonical shape — comunicacao should adopt it. Per CO-347 yoruba ships as a sub-universe of comunicacao (no standalone repo). Mbya, however, has its own repo and deserves first-class status (matches the model of "one repo = one universe").

## Design

### Part A — Mbya as first-class

1. Add /Users/artelonga/projects/mbya/_universe.yaml. Copy the schema from /Users/artelonga/projects/topologia/guarani-mbya/_universe.yaml (which is the CO-141 reference shape) and adjust only `name`/`description`:

   ```yaml
   name: mbya
   description: Mbyá Guarani lexicon — terms, morphology, cross-references to concepts.
   language_code: gn-mbya
   version: 1
   content_types:
     - term
   properties: {...same as topologia/guarani-mbya...}
   ```

2. Walk `~/projects/mbya/content/` and `~/projects/mbya/refs/` and confirm each markdown file has the expected term frontmatter shape. If anything diverges, add a follow-up sub-task.

3. Remove (or symlink) `~/projects/comunicacao/mbya/`:
   - Option 1: `git rm -r mbya/` in comunicacao + commit + push.
   - Option 2: replace with a `README.md` pointer: "Mbya lexicon lives in https://github.com/artelonga/mbya — pulled into CO as the `mbya` universe."
   - Decision: **Option 1**, clean removal. Symlinks confuse the seed walker.

4. CO-347 adds the prod row for mbya, but currently as a sub-universe of `language`. After this part lands, update the seed config in /Users/artelonga/projects/co/co-web/src/storage/seed.rs to populate `remote_url='https://github.com/artelonga/mbya'`, `remote_ref='main'`. Keep `parent_key='language'`.

### Part B — Yoruba merge

The `comunicacao/yoruba/terms/` is the canonical target (superset). For each of the 5 topologia terms (`ede, iemanja, iya, ogum, ogunte`) that exist in both:

1. `diff ~/projects/topologia/yoruba/terms/<term>.md ~/projects/comunicacao/yoruba/terms/<term>.md`
2. If identical → ignore.
3. If divergent → manual review. The ogunte.md case is called out as divergent; expect the topologia version to have more rigorous frontmatter, and comunicacao to have more body content. Merge into comunicacao by hand.

`olokun, orixa, oro` exist in both — diff and merge as above.

After merge, delete `~/projects/topologia/yoruba/terms/*.md` (keep the directory + `_universe.yaml` + `index.md` as the lexicon-shape exemplar). Add a top-of-file comment in topologia's `_universe.yaml` or `index.md`: "Demonstration shape. Live yoruba content lives at github.com/artelonga/comunicacao/yoruba."

### Part C — topologia stays as exemplar

No content move out of topologia for the term schema work itself — topologia/`_template-language/` is the reference template that authors copy when starting a new language universe. Document this in /Users/artelonga/projects/topologia/README.md if not already stated.
