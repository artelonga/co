## As

a mobile/tablet user (and any user who wants CO on their home screen or readable on a flaky train Wi-Fi)

## I Need

CO to install as a proper PWA — manifest, icons, themed splash, install prompt, and a service worker that actually serves cached content when the network drops — not just an "add to home screen" stub.

## So That

- CO is launchable from the iOS/Android home screen and the macOS/Windows dock with our brand chrome, not a Safari/Chrome wrapper.
- Already-visited universes remain readable offline (board, garden notes, references) using the IndexedDB read-through path the SW already hints at.
- Lighthouse PWA score is ≥ 90, which doubles as a checklist for "we did this properly" (HTTPS, manifest, icons, theme color, scope, SW with offline fallback).
- The frontend stops being a vague "web app on mobile" and starts being a first-class app surface.

## Context

A draft `/co-web/static/sw.js` (275 lines, `CACHE_NAME = 'co-v5-offline'`) already exists with network-first HTML/JS/CSS, cache-first icons/fonts, IDB read-through for vault reads, and a background-sync `co-vault-writes` queue. **No manifest file exists** (`static/manifest.json` is referenced by sw.js but missing — see `STATIC_ASSETS = ['/shared/manifest.json', ...]`). No `<link rel="manifest">` is wired into the SPA shell. No install-prompt UI. No apple-touch-icon. iOS Safari currently treats the app as a regular web page.

Today's symptoms:
- `navigator.serviceWorker.register('/sw.js')` may or may not be called from the SPA boot — verify and standardize.
- Manifest 404 on every page load (broken link in `sw.js`'s `STATIC_ASSETS`).
- No installability heuristic met → no "Add CO to home screen" prompt fires on Android Chrome.
- Lighthouse PWA category fails on "manifest", "icons", "apple-touch-icon", "theme-color meta".

## Design

### 1. Manifest

Create `/Users/artelonga/projects/co/co-web/static/manifest.json`:

```json
{
  "name": "CO — Collective Consciousness",
  "short_name": "CO",
  "description": "Graph-based content management. Cocriar. Colaborar. Conectar.",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "orientation": "any",
  "background_color": "#ffffff",
  "theme_color": "#2563eb",
  "lang": "pt-BR",
  "icons": [
    { "src": "/shared/icons/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "/shared/icons/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "/shared/icons/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

Also update `sw.js` `STATIC_ASSETS` to point at `/manifest.json` (or move the manifest to `/shared/manifest.json` — pick one path and use it everywhere).

### 2. Icons

Add icon set under `/Users/artelonga/projects/co/co-web/static/shared/icons/`:

- `icon-192.png` (192×192 PNG, app launcher)
- `icon-512.png` (512×512 PNG, splash + store)
- `icon-maskable-512.png` (512×512, safe-area padded for Android adaptive icons)
- `apple-touch-icon.png` (180×180, iOS home screen)
- `favicon.svg` (already exists — keep)

Source the artwork from the existing CO mark; if no PNG mark exists, render from `static/favicon.svg` via a one-off build script (`scripts/render-icons.sh` using rsvg-convert or sharp).

### 3. HTML shell wiring

Edit the SPA template (likely `/Users/artelonga/projects/co/co-web/templates/index.html` or wherever `<head>` is rendered — confirm) to add:

```html
<link rel="manifest" href="/manifest.json">
<link rel="apple-touch-icon" href="/shared/icons/apple-touch-icon.png">
<meta name="theme-color" content="#2563eb">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="default">
<meta name="apple-mobile-web-app-title" content="CO">
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

### 4. Service worker registration

In the SPA boot (`/Users/artelonga/projects/co/co-web/static/variants/a/modules/.../index.js` — locate the boot module), ensure:

```js
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js', { scope: '/' })
      .catch(err => console.warn('[SW] register failed', err));
  });
}
```

### 5. Service worker strategy refinement

The existing `sw.js` is mostly correct. Confirm/adjust:

- **Cache-first** for `/lib/*.js`, `/static/*`, `/shared/icons/*`, `/favicon.svg`, fonts.
- **Network-first with cache fallback** for `/api/v1/*` (so a stale read is shown when offline, but fresh data wins online).
- **Cache-only (read-through IDB)** for `/api/v1/universes/{key}/entries` snapshots — populated on first network success, served from IDB when offline. Already drafted in `sw.js`; confirm it works end-to-end.
- **Navigation fallback**: if a navigation request fails and no cache, serve a small `/offline.html` fallback (new file, ~30 lines, "You're offline. Cached content is still browsable.").

Bump `CACHE_NAME` to `co-v6-offline` so existing clients purge the stale `v5` skeleton.

### 6. Install prompt UI

Listen for `beforeinstallprompt`, stash the event, surface a small "Install CO" button (header overflow menu on desktop, bottom bar on mobile). Dismissal persists in `localStorage` under `co.installPromptDismissed = '<iso-timestamp>'`. Re-prompt after 30 days. iOS Safari has no `beforeinstallprompt` — show a one-shot tooltip the first time the app loads on iOS Safari explaining "Tap Share → Add to Home Screen".

New module: `/Users/artelonga/projects/co/co-web/static/variants/a/modules/install/wire.js` (~60 lines).

### 7. Static file serving

Confirm `co-web` serves `/manifest.json`, `/sw.js`, and `/shared/icons/*` with correct MIME types and short cache headers (no `immutable` — see memory `feedback_cache_headers`). Manifest must be `application/manifest+json`. SW must be served from root scope (already true) with `Service-Worker-Allowed: /`.

### 8. Telemetry

Emit `pwa_install_prompt_shown`, `pwa_install_prompt_dismissed`, `pwa_installed` (from `appinstalled` event) via the existing `crate::telemetry` envelope so we can measure adoption on the CO-360 dashboard.
