GIVEN bulk-imported markdown (CO-67 seed pattern) lands in the entries table without an explicit `type:` field in its frontmatter, and the Conteúdo view at `/co/<slug>` filters by `type=page|task|event|clip` — meaning hundreds of imported `.md` files appear in the API but render as "Nenhuma página" in the UI; AND yuri wants an Obsidian-like flat-or-folder vault view that shows ALL markdown regardless of typing,
WHEN we (1) fold untyped `*.md` entries into the existing folder-tree renderer (immediate quick win — already preview-shipped), and (2) add a dedicated "Vault" tab that mirrors Obsidian's UX — left pane file tree + center pane rendered markdown + click-to-navigate file links + breadcrumbs,
THEN any bulk-uploaded universe (artelonga, qa-dev, rfq) immediately becomes browsable as content rather than appearing empty.

## Two-phase approach

### Phase 1 (preview, this commit)

Patch the existing Conteúdo renderer to include untyped `.md` entries in the Pages folder tree. Single 15-line change to `app.js::renderConteudo` — fetches `getUniverseEntries(slug)` (no type filter) in addition to the typed queries; folds entries that are NOT in `task|event|page|clip` into the page list before building the folder tree.

Result: ~146 artelonga entries, ~315 qa-dev entries, ~205 rfq entries (post-cleanup of `.claude/` noise) all show in the folder tree under the Pages section.

### Phase 2 (proper Obsidian-like view, follow-up)

Add a dedicated "Vault" tab next to "Kanban / Conteúdo" with:

```
┌──────────────────┬──────────────────────────────────────────┐
│ FILE TREE        │ ENTRY VIEWER                             │
│                  │                                          │
│ ▼ projects/      │ # Title from frontmatter                 │
│   ▼ artelonga/   │                                          │
│     sobre.md     │ Rendered markdown body...                │
│     servicos/    │ With Mermaid diagrams (CO-83) inline.    │
│       drywall.md │ Wikilinks [[other-entry]] are clickable. │
│   relatos/       │                                          │
│ ▶ comunidades/   │ ─────────                                │
│                  │ Backlinks panel                          │
│                  │ Edit button (opens CodeMirror)           │
└──────────────────┴──────────────────────────────────────────┘
```

Features:
- **File tree** in left pane — collapsible folders, file count per folder, type-filter toggle (all / pages / tasks / events / clips)
- **Search** (Cmd+P / Ctrl+P) — fuzzy match across titles + paths in the current universe
- **Backlinks** — derived from `[[wikilinks]]` in entry bodies; uses CO-74 typed relations once that ships
- **Inline preview on hover** — hover a file in the tree, get a small preview tooltip
- **Drag-and-drop** to reorganize (rename + move) — vault PUT with old path delete

## Cleanup of `.claude/worktrees/` noise

The first bootstrap on prod pulled `.claude/worktrees/agent-XXX/...` directories — co-auto runtime state, not user content. Delete via:

```bash
bash scripts/cleanup-vault-noise.sh                     # dry-run on prod
bash scripts/cleanup-vault-noise.sh --execute           # actually delete on prod
bash scripts/cleanup-vault-noise.sh --to uat --execute  # UAT
```

Patterns deleted: `.claude/`, `.obsidian/`, `.cache/`, `seed-co/` substring matches.

After cleanup, `rfq` drops from 205 → ~12, `qa-dev` drops from 315 → ~93. Future bootstraps won't re-introduce because the seed script's `find` excludes are tightened.
