## As

a first-time user opening chat on CO

## I Need

a single coherent surface ("Conversas") that immediately conveys
**privacy through context** — I see exactly who can read what I'm
about to type, before I type it, without anyone needing to explain it

## So That

the privacy model isn't a feature in settings I have to discover; it's
the **default visible state** of the chat itself. Slack/Discord
established the pattern of clear context per conversation; CO does
the same but explicitly grounded in universe membership.

---

## Conceptual model (already true at the schema layer)

Every conversation in CO is one of:

1. **Universe chat** — bound to a universe. Readable only by that
   universe's members. The universe-as-context defines the audience.
2. **DM** — bound to exactly two users. Readable only by those two.

Sub-universes get their own chats automatically (a sub-universe IS a
universe). Copies / staging environments / project subsets share this
pattern.

`CO-geral` is the universe chat for the root `co` universe — the
top-level announcement channel. Members are auto-seeded from the CO
universe membership.

## Surfaces being unified

Today:

- `💬 Chat` button → universe rooms drawer (CO-193 → CO-196)
- `📩 Mensagens` button → DMs drawer (CO-198)
- Two separate surfaces, similar but visually disjoint.

After CO-209:

- **`💬 Conversas`** single sidebar entry → drawer with two sections:
  - **"Universos"** — list of universe chats the user belongs to
    (one per universe, nested by `parent_key` per CO-191/192)
  - **"Mensagens privadas"** — DM threads (collapsible)
- Clicking either section item opens that conversation in the
  scrollback pane. The current chat-drawer + dm-drawer becomes ONE
  drawer with two left-rail sections.

## First-time experience (the welcome pop-up)

Trigger: user clicks `💬 Conversas` for the first time per browser
profile (tracked via `localStorage["co_chat_welcome_seen"] === "1"`).

Pop-up appears as a modal **over** the chat drawer:

```
┌────────────────────────────────────────────────────────┐
│                       Conversas                         │
│                                                          │
│   Sua autonomia para o futuro: seus dados são seus.     │
│                                                          │
│   Mensagens só podem ser lidas pelos membros            │
│   de um Universo — privacidade e segurança.             │
│                                                          │
│   Veja todos os membros no menu lateral.                │
│                                                          │
│   [Click outside ◴ click [×] ◴ press Enter to dismiss]   │
└────────────────────────────────────────────────────────┘
```

**Dismissal mechanics — three equally-valid paths:**

| Action | Effect |
|---|---|
| `Enter` key | Dismiss + set `localStorage` flag |
| Click outside the modal | Same |
| Click the `×` button | Same |

**Why `Enter` specifically?** It teaches the chat keyboard shortcut by
muscle memory. Once dismissed, the user is left in the composer-
focused state where `Enter` will then *send* the message they type.
The transition from "Enter dismisses" → "Enter sends" is intentional:
the user just rehearsed the pattern.

**No text explaining the keyboard shortcut.** The bullet line with
three icons (` ⌫ ` for `Enter`, ` ⊠ ` for click-outside, ` × ` for
the close button) communicates dismissal visually. The lack of
explicit explanation forces a tiny moment of discovery.

## Member visibility (the "see all members" promise)

Below the privacy pop-up dismisses, the chat drawer renders with a
**Members section prominent in the left rail** for the currently-
selected conversation:

```
┌─────────────────┬───────────────────────────────────────┐
│ 💬 CONVERSAS    │ # CO-geral                            │
│                  │                                        │
│ Universos        │ Yuri · há 2 min                       │
│   ▾ Co           │   Bem-vindos ao CO-geral!             │
│     # geral ←    │                                        │
│     # random    │ Mariana · há 5 min                    │
│     + nova      │   Olá!                                │
│   ▸ tempo       │                                        │
│   ▸ quilombo    │                                        │
│                  │ ┌──────────────────────────────────┐ │
│ Mensagens        │ │ Escreva uma mensagem...          │ │
│   📩 Maria       │ └──────────────────────────────────┘ │
│   📩 Pedro       │                       [Enviar ⏎]    │
│                  │                                        │
│ 👥 MEMBROS (12) │                                        │
│   ● Yuri (você) │                                        │
│   ● Mariana     │                                        │
│   ○ Pedro       │                                        │
│   ○ ana@...     │                                        │
│   ○ ...         │                                        │
└─────────────────┴───────────────────────────────────────┘
```

Member rail shows:

- All `chat_room_members` for the current conversation (or, for DMs,
  just the two parties)
- Presence dot: `●` online (within last 60s), `○` offline
- Click a member → open DM with them (only if `dm_policy` allows)
- Search/filter input above the list when count > 10

For DMs, the member rail shows just two rows — but **importantly, it
still shows them**, reinforcing "this conversation can be read by
these two people, period."

## What changes in code

### Frontend (the bulk of this ticket)

| File | Change |
|---|---|
| `modules/chat.js` | Split into `modules/conversas.js` (the drawer shell) + `modules/conversation-view.js` (one conversation's scrollback). Subsumes both old `chat.js` (universe rooms) and `dm.js` (DMs). |
| `modules/conversas-welcome.js` | NEW — the first-time pop-up. `localStorage["co_chat_welcome_seen"]` tracks dismissal. |
| `index.html` | Replace `💬 Chat` + `📩 Mensagens` sidebar buttons with single `💬 Conversas`. Remove the two old drawers; add one new `#conversas-drawer`. |
| `style.css` | Welcome modal overlay + left-rail two-section layout + member rail with presence dots. |
| `i18n.js` | New keys: `conversas.title`, `conversas.welcome.headline`, `conversas.welcome.body`, `conversas.welcome.members_hint`, `conversas.section.universos`, `conversas.section.mensagens_privadas`, `conversas.members_header`. PT first; EN equivalent. |

### Backend (minimal)

`general` room slug stays `general` (English; SQL-friendly). The
**display name** for the auto-seeded CO room becomes "CO-geral"
(stored in `chat_rooms.name`). New universes seed with name "geral"
(lower-cased Portuguese). Migration optional — can do this via a
runtime rename of the existing CO universe's general room:

```sql
UPDATE chat_rooms
SET name = 'CO-geral'
WHERE universe_key = 'co' AND slug = 'general' AND is_default = 1;
```

For all other universes, `name = 'geral'` becomes the new default in
`ensure_default_room`. Existing rooms keep their current names.

### Member rail data source

`GET /api/v1/universes/:slug/chat/rooms/:room_slug/members` — new
endpoint OR reuse `GET /universes/:slug/members` (CO-189 already
exposed). For DMs (`slug=dm`), use the two `chat_room_members` rows
for the room.

Presence dots: reuse the WebSocket presence broadcast from CO-194.
A member is "online" if they currently have an open WS to that room.

## Acceptance

- [ ] Click `💬 Conversas` for the first time → welcome pop-up appears

- [ ] Click outside the modal → same dismissal behavior as Enter
- [ ] Click `×` → same

- [ ] Single `💬 Conversas` button in sidebar (no more separate `📩 Mensagens`)
- [ ] Drawer opens with left rail showing two sections: "Universos" and
      "Mensagens privadas"
- [ ] Universos list includes every universe the user is a member of,
      with sub-universes nested
- [ ] CO universe's chat is named "CO-geral" in the rail
- [ ] Other universes' default room is "geral"
- [ ] Clicking a universe in the rail loads its chat
- [ ] Clicking a DM in the rail loads that DM

      bottom-aligned panel)
- [ ] Shows all `chat_room_members` for the current conversation

- [ ] Click a member → opens DM with them (if `dm_policy` allows)

## Out of scope

- **Roles in the member rail** — admin/owner badges. Can layer in later.
- **Member sorting** by recent activity. Alphabetical for v1.
- **Per-conversation notification mute** beyond the global setting (CO-202).
- **Threading** within a conversation (replies-to as a tree). Separate
  ticket.
- **Reactions** (👍, ❤️). Separate ticket.
- **Search across conversations**.
