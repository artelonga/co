## As

A visitor to https://co-artelonga.fly.dev/co (anonymous or logged-in)

## I Need

The board to render the content that the API clearly has (1227 entries for `co` per `/api/v1/universes/co`).

## So That

The CO universe stops appearing empty when its data is intact and reachable via API. Today the user opens the board and sees nothing, despite working endpoints.

## Context

Prod symptom:

- `GET /api/v1/universes/co` reports `content_count=1227`.
- The entries endpoint returns content to anonymous callers.
- The board UI renders empty.

Three plausible causes, in decreasing likelihood:

1. **Board renders only projects+tasks.** `bootAppForUniverse` (/Users/artelonga/projects/co/co-web/static/variants/a/modules/boot.js:172) calls `api.getUniverseProjects(slug)` and shows the empty-board state when there are no projects. The `co` universe's 1227 entries are mostly `page`/`user-story`/`task` from `work/co/` — but the kanban "project" wrapper may be absent or wrongly keyed, so the project list comes back empty and the board never even tries to load entries.
2. **Anonymous-clone redirect.** The boot logic in /Users/artelonga/projects/co/co-web/static/variants/a/app.js:823–938 has multiple branches. If the user hits `/co` while logged in with universes of their own, `bootApp` (line 881) auto-redirects to the user's primary universe instead of staying on `co`. The user "sees an empty board" because they're actually on their own freshly-created clone, not on `co`.
3. **Sidebar default + URL parse.** `readUniverseSlugFromUrl` (app.js:145) defaults to `'template'` for the root path. Reaching `co` requires the URL `/co` — if any redirect (CO-323 subdomain logic, anonymous-clone resolver, etc.) bounces the user back to `/`, they land on `template`, which is empty for them.

## Design

### Step 1 — Reproduce + diagnose

Add a brief diagnostic phase. Open https://co-artelonga.fly.dev/co in:

- incognito (anonymous, no clone yet)
- logged-in admin (yuri)
- logged-in fresh user (no universes of their own)

For each, capture `state.currentUniverseSlug`, `state.projects.length`, the actual entries returned by `GET /api/v1/universes/co/entries`, and the network panel's last request before the board renders. Record findings in the PR description.

### Step 2 — Fix the actual cause

Whichever of the three matches:

- **(1) Missing default project:** /Users/artelonga/projects/co/co-web/src/storage/seed.rs line 862 already excludes `co` from `seed_default_project_if_missing` ("the `co` universe is the exception — `seed_co_universe_tasks` runs later"). Verify `seed_co_universe_tasks` actually creates a project row on a fresh prod DB and that `list_projects_for_universe("co")` returns it. If not, drop the exception (let the generic default fire for `co` too) or fix the CO-specific seed.
- **(2) Auto-redirect away from co:** Guard the redirect at app.js:881 — never auto-redirect away from `co` (or any explicit URL slug); the auto-redirect should only fire when the URL is `/` or `/template` AND the user has their own universes. Mirror the existing `stayOnTemplate` guard for `co`.
- **(3) URL/subdomain reset:** Trace `readUniverseSlugFromUrl` and the subdomain injection; if `co.artelonga.com.br` (when it exists) sets `__CO_SUBDOMAIN_UNIVERSE__` wrong, fix the injector.

### Step 3 — Lock it down

Add an E2E test in /Users/artelonga/projects/co/co-web/e2e/ (Playwright):

```ts
test('anonymous visitor to /co sees content', async ({ page }) => {
  await page.goto(`${BASE_URL}/co`);
  await page.waitForSelector('[data-board], [data-entry-list]');
  const entryCount = await page.locator('[data-entry-id]').count();
  expect(entryCount).toBeGreaterThan(0);
});
```

(Adjust selectors to whatever the renderer actually uses — confirm during Step 1.)
