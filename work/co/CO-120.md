## As

a CO operator preparing to ship telemetry from arbitrary user deployments

## I Need

a `CoAgent` trait in `co-core` defining a stable shipping contract, plus a reference Fly-sidecar implementation that tails container logs, batches+zstd-compresses, and pushes to the CO ingest endpoint with HMAC

## To

lock in the abstraction now (cheap), so subsequent phases just add adapter variants (CF Worker tail, Vercel Log Drains, browser SDK) without re-arguing the API shape

## Given / When / Then

GIVEN the SR plan describes co-agent as "a tiny Rust sidecar" but glosses over Vercel/Workers/static targets where sidecars don't exist,
WHEN we define the agent contract as a trait with multiple implementations and ship the Fly variant first,
THEN every later target gets a thin adapter, the contract stays stable, and §C.1 of the platform review is satisfied.

## Trait shape (proposal)

```rust
pub trait CoAgent: Send + Sync {
    fn ship(&self, events: &[TelemetryEvent]) -> impl Future<Output = Result<()>>;
    fn heartbeat(&self) -> impl Future<Output = Result<()>>;
    fn flush(&self) -> impl Future<Output = Result<()>>;
}

pub struct FlySidecarAgent {
    ingest_url: Url,
    universe_id: String,
    hmac_key: SecretBytes,
    batch: Mutex<Vec<TelemetryEvent>>,
    config: AgentConfig,  // batch_size, flush_interval, max_retries
}
```

The sidecar reads from a configurable source (stdin, named pipe, or HTTP-localhost), batches events, zstd-compresses the JSON-Lines payload, signs with HMAC-SHA256 over `(timestamp || universe_id || body_hash)`, POSTs to `https://ingest.co.artelonga.com.br/v1/events`. Heartbeat every 60s. On 5xx, exponential backoff with jitter. On 4xx, log + drop.

## Acceptance

- [ ] `CoAgent` trait + `FlySidecarAgent` impl in `co-core`
- [ ] Standalone `co-agent` binary builds for `aarch64-unknown-linux-musl`
- [ ] Docker image `co-agent:0.1.0` published to GHCR
- [ ] Reference compose snippet in `docs/co-agent/fly-sidecar.md` showing how to add it as a sidecar to a Fly Machine
- [ ] Unit tests cover: batch flush at size threshold, batch flush at time threshold, retry-then-drop on persistent 5xx, HMAC validation
- [ ] One end-to-end test: stand up sidecar against UAT ingest, emit 100 events, confirm ≥99 land

## Out of scope

- CF Worker tail variant — CO-124
- Vercel Log Drain variant — CO-124
- Browser SDK / static-target beacon — Phase 2 follow-up
- Encrypted payloads — Phase 4 (sidecar will already accept a `Cipher` strategy hook for that phase)

## Risks

- **Backpressure & event loss.** Mitigation: bounded ring buffer with documented overflow policy (drop-oldest); emit a `co_agent_dropped_events_total` counter via heartbeat.
- **Clock skew breaking HMAC freshness.** Mitigation: ±5min skew window on ingest; log+reject outside.
