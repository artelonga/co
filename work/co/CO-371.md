## As
The platform operator wanting to see end-to-end conversion in one place

## I Need
A single endpoint that joins acquisition (analytics_rollups), goals (telemetry events), signups (auth_events), leads (lead state machine), and payments (billing_events) into one funnel report with per-step drop-off, broken down by source / day / country.

## So That
- The 8 funnel steps from the lead-acquisition review render in ONE chart, not five.
- I can answer "of the visitors that arrived via HN this week, what % converted to paid?" — today this requires manual SQL across 4 stores.
- The `/gestao/resumo` dashboard (CO-360) has its killer metric.
- Optimization targets are visible: where's the biggest drop-off this week?

## Context

The funnel today is measurable in pieces:
- Acquisition + engagement: `analytics_rollups` (CO-340)
- Goals (CTA clicks): telemetry events (CO-291)
- Signups: auth events + `users` table
- Leads: `leads` state machine (CO-183, + CO-370 unification)
- Payments: `billing_events` (CO-366 — coming)

No endpoint joins them. This spec stitches them via the email join key established in CO-370.

## Design

### The 8 steps + their data sources

| # | Step | Data source | Count = |
|---|---|---|---|
| 1 | Discover | `analytics_rollups.visits` | distinct sessions in window |
| 2 | Engage | `analytics_rollups.visits` WHERE `dwell_ms > 5000` | dwelled |
| 3 | Intent | telemetry events `kind=click_cta` | unique sessions with at least 1 CTA click |
| 4 | Capture | `users` WHERE `created_at` in window OR `leads` WHERE `created_at` in window | distinct emails (CO-370 join) |
| 5 | Qualify | `leads` WHERE `status IN ('triaged', 'in_progress', 'closed_won', 'closed_lost')` | leads triaged |
| 6 | Register | `users` WHERE `verified_at IS NOT NULL` AND in window | verified accounts |
| 7 | Convert | `billing_events` WHERE `event_type='payment_succeeded'` AND in window | paid users |
| 8 | Onboard | `universes` WHERE `owner_id IN (paid users)` AND `created_at >= billing.paid_at` | universes created post-payment |

### Endpoint

```
GET /api/v1/analytics/public/funnel
  ?window=7d|30d|90d|custom
  &start=<iso>            (if custom)
  &end=<iso>              (if custom)
  &breakdown=source|day|country|none
```

Response:

```json
{
  "window": {"start": "...", "end": "..."},
  "breakdown": "source",
  "steps": [
    { "step": 1, "name": "discover", "count": 5230 },
    { "step": 2, "name": "engage", "count": 1840, "drop_off_pct": 64.8 },
    { "step": 3, "name": "intent", "count": 312, "drop_off_pct": 83.0 },
    ...
  ],
  "by_source": {
    "(direto)": [...same shape per step...],
    "hn.algolia.com": [...],
    "google.com": [...]

  "kpis": {
    "intent_rate": 0.169,
    "capture_rate": 0.385,

    "conversion_rate": 0.034,

```

### Implementation

New `co-web/src/analytics/funnel.rs`:
- Single batched query (CTE-driven, sqlite-compatible)
- Window pre-aggregations from `analytics_rollups` for steps 1-2
- Live joins from `leads` + `users` + `billing_events` for steps 4-7
- Step 8 is a single COUNT with a subquery

Performance budget: < 200ms on current prod (~12K entries, ~100 users, ~16 leads). Indexes on `users.created_at`, `users.verified_at`, `leads.created_at`, `billing_events.created_at` (likely already present; add if missing).

### Breakdown semantics

- `breakdown=source`: by `analytics_rollups.referrer` bucket
- `breakdown=day`: per-day counts in the window
- `breakdown=country`: by geo (CO-340 already aggregates)
- `breakdown=none`: just the aggregated steps

### KPIs

Computed from the same query:
- `intent_rate = step3 / step2`
- `capture_rate = step4 / step3`
- `verify_rate = step6 / step4`
- `conversion_rate = step7 / step6`
- `t_register_to_payment_median_s` — median diff between `users.verified_at` and earliest `billing_events.event_type=payment_succeeded` for the same user_id

### Surface

`/gestao/resumo` (CO-360) renders the funnel as a vertical bar chart with drop-off labels. Reuses existing canonical canvas rendering primitive (`co-web/static/variants/a/lib/co-graph.js` or new `lib/co-funnel.js` — small, no library).

### Telemetry

Per CO-361 atividades:
- `event_type = funnel.queried` per request (audit who's looking at conversion)
