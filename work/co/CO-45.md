GIVEN the user wants to test changes on UAT (data, config, content), then commit those changes back to the dev codebase so they're included in future deployments,
WHEN I build a state tracking + version control backend that records UAT mutations and exports them as a patch,
THEN:

## State Tracking

- [ ] New table `uat_mutations`:
  ```sql
  CREATE TABLE uat_mutations (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      timestamp TEXT NOT NULL,
      user_id TEXT,
      action TEXT NOT NULL,        -- 'entry.create', 'entry.update', 'config.update', etc.
      target TEXT NOT NULL,         -- entry path or config key
      before_value TEXT,            -- JSON snapshot before
      after_value TEXT,             -- JSON snapshot after
      metadata TEXT                 -- additional context
  );
  ```
- [ ] Middleware on UAT: every write operation logs to `uat_mutations`
- [ ] Excludes: telemetry, sessions, ephemeral state

## Version Control Backend

- [ ] Each UAT deploy snapshots the DB schema + config to `co-web/data/uat-snapshots/v{N}.json`
- [ ] Mutations between snapshots tracked
- [ ] On request, generate a patch:
  - Schema migrations needed (DDL)
  - Content changes (which entries were created/modified)
  - Config changes
  - User-uploaded assets

## Promotion Endpoint

- [ ] `GET /api/v1/uat/changes?since={snapshot_version}` — admin only
- [ ] Returns:
  ```json
  {
    "snapshot": "v3",
    "mutations": [...],
    "schema_changes": [...],
    "content_diff": {
      "added": [...],
      "modified": [...],
      "deleted": [...]
    }
  }
  ```
- [ ] `POST /api/v1/uat/export-patch` — generates a git patch file:
  - SQL migrations as `migrations/v{next}_uat_promote_{timestamp}.sql`
  - Content as `data/promoted/*.md` files
  - Config diff as YAML
  - All bundled into a `.tar.gz` for download

## Workflow

1. Make changes on UAT (logged in as yuri)
2. Verify behavior
3. `GET /api/v1/uat/changes` to preview
4. `POST /api/v1/uat/export-patch` to download tarball
5. Locally: `tar -xzf patch.tar.gz && git add . && git commit -m "promote UAT changes"`
6. Future deploys include these changes
7. UAT keeps the changes (not rolled back) until next snapshot

## Snapshot Reset

- [ ] After successful promotion, optionally bump snapshot version
- [ ] Or: reset UAT to match prod after promotion (using CO-44 reset flag)

## Acceptance

- [ ] All write operations on UAT are logged to `uat_mutations`
- [ ] `GET /api/v1/uat/changes` returns accurate diff
- [ ] `POST /api/v1/uat/export-patch` generates valid tarball
- [ ] Tarball can be applied to dev codebase via `git apply` or manual integration
- [ ] Production: tracking disabled (CO_ENV != uat)
- [ ] `cargo test` passes
- [ ] Integration test: make change on UAT → export → verify content
