## As
The platform operator running the bi-weekly Thursday release

## I Need
A Playwright suite running against `staging.co.artelonga.com.br` that exercises universe recursion, sub-universe promotion to root, the lead funnel + conversion, and all general user routes — gating prod release on a green run.

## So That
- Wave 4 (16 PRs to v3.0) gets continuous validation as each PR merges to main.
- Schema migrations land on staging first; any breakage caught before prod.
- Acceptance criteria from each `work/co/CO-N.md` become real test cases (CO-369 generator).
- The release-Thursday 12:00 BRT smoke window has objective pass/fail.

## Context

CO-379 provides the staging Fly app + reset fixtures. CO-374 consumes it. CO-369 (just shipped) parses every spec's `## Acceptance` checklist — this spec extends that to emit Playwright test stubs.

Default `co-web/e2e/` runs in CI against an ephemeral local server. New `co-web/e2e-staging/` runs against the live staging URL with the fixture data.

## Design

### Suite structure

```
co-web/e2e-staging/
├── playwright.staging.config.ts      — Base URL, retries, parallel: 1 (avoid fixture clashes)
├── fixtures.ts                       — Shared yuri login, fixture user logins
├── helpers.ts                        — Resync to staging baseline (touches reset flag if needed)
├── scenarios/
│   ├── universe-recursion.spec.ts    — A → A/B → A/B/C breadcrumbs + graph + entries
│   ├── subuniverse-promotion.spec.ts — promote A/B to root, verify A/B/C reparents
│   ├── lead-funnel.spec.ts           — visit → CTA → form → signup → verify → tier check
│   ├── general-user-routes.spec.ts   — login, board CRUD, theme, lang, feedback, search
│   ├── security-headers.spec.ts      — X-RateLimit, CSP, HSTS, Retry-After
│   └── auth-flows.spec.ts            — magic code, password, OAuth, logout, session expiry
└── generated/
    └── from-acceptance.spec.ts       — auto-generated from work/co/CO-*.md acceptance lists
```

### Key scenarios

#### Universe recursion (`universe-recursion.spec.ts`)

```typescript
test("A → A/B → A/B/C: breadcrumbs render full trail", async ({ page }) => {
  await loginAsYuri(page);
  await page.goto("/u/A/B/C");
  await expect(page.locator("#breadcrumbs")).toContainText(["CO", "A", "B", "C"]);
});

test("graph view aggregates across A,B,C universes", async ({ page }) => {
  await page.goto("/u/A/graph?universes=A,B,C&depth=2");
  const nodes = await page.locator(".graph-node").count();
  expect(nodes).toBeGreaterThan(10);
});

test("cross-universe wikilink resolves: [[A::path]] from C", async ({ apiContext }) => {
  const res = await apiContext.get("/api/v1/universes/C/entries/notes/cross.md");
  const entry = await res.json();
  expect(entry.related_resolved).toContain("A::overview.md");
});
```

#### Subuniverse promotion (`subuniverse-promotion.spec.ts`)

```typescript
test("promote A/B to root B; verify A/B/C reparents to B/C", async ({ apiContext }) => {
  const before = await apiContext.get("/api/v1/universes/B");
  expect(before.status()).toBe(404);          // doesn't exist as root yet
  
  await apiContext.post("/api/v1/admin/universes/promote", {
    data: { key: "A/B", new_parent: null },
  });
  
  const after = await apiContext.get("/api/v1/universes/B");
  expect(after.status()).toBe(200);
  
  const child = await apiContext.get("/api/v1/universes/C");
  const childData = await child.json();
  expect(childData.parent_key).toBe("B");
});
```

#### Lead funnel (`lead-funnel.spec.ts`)

```typescript
test("visit → CTA → signup → verify → tier", async ({ page, apiContext }) => {
  // 1. Visit with UTM
  await page.goto("/?utm_source=playwright-test");
  
  // 2. Click CTA
  await page.click('a[href="/faca-parte/"]');
  
  // 3. Submit signup
  const email = `test-${Date.now()}@playwright.staging`;
  await page.fill("#email", email);
  await page.click("#submit-signup");
  
  // 4. Get magic code from server logs
  const code = await getMagicCodeFromStagingLogs(email);
  await page.fill("#code", code);
  await page.click("#verify");
  
  // 5. Verify lead created with source=signup (CO-370)
  const lead = await apiContext.get(`/api/v1/admin/leads?email=${email}`);
  const leadData = await lead.json();
  expect(leadData.source).toBe("signup");
  expect(leadData.status).toBe("in_progress");
  
  // 6. Verify user shell linked
  expect(leadData.user_id).toBeTruthy();
});
```

#### General user routes (`general-user-routes.spec.ts`)

Iterates over: `/`, `/co`, `/yuri`, `/scrum/calendar`, `/gestao/resumo`, `/settings/sync`, `/notifications`, `/recover`. Each: load < 3s, no console errors, expected H1, no 5xx on `/api/v1/*` calls.


### CO-369 acceptance → test generator

New script `scripts/scrum/acceptance-to-playwright.ts`:

1. Walk `work/co/CO-*.md`
2. Parse `## Acceptance` checklist items
3. Emit a `.spec.ts` stub per item with the spec ID + acceptance text

```typescript
// generated/from-acceptance.spec.ts
import { test, expect } from "@playwright/test";

test.describe("CO-352 — Workspace primitive", () => {
  test("btn-compor opens compose modal", async ({ page }) => {
    // TODO: implement
    test.fixme();
  });
  test("login CTA on btn-publish for anon", async ({ page }) => {
    test.fixme();
  });
});
```

Devs fill in `// TODO`s during the PR. CI counts `fixme`s — Wave 4 DoD = all CO-352..359 acceptance items have non-fixme tests.
