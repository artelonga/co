## As
Yuri running `co serve` on his Mac

## I Need
macOS native notifications when CO events happen (new message via CO-326, build completes, claude session needs input, …)

## So That
I don't have to keep the browser tab in focus to see what's happening

## Scope

### Notification triggers
- Direct message received (CO-326) → "New message from <name>: <subject>"
- Local LLM finished a query (CO-328)
- Claude Code session paused for input (CO-328)
- Background process started/finished (CO-329)

### Implementation
Two options:

**A. notify-rust crate** (cross-platform, recommended)
- Add to `co-cli/Cargo.toml`: `notify-rust = "4"`
- New module `co-cli/src/notify/macos.rs` with `pub fn send(title: &str, body: &str)`
- Stub on non-Mac platforms

**B. osascript shim** (no extra dep)
- `Command::new("osascript").arg("-e").arg(format!("display notification \"{body}\" with title \"{title}\""))`
- macOS-only

Pick A — cleaner + multi-platform.

### Wiring
- Notifications worker (background tokio task) polls a channel
- Each CO event that needs a desktop notification publishes to the channel
- The macos worker debounces (don't fire 50 notifications in a second)

### Config
- `CO_DESKTOP_NOTIFY=on|off` env var (default on if running on Mac)
- User can toggle in settings

### Permissions
- First notification triggers macOS permission prompt
- Document in README how to grant permission

## Acceptance
- [ ] Running `co serve` + CO-326 message → desktop notification appears
- [ ] `CO_DESKTOP_NOTIFY=off co serve` → no notifications fired
- [ ] Notification click opens browser to `/notifications`
- [ ] No notification on Linux/Windows (graceful no-op)

## Blast radius
- 1 new dep (notify-rust)
- ~80 lines in `co-cli/src/notify/`
- 1 wiring point in notifications worker
- Per-platform `#[cfg]` blocks

## Why now
The local LLM + claude-hook + messaging features all benefit from out-of-browser awareness. Without notifications they all require active polling.
