## As

A visitor of `/yggdrasil`, `/rfq`, `/quilomboaraucaria`, `/artelonga` universes

## I Need

The sister-repo `work/<space>/*.md` files (plus root `CHANGELOG.md`/`README.md`/`LICENSE.md`) to be available as entries in their corresponding CO universes — same model as CO-261 for the local `/co` universe.

## So That

The live-dev-board promise CO-261 made for `/co` extends to all 5 universes. /yggdrasil shows YG-1..62 tasks, /rfq shows RFQ-1..27, etc.

## Context

CO-261 phase A walks the **local** `/Users/artelonga/projects/co/work/co/` folder during boot. Sister repos (yggdrasil/rfq/qb/artelonga) are separate git repos at `/Users/artelonga/projects/<repo>/`. The CO server process doesn't have read access to those paths in production (Docker filesystem isolation).

### Decision — push from sister repos via co-sync

Three options considered earlier (CO-261 spec):
- **A. Boot-time walk** — only works for local /co
- **B. File-watcher** — same constraint; doesn't cross repos
- **C. Bidirectional Vault sync** — sister repos PUSH their work to CO

C is the right answer for cross-repo. Each sister repo runs `co-sync` (the existing tool) on every merge, pushing its `work/<space>/*.md` to CO via the Vault API.

## Scope

### 1. `co-sync` tool extension

Update `co-sync` (or write `scripts/sync-work-to-co.sh`) to:

- Read a config from `co-universes.yaml` declaring which folders sync to which universes:
  ```yaml
  syncs:
    - source: work/yggdrasil/
      target: yggdrasil/
      include: ['*.md']
      exclude: ['CLAUDE.md', '.gitkeep']
    - source: work/rfq/
      target: rfq/
    # etc.
  ```
- For each file: `PUT /api/v1/universes/<target>/vault/<path>` with Bearer token
- Cache hash → skip unchanged files
- Idempotent

### 2. Per-repo CI integration

Add a GH Action to each sister repo (yggdrasil, rfq, qb, artelonga):

```yaml
on:
  push:
    branches: [main]
jobs:
  sync-to-co:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: cargo install co-sync --git https://github.com/artelonga/co
      - run: co-sync push --config co-universes.yaml
        env:
          CO_TOKEN: ${{ secrets.CO_VAULT_TOKEN }}
```

### 3. Token provisioning

Each sister repo needs a CO Vault token. One per repo (least privilege). Stored as a GH secret.

### 4. Backend: accept the synced entries

Vault PUT already exists. The existing seed walker (CO-261) needs to **not overwrite** synced entries on next boot — check for `entry_origin: synced` vs `entry_origin: walker` in the entry metadata.

## Acceptance

- After CO-267 lands + sister repos run their sync action:
  - `/yggdrasil` shows YG-N tasks
  - `/rfq` shows RFQ-N tasks
  - `/quilomboaraucaria` shows QB-N tasks
  - `/artelonga` shows AL-N tasks
- Each sister repo's CHANGELOG.md is at the universe root
- Idempotent: running sync twice doesn't re-write unchanged files
- Tests: integration test in co-sync that mocks the Vault API and verifies the hash-skip logic
