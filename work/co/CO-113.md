## As

a CO operator running a sustained public test

## I Need

per-universe SQLite isolation (LiteFS), a single-node ClickHouse for ad-hoc analytics, and co-agent variants for non-sidecar deployment targets (Cloudflare Worker tail, Vercel Log Drains)

## To

isolate noisy universes from each other, give yuri a query surface richer than WAE for ad-hoc analytics, and start collecting telemetry from user deployments on platforms that don't allow sidecars — all without standing up the full streaming bus yet

## Stories

- CO-123 — ClickHouse single-node on Fly + Iceberg-table-function ready
- CO-124 — Co-agent variants for CF Workers tail + Vercel Log Drains

## Acceptance gates

- [ ] LiteFS replica reads work in 2+ regions (existing CO-77)
- [ ] ClickHouse on Fly answers an aggregate query over WAE export in <1s
- [ ] A sample CF Worker deployment ships ≥99% of its emitted log lines to CO ingest
- [ ] A sample Vercel project's Log Drain delivers structured events to CO ingest

## Out of scope

- Iceberg lake creation — Phase 3
- Pinot — defer to Phase 5 unless user-facing kQPS demand emerges
- Apple-style conflict UI — Phase 3

## Why now

ClickHouse is the cheap interim between WAE (limited cardinality) and the full Iceberg lake. Multi-target co-agent unlocks observability of user deployments, which is required before §C.4's deployer abstraction in Phase 5.
