## As

a user working in a Sala (CO-352) with collaborators — co-authoring a workspace on the mbya lexicon, planning a comunicacao event, drafting a piece of game content — I need to *see* the other people in the room: their cursors, their moves, their edits, in real time.

## I Need

a WebSocket layer dedicated to workspace canvases that broadcasts cursor positions, node placements/moves, edge creations, and suggest/publish events to every connected client of that workspace, with server-as-arbiter conflict resolution (LWW) and persistence into `workspace_states`.

## So That

a Sala stops being a single-user offline tool and becomes a shared room — the "Sala" metaphor pays off. Multiple authors can compose around the same canvas; suggestions appear live; the surface feels alive even with no synchronous voice/video layer underneath.

## Context

### Today

- CO-352 ships the workspace canvas as a per-user surface — your layout is yours, you don't see anyone else.
- yggdrasil-web already has the patterns we need: `~/projects/yggdrasil/yggdrasil-web/src/lobby/` (room lifecycle, connection management) + `~/projects/yggdrasil/yggdrasil-web/src/auth/` (token → user). These are battle-tested in the game runtime.
- No CRDT yet; CO-61 covers eventual offline-first CRDT sync. For v1 of realtime, server-as-arbiter LWW is enough — it matches the game model (Yggdrasil already does this) and is simple to ship.

## Design

### WebSocket route

```
GET /ws/sala/{universe_key}/{workspace_slug}
  Upgrade: websocket
  Cookie: session=<JWT>   (or anon session; gated like the rest of CO-352)
```

Connection lifecycle:
1. Client connects → server authenticates session (or assigns `anon:<uuid>` for read-only)
2. Server adds to `hot_rooms[workspace_id].connections`
3. Server sends `{type: "snapshot", state: <full layout>, users: [...]}` to the new client
4. Server broadcasts `{type: "user_join", user: {id, name, color}}` to existing clients
5. On disconnect: remove + broadcast `user_leave`

### Message types (client ⇄ server)

| Type | Direction | Payload |
|---|---|---|
| `cursor` | C→S→C | `{x, y}` — throttled to ~20 Hz |
| `node_move` | C→S→C | `{entry_path, x, y}` |
| `node_add` | C→S→C | `{entry_path, x, y}` |
| `node_remove` | C→S→C | `{entry_path}` |
| `edge_add` | C→S→C | `{from, to, type}` |
| `edge_remove` | C→S→C | `{from, to}` |
| `suggest` | C→S→C | `{entry_id, status: "draft"}` (notifies room; pipeline in CO-354) |
| `publish` | C→S→C | `{entry_id}` |
| `snapshot` | S→C | full layout (sent on join + on demand) |
| `user_join` / `user_leave` | S→C | presence delta |

All messages are JSON. Server validates schema; rejects malformed.

### State map (server-side)

```rust
// platform/realtime/lobby.rs
struct Lobby {
    rooms: Arc<DashMap<WorkspaceId, RoomState>>,
}
struct RoomState {
    connections: HashMap<UserId, Tx>,
    cursors: HashMap<UserId, (f32, f32)>,
    last_persisted: Instant,
}
```

- `Tx` = `tokio::sync::mpsc::UnboundedSender<Message>` for the client's outbound stream.
- Persistence: every 2 s OR on disconnect of last user, flush the room's layout to `workspace_states` (debounced — CO-352's PUT endpoint is reused via internal call, not HTTP).

### Conflict resolution

- **LWW (last-write-wins)** per node/edge, ordered by server-receive timestamp.
- Optimistic UI client-side: apply locally, send, reconcile on server echo. If server rejects (invalid entry, gone), client receives `{type: "revert", op_id}`.

### Presence identity

- Each user gets a stable color hash (from `user_id`) and a display name (from session).
- Anon users get `Visitante <4-char-id>` and a desaturated color.
- Cursor rendered as a small SVG arrow + label in the assigned color.

### Yggdrasil pattern port

- Copy structure from `~/projects/yggdrasil/yggdrasil-web/src/lobby/mod.rs` (room map, broadcast helpers, throttling).
- Adapt auth: use CO's existing JWT/session middleware (`co-web/src/auth/`) instead of yggdrasil's bespoke flow.
- New module: `/Users/artelonga/projects/co/co-web/src/realtime/lobby.rs` + `workspace_ws.rs`.

### Frontend wiring

- Workspace view (CO-352's `workspace.js`) opens a WebSocket on mount.
- Local-first: every drag/edge-add applies optimistically, then sends.
- Render presence layer on top of canvas (cursors + name labels).
- Reconnect with exponential backoff on disconnect; on reconnect, re-request snapshot.

## Acceptance

- [ ] `/ws/sala/{universe}/{slug}` upgrades and authenticates
- [ ] Two browsers joining the same room each see the other's cursor live
- [ ] `node_move` from client A appears in client B within ~100 ms (local network)
- [ ] On last-user-disconnect, layout flushes to `workspace_states`
- [ ] On reconnect, snapshot restores layout
- [ ] Throttling: cursor messages ≤ 20 Hz outbound per user
- [ ] Anon users get read-only socket (writes rejected server-side); login CTA in UI
- [ ] Optimistic UI: a node drag with packet loss still feels smooth locally; server revert reverts cleanly
- [ ] Load test: 50 connections per room remain responsive (manual smoke + a tokio test)
- [ ] E2E: two Playwright contexts, both navigate to `/u/yggdrasil/sala`, one moves a node, the other sees it move
