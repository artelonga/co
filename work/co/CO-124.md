## As

a CO operator running user deployments on Cloudflare Workers and Vercel

## I Need

two non-sidecar implementations of the `CoAgent` contract: (a) a Cloudflare **tail Worker** that subscribes to a target Worker's logs and ships to CO ingest, and (b) a Vercel **Log Drain** receiver that turns Vercel's drain protocol into CO events

## To

extend the agent abstraction to the two deployment targets that **don't allow sidecars** — the gap §C.1 of the platform roadmap review flagged in the SR plan

## Given / When / Then

GIVEN the Fly-sidecar reference impl from CO-120 only covers container-shaped targets,
WHEN we add a CF tail Worker (Cloudflare-native log streaming) and a Vercel Log Drain endpoint (HTTPS receiver),
THEN user deployments on both platforms ship telemetry to the same CO ingest endpoint with the same HMAC-signed envelope as the Fly sidecar.

## Cloudflare tail Worker

```js
// co-tail/src/index.ts
export default {
  async tail(events, env) {
    const filtered = events.flatMap(e =>
      e.logs?.map(log => toCoEvent(log, e.scriptName)) ?? []
    );
    if (filtered.length === 0) return;
    const body = compress(JSON.stringify(filtered));
    await fetch(env.CO_INGEST_URL, {
      method: 'POST',
      headers: hmacHeaders(body, env.CO_HMAC_KEY),
      body,
    });
  }
};
```

User attaches the tail Worker via `[[tail_consumers]]` in their `wrangler.toml`. CO publishes a deploy template.

## Vercel Log Drains receiver

A small route on `co-web` (or a dedicated `co-ingest` Fly app) at `POST /v1/log-drains/vercel` that:
- Validates the Vercel signature header
- Maps Vercel's NDJSON log format to CO `TelemetryEvent`
- Writes via the same path as the Fly sidecar (HMAC + zstd → ingest)

Users add a Log Drain in Vercel pointing at this URL with their per-universe HMAC key.

- [ ] CF tail Worker repo published, deployable via `wrangler deploy`, with documented setup
- [ ] Vercel Log Drain route accepts and processes the Vercel test payload
- [ ] Sample deployments on both platforms ship ≥99% of emitted log lines to the CO ingest within 60s
- [ ] Both variants reuse the same HMAC + zstd + ingest URL contract as CO-120
- [ ] `docs/co-agent/cloudflare-workers.md` and `docs/co-agent/vercel.md` published

## Out of scope

- Browser SDK for static-on-R2 deployments — Phase 5 follow-up
- Self-hosted (non-Fly) container variant — eventual; not blocking
- Bidirectional control (CO → user deployment) — Phase 5

## Risks

- **Tail Worker quota.** Cloudflare tail consumers have per-zone limits; document and surface in the dashboard
- **Vercel Log Drain delivery semantics.** At-least-once with retry; design ingest to dedupe via event-id hash
