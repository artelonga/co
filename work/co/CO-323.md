## As
Yuri (the user) wanting a personal sub-site backed by his private universe

## I Need
`yuri.artelonga.com.br` to serve the `yuri` universe as its root experience — index of entries, query interface, daily-notes timeline. Unrelated universes (artelonga, quilombo, etc.) stay reachable at their normal paths on the main `co-artelonga.fly.dev` host.

## So That
I can give out a clean subdomain URL for my notes/references without exposing CO's full multi-universe sidebar to visitors.

## Scope

### Subdomain handling
1. New axum middleware that reads the `Host` header on every request
2. If `Host == yuri.artelonga.com.br`:
   - Rewrite `/` → `/yuri` (universe key=yuri's index)
   - `/2026-05-31` → daily note for that date in yuri universe (CO-324A daily-notes feature)
   - `/<other-path>` → resolve within yuri universe scope
   - Sidebar hidden by default (or shows only yuri universe + its sub-sections)
3. If `Host == co-artelonga.fly.dev` (or anything else): existing behavior unchanged

### DNS + Fly
- Add CNAME for `yuri.artelonga.com.br` → `co-artelonga.fly.dev` (operator action, document in `docs/dns.md`)
- Fly app `co-artelonga` already terminates TLS for any subdomain via wildcard — verify or add explicit cert
- Update `co-cookie-domain` to `.artelonga.com.br` so sessions work across yuri.* and root

### SPA scope mode
- New URL param or path prefix detection → "single-universe mode"
- Sidebar collapsed/hidden in single-universe mode
- Header simplified
- Existing universe-switcher remains accessible for the universe's owner when logged in

## Acceptance
- [ ] `curl -H "Host: yuri.artelonga.com.br" https://co-artelonga.fly.dev/` returns the yuri universe SPA
- [ ] In a browser at https://yuri.artelonga.com.br/ the page shows only yuri's entries; no sidebar of other universes
- [ ] Anonymous visitor sees only entries with `visibility: public` (depends on CO-324)
- [ ] yuri (logged in via .artelonga.com.br cookie domain) sees all entries
- [ ] `/2026-05-31` resolves to a daily note (depends on CO-324A)

## Dependencies
- CO-324 (per-entry visibility) — needed for the "public anonymous + private logged-in" distinction
- CO-324A (daily-notes routing) — needed for `/YYYY-MM-DD` paths

## Blast radius
- 1 new middleware in `co-web/src/server/`
- ~50 lines of SPA logic to detect single-universe mode + hide sidebar
- 1 docs file `docs/dns.md`
- 0 schema changes

## Why now
Foundation for the yuri.artelonga.com.br vision. Other features (CO-324..329) plug into this subdomain.
