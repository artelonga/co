GIVEN the M4 becomes sole prod with NO UPS (deferred), so the origin can go away
(sleep / power-out / offline), and co-web already CDN-tunes public-static reads
(`s-maxage=60, stale-while-revalidate=86400`) — but `stale-while-revalidate` only
serves stale while the origin is UP,
WHEN the origin is unreachable,
THEN the CDN must keep the public site available by serving the last-good cached
version ("return latest if unavailable") instead of erroring.

## Acceptance

- [x] `PUBLIC_STATIC_CACHE_CONTROL` adds `stale-if-error=604800` (serve last-good for
  up to 7d when the origin errors/is unreachable), alongside the existing
  `s-maxage`/`stale-while-revalidate`.
- [x] The `cache_control_is_cdn_tuned` test asserts `stale-if-error`.
- [x] Documented as the self-host availability backstop that pairs with Cloudflare
  "Always Online" (the UPS-skip compensation).

## Notes
- The dynamic/auth/API surface (`/api/*`, `/auth/*`, admin) is NOT cacheable and is
  unavailable while the origin is down — only the public read site stays up from cache.
  That is the accepted tradeoff for skipping the UPS/failover; full availability is the
  deferred CO-539 (cloud standby).
- Cloudflare side (operator): enable **Always Online** + a cache rule for the public GET
  surfaces + bypass cache for `/api/*`, `/auth/*`, `/gestao/*`, `/co/*` (admin) and any
  cookie'd request. See CO-538 runbook.
