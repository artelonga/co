GIVEN CO-24 adds form config per universe (theme_preset, layout, custom_tokens) and CO-25 gates theme access,
WHEN I build a CSS engine that generates token stylesheets from universe config at runtime,
THEN:

- [ ] New module `co-web/src/theme_engine.rs`
- [ ] `ThemePreset` struct: name, tokens (HashMap<String, String>), fonts (headline, body, label)
- [ ] Built-in presets loaded at startup:
  - `scholarly`: warm cream + bronze (bg=#FFF9ED, accent=#CD7F32)
  - `scholarly-dark`: dark chocolate + bronze (bg=#1c1610, accent=#CD7F32)
  - `relic`: near-black + muted rose (bg=#131313, accent=#e0505f)
  - `relic-light`: off-white + burgundy (bg=#F5F0F0, accent=#af2b3e)
  - `modern`: current default (bg=#f0f2f5, accent=#6366f1)
- [ ] Each preset defines ALL CSS tokens: `--bg`, `--sidebar-bg`, `--card-bg`, `--text-primary`, `--text-secondary`, `--accent`, `--border`, `--status-*`, `--priority-*`, `--font`, `--font-mono`, `--radius-*`, `--shadow-*`
- [ ] `generate_css(preset: &ThemePreset, overrides: Option<&serde_json::Value>) -> String` — outputs complete `:root { ... }` block
- [ ] Custom token overrides merge on top of preset (user can override any single token)
- [ ] `GET /api/v1/universes/:slug/theme.css` — returns generated CSS, `Cache-Control: no-cache, ETag` based on config hash
- [ ] HTML injection: served pages include `<link rel="stylesheet" href="/api/v1/universes/:slug/theme.css">` dynamically based on universe
- [ ] Font loading: if custom fonts specified, inject `<link rel="preload" href="https://fonts.googleapis.com/css2?family=...">`
- [ ] Dark/light mode: each preset has a companion (scholarly ↔ scholarly-dark, relic-light ↔ relic), toggled via `prefers-color-scheme` or manual button
- [ ] Runtime switch: changing theme in UI fetches new `/theme.css` and hot-swaps `<link>` href — no reload
- [ ] Settings panel (owner only): theme dropdown, dark/light toggle, optional custom token overrides (JSON textarea for MVP)
- [ ] Variant CSS files (variants/a/style.css etc.) become fallbacks — theme.css takes precedence when universe config exists
- [ ] Test: create universe → set theme → GET /theme.css → verify all tokens present → change theme → verify CSS changes
- [ ] `cargo test` passes, `cargo clippy -- -D warnings` clean
