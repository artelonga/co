## As

A developer merging a co-auto PR via `gh pr merge --squash --delete-branch`

## I Need

The merge command to **wait until GitHub computes mergeable status** (or fail loudly) before allowing `--delete-branch`. Today's failure mode: GH returns `mergeable: UNKNOWN, state: OPEN`, the merge command fails with "Pull Request is not mergeable", BUT `--delete-branch` still runs and silently CLOSES the PR (deletes the branch ref → PR state becomes CLOSED without merge).

## So That

A PR doesn't get destroyed by a transient GH state-computation lag. Today's track record: PRs #49 (CO-237), #52 (CO-238), #59 (CO-253) were all closed-not-merged this way, requiring a fresh PR each time on a `-stitch` / `-retry` / `-v2` branch.

## Context

The chain of events I keep hitting:

1. Push freshly rebased branch with valid commit
2. `gh pr merge -R ... <pr> --squash --delete-branch`
3. GitHub's mergeable check returns `UNKNOWN` (transient)
4. gh exits with error "Pull Request is not mergeable"
5. **But the branch deletion side-effect already ran** — PR moves to CLOSED state
6. Have to push a fresh branch + create a fresh PR

## Scope

Add a wait+retry helper. Options:

**A. Standalone `scripts/safe-merge-pr.sh`** — wraps `gh pr merge`:

```bash
#!/usr/bin/env bash
# Usage: safe-merge-pr.sh <repo> <pr-number>
REPO="$1"
PR="$2"
for attempt in 1 2 3 4 5 6; do
    STATE=$(gh pr view -R "$REPO" "$PR" --json mergeable,mergeStateStatus --jq '"\(.mergeable):\(.mergeStateStatus)"')
    case "$STATE" in
        MERGEABLE:CLEAN|MERGEABLE:UNSTABLE)
            gh pr merge -R "$REPO" "$PR" --squash --delete-branch
            exit $?
            ;;
        CONFLICTING:*|*:DIRTY)
            echo "ERROR: PR is conflicting/dirty: $STATE" >&2
            exit 1
            ;;
        UNKNOWN:*|*:UNKNOWN)
            echo "  attempt $attempt: state=$STATE; waiting 5s..."
            sleep 5
            ;;
        *)
            echo "ERROR: unrecognized state: $STATE" >&2
            exit 1
            ;;
    esac
done
echo "ERROR: state stayed UNKNOWN for 30s; refusing to merge" >&2
exit 1
```

**B. Inline in `ship-task.sh`** — when --auto-pr is set and the PR is opened, the script tracks the PR number and uses the safe-merge helper instead of `gh pr merge` directly.

## Acceptance

- `scripts/safe-merge-pr.sh artelonga/co 99` polls every 5s until state is determinable.
- On `CONFLICTING`, exits with informative error.
- On `MERGEABLE:CLEAN|UNSTABLE`, runs squash-merge with delete-branch.
- On 30s timeout, refuses to merge — leaves PR open.
- README/CLAUDE.md updated to recommend `safe-merge-pr.sh` over bare `gh pr merge --delete-branch`.
