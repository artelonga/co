GIVEN a self-host node should be reachable by anyone on a LAN without first
installing a Rust toolchain and compiling from source — the distribution must be a
thin binary plus a content delta, not a from-scratch build,
WHEN someone stands up a new LAN node,
THEN they must be able to fetch a prebuilt thin binary and pull content via delta
sync, which requires prioritising and implementing CO-484 (bundle export, ~90 MB),
CO-485 (delta sync), and CO-486 (meta.db growth) so the seed is small, sync is
incremental, and the global DB does not balloon over time.

## Acceptance checklist

- [ ] CO-484 implemented: bundle export produces a portable seed (~90 MB target).
- [ ] CO-485 implemented: delta sync pulls only changed content (op_log delta, not full re-fetch).
- [ ] CO-486 addressed: meta.db growth bounded so a long-lived node does not hit CO-446 disk-full.
- [ ] A fresh LAN node can run from the thin binary + delta with **no Rust toolchain** installed.
- [ ] `docs/SELF-HOST.md` documents the thin-binary install + delta-sync onboarding path.

## Notes
- Links and depends on CO-484 (bundle export ~90 MB), CO-485 (delta sync),
  CO-486 (meta.db growth). This task is the self-host umbrella that prioritises
  them so a LAN node is install-from-binary, not build-from-source.
- Aligns with the distribution-model memory: 66 MB binary + op_log delta (not a
  fat-embed); ~90 MB public seed; meta.db growth is the CO-446 risk to contain.
