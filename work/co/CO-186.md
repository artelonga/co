## What changed

Handover tokens (CO-185) now signed ES256 with CO's existing P-256 private
key (CO-166). Receivers validate the public key fetched from
`/.well-known/jwks.json`. Eliminates the need to distribute `JWT_SECRET` to
every universe deployment.

## Per-universe deployment template

Once-per-universe checklist for any new deployment that wants SSO with CO:

### 1. Implement `/auth/co-handover` endpoint

Pseudo-code for any framework / language. Adapt to the deployment's stack.

```
GET /auth/co-handover?co_token=<JWT>
  1. Read co_token from query string
  2. Decode JWT header, extract `kid` and `alg`
  3. If `alg != ES256` → 401 (legacy fallback optional during migration)
  4. Fetch JWKS from CO_JWKS_URL (default: https://co.artelonga.com.br/.well-known/jwks.json)
     - Cache for 1 hour (or whatever sensible TTL)
     - On miss for `kid`: refresh once, then 401 if still not found
  5. Verify signature against the matching public key
  6. Verify exp not expired
  7. Mint a local session JWT with the deployment's own secret + 7-day TTL
  8. Set local session cookie (httpOnly, secure, sameSite=lax)
  9. 303 redirect to `/`
```

### 2. Update login UI

Point the Google sign-in anchor at:

```
https://co.artelonga.com.br/api/v1/auth/google/start?return_to=https%3A%2F%2F<your-domain>%2Fauth%2Fco-handover
```

Same for the "Esqueci minha senha" anchor (already a CO-176/QB-9 pattern):

```
https://co.artelonga.com.br/recover?return_to=https%3A%2F%2F<your-domain>%2Fauth%2Fco-handover
```

### 3. Add the deployment domain to CO's safelist

In `co-web/src/recovery_routes.rs::is_allowed_return_to`, add the new
host:

```rust
host == "quilomboaraucaria.com.br"
    || host == "artelonga.com.br"
    || host == "your-new-universe.com.br"  // ← here
    || host.ends_with(".artelonga.com.br")
```

This is the ONLY change required in the CO repo per new universe. No
schema changes, no env vars, no secret distribution.

### 4. (Optional) Set CO_JWKS_URL env var

Defaults to `https://co.artelonga.com.br/.well-known/jwks.json`. Override
only for testing against a non-prod CO.

### What's NOT required per universe

- ❌ `CO_JWT_SECRET` shared from co-artelonga
- ❌ Coordinated `JWT_SECRET` rotation
- ❌ Any database schema changes
- ❌ Per-deploy Google OAuth client (CO handles Google entirely)
- ❌ Reverse-bridge code (CO-184 runs server-side on co-artelonga)
