GIVEN CO-49 defines the access model (owner/admin/editor/viewer) and CO-52 implements subscriptions (viewer-level),
WHEN I add invite-based membership + task review workflow,
THEN:

## Permission Matrix

| Role | View | Create/edit own | Edit all | Review (approve/reject) | Invite others | Manage members |
|------|------|----------------|----------|------------------------|---------------|----------------|
| **subscriber** | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| **viewer** (invited) | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| **editor** (invited) | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| **admin** (invited) | ✅ | ✅ | ✅ | ✅ | ✅ editors | ❌ |
| **owner** | ✅ | ✅ | ✅ | ✅ | ✅ all | ✅ |

## Invite Flow

### API
- [ ] `POST /api/v1/universes/:slug/invite` — owner/admin only
  ```json
  { "email": "user@example.com", "role": "editor" }
  ```
  - If user exists: creates pending invite in `invites` table
  - If user doesn't exist: stores invite (claimed on registration)
  - Returns 201 Created with invite ID
  
- [ ] `GET /api/v1/universes/:slug/invites` — owner/admin: list pending invites
- [ ] `POST /api/v1/invites/:id/accept` — invitee accepts (auth required)
- [ ] `DELETE /api/v1/universes/:slug/invites/:id` — owner/admin: cancel invite
- [ ] `PUT /api/v1/universes/:slug/members/:user_id` — owner: change role `{ "role": "admin" }`
- [ ] `DELETE /api/v1/universes/:slug/members/:user_id` — owner: remove member

### Database
- [ ] New table `invites`:
  ```sql
  CREATE TABLE invites (
    id TEXT PRIMARY KEY,
    universe_key TEXT NOT NULL,
    email TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'editor',
    invited_by TEXT NOT NULL,
    created_at TEXT NOT NULL,
    accepted_at TEXT,
    UNIQUE(universe_key, email)
  );
  ```
- [ ] On accept: insert into `universe_members` with invited role, set `accepted_at`
- [ ] On registration: check `invites` table for email, auto-accept pending invites

### Frontend
- [ ] Universe settings → "Membros" tab (owner/admin only)
  - List current members with role badges
  - "Convidar" button → modal: email + role dropdown
  - Remove member (X button, confirmation)
  - Change role (dropdown per member)
- [ ] Notification for invitee: banner "Você foi convidado para {universe}" with Accept/Decline
- [ ] Sidebar: invited universes appear with invite badge until accepted

## Task Review Workflow

### Statuses
```
todo → in_progress → review → done
                       ↓
                  in_progress (request changes)
```

- [ ] `review` status re-added as a Kanban column (optional per universe)
- [ ] Universe config: `review_enabled: bool` (default false)
- [ ] When `review_enabled`: 4 columns (A fazer, Em progresso, Em revisão, Concluído)
- [ ] When not enabled: 3 columns as today

### Review Actions (admin/owner only)
- [ ] `POST /api/v1/universes/:slug/entries/:path/review`
  ```json
  { "action": "approve" }       → status: done
  { "action": "request_changes", "comment": "..." }  → status: in_progress
  ```
- [ ] Review action logged in activity/telemetry
- [ ] Reviewer name shown on task card when in review

### Frontend
- [ ] "Em revisão" column with distinct color (amber)
- [ ] Task card in review: shows reviewer badge + "Aprovar" / "Solicitar alterações" buttons (admin only)
- [ ] Non-admin sees review column but no action buttons
- [ ] Moving a task to "review" column via drag triggers review request

## Write Permission Enforcement

- [ ] `POST /api/projects/:key/tasks` — check: user is editor+ on this universe
- [ ] `PUT /api/projects/:key/tasks/:id` — check: editor can edit own, admin can edit all
- [ ] `DELETE /api/projects/:key/tasks/:id` — check: admin+ only
- [ ] `POST /api/v1/universes/:slug/entries` — same permission check
- [ ] Subscribers (viewer) get 403 on all write operations
- [ ] Error message: "Você precisa de permissão para editar" / "You need permission to edit"
