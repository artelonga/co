GIVEN `scripts/smoke-prod.sh` and `uptime-probe.sh` hard-code the Fly prod URL and
estate-specific seed counts (tempo=21 / humanity=26 / universo=28), so they FAIL against
a tenant-free M4 self-host shell (the de-embed leaves co with zero seeded content),
WHEN we self-host co on the M4,
THEN a content-agnostic smoke verifies the software's *capabilities* against a
`BASE_URL`, with NO dependency on any seeded universe — the self-host analogue of the
prod smoke, honoring template=software.

## Acceptance

- [ ] `scripts/smoke-selfhost.sh [BASE_URL]` (default `http://localhost:8742`): checks
  `/api/health` (status ok + version == Cargo.toml), the serve-allowlist (`audit_serve`
  clean), and a generic capability round-trip (create an ephemeral universe → add an
  entry → list it → delete) using a synthetic fixture, then tears it down.
- [ ] **Zero hard-coded seed counts / tenant names / Fly URLs** — runs green on a fresh,
  empty instance.
- [ ] Exits non-zero on any failed invariant (usable as a boot/deploy gate).
- [ ] Documented in `docs/SELF-HOST.md` (run after first boot, before opening to LAN).
