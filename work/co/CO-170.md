## Findings (1.85.0 prod, 2026-05-09)

### 1. Cross-universe project leak

`co` universe `/projects` returns: AL (Arte Longa), API, CO, DS, PLT, plus its own work-tracker projects. AL clearly belongs in `artelonga`.

`artelonga` universe `/projects` returns: API, ARTEP, CW (CO Web), DS, PLT, plus its own. CW clearly belongs in `co`. ARTEP is a stray "Bem-vindo ao Co" — template tutorial leak.

These came from filesystem syncs that wrote `projects/<KEY>/_project.md` into the wrong universe directories. The data is real, just in the wrong table. **Code is not buggy — this is one-time data cleanup.**

### 2. `mbya` is NOT merged into `comunicacao`

- `mbya` universe (4620 entries) holds the actual content: `refs/CADERNO4_CRISTINE_TAKUA_GUA.md`, `refs/educacao_indigena_*`, `refs/GNDicInt.md`, `ROADMAP.md`, `CLAUDE.md`. The dictionary corpus.
- `comunicacao` universe (4689 entries) has totally different content: `states/`, `branches/`, `proposals/`, `concepts/testing-the-merge-flow.md`, `_universe.yaml`. **These are CO-native versioning artifacts** (Phase 8 test runs), not the Mbya dictionary.
- Sample mbya path: `refs/CADERNO4_CRISTINE_TAKUA_GUA.md`. Sample comunicacao path: `states/2026-05-05T234458Z-2a00H-qf.md`.

The 1.69.0 changelog claimed comunicacao "absorbs mbya, topologia, language" but the actual content move never happened — only the registry `co-universes.yaml` was updated. Local merged dir at `~/projects/comunicacao` either never had real content synced up, or was used as a versioning playground.

`guarani-mbya` returns 404 — that one was correctly cleaned up at some prior point.

### 3. `time` universe — timeline view empty

`/api/v1/universes/time/entries?type=event` returns 1 event. The `/linhadotempo` and `/timeline` URLs both return 200 (SPA shell) but the SPA can't render a timeline against 1 entry. Either the universe wasn't seeded with the timeline JSON manifests (`seed_all_timeline_universes` exists in storage.rs:729), or the seed doesn't write `event` type entries.

### 4. Quilombo Araucária — 95 entries

Stub-level content. Real Quilombo content (eventos, missões, comentários, telemetria) is in separate per-quilombo SQLite tables (`quilombo_eventos`, etc.), not in the entries table that `content_count` reflects. Empirically the universe IS being used (login flow + event tests pass) — but the entries surface is sparse.

### 5. yuri's "1 página" not visible

User reports a personal universe shows `content_count = 1` (1 page) but the page doesn't render in any view. Likely an entry orphaned from `project_universe_index` (not associated with a project), so kanban/board hides it; Conteúdo view should show it but might be filtering by type.

### 6. Co universe sidebar shows out-of-scope items

Image submitted by user shows Co sidebar listing: AL, API, CO, DS, PLT, QA, LOCACO, CO (template's "Bem-vindo ao Co"), MP. Mix of (a) projects from `co` universe (correct), (b) projects from other universes leaked in (#1), (c) the template tutorial (`Bem-vindo ao Co` / key=CO from `template`).

## Proposed cleanup plan (ordered, smallest first)

### A. Quick win — hide deprecated mbya from default sidebar (~½ day)

Add `mbya` to a new "deprecated/hidden" list. Don't delete — content is real. Set `visibility = 'hidden'` (new column or repurpose `archived`) so it stops appearing in the public/admin sidebar but the content stays accessible by direct URL until it's properly migrated.

### B. Cross-universe project audit + cleanup (~1-2 days)

For each universe, list its `entry_type='project'` rows. For each project, decide canonical home (likely by project_key prefix convention — CO→co, AL→artelonga, QA→quilomboaraucaria, etc.). For misplaced projects:
1. Move all entries (`projects/<KEY>/**`) from wrong universe to right universe.
2. Update `project_universe_index` to point project_key → correct universe.
3. DELETE rows from the wrong universe's entries table.

Backup the meta DB and per-universe DBs before doing this.

### C. Real `mbya` → `comunicacao` content merge (~1 day)

Decision needed first: does `comunicacao` get to keep the existing CO-versioning-test entries, or are those wiped? Likely the latter (versioning state belongs in the `co` universe's branches table, not as content).

Then bulk-copy mbya's 4620 entries into `comunicacao` under a `mbya/` path prefix (so future Yoruba/Quéchua/etc. imports get their own `yoruba/`, `quechua/` prefixes — the language symbol scoping the user mentioned).

After successful copy + verification, mark `mbya` archived (don't delete the row in case rollback needed).

### D. Timeline seeding (~½ day)

Find why `time` only has 1 event. Check `seed_all_timeline_universes` writes `event`-type entries (not just universe row + manifest). Re-seed from the bundled JSON manifests.

### E. Quilombo content — needs real authoring (out of scope for this ticket)

If 95 entries is wrong, the user needs to either bulk-import real content or accept that quilombo's "content" lives mostly in the quilombo_* tables (not entries).

### F. yuri "1 página" investigation (~1h)

Find the entry, determine why it's invisible, fix Conteúdo view to render orphan pages without a project association.
