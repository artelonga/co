## As

a CO user wanting to deploy a universe to my own infrastructure

## I Need

a `deploy.yaml` (or `_universe/deploy.yaml`) schema as a first-class universe artifact, with strict validation that gives actionable errors before any platform API is called

## To

make universes self-describing for deployment, decouple deployment intent from CO core, and make platform-pluggability a **schema** decision rather than a code decision

## Given / When / Then

GIVEN `platform-evaluation.md` Part III §18 sketched a `deploy.yaml`,
WHEN we formalize it as a schema, version it, and validate every universe's manifest against it on save and before deploy,
THEN deployer adapters (CO-134, CO-135) consume a typed, validated `Manifest` struct rather than parsing freeform YAML.

## Schema (v1)

```yaml
# Schema lives at work/schema/deploy.v1.json (or .yaml)
# Universe carries deploy.yaml at its root.
version: 1                      # required; strict
target: cloudflare-pages        # required; enum: static-on-r2 | cloudflare-pages | fly | vercel | fargate
domain: meu-portfolio.co.app    # optional; if absent, deployer chooses default
runtime:
  kind: static                  # required for static targets; enum varies by target
  build:
    command: "co build"         # optional; default per-target
    output: "dist/"             # optional; default per-target
bindings:
  storage:
    type: r2                    # enum
    bucket: u-meu-portfolio
    encrypted: true
  secrets: [STRIPE_KEY]         # names only; values resolved per-target from CO secrets
scaling:
  min: 0                        # int >= 0
  max: 100                      # int >= min
telemetry:
  sink: co-central              # enum: co-central | none
  sampling: 1.0                 # 0.0 to 1.0
backup:
  schedule: daily               # enum: hourly | daily | weekly | none
  retention: 30d                # duration string
```

## Acceptance

- [ ] JSON Schema (or equivalent) for `deploy.yaml` v1 committed under `work/schema/deploy.v1.json`
- [ ] Rust struct `Manifest` derived (`serde` + `schemars`); round-trip-stable
- [ ] Validation called on universe save and on `co deploy` invocation; errors point to file + line + path
- [ ] 10 fixtures in `tests/fixtures/deploy/`: 5 valid, 5 invalid (each invalid one tests a specific error)
- [ ] `co validate deploy` CLI subcommand
- [ ] Docs: `docs/DEPLOY-MANIFEST.md` with one full example per target

## Out of scope

- Adapter implementations themselves — CO-134 (static-on-R2), CO-135 (cloudflare-pages); Vercel and Fargate adapters are follow-ups
- Pre-deploy `co plan` (dry-run) — separate ticket
- Multi-environment manifests (`production` / `staging`) — v2

## Risks

- **Schema drift between versions.** Mitigation: strict `version: 1` field; v2 must increment + provide a migration tool
- **YAML ambiguity around booleans/strings.** Mitigation: tests + `--strict` parser flag
