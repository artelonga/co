## As
A universe author (grcsamazonia, retro-umarizal, comunicacao …) and the platform maintainer

## I Need
The SPA reorganized so every universe feature is a composable module, the UI is split
into **content lenses (read)** and a **schema-driven form engine (write)**, and a
universe's whole surface is declared by its `_universe.yaml` manifest — not hand-wired
in JS.

## So That
- Adding a `content_type` yields a working create/edit form **and** eligible lenses with
  zero UI code (composability).
- Child universes (`parent_key`) compose into the parent shell; lenses span universes via
  the multi-universe graph (CO-345).
- The bespoke-form sprawl in `modals.js` and the 74 KB `conteudo.js` monolith are retired.

## Context

> **Pre-flight traps (2026-06-10):** new `data-i18n` keys MUST be added to both
> pt and en dicts in `co-web/static/shared/i18n.js`. Meta-DB next free
> migration: v74. The lens frame must not grow a canvas — the Sala surface
> rule (docs/architecture/sala-surface.md) applies to lenses too: one frame,
> instances register into it.


See `docs/ui-architecture.md` for the full design + current-state review. Summary of the
gap: content is already lens-based (`modules/views/`) but the lens registry is hardcoded
(`injectManifestViewTabs` only handles `gantt`); forms are bespoke hand-coded HTML in
`modules/modals.js` with no schema→form generation, even though `_universe.yaml`
`content_types[].schema` already declares the field shapes.

## Design

### Phase 1 — Lens registry (read)
- Define a lens interface `{ id, label, icon, supports(type), render(entries, type, viewState) }`.
- Wrap existing `views/*` (`kanban`, `table`, `timeline`, `calendar`, `dashboard`, the
  `conteudo` document view, `graph`) as registered lenses.
- Generalize `injectManifestViewTabs`: visible lenses derive from `manifest.views` +
  declared `content_types`, not a hardcoded `gantt` check. No visual regression.

### Phase 2 — Form engine (write)
- `modules/form/engine.js`: `renderForm(schema, value?) → <form>` + `collect(form) → value`.
- Field renderers per type: `string`, `text`, `number`, `date`, `enum`, `boolean`,
  `ref` (cross-universe entry picker → grafo).
- Migrate, in order: entry create/edit → universe create/edit → the `modals.js` grab-bag.
- Forms validate against the same schema the server validates (single source of truth).

### Phase 3 — Child-universe shell
- Sidebar renders the `parent_key` tree (CO-98); switching child ↔ parent is composition.
- Graph lens uses `GET …/graph?universes=…` (CO-345) so child content shows in the parent network.

### Phase 4 — Decompose `conteudo.js`
- Split the 74 KB monolith into `lenses/document.js` + shared render helpers (SPA analog
  of the server `MODULES.md` 500-LoC rule).

### Delivery behind variants
Each phase ships as a new `variants/` build (e.g. `variants/i`) so `a` stays stable;
promote when proven, per the existing A/B variant mechanism.

## Acceptance

- [ ] Lens registry: all existing views registered; manifest drives visible lenses (no `gantt`-only hardcode)
- [ ] Form engine renders + collects from a `content_types[].schema`; entry create/edit uses it
- [ ] Universe create/edit (the CRUD from `docs/universe-crud.md`) uses the form engine
- [ ] Adding a new `content_type` to `_universe.yaml` produces a working form + eligible lenses with **no JS change** (demonstrated test)
- [ ] Sidebar renders `parent_key` children; graph lens spans universes
- [ ] `conteudo.js` split; no SPA file > 500 LoC
- [ ] No regression to `variants/a`; new variant promoted only after parity

## Blast radius

- New `modules/form/`, `modules/lenses/` (registry + wrappers); refactor of `views/` + `modals.js`
- Decompose `conteudo.js` (74 KB)
- 0 server changes for phases 1–2 (endpoints already exist); phase 3 reuses CO-345
- 0 schema changes

## Not in scope

- Visual redesign / new theme (this is structure + composability, not a restyle)
- Workspace/Sala canvas (CO-352) — composes as another lens later, separate task
- Server-side form/schema changes (the manifest schema is the contract as-is)
