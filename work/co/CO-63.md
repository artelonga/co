GIVEN Co today has a single global content schema (work/agents/tools schemas baked into core) and a single board UI tuned for tasks, and the platform must scale to thousands of universes per user with thousands of concurrent requests,
WHEN every universe-as-repo can ship its own manifest declaring its content types, schemas, doc generators, and presentation hints,
THEN the same Co board can render Scaladocs, Sphinx output, OpenAPI specs, blog posts, eventos, tarefas, notas — all as queryable typed entries with relationships and full version history.

## Sub-tasks (sequenced)

- CO-70 — Manifest format spec (`_universe.yaml`)
- CO-71 — Per-universe schema validator + generic JSON entry storage
- CO-72 — Doc-generator hooks (depends on CO-78 job queue)
- CO-73 — Temporal model
- CO-74 — Relationship graph
- CO-75 — Version reconstruction (depends on CO-61 op log)

## Prerequisite tasks (separate, parent: 20)

- CO-64 (post-GitHub cleanup), CO-65 (visibility-on-PUT), CO-66 (API hygiene), CO-67 (prod seed), CO-68 (Obsidian deep-sync INFRA-3), CO-69 (PWA offline INFRA-4)

## Scale-driven design constraints (mandatory across all sub-tasks)

- All per-universe data must shard cleanly by `universe_key` (precondition for CO-77)
- All manifest reads must be cacheable (per-universe LRU, invalidated on universe update — CO-79)
- All write paths idempotent (CO-54)
- Doc-generator runs are jobs, never request-blocking (CO-72 + CO-78)
- Indexes on JSON payload fields declared in manifest; server creates expression indexes
- Reject manifests > 100 KB or with > 100 content types (resource bound)

## Tradeoffs decided

- **Storage: generic JSON payload + selective indexes**, NOT per-universe DDL — chosen for migration safety; cost is slightly worse cold-query performance, mitigated by indexes
- **Doc generators: job queue**, NOT in-request — scaladoc/sphinx take 10–60s; blocking request threads at 1K concurrent reqs is fatal
- **Schema validation: write-time only**, NOT read-time — read path stays fast; data may need migration on schema bump

## Acceptance

- Universe with `_universe.yaml` declaring 5 content types renders correctly on board
- Doc-generator hook produces entries from scaladoc output
- Query "events this week, with attendee X" returns correct results
- "Show entry as of timestamp T" returns historical state
- All sub-task acceptance tests pass

## Out of scope

- WYSIWYG manifest editor (raw YAML for v1)
- Manifest marketplace / sharing across universes
- Cross-universe queries (needs CO-77's metadata index; later epic)
