## As

a CO operator (Yuri, today; admins generally)

## I Need

one cohesive `/gestao` admin SPA backed by one batched endpoint — not the current 6-route patchwork (analytics_routes, storage_dashboard, deployment_dashboard, dev_board, uat_mirror, gestao_routes) each rendering its own page in its own style with its own auth check.

## So That

I can see totals, top pages, traffic, referrers, broken links, recent activity, and storage health on a single screen with a single round-trip. Today I open 4-6 tabs to assemble the same picture, and every redesign means touching 6 handlers.

CO should port that pattern.

## Design

### 1. New batched endpoint

`GET /api/v1/gestao/resumo` returns:

```json
{
  "totals": {
    "users": 142,
    "universes": 31,
    "entries": 2871,
    "sessions_24h": 89,
    "disk_used_mb": 412,
    "disk_total_mb": 3072
  },
  "top_pages":        [{"path": "/co", "visits": 312}, ...],
  "visits_by_hour":   [{"hour": 0, "count": 12}, ... 24 buckets],
  "visits_by_dow":    [{"dow": 0, "count": 84},  ...  7 buckets],
  "referrers":        [{"referrer": "google.com", "count": 47}, ...],
  "broken_links":     [{"path": "/x/y", "status": 404, "last_seen": "..."}, ...],
  "recent_activity":  [{"acao": "criar", "entidade": "task", "user": "yuri", "at": "..."}, ...],
  "schema_versao":    56,
  "app_versao":       "2.39.0"
}
```

Implementation: new `/Users/artelonga/projects/co/co-web/src/admin/resumo_routes.rs`. Single handler reads the analytics buffer (`platform::observability`), `telemetry_events` table, `universes`/`users`/`entries` counts, `atividades` (from CO-361) once each, joins in memory, returns one JSON. Target: < 200 ms p95.

### 2. Secondary endpoints (still batched)

- `GET /api/v1/gestao/universes` — list of universes with key/name/owner/entry_count/last_activity (replaces `storage_dashboard`'s table)
- `GET /api/v1/gestao/atividades?limit=50&since=…` — paginated audit log feed (from CO-361)

That's it. Three endpoints total power the entire admin SPA.

### 3. New SPA route

Mount `/gestao` as a single SvelteKit-style SPA (CO's variant `a` already does in-page routing). Add module `/Users/artelonga/projects/co/co-web/static/variants/a/modules/gestao/`:

```
gestao/
├── index.js          -- entry, loads tab manifest
├── wire.js           -- tab navigation, fetch orchestration
├── render.js         -- tab body rendering
├── style.css         -- gestao-scoped styles
└── tabs/
    ├── resumo.js     -- totals + sparklines + top pages
    ├── conteudo.js   -- universes list + entry breakdown
    ├── usuarios.js   -- users table + sessions
    └── atividades.js -- audit log feed (from CO-361)
```

Single fetch on tab activation; results cached for 30 s to avoid hammering.

### 4. Tabs

| Tab | Reads | Renders |
|---|---|---|
| **Resumo** | `/api/v1/gestao/resumo` | KPI cards (users, universes, entries, sessions_24h, disk) + visits-by-hour sparkline + top 10 pages + recent activity teaser (5 rows) |
| **Conteúdo** | `/api/v1/gestao/universes` + `resumo.top_pages` | Universes table sorted by activity, drill-down to entry counts per type |
| **Usuários** | `resumo.totals` + `/api/v1/gestao/universes` (owner counts) | Users table (admins surfaced first), session-24h breakdown |
| **Atividades** | `/api/v1/gestao/atividades` (paginated) | Full audit log feed (action / entity / user / when / diff hover) — primary surface for CO-361 |

### 5. Deprecation plan for old routes

- Keep `/admin/analytics`, `/admin/storage`, `/admin/deployment`, `/admin/dev` reachable for one release with a top banner: "Movido para /gestao. Este painel será removido em v2.41."
- Remove handlers in the release after.
- `dev_board.rs` stays alive — it's not analytics, it's an agent surface. Re-mount its body under `/gestao/dev` as a 5th tab in a follow-up, not this ticket.
- `uat_mirror.rs` already obsolete per `feedback_no_uat` — delete in this PR.
- `gestao_routes.rs` (partial existing surface) gets folded into `resumo_routes.rs`.

### 6. Auth

Same admin check (`require_admin`) on all three new endpoints. Reuse `admin_routes::admin_guard` middleware (or equivalent). 403 with JSON error on non-admin; SPA hides `/gestao` link from non-admins.

### 7. Performance

- One SQL transaction batches the counts.
- Top-pages / visits use the existing `platform::observability` in-memory buffer (fast).
- Recent-activity reads `atividades` LIMIT 5 — sub-ms.
- Schema_versao + app_versao come from `schema_versoes` (CO-361) — single row read.
- No N+1 queries; everything aggregated server-side.
