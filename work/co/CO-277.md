## As

A developer working on a multi-universe project (yggdrasil has shandara, tagmar, godot sub-universes; CO itself is starting to look the same way with sister-universes)

## I Need

`co-auto` to address tasks **inside sub-universes** as cleanly as it addresses top-level tasks, with **prefix discovery walking the full tree** so a bare key like `SHN-1` resolves to `work/yggdrasil/shandara/SHN-1.md` without me having to spell out the nesting.

## So That

The yggdrasil roadmap (which has YG-N at root, SHN-N inside shandara, TGM-N inside tagmar) is runnable end-to-end with the same one-liner ergonomics as `co-auto 272`. No hand-rolled `--workdir … --space … --task …` per sub-universe.

## Context

### Where CO-276 landed

CO-276 introduced `resolve_task_id(input, space, workdir)` with this resolution order:

1. `<workdir>/work/<space>/_universe.yaml` → `task_prefix:` field
2. Hardcoded table (`co → CO`, `yggdrasil → YG`, `rfq → RFQ`, `qb → QB`, `artelonga → AL`)
3. First `<PREFIX>-N.md` file in `<workdir>/work/<space>/`
4. Fallback: `space.to_uppercase()`

That model assumes **one prefix per space**. Yggdrasil breaks this: one space (`yggdrasil`) hosts multiple prefixes (`YG`, `SHN`, `TGM`, `GDT`, ...).

### The yggdrasil layout (target)

```
work/yggdrasil/
├── _universe.yaml            # task_prefix: YG, version: 1.1.0
├── YG-64.md
├── YG-65.md
├── shandara/
│   ├── _universe.yaml        # task_prefix: SHN, version: 0.3.1, parent: yggdrasil
│   ├── SHN-1.md
│   └── SHN-2.md
├── tagmar/
│   ├── _universe.yaml        # task_prefix: TGM, version: 0.1.0, parent: yggdrasil
│   └── TGM-1.md
└── godot/
    ├── _universe.yaml        # task_prefix: GDT, version: 0.0.0, parent: yggdrasil
    └── GDT-1.md
```

A sub-universe is just a folder with its own `_universe.yaml`. The pattern is recursive — `work/yggdrasil/shandara/expansions/_universe.yaml` is equally valid.

### How addressing should feel

| Invocation (from yggdrasil cwd) | Resolves to |
|---|---|
| `co-auto 64` | `work/yggdrasil/YG-64.md` (root prefix wins for bare numbers) |
| `co-auto YG-64` | same |
| `co-auto SHN-1` | `work/yggdrasil/shandara/SHN-1.md` (prefix uniquely owned by shandara) |
| `co-auto -u shandara 1` | `work/yggdrasil/shandara/SHN-1.md` (explicit subspace) |
| `co-auto -u shandara` | next unblocked SHN-N |
| `co-auto` | next unblocked YG-N (root) |

Ambiguity is the only failure mode worth designing around. If two subspaces ever share a prefix (they shouldn't, but…), abort with a clear "specify -u".

## Decision

### A. Subspace discovery walks the tree at startup

New function `co_auto::universe::discover_subspaces(workdir, space) -> Vec<Subspace>` that recursively walks `work/<space>/**/_universe.yaml` (cap depth at 8 for sanity).

```rust
pub struct Subspace {
    pub key: String,           // "shandara"
    pub rel_path: PathBuf,     // "yggdrasil/shandara"
    pub abs_path: PathBuf,     // /Users/.../work/yggdrasil/shandara
    pub prefix: String,        // "SHN"
    pub parent: Option<String>,// "yggdrasil"
    pub version: Option<String>,// "0.3.1"
}
```

The walker:
1. Reads root `work/<space>/_universe.yaml` as the seed.
2. For every directory that contains `_universe.yaml`, registers a `Subspace`.
3. Skips `.worktrees`, `.git`, `node_modules`, `target`, `CHANGELOG-PENDING`.

### B. Resolver becomes prefix-aware across the tree

`resolve_task_id(input, space, workdir)` becomes:

```rust
pub fn resolve_task_id(
    input: &str,
    space: &str,
    workdir: &Path,
    subspaces: &[Subspace],   // built by discover_subspaces
) -> Result<ResolvedTask>;

pub struct ResolvedTask {
    pub key: String,            // "SHN-1"
    pub subspace: Subspace,     // the owning subspace (may be the root)
    pub spec_path: PathBuf,     // .../shandara/SHN-1.md
}
```

Resolution rules:
- `input` contains `-` (e.g. `SHN-1`): look up prefix `SHN` in the subspaces table; if exactly one match, return it; if zero matches, fall back to root space; if multiple, error with a "specify -u" hint.
- Bare number (`1`): if `-u <key>` is set, use that subspace's prefix; otherwise use the root space's prefix.

### C. New CLI flag `-u, --universe`

`-u <subspace-key>` selects a sub-universe within the current space. Optional. When set:
- Prefix used for bare numbers comes from that subspace's `_universe.yaml`.
- "pick next unblocked" scans only that subspace's directory.
- The worktree branch name becomes `feat/SHN-1-...` (already inferred from key).

### D. Recursive task picker

`pick_next_task(space, workdir, subspace: Option<&str>) -> Option<TaskSpec>`:
- If `subspace` set: scan only that subspace's `.md` files.
- Else: scan the root space's top-level `.md` files (do NOT auto-cross into subspaces — user must opt-in with `-u`, otherwise root-vs-children ambiguity is too noisy).

A new `--recursive` flag (opt-in) would scan the whole tree across all subspaces — useful for a "what's next anywhere in yggdrasil" mode. Defer to phase B.

### E. Versioning aggregation (scope-adjacent, deferred)

Sub-universe `_universe.yaml` carries `version:`. A future `co-auto version-rollup` command walks the tree, sums children-pending-bumps, and proposes a parent version bump. **Out of scope for CO-277**; called out for CO-278.

## Scope

### 1. New module `dev/co-auto/src/universe.rs`

- `Subspace` struct + `discover_subspaces()` walker
- `read_universe_yaml()` reading `task_prefix`, `version`, `parent`
- Unit tests: nested fixtures (`work/yg/`, `work/yg/sh/`, `work/yg/sh/exp/`) — depth 3 detection

### 2. Update `dev/co-auto/src/auto.rs`

- `resolve_task_id` signature gains `subspaces: &[Subspace]` and returns `ResolvedTask`
- `pick_next_task` gains optional `subspace: &str` param
- `run()` calls `discover_subspaces(workdir, space)` once at startup, threads through

### 3. Update `dev/co-auto/src/main.rs`

- Add `#[arg(short, long)] universe: Option<String>` (alias `subspace`)
- Pass through to `AutoConfig`/resolver
- Help text includes `-u shandara 1` example

### 4. Yggdrasil scaffolding (out-of-repo follow-up)

Document the `_universe.yaml` shape so the user can scaffold yggdrasil:

```yaml
# work/yggdrasil/shandara/_universe.yaml
task_prefix: SHN
version: 0.3.1
parent: yggdrasil
name: Shandara
description: "RPG brasileiro de fantasia heroica baseado em D&D 3.5"
```

### 5. Tests

- `tests/recursive_resolver.rs`:
  - 2-level depth (yg + shandara) → `SHN-1` resolves correctly
  - 3-level depth (yg + shandara + expansions) → grandchild resolves
  - Ambiguous prefix (two subspaces claim `XX`) → returns Err with hint
  - Bare number + `-u shandara` → `SHN-N`
  - Bare number + no `-u` → root prefix (`YG-N`)
- `tests/discover_subspaces.rs`: fixtures with skipped dirs (`.worktrees/`) validate the walker exclusions

## Acceptance

- From a yggdrasil workdir: `co-auto SHN-1` finds and runs the spec at `work/yggdrasil/shandara/SHN-1.md`
- `co-auto -u shandara 1` is equivalent
- `co-auto -u shandara` picks the next unblocked SHN task
- `co-auto 64` (no `-u`) resolves to YG-64 (root)
- Existing CO invocations are unchanged (the resolver still works with zero subspaces discovered)
- Help text via `co-auto --help` documents `-u`
- A new ambiguous-prefix test confirms the error mode is friendly

## Blast radius

- New file `dev/co-auto/src/universe.rs` (~150 LOC)
- `dev/co-auto/src/auto.rs` — resolver signature change (~50 LOC delta)
- `dev/co-auto/src/main.rs` — new flag + thread-through (~20 LOC delta)
- New tests (~120 LOC)
- Zero behavior change when no `_universe.yaml` nesting exists — fully backwards-compatible

## Why now

User just asked: *"how would i run within the new functionality the following yggdrasil universe tasks? note that there are sub universes (recursive) functionality"*. CO-276 just shipped — extending its resolver to walk a tree before more spaces adopt sub-universe layouts (CO itself, quilombo, etc.) is one cheap delta away. Waiting means more places to retrofit later.
