## As

a consumer reading from the `guarani-mbya` plane

## I Need

a Rust crate `topologia-mbya-adapter` at `~/projects/topologia/crates/topologia-mbya-adapter/` that opens `~/projects/mbya/mbya_lexicon.db` (the digitized Dooley 2006 lexicon) and exposes its rows as a `topologia-core::LanguagePlane`

## To

let the shallow `topologia/guarani-mbya/` plane (currently 8 hand-authored draft entries) become a thin facade over the dense, primary-source-driven Arandu lexicon — same trait surface, dramatically more coverage

## Schema awareness

`mbya_lexicon.db` is owned by the Arandu project (`~/projects/mbya/schema_v2.sql`). Adapter is **read-only** — it doesn't migrate, doesn't write. If Arandu's schema changes the adapter is the one that breaks; this is intentional. Pin to a known schema version and bump the adapter when the lexicon evolves.

```rust
// topologia-mbya-adapter/src/lib.rs
use rusqlite::{Connection, params};
use topologia_core::*;

pub struct MbyaLanguagePlane {
    conn: Connection,
}

impl MbyaLanguagePlane {
    pub fn open(db_path: impl AsRef<Path>) -> anyhow::Result<Self> { ... }
}

impl LanguagePlane for MbyaLanguagePlane {
    fn code(&self) -> &LanguageCode {
        // gn-mbya is the topologia convention; Arandu's schema may use a
        // different code internally. The adapter is the bridge.
        static CODE: LanguageCode = LanguageCode("gn-mbya".into());
        &CODE
    }

    fn get_term(&self, key: &str) -> Option<Term> {
        let row = self.conn.query_row(
            "SELECT word, pronunciation, definition FROM lexemes WHERE key = ?1",
            params![key], |row| Ok(...)
        ).ok()?;
        Some(Term {
            key: key.into(),
            language: self.code().clone(),
            word: row.0,
            // ...
            seed_status: SeedStatus::NativeConfirmed,  // Dooley = authoritative
            ...
        })
    }

    fn iter_terms<'a>(&'a self) -> Box<dyn Iterator<Item = Term> + 'a> { ... }
}
```

## Mapping (Arandu → topologia-core)

| Arandu column | `Term` field |
|---|---|
| `lexemes.key` | `key` |
| `lexemes.word` | `word` |
| `lexemes.pron_ipa` | `pronunciation` |
| `lexemes.definition` | `body` (rendered as markdown) |
| `lexemes.compounds` (M:N table) | `appears_in` |
| `lexemes.related` (M:N table) | `related` |
| (none — derived) | `seed_status: NativeConfirmed` |
| (none) | `concept` (this is *the* gap; user has to author the cross-link) |

The `concept` field is **not** in the Arandu lexicon — it's a topologia-only abstraction. Resolution: a sibling table `topologia_overlay.concept_map` (keyed by Mbyá word → concept anchor) lives in `~/projects/topologia/data/concept_map.sqlite`, authored by the topologia team. Adapter joins on read.

## Out of scope

- Writing back to Arandu. Read-only.
- Hot-reload when the underlying DB changes. Adapter opens once.
- Authority resolution: when both `topologia/guarani-mbya/terms/<key>.md` AND Arandu have the same key, which wins? Current answer: the .md wins (it's where the topologia team tracks edits). Arandu wins for keys only in the lexicon DB. Codify in the adapter.
