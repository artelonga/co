## Contexto
Para servir **storage as a service** (StaaS) a parceiros, o CO precisa de **um ponto
de abstração** de armazenamento de blobs/conteúdo — hoje espalhado em escrita direta
no filesystem. Esta tarefa cria o **trait `StorageBackend`** + uma impl **local
(sharded FS)** selecionada por config. **Sem S3 agora** — o CO-81 (S3) e backends de
parceiro viram impls alternativas do mesmo trait, sem tocar call-sites.

## Design
- **`trait StorageBackend`** (em `co-web/src/storage/backend/mod.rs`), assíncrono:
  - `put(key, bytes, content_type) -> Result<BlobRef>` (content-addressed: key derivável de sha256)
  - `get(key) -> Result<Bytes>` · `head(key) -> Result<BlobMeta>` · `delete(key)` · `exists(key)`
  - `list(prefix) -> Stream<BlobRef>` (paginado)
  - tudo `Send + Sync`, erros via `AppError`.
- **`LocalFsBackend`**: grava em `/data/blobs/<shard>/<hash>` (sharding por prefixo do
  hash, ex.: 2 níveis de 2 hex), content-addressed + dedupe por refcount.
- **Seleção por config (CO-434 pattern)**: `CO_STORAGE_BACKEND=local|s3` (default `local`);
  só `local` implementado aqui. Factory `StorageBackend::from_config()`.
- **Migração PINADA v086** (`co-web/src/storage/migrations/v086.rs`; tip atual v085 —
  re-confirmar max+1 vs PRs abertos): tabela **`blob_refs`** (hash PK, backend, size,
  content_type, refcount, created_at) pra dedupe + rastreabilidade + futura cobrança StaaS.
- **Wire um call-site real** como prova (ex.: avatar/anexo upload OU o snapshot de
  backup) através do backend — não precisa migrar todos os call-sites agora.

## Acceptance
- [ ] `trait StorageBackend` (put/get/head/delete/exists/list) em `storage/backend/`, `Send+Sync`, async.
- [ ] `LocalFsBackend` content-addressed + sharded em `/data/blobs/`, com dedupe por refcount.
- [ ] `StorageBackend::from_config()` seleciona por `CO_STORAGE_BACKEND` (default `local`).
- [ ] Migração **v086** `blob_refs` (hash, backend, size, content_type, refcount, created_at). Confirmar v086 livre (tip v085).
- [ ] ≥1 call-site real passa a escrever/ler via o backend (prova de integração).
- [ ] Testes: put→get round-trip, dedupe (mesmo hash → refcount++ não regrava), delete decrementa refcount, list por prefixo. `tempfile` pro FS.
- [ ] `cargo test` + `clippy -D warnings` + `fmt` limpos; sem MCP.
- [ ] `api-catalog.md` inalterado (sem rota nova nesta fatia) OU, se expor upload, documentar + `openapi:check` sem drift.

## So that
O CO ganha o **ponto único** onde S3 (CO-81), backends de parceiro e cobrança StaaS
se conectam — começando 100% local, sem nova infra. É a quilha do produto "storage
as a service".
