### Why the first iteration missed these

The agent reported "seeded co/CHANGELOG.md and co/public/index.md" but the files were probably added to a source directory **without** being:
- Embedded via `rust-embed` (so they reach the binary), OR
- Inserted into SQLite at boot via the seed orchestrator path

On macOS the local server may have file-system fallback that finds them; CI's `cargo run --bin co-web` on Linux only sees what's in the binary.

## Decision — fix at the correct layer per failure

### Tests #1-2 (Anonymous ownership) — fixture additive

CO-302's apiContext now authenticates as yuri. Tests that need an UNauthenticated browsing experience need a separate fixture:

```ts
// e2e/fixtures.ts addition
anonContext: async ({ playwright }, use) => {
  // No login — fresh context with no session cookie
  const baseURL = process.env.BASE_URL ?? "http://localhost:3000";
  const ctx = await playwright.request.newContext({ baseURL });
  await use(ctx);
  await ctx.dispose();
},
```

Update the 2 failing tests to use `anonContext` instead of `apiContext`.

### Tests #3-4 (Changelog API) — investigate + fix

Two possibilities:
- **Data**: seed data for the changelog doesn't include the entries the test expects
- **Server**: sort/filter logic regressed in some recent change

Run locally against the test server:
```bash
curl -s 'http://localhost:3000/api/v1/changelog?sort=desc' | jq '.[] | .version'
curl -s 'http://localhost:3000/api/v1/changelog?type=feat' | jq '.[] | .type'
```

Fix whichever side is wrong.

### Tests #5-6 (CO-264 recursive-universe routing) — investigate + fix

These test routes added by CO-264 (universe = recursive folder tree). Either:
- The routes were unintentionally changed in a later commit
- The tests use outdated URLs (CO-264's design may have evolved)

Check the route table in `co-web/src/server/router.rs` for `/co/changelog`, `/co/public`, `/{universe}/changelog` patterns. Fix either the route or the test.

### Test #7 (Mobile sidebar hamburger) — likely real bug

CO-280 restructured the sidebar (3 sections). The mobile hamburger button may have been moved or renamed. Check:
- `co-web/static/variants/a/modules/sidebar/wire.js` (setupHamburgerMenu)
- Whether the hamburger still toggles `.sidebar-mobile-open` class
- Whether responsive CSS still recognizes the toggle

### Tests #8-9 (Seed-links) — likely data

The template universe seed is supposed to include a `seguranca` page and a `/sobre` redirect. Either:
- The seed dropped these pages (CO-279's `TUTORIAL → CO` rename or CO-264 restructure)
- The redirect logic regressed

Check `co-web/seed/template/` (or wherever seed data lives) for `seguranca.md` and the `sobre` redirect manifest.
