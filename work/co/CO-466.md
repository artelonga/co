# CO-466 — No registry: every content folder is a universe

> Owner directive: *"we don't need a universe registry — all folders are
> universes, all it takes to be a universe is being a folder."*

Removes the last opt-in gate from the local-dev workspace scan and makes the
seeded admin able to CRUD every workspace universe through the web/vault.

## Done (this increment)
- **Scan no longer requires `_universe.yaml`**: `register_universes_from_local_dir`
  (gated on `CO_LOCAL_REPOS_DIR`, prod-never) registers a folder when it has a
  manifest **or** holds markdown content (`content/`, `index.md`, or root `*.md`).
  `_universe.yaml` stays optional metadata; name falls back to the folder name.
- **Build/system dirs skipped**: `target`, `node_modules`, `dist`, `build`,
  `backups`, `.git`, `.worktrees`, dot-dirs.
- **Owner CRUD**: workspace universes are owned by `'system'` at registration, so
  the admin could read but not write (vault 403). `ensure_admin_universe_memberships`
  now also grants admin membership on every universe with a `local_repo_path`
  (DB-driven, no hardcoded key list), and is re-invoked at login
  (`verify_handler`, gated to `CO_SEED_ADMIN_EMAIL`) because passwordless login
  means the admin user doesn't exist at boot.

## Acceptance
- [x] A folder with markdown content but **no** `_universe.yaml` registers as a universe.
- [x] A folder with `_universe.yaml` still registers and uses its manifest metadata (name/parent).
- [x] Build/system dirs (`target`, `node_modules`, `backups`, `.worktrees`, dot-dirs) are skipped.
- [x] Scan is idempotent (second run registers nothing new).
- [x] The seeded admin can CRUD a workspace universe via the vault (verified: PUT 201 / GET 200 / DELETE 204 on `yuri/content/co/`).
- [x] Local-dev only — prod (no `CO_LOCAL_REPOS_DIR`, no `local_repo_path` universes) is unaffected.
- [x] `cargo test` (scan test) + `cargo clippy -- -D warnings` clean.
