## What this slice does

Extends CO-223's `Worker` trait (which only models `tick`) with `enqueue`, `run_now`, and `cancel` operations behind a `WorkerExecutor` trait. The default impl is "spawn a tokio task"; future impls (NATS queue, Temporal, k8s Jobs) plug in without touching domain code.

## Scope

1. New trait `WorkerExecutor` in `co-web/src/infra/workers.rs`:
   ```
   trait WorkerExecutor {
       async fn enqueue(&self, job: Job) -> Result<JobHandle>;
       async fn run_now(&self, job: Job) -> Result<JobResult>;
       async fn cancel(&self, handle: JobHandle) -> Result<()>;
       async fn status(&self, handle: JobHandle) -> Result<JobStatus>;
   }
   ```
2. `Job` is a serializable enum / dynamic dispatch around the existing Worker types (embedding worker, notification worker, deployment_snapshot_worker, push worker)
3. Default impl `InProcessExecutor` — wraps `tokio::spawn` with handle tracking
4. Migrate the existing `WorkerSupervisor` (CO-223) to use the trait
5. `AppState.integrations.worker_supervisor` becomes `Arc<dyn WorkerExecutor>`

## Acceptance

- [ ] Trait `WorkerExecutor` exists in `co-web/src/infra/workers.rs`
- [ ] `InProcessExecutor` implements it; existing worker behavior unchanged
- [ ] All current Worker impls (embedding, notification, push, deployment_snapshot) work through the trait
- [ ] Tests pass (`cargo test --workspace`)

- Cross-machine work distribution — Phase 4 (CO-300+) territory
