## As

a CO user with a static universe (markdown + a few HTML pages)

## I Need

a `DeployerAdapter` trait and a first implementation that takes a built universe artifact and publishes it to R2 with a public URL

## To

prove the adapter abstraction (CO-116 epic goal) on the simplest possible target before tackling Cloudflare Pages and beyond

## Given / When / Then

GIVEN CO-133 produces a validated `Manifest`,
WHEN we define `trait DeployerAdapter { fn deploy(&self, artifact: BuildArtifact, manifest: &Manifest) -> DeployResult }` and ship the `static-on-r2` impl,
THEN universe `u_test` with `target: static-on-r2` deploys end-to-end and serves its landing page from R2's public domain.

## Trait shape

```rust
pub trait DeployerAdapter: Send + Sync {
    fn name(&self) -> &'static str;

    fn deploy(
        &self,
        artifact: BuildArtifact,
        manifest: &Manifest,
        secrets: &SecretResolver,
    ) -> impl Future<Output = DeployResult>;

    fn rollback(&self, deploy_id: &str) -> impl Future<Output = Result<()>>;

    fn status(&self, deploy_id: &str) -> impl Future<Output = DeployStatus>;
}

pub struct StaticOnR2Adapter {
    s3: S3Client,           // points at R2
    base_domain: String,    // e.g., "co.app"
}
```

## Static-on-R2 implementation outline

1. Generate deploy id = `{universe_id}/{utc-timestamp}`
2. Upload `artifact.tarball` to `r2://co-deployments/{deploy_id}/`, extracted, with content-types from extensions
3. If `manifest.bindings.storage.encrypted == true`, upload ciphertext + a manifest pointing at it (Phase 4 wiring)
4. Update `r2://co-deployments-current/{universe_id}/` symlink (atomic via R2 versioning)
5. Optionally configure `manifest.domain` via a future DNS adapter; for v1, return the R2 public URL
6. Return `DeployResult { deploy_id, url, snapshot_id }`

## Acceptance

- [ ] `DeployerAdapter` trait in `co-core::deploy`
- [ ] `StaticOnR2Adapter` with full deploy + rollback + status
- [ ] Unit tests with mock S3 client (via `mockall` or similar)
- [ ] Integration test: real R2 bucket, deploy a 3-file fixture universe, fetch the landing page, assert content
- [ ] `co deploy --target static-on-r2` CLI subcommand wired
- [ ] Rollback test: deploy v1, deploy v2, rollback to v1, verify v1 served

## Out of scope

- DNS adapter (custom domain pointing) — separate ticket
- CDN configuration on top of R2 — Phase 5 follow-up
- Encrypted-deploy-artifact path — depends on Phase 4 work; trait already accommodates

## Risks

- **R2 atomic switch via versioning.** Mitigation: test the failure mode of half-uploaded deploys; ensure the "current" pointer only updates after all objects land
- **Rollback semantics.** Mitigation: define rollback as "switch the pointer back" — keeps simple; old deploys retained for `manifest.backup.retention`
