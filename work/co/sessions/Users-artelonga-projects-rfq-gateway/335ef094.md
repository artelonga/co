### 2. Swagger UI

You already have the OpenAPI spec (`api/rfq-api.yaml`). To serve Swagger UI, you have two options:

- **Option A — Embed in the Rust app** using [`utoipa-swagger-ui`](https://crates.io/crates/utoipa-swagger-ui): adds a `/swagger-ui` route that serves the interactive docs directly from the binary. No extra infra needed.
- **Option B — Static hosting**: serve the YAML via S3/CloudFront and point Swagger UI at it. More decoupled but more moving parts.

I'd recommend **Option A** — add `utoipa` + `utoipa-swagger-ui` to Cargo.toml and mount the Swagger route. It's ~20 lines of code.

### 3. AWS Infrastructure (new account)

You need:

| Component | Purpose |
|-----------|---------|
| **ECR** | Docker image registry |
| **ECS Fargate** (or EC2) | Run the container — Fargate is simplest for a single service |
| **ALB** | HTTPS termination + routing |
| **Route 53** | DNS (e.g., `rfq.artelonga.com.br` or `api.hedix-rfq.com`) |
| **ACM** | TLS certificate for the domain |
| **Secrets Manager** or **SSM Parameter Store** | Store `RFQ_API_KEY` securely |
| **CloudWatch** | Logs (the app already outputs JSON logs) |

Minimal path: **ECR + ECS Fargate + ALB + ACM**.

### 4. CI/CD Pipeline

The current CI runs check/test/fmt/clippy but has **no deployment step**. You'll need to add:

- Docker build + push to ECR
- ECS service update (or use GitHub Actions `aws-actions/amazon-ecs-deploy-task-definition`)

### 5. Persistence

The store is **in-memory** (`MemoryStore` backed by `HashMap`). This means quotes are lost on restart/redeploy. For Hedix-only MVP this might be acceptable if quotes are short-lived, but flag it — the `QuoteStore` trait is already abstracted for swapping in Redis/DynamoDB later.
