## Postmortem: Content Overwrite Incident #2 (2026-04-07)

### Incident
User-edited content in the `conteudo` table was overwritten by `content-import.ts` during deploy. Affected:
- `reuniao-da-coordenacao` — user added meeting notes (Mensagem de Silo, Arraiá do Quilombo, missões) via admin editor. Body overwritten with empty content from repo.
- `conversa-com-eag` — fotos array removed from meta
- `oficina-captacao-agua` — fotos array removed from meta

### Root Cause
In the previous fix for the Dockerfile, I moved `content-import.ts` to run on **every deploy** (not just first boot). This was needed for institutional pages but had the side effect of overwriting user-edited posts. The import script compared file hashes and overwrote any record where the repo file differed from the DB — including posts where the *user* was the one who changed the content.

### Timeline
1. User edited `reuniao-da-coordenacao` via admin panel (added meeting notes, changed title)
2. Deploy ran `content-import.ts` → repo's empty `reuniao-da-coordenacao.md` overwrote user's content
3. Same deploy overwrote `fotos` arrays in `conversa-com-eag` and `oficina-captacao-agua`

### Recovery
Content recovered from `versoes` table (version history). The system had v3 with the user's content.

### Fixes Applied
1. **`content-import.ts`** — Posts (tipo='post') are now **never overwritten** after initial seed. Only pages (tipo='pagina', institutional content) are updated on each deploy. This is the correct semantic: pages are git-controlled, posts are user-controlled.
2. **Local repo** — Updated `reuniao-da-coordenacao.md` to match user's content so the repo stays in sync.

### Prevention Rules (updated)
- **`content-import.ts` MUST skip existing posts.** Import creates new posts only (seed). Pages are always overwritten (institutional, git is source of truth).
- **NEVER assume repo content is more recent than DB content for posts.** Users edit posts via the admin panel. The DB is the source of truth for posts.
- **The `versoes` table is your safety net.** Always check version history before declaring data lost.
