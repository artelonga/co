## Telemetry & Analytics review

The system is well-designed: local queue + batch POST + schema versioning + privacy gates + deterministic A/B. But there are **four practical issues that the move to `co.artelonga.com.br` either creates or makes urgent**:

### 1. Cross-subdomain visitor identity is broken (biggest one)

`vid` lives in `localStorage`, which is **scoped per origin** — `artelonga.com.br` and `co.artelonga.com.br` get different `vid`s. That means:

- A visitor browsing the marketing site, clicking through to `co.artelonga.com.br`, and signing up there will appear as **two separate visitors** in the unified table.
- A/B experiments cannot span both surfaces (different `vid` → different bucket).
- `localStorage.al_optout` doesn't propagate either — opting out on the marketing site does NOT opt out on Co.

**Options** (all in `analytics.js` + the Co client):
- **(a) Accept it.** Document the limitation. Backend joins via `ip_hash` heuristically when needed. Privacy posture stays clean.
- **(b) Cookie on `.artelonga.com.br`.** Replace `localStorage.al_vid` with a first-party cookie scoped to `Domain=.artelonga.com.br; SameSite=Lax`. True unified identity, but breaks the "no cookies" commitment in `analytics-api.md §4`.
- **(c) Hybrid.** Keep `vid` in localStorage, but *also* set a domain-scoped cookie carrying the same id, used only for cross-subdomain threading. Document as "essential, no third-party tracking." This is what most SaaS does.

My recommendation: **(c)** if unified funnel matters (almost certainly does — landing → Co signup is the primary conversion), **(a)** if you want to stay strict.

### 2. Same-origin-but-different-host links classified as `click_outbound`

`analytics.js:310` — `isOutbound = isAbs && !href.includes(location.hostname)`. After today's change, every `https://co.artelonga.com.br/...` link will fire `click_outbound` instead of something like `click_app`. Technically correct, conceptually wrong — these are part of the same product.

Easy fix: special-case `*.artelonga.com.br` to fire `click_app` (or `click_co` specifically). Two-line change.

### 3. CORS allowlist needs `co.artelonga.com.br`

`docs/analytics-api.md §1` says `allow origin https://artelonga.com.br (and dev origins)`. When Co's client also POSTs to `/events` from `co.artelonga.com.br`, it'll be CORS-blocked. Update the spec + the actual `Access-Control-Allow-Origin` logic in the `co` Rust handler before launch.

Right now every event queues in `localStorage` (cap 1000, oldest dropped). Until `artelonga/co` ships `POST /events` and `analytics.js` line 46 is set, **you have zero data**. This is the gating item for May 1.
