## CO-73 — Temporal Model: Deliverables

**Migration** — `entry_dates(universe_key, entry_path, semantic, value)` table added to per-universe `data.db` (migration v2) with a composite index on `(universe_key, semantic, value)` for O(log n) range queries.

**DateSemantic extended** — Added `scheduled`, `published`, `expires`, `effective` to the existing `due`/`event`/`created`/`updated` variants. New `canonical_name()` method returns `due_at`, `event_at`, etc. and `from_canonical()` enables round-trip from query params.

**Write hook** — On every `POST` and `PUT` entry, the manifest is consulted to find date fields with a declared semantic; matching values are upserted to `entry_dates`. On `DELETE` the rows are cleaned up.

**Query API** — `GET /api/v1/universes/:slug/entries?date_semantic=event_at&from=2026-06-01&to=2026-06-30` with optional `&type=` filter. Open intervals work (omit `from` or `to`). Invalid semantic → 400.

**Calendar view** — `/shared/calendar.html`: monthly grid in user's timezone, configurable universe/type/semantic, colour-coded event chips per semantic, hover tooltip.

**Gantt view** — `/shared/gantt.html`: horizontal bar chart for entries with configurable start/end semantics, today line, overdue styling, auto-scaling week/month axis. Driven by manifest `views: [{type: gantt, date_start: …, date_end: …}]` with no code changes required.

how does istalling work

## Assistant · 2026-05-01T19:23:21

When the browser decides the site qualifies as installable (HTTPS + service worker + web manifest), it fires `beforeinstallprompt`. The app captures that event and shows the install button. When you click **Instalar agora** in the popover, it calls `_installPrompt.prompt()` — that's the browser's own native dialog ("Add Co to Home Screen" / "Install Co"). The user accepts or dismisses in that dialog. The app itself just calls `.prompt()` and gets back `outcome: accepted | dismissed`.

**What actually happens after install:**
- The app is added to your home screen / dock / app launcher
- Opens in standalone mode (no browser chrome, address bar, tabs)
- The service worker (`co-v4-offline`) is already registered from the first visit, so it was already caching static assets — install doesn't change the cache, it just changes how the app opens
- Subsequent launches go through the SW first, so static assets (HTML, JS, CSS) load instantly from cache even offline
- API calls still go to the server; offline write queue (`CoOffline.queueWrite`) buffers PUT/POST to entries and vault if the server is unreachable, and Background Sync flushes them when connectivity returns

**What it does NOT do:**
- Copy your data locally (entries still live on the server)
- Create a separate user account or universe
- Change any URL or cookie
- Collect any extra data

**The install button only appears** when the browser itself decides the criteria are met (it won't show on localhost, Firefox mobile needs a flag, Safari on iOS has no `beforeinstallprompt` so the button never appears there — iOS users use "Add to Home Screen" manually from the share sheet).
