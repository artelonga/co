## Assistant · 2026-04-27T11:50:21

From `storage.rs`, the logic is:

1. **Look up user by email** — `query_row` on `users WHERE email = ?1`, returns `(id, password_hash)` or `None`.
2. **Three branches:**
   - `Some((_, hash))` where `hash == env_hash` → **no-op**, logs "hash unchanged"
   - `Some((user_id, _))` where hash differs → **UPDATE** `password_hash + tier='admin'` by `user_id`, logs "hash updated"
   - `None` → **INSERT** new row with `id=usr_admin_<8-char uuid>`, `tier='admin'`, logs "admin user seeded"
3. **Format warning** if the hash doesn't start with `$argon2id$` (catches misconfiguration like a plaintext password in the env var).

Called once from `start_server` after migrations, any env:

```rust
if let (Some(email), Some(hash)) = (
    std::env::var("CO_SEED_ADMIN_EMAIL").ok(),
    std::env::var("CO_SEED_ADMIN_PASSWORD_HASH").ok(),
) {
    storage.seed_admin_user_from_env(&email, &hash)?;
}
```

The key invariant: "same hash → no UPDATE" means repeated restarts with identical secrets are truly silent — no write, no lock contention. Only a secret rotation (new `$HASH` in Fly secrets) triggers an update.
