## GIVEN / WHEN / THEN

- GIVEN prod `/api/health` failing (non-200 or timeout) for > N consecutive
  checks, WHEN the probe detects it, THEN Yuri is notified within ~5 minutes
  (e-mail via Resend — already configured — and/or ntfy/webhook push), and a
  `health.down` event lands in atividades/`/agora` when the server returns.
- GIVEN recovery, THEN a `health.recovered` notice with downtime duration.
- The probe lives OUTSIDE the prod machine (a Fly scheduled machine,
  GitHub Actions cron, or the staging app probing prod — cheapest wins;
  GH Actions cron costs nothing and needs no new infra).
- Scope check: staging probed too, but staging alerts are digest-only.

## Context

2026-06-11: prod crash-looped for ~3 hours (disk-full panic) and was found
only by manually testing the site. Two prior incidents (2026-04-30 column
reads, 2026-05-12 mutex poisoning) were likewise user-discovered. Three
strikes — alerting is no longer optional.
