GIVEN universes today can only be created via API call (`POST /api/v1/universes`) — no SPA UI surface — and renaming, duplicating, or deleting are similarly CLI-only, AND the user wants the create flow to be intuitive (sidebar button, modal with required fields, optional copy-from),
WHEN we add a clean CRUD surface to the SPA covering the full universe lifecycle (create → rename → change visibility → duplicate → delete) with reasonable confirmations and per-universe context menus,
THEN any user can manage their universe collection from the browser without scripting, and the platform feels like a productized content workspace rather than a CLI-driven tool.

## Surface design

### Sidebar: `+ New universe` button

Top-right of the sidebar header. Opens a modal:

```
┌────────────────────────────────────────────┐
│ New universe                          ✕    │
├────────────────────────────────────────────┤
│ Key:         [quilombo-blog            ]   │  (lowercase, digits, hyphens)
│ Name:        [Quilombo Blog (perf-test)]   │
│ Description: [Performance + scale ...  ]   │
│                                            │
│ Visibility:  ◯ Private  ◉ Public-subscribable  ◯ Login-required
│                                            │
│ ▢ Copy from existing universe             │
│   [select: artelonga ▾]                    │
│                                            │
│         [Cancel]   [Create]                │
└────────────────────────────────────────────┘
```

When "Copy from" is checked + universe selected:
- Calls `POST /api/v1/universes/<source>/duplicate` (CO-95 Phase 1)
- New universe gets all source entries
- Source stays unchanged

When unchecked:
- Calls `POST /api/v1/universes` (existing endpoint)
- Empty new universe

After success: redirect to `/co/<new-key>`.

### Sidebar: per-universe context menu (right-click)

```
┌─────────────────────┐
│ Open                │
│ Open timeline       │
│ ─────────           │
│ Rename...           │
│ Change visibility ▸ │
│ Duplicate...        │
│ ─────────           │
│ Settings...         │
│ ─────────           │
│ Archive             │
│ Delete...           │
└─────────────────────┘
```

- **Rename**: prompt for new name (key is immutable to avoid breaking links)
- **Change visibility**: submenu with `Private` / `Public-subscribable` / `Login-required`; calls `PUT /api/v1/universes/:slug` with `visibility`
- **Duplicate**: same modal as create-with-copy-from, source pre-filled
- **Settings**: full universe form (theme, description, etc.) — links to existing config UI
- **Archive**: soft-hide (sets `is_archived: true`; not yet a backend field — defer)
- **Delete**: confirmation dialog "Type the universe key to confirm"; calls `DELETE /api/v1/universes/:slug`

### Settings tab on each board

A "Universe settings" panel accessible from the board header. Shows:
- Editable name + description
- Visibility selector
- Theme picker (existing)
- Members list (with add/remove for owner)
- Subscriber count (read-only stat)
- Danger zone: Archive / Delete buttons at bottom

### Empty state

When user has zero universes (rare — every seeded admin gets memberships):

```
You don't have any universes yet.
[+ Create your first universe]   [Browse public universes]
```

## API requirements

Mostly already exist:

| Need | Endpoint | Status |
|------|----------|--------|
| Create | `POST /api/v1/universes` | exists |
| Read (list) | `GET /api/v1/universes` | exists |
| Read (single) | `GET /api/v1/universes/:slug` | exists |
| Update name/desc | `PUT /api/v1/universes/:slug` | exists |
| Update visibility | `PUT /api/v1/universes/:slug` (CO-65) | exists |
| Duplicate | `POST /api/v1/universes/:slug/duplicate` (CO-95) | shipped 1.20.0 |
| Delete | `DELETE /api/v1/universes/:slug` | **needs verification — may not exist; spec deletion semantics** |
| Search | `GET /api/v1/universes/search?q=` | exists |

Delete semantics gap:
- Does the platform delete the universe row + entries + members + ops + filesystem dirs?
- Soft-delete (set `is_deleted=1`, retain data for 30 days) vs hard-delete?
- **Recommend**: soft-delete (`is_deleted` column + filter from `list_universes_for_user`); hard-delete via admin tool after 30 days. Avoids accidental data loss.

If the DELETE endpoint doesn't exist or hard-deletes today, add a soft-delete first:
