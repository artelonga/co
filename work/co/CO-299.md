## What this slice does

When `co serve --staging` is on (per CO-298), automatically point CO-291's OTLP exporter at `http://localhost:4317` so spans flow to a local Jaeger instance. User runs Docker once, runs `co serve --staging`, opens `localhost:16686`, sees full distributed traces of every request. Validates the trace UX before any prod APM rollout.

## Scope

1. In `co serve --staging` startup, default `CO_TELEMETRY_OTLP_ENDPOINT` to `http://localhost:4317` if not already set
2. Print a helpful banner at startup:
   ```
   ✓ co 2.30.x staging mode
   ✓ OTLP exporter → http://localhost:4317
     Run a local Jaeger first: docker run -d -p 16686:16686 -p 4317:4317 jaegertracing/all-in-one
     View traces at: http://localhost:16686
   ✓ Latency injection: ~20ms per storage op
   ✓ Fault injection: ~5% blob ops will 503
   Listening on http://127.0.0.1:54321
   ```
3. Docs `docs/staging.md` adds a "Tracing" section with the Docker command + screenshot
4. Add an example trace assertion in tests: spawn TestServer (CO-300), make a request, assert the OTLP span was emitted (use a mock collector or `tracing-test`)

## Acceptance

- [ ] `co serve --staging` against a running local Jaeger shows full traces in `localhost:16686` within 10s
- [ ] Banner prints the OTLP config + Docker command
- [ ] Trace spans include: HTTP request, auth, DB queries, blob ops
- [ ] Without `--staging`, no OTLP attempt (zero overhead)
