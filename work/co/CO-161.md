## As

a maintainer who just shipped 1.41.1's per-handler privacy gate (`check_reader_for_entries` called from 13 call sites) after discovering anonymous reads were leaking entries from private universes

## I Need

a single tower-style middleware applied once on the `/api/v1/universes/{slug}/...` prefix that runs the same visibility check for every read handler, so adding a new endpoint can never silently regress the gate

## To

(a) eliminate per-handler boilerplate that's easy to forget on the next route added,
(b) move the auth/visibility decision from "pattern" to "structure" (a route below the prefix automatically inherits the gate),
(c) make the gate uniformly testable in one place,
(d) close two latent bugs the per-handler scan flagged: **CO-156 reference writes** (POST/PUT/DELETE on `/references`) currently authenticate via `vault_auth` indirectly; should also enforce ownership/membership; **vault_routes** writes already require auth but should be unified.

---

## Current state (1.41.1)

The gate is `entry_routes::check_reader_for_entries(state, headers, universe_key)` — public/template universes pass through; private require login + (owner OR `universe_members` row); otherwise 401/403. Called from 13 read handlers:

- `entry_routes`: list_entries, get_entry, list_entry_tags, entry_tree, get_manifest, query_handler, list_references (citations), list_orphan_wikilinks (citations)
- `relation_routes`: get_inbound_relations, get_outbound_relations
- `reference_routes`: list_references, orphan_blobs, broken_cards, get_reference, list_works
- `asset_routes`: had its own equivalent `check_reader` before this leak was found (different impl, same shape — should consolidate)
- `vault_routes`: write handlers use `vault_auth` (token-or-cookie); reads aren't currently rate-limited or checked beyond auth — should pass through the same gate

## Design

```rust
// co-web/src/server.rs (router build)
let universe_api = Router::new()
    // ... all the /:slug/* sub-routers ...
    .layer(axum::middleware::from_fn_with_state(
        state.clone(),
        crate::auth::universe_visibility_gate,
    ));
```

```rust
// co-web/src/auth.rs
pub async fn universe_visibility_gate(
    State(state): State<AppState>,
    req: Request<Body>,
    next: Next,
) -> Result<Response, Response> {
    // Extract slug from request path: /api/v1/universes/<slug>/...
    let slug = match extract_universe_slug(req.uri().path()) {
        Some(s) => s,
        None => return Ok(next.run(req).await), // not a universe-scoped path
    };

    let storage = state.storage.lock().map_err(|_| internal_500())?;
    let universe = match storage.get_universe(&slug) {
        Some(u) => u,
        None => return Err(not_found_404("Universe")),
    };

    // Public/template — let the request through.
    if universe.is_public || universe.is_template {
        return Ok(next.run(req).await);
    }

    // Private — require authentication.
    drop(storage);
    let user_id = match resolve_user_id(&state, req.headers()) {
        Some(id) => id,
        None => return Err(unauthorized_401("Login required")),
    };

    // Owner or member.
    let storage = state.storage.lock().map_err(|_| internal_500())?;
    let universe = storage.get_universe(&slug).ok_or_else(|| not_found_404("Universe"))?;
    if universe.owner_id == user_id {
        return Ok(next.run(req).await);
    }
    let is_member = storage.conn().query_row(
        "SELECT 1 FROM universe_members WHERE universe_key = ?1 AND user_id = ?2",
        params![&slug, &user_id],
        |_| Ok(true),
    ).unwrap_or(false);
    if is_member {
        Ok(next.run(req).await)
    } else {
        Err(forbidden_403("Not authorized"))
    }
}
```

The middleware runs once per request; sub-handlers stay simple.

### Method-aware variant (writer gate)

A second middleware `universe_writer_gate` for POST/PUT/PATCH/DELETE that requires `owner_id == user_id OR member with role IN ('admin','editor')`. Today's CO-156 reference write handlers and CO-149 asset write handlers each implement this ad-hoc.

```rust
// Apply to write-only sub-routers
let writes = Router::new()
    .route("/{slug}/entries/{*path}", put(update_entry).delete(delete_entry))
    .route("/{slug}/references", post(create_reference))
    // ...
    .layer(middleware::from_fn_with_state(state.clone(), universe_writer_gate));
```

## Migration steps

1. Define `auth::universe_visibility_gate` + `auth::universe_writer_gate`.
2. In `server::build_router`, scope `entry_api`, `relation_api`, `reference_api`, `asset_api`, `vault_api` under one `universe_api` router and apply the gate(s) once.
3. Remove the 13 per-handler `check_reader_for_entries(...)?` lines (and their CO-145 `asset_routes::check_reader` siblings) — leave a comment pointing to the middleware.
4. Add 4 test cases: anon-on-public 200, anon-on-private 401, owner-on-private 200, non-member-on-private 403.
5. Run `cargo test -p co-web` — all 316+ tests should still pass.
6. Cosmetic: also fix the recurring linter-reverts-Cargo.toml-version issue by ensuring CHANGELOG version-bump entries are committed first; no code change needed.

## Acceptance

- [ ] Single middleware function exists in `auth.rs`, applied once in `server::build_router`
- [ ] Zero `check_reader_for_entries` calls in entry_routes / relation_routes / reference_routes (the call sites are removed because the middleware does the work)
- [ ] `asset_routes::check_reader` removed, replaced by the same middleware (asset routes inherit the gate)
- [ ] All read paths pass through the gate; all write paths additionally pass through the writer gate
- [ ] 4 new integration tests cover anon/owner/member/stranger × public/private
- [ ] Existing 316+ tests still pass
- [ ] No regression in the empirical privacy verification (`/api/v1/universes/<private>/entries` returns 401 to anon; `<public>` returns 200)

## Out of scope

- Rate-limiting consolidation (already a tower middleware via `rate_limit::rate_limit_middleware`; just unrelated).
