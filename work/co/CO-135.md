## As

a CO user wanting their universe deployed to Cloudflare Pages with a custom subdomain

## I Need

a second `DeployerAdapter` impl (`CloudflarePagesAdapter`) that takes the same `BuildArtifact` and deploys it via the Cloudflare API, configures the custom domain, and returns the live URL

## To

validate the adapter abstraction by adding a **structurally different** target (managed PaaS vs. raw object storage), proving the trait holds up before adding Vercel and Fargate

## Given / When / Then

GIVEN `static-on-r2` (CO-134) ships and validates the trait shape,
WHEN we implement `CloudflarePagesAdapter` using the Cloudflare REST API,
THEN the same universe `u_test` with `target: cloudflare-pages` deploys to `*.pages.dev` (or the user's custom domain) without source changes from the static-on-R2 path.

## Implementation outline

1. Resolve secrets: `CF_API_TOKEN`, `CF_ACCOUNT_ID`
2. Create or update a Pages project named `co-{universe_id}`
3. Upload artifact via the Pages direct-upload API (or the Wrangler protocol)
4. If `manifest.domain`, configure it as a custom domain on the Pages project
5. Wait for build success; surface logs back to CO for the user
6. Return `DeployResult { deploy_id, url: pages_subdomain_or_custom, snapshot_id }`

## Acceptance

- [ ] `CloudflarePagesAdapter` in `co-core::deploy`
- [ ] Reuses `BuildArtifact` shape; no special-casing in the build pipeline
- [ ] Integration test against a real Cloudflare account (test account, not personal): deploy → fetch → rollback → fetch
- [ ] Custom domain path: configure → DNS validation → live within 5 min
- [ ] Logs surfaced back to CO via the same telemetry path as Fly deploys
- [ ] Documented setup procedure (`CF_API_TOKEN` scopes, account binding)

## Out of scope

- Cloudflare Workers deployer (different shape — needs the `wrangler` API for Workers, not Pages) — separate ticket
- Build customization beyond what the manifest declares — separate ticket
- Per-PR preview deploys — Phase 5 follow-up

## Risks

- **CF API rate limits.** Mitigation: serialize per-account; document
- **Custom domain DNS race.** Mitigation: validate DNS before declaring deploy successful; surface "DNS pending" state to user
