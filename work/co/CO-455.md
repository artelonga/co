## Contexto
Doc-sync review (2026-06-14): o site público `/docs` (artelonga.com.br) anuncia um
endpoint de contato, mas a rota real — **`POST /api/v1/universes/{slug}/messages`**
(formulário de contato CO-326: anon, rate-limit 5/h/IP, honeypot) — estava
**servida mas ausente** do `api-catalog.md`, do `openapi.yaml` e do Swagger
(`/api/docs`). A fonte de verdade da API não documentava um endpoint público real.

## Acceptance
- [ ] `POST /api/v1/universes/{slug}/messages` consta no `docs/architecture/api-catalog.md` (seção universes), com auth `anon` e descrição do corpo.
- [ ] `co-web/openapi.yaml` regenerado a partir do catálogo inclui a rota (`openapi:gen`).
- [ ] `openapi:check` sem drift (catálogo == código == openapi.yaml).
- [ ] A rota aparece no Swagger UI (`/api/docs`, CO-452), fechando o gap com o `/docs` público.
- [ ] Sem código novo, sem migração — apenas documentação/contrato.

## So that
O contrato documentado da API bate com o que o site público anuncia e com o que o
servidor realmente serve — sem endpoint público "fantasma" fora do Swagger.

## Não no escopo
- Mudar o comportamento do endpoint (CO-326 já está estável).
- Renomear para um alias `/api/v1/contact` (o `/docs` usa rótulo amigável; a rota canônica é a documentada).
