## As

visitante de `artelonga.com.br/analytics`

## I Need

dois endpoints JSON read-only que a página estática já chama mas que retornam 404 hoje:
- `GET /api/v1/analytics/public/summary?days=N`
- `GET /api/v1/analytics/public/recent?limit=N`

## So That

o dashboard pare de cair no fallback localStorage (que mostra só os events do browser corrente) e renderize agregado real do `telemetry_events`.

---

## Estado atual

`assets/analytics-dashboard` no repo artelonga chama esses URLs em `co.artelonga.com.br/api/v1/analytics/public/{summary,recent}`. Não existem. `renderEmpty()` roda, mostra "Fila local · N eventos neste navegador.".

Equivalentes admin já existem: `/api/v1/admin/telemetry/summary`. Reusar query helpers.

## Shape

### `GET /api/v1/analytics/public/summary?days=N`

```jsonc
{
  "as_of": "2026-05-09T00:00:00Z",
  "window_days": 30,
  "views": 12345,
  "events_total": 28910,
  "visitors": 2341,
  "returning": 412,
  "sessions": 3877,
  "session_avg_ms": 71200,
  "countries": 18,
  "cities": 67,
  "timeseries": [{ "bucket": "2026-04-10", "count": 142 }, ...],
  "top_pages": [{ "path": "/", "views": 1240, "visitors": 412 }, ...],
  "geo":       [{ "country": "BR", "city": "São Paulo", "visitors": 410, "sessions": 622 }, ...]
}
```

`days` clamp `[1, 365]`, default 30. Filtra `WHERE universe_key = 'artelonga' AND timestamp >= now - days` — o index composto de CO-177 deixa isso barato.

### `GET /api/v1/analytics/public/recent?limit=N`

```jsonc
{
  "events": [
    { "ts": 1746820000000, "name": "page_view", "path": "/", "country": "BR", "city": "São Paulo" },
    ...
  ]
}
```

`limit` clamp `[1, 200]`, default 50. Order by `timestamp DESC`.

### Strip (não expor)

- `vid`, `sid`
- `ip_hash`
- `properties` cru (UTM, experiments — só agregar)
- per-user sequences

### Cache

5 min in-memory por (endpoint, query). Mesmo padrão de CO-105.

### CORS

Mesmo allowlist de CO-177 (`https://artelonga.com.br`).

## Implementação

1. Módulo novo `co-web/src/analytics_public.rs` com 2 handlers.
2. Mount em `Router::new().route("/summary", get(...)).route("/recent", get(...))`, nest sob `/api/v1/analytics/public`.
3. Reuse query helpers de `summary_handler` admin; extrair shared se duplicar.
4. Response struct separada da admin variant pra strip campos sensíveis.
5. CORS herda layer de CO-177.
6. Hardcode filter `universe_key = 'artelonga'` por enquanto. Se mais universes precisarem, extrair em param de query/path depois.

## Tests

- `summary?days=7` retorna shape esperado, counts não-negativos.
- `summary?days=999` clamp 365.
- `summary?days=0` → 400.
- `recent?limit=200` retorna até 200 events DESC.
- Response não tem `visitor_token` / `ip_hash` / `properties`.
- Preflight OPTIONS de artelonga.com.br passa.
- Cache: 2ª request idêntica é mais rápida.

## Critérios de aceitação

- [ ] Ambos endpoints retornam 200 com o shape documentado.
- [ ] Campos sensíveis strippados (verificado por test).
- [ ] CORS allow artelonga.com.br.
- [ ] Cache TTL 5 min.
- [ ] Smoke-test contra UAT após deploy: `/analytics` em artelonga.com.br renderiza dados reais.
- [ ] `docs/analytics-api.md` documenta os dois endpoints.

## Out of scope

- Multi-universe parameterization. Hoje hardcode artelonga; se quilombo/redearte vierem, vira `:universe_key` no path — mudança barata depois.
- Realtime / SSE.
- Date ranges customizadas além de `days=N`.
