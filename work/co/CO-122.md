## As

a CO operator planning multi-tenant scaling

## I Need

a documented quota/tier model — what counts (entries, storage MB, deployments, telemetry events/day), what the per-tier limits are, what happens at the limit (soft warn, hard block, paywall) — committed to the repo as a spec **before** any enforcement code lands

## To

avoid relitigating these tradeoffs in three places (UI, API, billing) once enforcement starts in Phase 2 (CO-80) and to give §C.6 of the platform roadmap review a concrete answer

## Given / When / Then

GIVEN the existing anonymous limit (100 entries) is the only quota in the system,
WHEN we draft a tier matrix and acceptance criteria for each tier transition,
THEN engineering can implement enforcement (CO-80) deterministically and product/marketing have something to point at when announcing tiers.

## Tier matrix (initial proposal — adjust during review)

| Tier | Entries / universe | Storage / universe | Universes | Telemetry events/day | Deployments | Price/mo |
|------|---------------------|---------------------|-----------|----------------------|--------------|----------|
| Anônimo | 100 | 50 MB | 1 (auto-clone) | 1k | 0 | — |
| Convidado (autenticado) | 1k | 500 MB | 5 | 10k | 1 (static-on-R2) | — |
| Cocriador | 10k | 5 GB | 25 | 100k | 5 (any target) | TBD |
| Coletivo | 100k | 50 GB | unlimited | 1M | unlimited | TBD |
| Admin | unlimited | unlimited | unlimited | unlimited | unlimited | n/a |

## Limit behaviors

| At | Behavior |
|----|----------|
| 80% of any limit | Soft warn in UI ("Você está próximo do limite") |
| 100% of soft-cappable limit | Hard block on writes, reads continue, "Crie sua conta para continuar" prompt |
| 100% of telemetry/day | Drop oldest events, surface in admin dashboard |
| 100% of deployment count | Deploy API returns 402 with upgrade link |
