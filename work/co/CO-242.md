## As

A user browsing a universe

## I Need

All files I've uploaded — .md, PDFs, images, videos, code — visible in the same unified tree, not split between 'entries' and 'assets'

## So That

A universe really is a single home for all my content, not a markdown-only space with assets relegated to a separate API.

## Context

- **Principles:** §6 (folders encapsulate features — every file under one model), §1 (composition — assets become a kind of entry)
- **Scope:** Today entries (`GET /api/v1/universes/{slug}/entries`) returns rows from the `entries` table only. Assets (CO-145/146/147) live in a separate `assets` table per universe, accessed via `/assets/<sha>` endpoints.

Merge the two listings:
- Add an `entries` row for every asset upload (entry_type = `'asset.pdf' | 'asset.image' | 'asset.video' | 'asset.code' | 'asset.binary'`).
- The row stores the path (e.g. `attachments/foo.pdf`), mime type, asset_sha256 reference, and ts.
- The body column is empty/short metadata; the actual bytes stay in the `assets` table (deduplicated by SHA-256).
- Renderer dispatches by entry_type:
  - `page`, `task`, etc. → existing markdown view
  - `asset.pdf` → embed pdf.js viewer
  - `asset.image` → `<img>` with the encrypted-decrypt streaming endpoint
  - `asset.video` → `<video>` with HLS or direct mp4
  - `asset.code` → CodeMirror read-only view

Phase 1 (this task): backfill entries rows for existing assets; surface in entries API + tree; renderer supports PDF + image + video + code-read-only.

Phase 2 (CO-245): inline editing for plaintext file types via CodeMirror.

## Acceptance

- New migration creates entries rows for each existing assets row (paths under `attachments/`).
- Vault PUT accepts binary uploads as first-class entries; creates assets row + entries row in one transaction.
- `GET /api/v1/universes/{slug}/entries` returns asset entries by default (filterable via `?type=asset.*`).
- Frontend renders PDF (pdf.js), image, video, and code (CodeMirror RO) when clicking an asset entry.
- `content_count` aggregates across both — universe page count increases after asset upload.

## Blast radius

Large — adds asset upload to entries flow + 4 renderer dispatches + 1 migration. Phase 1 only; editing comes in CO-245.
