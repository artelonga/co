## As

A person arriving at CO for the first time (the concrete case: Miguel,
stakeholder of the `miguel` universe), I need onboarding documentation that
tells the story of the platform and shows the two everyday gestures — getting
a universe in/out, and shipping a change — so that I can participate without
first learning the internals.

## Scope (already written, uncommitted in the working tree)

- `docs/WELCOME.md` — new: history-teller onboarding in seven movements
  (the co- prefix as feature list, abstractions in arrival order, layers,
  five-act history, the inhabited neighbors, CRUD by worked example on the
  miguel universe, pointers). Includes "Bringing a universe with you — two
  doors": add a local folder (`offscholars` + `co push`) or clone from a
  remote (`git clone` of miguel, calendar + original entries).
- `docs/delivery-pipeline.md` — new section "The invariant — review on
  localhost, approve, merge": the three gestures mapped onto traditional git
  (branch → PR + preview → approval → merge ⇒ deploy) and CO-native/jujutsu
  (jj change → states → proposta + localhost serve → approval → mesclar /
  bookmark move ⇒ publish), with one worked example each.
- Links: `README.md` and `docs/README.md` point to WELCOME; WELCOME §7 points
  to delivery-pipeline.

## Given / When / Then

GIVEN a newcomer with no CO context, WHEN they read `docs/WELCOME.md` end to
end, THEN every command shown runs as written (`co push` flags per
`docs/universe-crud.md`; Vault API verbs per `vault_routes.rs`) and the
delivery-pipeline doc answers "how does my change reach production" in both
git and jj vocabularies.
