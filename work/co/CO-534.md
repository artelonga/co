GIVEN CO-525 chose to wire three external Python add-ons — **LlamaIndex** (the missing
ingestion pipeline + RAG), **DSPy** (offline prompt-compile, optimizes prompts, never
touches weights), and **RAGAS** (the eval gate CO lacks) — all as local services
behind the canonical contract (CO-503) via the HTTP invoker (CO-523),
WHEN we land them (compose > new code; manifest > binary),
THEN each enters as a `tools.d/` **manifest** (NOT MCP, NOT a fork) in the order
**ingest → compile → eval** — LlamaIndex feeds DSPy's optimization which RAGAS
measures — with **zero CO binary change**.

## Acceptance

- [ ] **Three manifests, no recompile.** `llama-index` (ingest/RAG, `predictive`,
  `input_schema: { query, k? }` and/or an ingest action), `dspy` (prompt-compile,
  offline), and `ragas` (eval-faithfulness gate) each added as a `tools.d/` manifest —
  **CO binary untouched** (CO-503 + CO-523).
- [ ] **Ordered ingest → compile → eval.** The manifests/docs make the pipeline order
  explicit: LlamaIndex ingests/retrieves → DSPy compiles a better prompt offline →
  RAGAS scores faithfulness as the quality gate.
- [ ] **External Python services, NOT MCP.** Each is reached as a plain local HTTP
  service / CLI through CO's native external-tool adapter — never via MCP
  (`feedback_no_mcp.md`).
- [ ] **Local-first.** All three run on one box (LlamaIndex index on disk under the
  universe; embeddings + RAGAS judge via local Ollama; DSPy is offline) — aligns with
  the CO-497 data-residency invariant; no cloud dependency in the default path.
- [ ] **Opt-in, degrades gracefully.** Registered only with external tools enabled
  (`CO_ENABLE_EXTERNAL_TOOLS=1` + trusted dir); an absent service is an unavailable
  tool, never a crash.
- [ ] CHANGELOG-PENDING/CO-534.md.
