## As
A universe owner who wants the content public as a site, not behind the CO board

## I Need
A `co construir <universe>` (build) that renders a universe's `content/` markdown into a
static digital-garden site via the redearte Quartz template, deployable at
`<slug>.artelonga.com.br`, while the interactive board stays gated at
`co.artelonga.com.br/<slug>`.

## So That
- Every universe gets a **public static site from its markdown** with no bespoke per-universe
  app (today: retro = hand-authored HTML, quilombo = SvelteKit).
- The wiki we interlink (map-of-content, `[[wikilinks]]`, graph via CO-394) renders as a
  static garden — Quartz does wikilinks/backlinks/graph natively.
- Board and site share one source (`content/*.md`): board via `co launch`/sync, site via
  `construir`.

## Context

See `docs/universe-public-site.md`. Today subdomains serve the SPA board; co-web has no
SSR/static render; static sites are bespoke apps. The generator already exists —
`redearte` is a Quartz instance — but nothing wires a universe's content into it.

## Design

### Phase 1 — build
- `co construir <universe> [--out public/]` — locate the universe's `content/` (same
  discovery as `co launch`), run the **redearte Quartz template** over it → static HTML.
- Quartz config derives site title/nav from `_universe.yaml`. Only published/public
  entries are included; `_source/` is excluded (it's not under `content/`).
- Output is a self-contained `public/` (HTML/CSS/JS, client-side graph).

### Phase 2 — deploy
- Per-universe Fly static app `artelonga-<slug>` mirroring `retro-umarizal/deploy/`:
  256 MB `shared-cpu-1x`, `gru`, static file server, no volume, cert for
  `<slug>.artelonga.com.br`.
- One-time: `fly apps create artelonga-<slug>`; `fly certs add <slug>.artelonga.com.br`.

### Phase 3 — routing split
- Point `<slug>.artelonga.com.br` DNS at the static app.
- Remove the slug from co-web's subdomain SPA routing (`server/subdomain_routing.rs`) so
  the subdomain is the site; the board remains at `co.artelonga.com.br/<slug>` (gated).

### First target
- `grcsamazonia`: build → deploy `artelonga-grcsamazonia` → `grcsamazonia.artelonga.com.br`;
  board at `co.artelonga.com.br/grcsamazonia`.

## Acceptance

- [ ] `co construir grcsamazonia` produces a static `public/` garden from `content/*.md`
- [ ] Wikilinks, backlinks, and graph render in the static output (no CO chrome, read-only)
- [ ] `_source/` PII and non-public entries are excluded from the build
- [ ] Deploy scaffold (`deploy/fly.toml` + Dockerfile) serves `public/` on `artelonga-<slug>`
- [ ] `<slug>.artelonga.com.br` serves the static site; `co.artelonga.com.br/<slug>` still serves the gated board
- [ ] Doc `docs/universe-public-site.md` reflects the shipped flow

## Blast radius

- New `co-cli` command `construir` (~150 LOC) + Quartz template integration (vendored or
  submodule of redearte)
- Per-universe `deploy/` scaffold (reuse retro's)
- Small edit to `subdomain_routing.rs` (skip site-mode slugs)
- 0 schema changes

## Not in scope

- Auto-rebuild on content change (manual `construir` for v1; watch is CO-51 territory)
- Migrating artelonga/quilombo off their existing bespoke sites (opt-in later)
- A server-side SSR reader mode (explicitly rejected in the doc in favor of Quartz)
