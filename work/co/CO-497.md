GIVEN data autonomy means two guarantees that must hold for everything in this
release:
  1. a user can **ALWAYS self-host** the whole thing (their data on their box,
     nothing required from our infra or any third party), OR
  2. they may **opt into managed infra** knowing their data is theirs, safe, and
     private — and we collect nothing (e.g. telemetry) without explicit consent
     under a **specific, versioned privacy policy** — including sensitive data
     (WhatsApp number, secrets) and identifying data (name, CPF) that a person
     chooses to keep as an instance-local variable,
WHEN we ship any component (transport, identity, consent, content, model),
THEN it must work fully self-hosted, and never transmit sensitive/identifying data
off the instance except by explicit, policy-bound, versioned consent.

## Acceptance

- [x] **WhatsApp transport works self-hosted (no Meta, no public webhook).** Every
  send (OTP, reply, greeting) goes through one cascade
  `notification_providers::whatsapp_provider_cascade()` — Cloud API (managed) →
  **Evolution** (self-host: QR-links your own WhatsApp, outbound-only, survives
  residential CGNAT). Inbound self-host arrives at the bridge `/webhook` (Evolution
  device push, no public port); managed arrives at co-web `/api/v1/whatsapp/webhook`.
- [ ] **Nothing in the per-user/identity/consent path hard-requires our infra or
  Meta.** Audit: per-user token store (local, encrypted), consent records (local),
  curated content (local universe), local model default — all run on one box.
- [ ] **Data residency — sensitive + identifying fields stay on the instance.**
  WhatsApp number, secrets/tokens, name, CPF are stored locally (encrypted at rest
  where applicable) and are **never** sent to our infra or any third party in the
  default path. A "local variable" stays local.
- [ ] **Managed-mode collection is separately consented.** Any data we collect on
  managed infra (e.g. telemetry, support diagnostics) is opt-in under its **own
  versioned policy** (distinct from the core-function consent, CO-491) — default OFF
  (mirrors `dados-rastreados.md` / Do-Not-Track). Define that policy before any
  managed collection ships.
- [ ] **Docs:** `docs/whatsapp-launch.md` → "Deployment modes" makes both paths
  first-class, with the self-host stack (Evolution + local Ollama + SQLite +
  encrypted secrets + Cloudflare Tunnel only if a public domain is wanted).

## Notes
- Aligns with the existing self-host posture: AGPL, `universe = any local folder`,
  the thin-binary + delta-sync distribution, and `infra/SELF-HOST-SECURITY.md`
  (LAN-only firewall, kill-switch, integrity). This task keeps the WhatsApp release
  inside that envelope.
- Cloudflare Tunnel / launchd / Litestream / UPS are the *operator's* self-host ops
  choices (public domain, autostart, live backup, power) — documented, not required
  by the app. Evolution needs none of them for a private/LAN deploy.
