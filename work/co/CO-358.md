## As

a phone or tablet user holding CO in one hand

## I Need

the SPA to actually be designed for a small screen — drawer sidebar, collapsible breadcrumbs, single-column board, card-view tables, full-screen modals, 44 px touch targets — instead of a desktop layout shrunken to 360 px wide.

## So That

CO is usable on the device most people read on. Today the sidebar is hidden or always-pushed-off-canvas with no clean affordance, breadcrumbs wrap to three lines, the kanban board horizontally scrolls inside a vertically scrolling page (terrible UX), tables overflow to the right, modals float at 320 px wide on a 360 px viewport. Mobile users bounce.

## Context

Most e2e specs skip mobile (`test.skip(!!(vp && vp.width <= 640))` appears in 8+ files), implicitly admitting the mobile UX isn't ready. This ticket fixes it; CO-359 then re-enables those skipped tests.

Today's state:
- Sidebar wire module: `/Users/artelonga/projects/co/co-web/static/variants/a/modules/sidebar/wire.js` — has an overlay/off-canvas mechanism but no consistent trigger.
- Breadcrumbs (CO-280) render full path even at 320 px.
- Board view: 3-column kanban with horizontal scroll inside a vertical-scroll page.
- Tables: native `<table>` overflow-x scrolling.
- Modals: fixed-width floating dialogs.
- Hit areas: many buttons under 32 px (e.g. tag chips, breadcrumb separators).

Reference for sizing: Apple HIG (44×44 pt minimum), Material Design (48 dp).

## Design

### 1. Breakpoints (CSS variables)

In `/Users/artelonga/projects/co/co-web/static/variants/a/style.css`, define:

```css
:root {
  --bp-mobile: 640px;
  --bp-tablet: 900px;
  --touch-target: 44px;
}
```

Use `@media (max-width: 640px)` consistently.

### 2. Sidebar → off-canvas drawer (< 640 px)

Edit `/Users/artelonga/projects/co/co-web/static/variants/a/modules/sidebar/wire.js`:

- Add hamburger button in header (visible only at `≤640px`). Tap toggles `body[data-sidebar="open"|"closed"]`.
- CSS: at `≤640px`, sidebar becomes `position: fixed; left: -100%; transition: left 0.2s` and slides to `left: 0` when open. Backdrop overlay (existing) gets `pointer-events: auto` on open.
- Swipe-from-left-edge (start-x < 20px, deltaX > 60px) opens the drawer. Swipe-right-on-drawer closes it. Reuse any touch-gesture helper already present; otherwise inline ~40 lines of touchstart/touchmove/touchend.
- Tap-outside (on overlay) closes. ESC closes (keyboard).
- Trap focus inside drawer while open (a11y).

### 3. Breadcrumb collapse (< 480 px)

In the breadcrumbs module (find under `/Users/artelonga/projects/co/co-web/static/variants/a/modules/`):

- At `≤480px`, render only: `← <current-page-title>`.
- Tap the back-arrow → navigate to parent (existing behaviour).
- Tap the title → opens a popover showing the full trail (click any segment to navigate).

### 4. Board (kanban) → single-column reflow (< 640 px)

Find the board module (likely `/Users/artelonga/projects/co/co-web/static/variants/a/modules/board/` — confirm). Add responsive guard:

- At `≤640px`, columns stack vertically instead of side-by-side. Each column is a full-width section with its own collapse toggle.
- Active column persists in `localStorage` (`co.board.mobileActiveColumn = 'doing'`).
- A small segmented control at the top lets the user switch active column without scrolling.
- Drag-and-drop still works (long-press to grab on touch); if too fiddly, fall back to a "Move to →" menu per task (already exists as fallback elsewhere).

### 5. Tables → card view (< 640 px)

For every `<table class="entries-table">` (or equivalent), add a CSS-only transformation: at `≤640px`, hide `<thead>`, render each `<tr>` as a stacked card using `display: block` and pseudo-elements for label/value. Use existing `data-label="…"` attribute on cells (add if missing).

### 6. Modals → full-screen (< 640 px)

In modal CSS / `modals/wire.js`:

- At `≤640px`, modal takes `100vw × 100vh`, no border-radius, with a sticky header containing the close button (top-right, 44×44 hit area).
- The feedback widget (CO-333) already bottom-sheets on mobile; keep that pattern.

### 7. Touch targets

Audit every `button`, `a.btn`, `.chip`, `.tag`, `.tab` inside the SPA. At `≤640px`:

```css
@media (max-width: 640px) {
  button, .btn, .chip, .tag, .tab, .nav-item {
    min-width: var(--touch-target);
    min-height: var(--touch-target);
  }
}
```

For inline chips that legitimately need to be smaller, wrap them in a 44 px hit-area padding via `::before` overlay.

### 8. Header reflow

Header logo + universe-switcher + theme picker + language toggle + user badge — at `≤640px`, collapse all but logo + hamburger + user badge into an overflow menu (kebab). Universe switcher becomes a top-of-drawer entry inside the sidebar.

### 9. Safe areas

Add `viewport-fit=cover` (covered by CO-357) + CSS env() padding for iOS notch:

```css
header { padding-top: env(safe-area-inset-top); }
.bottom-sheet { padding-bottom: env(safe-area-inset-bottom); }
```
