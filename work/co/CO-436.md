## As
Yggdrasil (e qualquer consumidor: CLI, mobile, runtime embarcado), QUERO
implementar o `Plugin` do `game-core` sem arrastar `axum`, PARA reusar o engine
de jogo em contextos sem HTTP. E o dev do co quer `migrations.rs`/`seed.rs`
fatiados para serem navegáveis.

## Contexto técnico (do audit 2026-06-12)
- `game-core/src/plugin.rs`: `trait Plugin { fn routes(&self) -> axum::Router; }`
  — `axum` é dependência **não-opcional** do game-core (Cargo.toml). Todo impl de
  jogo paga Axum mesmo sem precisar de HTTP. Yggdrasil hoje contorna ignorando o
  trait Plugin.
- `co-web/src/storage/migrations.rs` = 2769 LoC (um arquivo, todas as versões);
  `seed.rs` = 2530 LoC misturando dados de seed com a camada de acesso a dados.

## Acceptance
- [ ] `Plugin` deixa de retornar `axum::Router`. Trocar por um descritor
      portável (`Vec<RouteDescriptor { path, method, handler-id }>` ou similar)
      que o co-web traduz para axum no seu lado. `game-core` compila **sem axum
      na árvore de deps** (`cargo tree -p game-core | grep axum` vazio).
- [ ] Os jogos atuais (snake/tetris/invaders/poker) e o registro de plugin
      continuam funcionando via a tradução no co-web; `cargo test -p game-core
      -p co-web` verde.
- [ ] `migrations.rs` fatiado: versões em `storage/migrations/` (um módulo por
      faixa de versão, ou um por versão a partir do v75), com o runner agregando.
      Nenhum arquivo de migração > 500 LoC. **Protocolo de claim de versão
      intacto** (não renumerar nada existente).
- [ ] `seed.rs` movido para o caminho de boot (`server/`), separado da camada de
      storage; storage não depende mais de dados de seed.
- [ ] **Zero mudança de comportamento**: schema final idêntico (mesma sequência
      de migrações aplicada), seed idêntico; `cargo test` verde; clippy limpo.

## Notas
Desbloqueia reuso real do game-core fora do co-web (a metade "external services"
do epic). O fatiamento de migrations é mecânico mas sensível — testar que um DB
fresco e um DB existente chegam ao mesmo schema_version.
