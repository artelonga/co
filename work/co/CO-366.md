## As
A brain owner who has registered on CO and wants to upgrade from anonymous/free to paid (own domain, unlimited storage, priority sync)

## I Need
A single CTA at register-success that opens a Hostinger checkout flow, plus a webhook that flips my `users` row to `tier: paid` on payment success.

## So That
- The BaaS thesis's `t_register → t_payment` conversion KPI exists end-to-end (today it's just designed).
- Public launch can charge the first interested brain owner without infra rebuild.
- The integration choice (Hostinger today, Stripe / Pix / others tomorrow) lives behind a trait so we don't lock in.

## Context

§5 + §8 of `ArteLonga/docs/brain-as-a-service.md` identifies conversion/payment wiring as the explicit open gap. Hostinger has a quick payment integration the user has prior experience with — fastest path to MVP. Long-term, Pix (zero-fee Brazilian instant payment) + Stripe (international cards) live as future providers.

CO has identity (`users` table), but no `tier` enforcement today beyond placeholder field. Per CO-90 (deferred): no global admin tier; tier is billing-only. This spec ships the billing-only enforcement.

## Design

### Provider trait

```rust
// co-web/src/billing/mod.rs
#[async_trait]
pub trait BillingProvider: Send + Sync {
    /// Create a checkout session for a user; returns the URL to redirect to.
    async fn create_checkout(&self, user_id: &str, plan: Plan) -> Result<CheckoutSession>;

    /// Verify a webhook payload signature.
    fn verify_webhook(&self, payload: &[u8], signature: &str) -> Result<WebhookEvent>;

    /// Provider name for telemetry.
    fn name(&self) -> &'static str;
}

pub struct CheckoutSession {
    pub url: String,
    pub session_id: String,
    pub expires_at: DateTime<Utc>,
}

pub enum WebhookEvent {
    PaymentSucceeded { user_id: String, plan: Plan, amount_cents: u64 },
    PaymentFailed { user_id: String, reason: String },
    SubscriptionCanceled { user_id: String },
}
```

Migration **v77** adds `tier_paid_at` + `tier_plan` to `users`:

```sql
ALTER TABLE users ADD COLUMN tier_paid_at TEXT;       -- ISO timestamp
ALTER TABLE users ADD COLUMN tier_plan TEXT;          -- 'free' | 'starter' | 'pro' | 'enterprise'
ALTER TABLE users ADD COLUMN billing_provider TEXT;   -- 'hostinger' | 'manual' | ...
ALTER TABLE users ADD COLUMN billing_external_id TEXT; -- provider's customer/subscription id
```

New `billing_events` table for audit:

```sql
CREATE TABLE billing_events (
    id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    event_type TEXT NOT NULL,  -- 'checkout_created', 'payment_succeeded', ...
    provider TEXT NOT NULL,
    payload_json TEXT,
    created_at TEXT NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### Endpoints

- `POST /api/v1/me/billing/checkout` — body `{ plan: "starter" }` → returns `{ url, session_id }`
- `POST /api/v1/billing/webhook/{provider}` — receives provider webhooks (Hostinger first), verifies signature, updates user tier, writes billing_event
- `GET /api/v1/me/billing/status` — returns current `{ tier, plan, paid_at, billing_provider }`
