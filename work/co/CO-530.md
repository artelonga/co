GIVEN the template IS the software and universes ARE use-cases — the `co` binary
must be constructible, distributable, and e2e-testable with **zero universe
examples**; content (comunicacao, quilombo, ArteLonga, the topology corpus) is a
**runtime add-on** (subscription / CO-503 manifest / portable artifact), never a
build/test/distribution prerequisite,
WHEN we build, e2e-test, or ship the template,
THEN it must succeed in a clean environment with **no content repos present** — and a
CI guard must enforce that so the property holds by construction, not by vigilance.

## Acceptance

- [ ] A CI job **builds + runs e2e on the template in a clean environment with NO content repos on disk** (no `~/projects/<content-repo>`, no sibling trees) — and **fails** if the template needs any of them. This is the enforcement.
- [ ] Sister-repo boot seeding (CO-317: `~/projects/<repo>` → universes) is **dev-only** (gated behind a dev flag), removed from the distributable template path; the shipped template seeds at most a **generic** example universe (or nothing).
- [ ] e2e uses **only ephemeral synthetic fixtures** (create-universe / add-entry / run-tool against a throwaway test universe) — never a real content universe.
- [ ] `examples/` and any tenant content are excluded from the build/test graph.
- [ ] Links the prerequisite-class violations: CO-509 (de-embed `universes/quilombo`) and CO-528 (topology as a runtime artifact, not a sibling-tree build dep).
- [ ] CHANGELOG-PENDING/CO-530.md.

## Notes
- The acceptance test for the whole composability direction (CO-503): if the binary
  can't build/ship/e2e in a clean room, it isn't a template yet. See
  [[feedback_template_zero_universe_examples]].
- Generic seed universes (Design System / Backend API / Platform) are fine — they are
  *generic examples baked as a demo*, not a specific tenant; the violation is
  tenant/content coupling (quilombo) and **reaching into local content repos** at
  boot/build.
