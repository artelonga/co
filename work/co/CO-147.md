## As

a user wanting to find / browse / filter assets in a universe without downloading them all

## I Need

a list endpoint that returns *only* metadata (sha256, mime, size, filename, tags, created_at), filterable by mime prefix, tag, date range, and a tags table that links assets to user-supplied tags

## To

power an asset browser UI and enable client-side search without leaking byte content

## Implementation

### Migration

```sql
CREATE TABLE IF NOT EXISTS asset_tags (
    sha256  TEXT NOT NULL,
    tag     TEXT NOT NULL,
    PRIMARY KEY (sha256, tag),
    FOREIGN KEY (sha256) REFERENCES assets(sha256) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_asset_tags_tag ON asset_tags(tag);
```

### Endpoints

```
GET /api/v1/universes/{u}/assets
    ?type=image/*           (mime prefix glob)
    ?tag=foo
    ?since=2026-01-01
    ?cursor=<sha>
    ?limit=100
    → { items: [{sha256, mime, size, filename, tags, created_at}], next_cursor }

POST /api/v1/universes/{u}/assets/{sha256}/tags
     Body: ["tag1", "tag2"]
     → 204

DELETE /api/v1/universes/{u}/assets/{sha256}/tags/{tag}
     → 204

GET /api/v1/universes/{u}/assets/tags
    → [{ tag, count }] sorted by count desc
```

### Refcount maintenance

`upsert_entry_row` scans the body for `![alt](path)` and `<img src="path">` references. Each path that matches `assets/<sha256>` (or a relative path resolving to one) increments the asset's refcount. Removed references decrement on next upsert.

Background GC (nightly): rebuild refcounts by scanning all entries; reconcile.

### Frontmatter index

Phase 2 also extracts indexable plaintext from markdown `entries.content` into a `frontmatter` shadow table:

```sql
CREATE TABLE IF NOT EXISTS frontmatter_index (
    entry_id    TEXT PRIMARY KEY,
    title       TEXT,
    entry_type  TEXT,
    status      TEXT,
    tags_json   TEXT,
    created_at_ns INTEGER,
    due_at_ns   INTEGER,
    parent_path TEXT,
    -- whatever else CO-86 typed Frontmatter declares
    FOREIGN KEY (entry_id) REFERENCES entries(id) ON DELETE CASCADE
);
```

This is the **searchable metadata** that survives encryption in Phase 3. It's a deliberate copy from the (Phase 1 plaintext, Phase 3 ciphertext) body.

## Acceptance

- [ ] `GET /api/v1/universes/{u}/assets?type=image/*` returns image-only rows
- [ ] `GET .../assets?tag=foo` returns tag-filtered rows
- [ ] `GET .../assets/tags` returns tag counts
- [ ] `POST .../assets/{sha}/tags` adds tags; reflected in next list
- [ ] `entries.upsert` increments refcount for each `![](sha256:...)` reference
- [ ] Nightly GC rebuilds refcount and matches a fresh count
- [ ] Frontmatter index populates on every entry upsert
