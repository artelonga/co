GIVEN we ship 5-15 deploys a day during the public-test window, AND the past several "loading forever" / "modern theme not sticking" / "404 on private universe" regressions only surfaced through manual testing by yuri, AND every silent regression that reaches a real user erodes trust we can't easily restore,
WHEN we add a one-shot bash smoke script that exercises the post-deploy invariants (health, the timeline trio shape, login form reachability, theme.css for known presets) and exits non-zero with a clear diagnostic on any miss,
THEN every deploy ends with `bash scripts/smoke-prod.sh && echo OK || rollback` and humans only look at the output when something is actually wrong.

## Scripts

### `scripts/smoke-prod.sh`

Defaults `BASE_URL=https://co.artelonga.com.br` (override via env). Runs the checks listed below, prints `OK` on full pass, prints failures + exits 1 on any miss.

### `scripts/smoke-uat.sh`

Same shape, defaults to `BASE_URL=https://co-artelonga-uat.fly.dev`. Recommended invocation from CI / pre-prod-deploy gate.

### Shared library `scripts/smoke-lib.sh`

Common helpers: `check_status`, `check_json_field`, `check_count`. Sourced by both.

## Checks (in order)

1. **Health is OK.** `GET /api/health` returns 200 with `status=ok` and a `version` field. Print the version.
2. **Health-deep is OK.** `GET /api/health/deep` returns 200 (CO-103-companion). DB read + write + disk all green.
3. **Template universe present.** `GET /api/v1/universes/template` returns 200 with `name`.
4. **Timeline trio present and shaped.** For each of `tempo`, `humanity`, `universo`:
   - `GET /api/v1/universes/<key>` returns 200 with `parent_key=template` (after CO-98) and `visibility=public-static`.
   - `GET /api/v1/universes/<key>/entries?type=event` has the expected event count: tempo=21, humanity=26, universo=28. (Counts pinned in the smoke script — when the seed grows we update both together.)
5. **Themes endpoint live.** `GET /api/v1/themes/modern` returns 200 with content-type `text/css`. Body contains `--accent: #6366f1`.
6. **Static assets reachable.** `GET /` returns 200 + content-type `text/html`. `GET /app.js` returns 200 + content-type `application/javascript`. `GET /shared/timeline.html` returns 200.
7. **Service worker is the network-first one.** `GET /sw.js` body contains `co-v3-network-first` (or whatever the current CACHE_NAME is — pinned in the script).
8. **Login endpoint reachable** (does NOT require valid credentials). `POST /api/v1/auth/password-login` with bogus body returns 401 (NOT 5xx, NOT timeout). This catches "JWT_SECRET missing" / "DB connection broken" without exposing real auth.
9. **Conteúdo view loads.** `GET /api/v1/universes/template/entries` returns 200 with `total >= 14` (template tasks + pages).
10. **Static-favicon present.** `GET /favicon.svg` returns 200.

## Diagnostic output format

For each check, print one line:
```
✓ [01] /api/health → 200 (version 1.21.1)
✗ [04] /api/v1/universes/tempo/entries?type=event expected 21, got 19  ← FAIL
```

On any failure, print a footer with `--- FAILED ---` and exit 1. On full pass, print `--- ALL CHECKS PASSED ---` and exit 0.

## Pinning event counts

The expected counts (21/26/28) are pinned at the top of `smoke-prod.sh` as variables:

```bash
EXPECTED_TEMPO_EVENTS=21
EXPECTED_HUMANITY_EVENTS=26
EXPECTED_UNIVERSO_EVENTS=28
EXPECTED_SW_CACHE_NAME='co-v3-network-first'
```

When the seed JSON is edited (adding / removing events), the smoke script is updated in the **same commit** as the JSON change. CHANGELOG entries should mention this.

## Constraints

- Pure bash + curl + python3 (already required by other scripts). No jq dependency.
- No auth required — only public endpoints + bogus-body login probe.
- Total runtime ≤ 30 seconds.
- Output is grep-friendly so a CI job can detect failure without parsing.

## Acceptance

- [ ] Two scripts at `scripts/smoke-prod.sh` and `scripts/smoke-uat.sh` plus the shared `scripts/smoke-lib.sh`.
- [ ] Each is executable (`chmod +x`).
- [ ] Running against current prod (1.21.1) exits 0.
- [ ] Running against a deliberately broken target (e.g. wrong `BASE_URL`) exits 1 with clear failure lines.
- [ ] At least one of the checks (#4, the event count pin) is verified to actually fire — author runs the script, deletes one event from the local seed, builds, deploys to UAT, runs `smoke-uat.sh`, confirms it fails on check 4 with the right message, then restores.
- [ ] `docs/OPERATIONS.md` references this script under "Smoke test post-deploy".

## Out of scope

- Authenticated smoke checks (separate ticket, requires test account).
- E2E browser-based smoke (Playwright; that's the heavier regression suite).
- Performance smoke (k6 — see CO-101).
