## As

A visitor (anonymous or logged-in) browsing a public universe they have not subscribed to (e.g. visiting `/co` while logged in but not a member, or visiting `/artelonga` anonymously)

## I Need

To be able to **read** the universe content immediately — same surface anonymous users get — and when I attempt any CRUD action, be prompted with:

- **Logged-in user**: "**Inscrever-se nesse universo**" (CTA button → on click, adds universe to user's subscribed list + reloads with full access)
- **Anonymous user**: "**Faça login para se inscrever**" (CTA button → opens login modal; after login, prompts again to subscribe)

All copy in **Portuguese** (with English equivalents in i18n).

## So That

Public universes have a **discoverable read path** for anyone (no friction), but writes are gated by an explicit "I want this in my list" subscribe action. Removes the current confusion where unsubscribed users either see 401s or are auto-redirected away.

## Context

- **Today**: visiting `/<universe>` when not a member of that universe either redirects, shows a partial view, or 401s depending on the route. CRUD endpoints uniformly return 401 with no UX explanation.
- **Why now**: directly tied to user feedback "accessing a universe which you werent subscribed will show universe as if you were in anonymous, non logged user (read only) and crud prompts to 'Subscribe' for logged users".
- **Subscribe semantics**: adds universe to user's `universe_members` table with role `subscriber` (read+write). Different from `owner` or `admin`. Already exists per CO-198 chat-room-members backfill notes; reuse the same surface.

## Scope

- **SPA**:
  - `state.canEditCurrentUniverse` derived from `state.me` + `state.universeInfo.is_public` + membership check.
  - All CRUD entry points (`+ Nova Tarefa`, edit, drag-status-change, delete, vault PUT) check `canEditCurrentUniverse` first — if false, open a new `subscribePrompt()` modal instead of executing.
  - Modal copy:
    - Logged-in: "Para criar/editar conteúdo neste universo, inscreva-se primeiro." + button "Inscrever-se nesse universo".
    - Anonymous: "Para criar/editar conteúdo, entre na sua conta." + button "Entrar" (opens login modal; after login, re-shows subscribe prompt).
- **Backend**:
  - New endpoint: `POST /api/v1/universes/<slug>/subscribe` — auth required, inserts caller as `subscriber` in `universe_members`. Idempotent: returns 200 if already subscribed.
  - Read endpoints (`GET /entries`, `GET /entries/<path>`, `GET /projects`, etc.) — verify they all return 200 for anonymous on `is_public` universes. If not, fix.
- **i18n**:
  - `subscribe.prompt.logged_in`: "Para criar/editar conteúdo neste universo, inscreva-se primeiro."
  - `subscribe.cta`: "Inscrever-se nesse universo"
  - `subscribe.prompt.anonymous`: "Para criar/editar conteúdo, entre na sua conta."
  - `subscribe.login_cta`: "Entrar"
  - EN equivalents.

## Acceptance

- Anonymous user at `/co` can read all entries, see the project board, click on tasks, view markdown.
- Anonymous user clicking `+ Nova Tarefa` → modal shows "Para criar/editar conteúdo, entre na sua conta." + "Entrar" button.
- Logged-in user at `/artelonga` (not a member) can read all entries.
- Logged-in user clicking `+ Nova Tarefa` → modal shows "Para criar/editar conteúdo neste universo, inscreva-se primeiro." + "Inscrever-se nesse universo" button.
- Clicking "Inscrever-se" → POST `/api/v1/universes/artelonga/subscribe` → universe appears in user's `meUniverses.subscribed` bucket → sidebar re-renders → CRUD now works.
- New Playwright spec `e2e/unsubscribed-access.spec.ts` covers both paths.

## Blast radius

- ~200 LOC SPA: shared `subscribePrompt()` modal + per-CTA guard at entry points + i18n strings.
- ~80 LOC backend: new `POST /subscribe` route + idempotency + `universe_members` insert.
- No schema changes (`universe_members` already exists).
