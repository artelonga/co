## What this slice does

Edits each low-traffic Fly app's `fly.toml` to enable `auto_stop_machines = "suspend"` + `min_machines_running = 0`. Idle machines suspend after 5min, cold-wake in ~250ms on next request. Saves ~$5/mo with no UX regression for the targeted apps (none has long-lived WebSocket connections).

Per CO-281 Phase 0 baseline (PR #94), targets are:

- **quilombo-araucaria** — KEEP 2GB RAM (justified by video-upload OOM), but flip min=1→0 + auto-suspend (~$10-12/mo idle savings)
- **yggdrasil** — shared-1x 512MB, flip to suspend (~$1-2/mo savings)
- **rfq** (artelonga-rfq-gateway) — has no `[[vm]]` block (default 256MB), highest-ROI single-line edit (~$1.50/mo savings)

## Scope

Edit fly.toml files in each repo:

- [ ] `~/projects/quilomboaraucaria/fly.toml` — add `auto_stop_machines = "suspend"`, `min_machines_running = 0`. Keep `[[vm]] memory_mb = 2048`.
- [ ] `~/projects/yggdrasil/fly.toml` — same auto-suspend + min=0
- [ ] `~/projects/rfq-gateway/fly.toml` (artelonga-rfq-gateway) — same auto-suspend + min=0

Per-app: open a PR in each repo with just the fly.toml diff + a CHANGELOG entry. Deploy. Verify: stop sending traffic for 10 min, confirm machine suspends via `flyctl status`; then curl `/api/health`, confirm 250ms wake-up.

co-artelonga is **NOT** in scope (has long-lived WebSockets — needs always-on).

## Acceptance

- [ ] 3 PRs open (one per repo)
- [ ] After deploy, each app's `flyctl status` shows `state=suspended` after 10 min idle
- [ ] `curl /api/health` on each app returns 200 within ~1s of cold-wake
- [ ] No user reports of slow first-request after 48h observation
- [ ] If any app shows wake-up regression, revert that single fly.toml (Phase 1 is reversible per-app)
