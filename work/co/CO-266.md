## As

Anonymous (or unsubscribed) visitor browsing `/co` or any other public universe

## I Need

The entries LIST endpoint to return both `total` AND `items` correctly when entries are visible to me — not just count them.

## So That

When the SPA renders the conteúdo/kanban view, the list query returns entries instead of `items: []`. Today (v2.25.0):

```
GET /api/v1/universes/co/entries?path_prefix=public/&limit=3
→ { total: 3, items: [] }
```

The `total: 3` proves the entries ARE visible at the visibility-gate level. The empty `items: []` proves a SECOND filter is being applied after the count is computed.

## Hypotheses

Looking at `co-web/src/content/entry_routes.rs::list_entries`:

1. **Visibility gate runs twice**: once for the COUNT subquery (correct → 3), once for the items SELECT (filtered to 0). Different WHERE clauses.
2. **Items filter is over-strict**: a separate filter (maybe `is_template = 0` AND `is_draft = 0` AND `published_at IS NOT NULL`) is applied only to items, not to count.
3. **Pagination off-by-one**: `LIMIT 3 OFFSET 0` somehow misaligned — but offset=0 should return rows 0,1,2.
4. **ORDER BY problem**: if ORDER BY is on a column that's NULL for these rows, they may be excluded.

## Scope

- Read `list_entries` carefully. Identify why count + items diverge.
- Likely fix: ensure the items SELECT and the count COUNT(*) use **identical** WHERE clauses.
- If a separate filter is justified for the items (e.g., "draft entries aren't surfaced"), make it explicit AND apply it to the count too — discrepancy is the bug, not the filter itself.

## Acceptance

- `GET /api/v1/universes/co/entries?limit=3` (anonymous) returns `total > 0 AND items.length > 0`
- `GET /api/v1/universes/co/entries?path_prefix=public/&limit=3` returns 3 items if 3 entries match
- The SPA's conteúdo view on `/co` shows entries instead of "no content"
- New integration test asserts: after seeding N entries, `list_entries` returns `total = N` AND `items.length = min(N, limit)`

## Blast radius

- ~20 LOC in `list_entries` (entry_routes.rs)
