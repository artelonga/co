### What CO-268 did

Looking at the merge commit `720cebb`:

> `fix(visibility): CO-268 — skip public/ path filter for public-subscribable universes (#86)`

CO-268 changed the count to skip a path filter. It didn't touch the items pipeline at a deeper layer.

### Where items get filtered to empty

Hypotheses, ranked by likelihood:

1. **Per-row Rust ACL filter** in the response builder. SQL returns rows, then `items.into_iter().filter(|e| can_view(e, ctx))` strips them. Anonymous context = filter returns false for every row.
2. **`require_universe_member` middleware** on the items route (not on count). Anonymous sees count for free but the items handler short-circuits.
3. **Response shape divergence**: items SELECT uses `LEFT JOIN universe_members` and only returns rows where the join matches. Anonymous → 0 rows.

The chain to read in order:
1. `co-web/src/server/router.rs` — `list_entries` route registration. Is it wrapped in `require_universe_member`?
2. `co-web/src/content/entry_routes.rs::list_entries` — final handler. After SQL, does it iterate + filter?
3. `co-web/src/auth/visibility_gate.rs` (or wherever the gate lives) — find the gate function. Does it have an early-exit `Vec::new()` for anonymous?

### Probe to run before writing code

```sql
-- in fly ssh:
sqlite3 /data/universes/co/entries.db
SELECT COUNT(*) FROM entries;
-- expect 1173
SELECT path, entry_type, body IS NOT NULL as has_body FROM entries WHERE path LIKE 'public/%' LIMIT 3;
-- if this returns 3 rows: SQL is fine, problem is in Rust layer
```

## Scope

1. Run the SQL probe above (or replicate locally) to confirm where the filtering happens.
2. Read the three files in the chain. Identify the silent-empty wrapper.
3. Fix it: either remove the over-strict gate for public-subscribable universes, OR apply the same gate to the count query so the divergence stops.
4. Add integration test: anonymous GET → `total > 0 AND items.len() > 0`.
5. Add e2e Playwright test: visit `/co` anonymously, assert at least one entry card renders in the kanban view.
