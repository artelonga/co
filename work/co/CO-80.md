GIVEN current rate limit is a flat 60 req/min per token (CO-35), and at scale we need per-tier limits + per-operation limits + per-universe quotas to prevent abuse and enable tiered pricing,
WHEN we add token bucket rate limiting with tier-aware budgets and storage/compute quotas,
THEN the platform protects itself against spikes and supports clear free / paid tier definitions.

## Architecture

- Token buckets stored in Redis (or in-process for v1): per `(user_id, operation_class)`
- Tiers: `anonymous`, `user`, `pro`, `admin` — declared in code, enforced in middleware
- Operation classes: `read`, `write`, `doc_gen`, `sync`, `search`
- Per-universe quotas: storage (entries × avg size), compute (doc-gen runs), bandwidth (egress)
- Quota enforcement: 80% warning, 100% reject with explanatory error

## Tier limits (proposal)

| Tier      | Reads/min | Writes/min | Doc-gen/hr | Storage cap | Universes |
|-----------|-----------|------------|------------|-------------|-----------|
| Anonymous | 20        | 5          | 0          | 100 entries | 1 (auto-clone) |
| User      | 200       | 60         | 5          | 10K entries | 10        |
| Pro       | 2000      | 600        | 50         | 1M entries  | unlimited |
| Admin     | unlimited | unlimited  | unlimited  | unlimited   | unlimited |

## Tasks

- [ ] Token bucket implementation (Redis ZINCRBY pattern or in-process)
- [ ] Middleware: extract tier from JWT/token, check + decrement bucket
- [ ] Quota tracking: counters in `meta.db` for storage/compute, updated on writes
- [ ] Quota check on universe create + entry write
- [ ] HTTP 429 with `Retry-After` header on rate limit
- [ ] HTTP 402 with body explaining quota exhaustion
- [ ] Admin override: `X-Admin-Override-Quota` header bypasses (audit logged)

## Scale notes

- Token bucket with Redis: ~1ms overhead per request
- In-process token bucket: ~10ns overhead but doesn't share across replicas (acceptable for v1)
- Quota counters update on every write; batch-flush to DB every 100 writes to reduce contention
- Tier upgrade flow: admin endpoint sets tier on user; takes effect on next token issuance

## Acceptance

- Anonymous user gets 429 after 20 reads/min
- Pro user can make 2000 reads/min without throttle
- Storage quota exhaustion returns 402 with usage details
- Admin override bypasses with audit log entry
