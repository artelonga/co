GIVEN CO-1 through CO-48 were implemented incrementally with evolving requirements, and the new architecture (CO-49–CO-56) introduces universe-as-repo, subscriptions, and CLI sync,
WHEN I audit existing implementations for compatibility gaps,
THEN:

## Known Incompatibilities

### 1. Universe visibility model
- **Current:** `is_public`, `is_template`, `requires_login` as separate booleans
- **New (CO-49):** Single `visibility` enum: `template`, `private`, `public`, `public-subscribable`
- **Migration:** ALTER TABLE, backfill from existing flags, remove old columns

### 2. Project key collision
- **Current:** Template and user boards can both have project key `CO`
- **Fixed in latest deploy:** User boards get `{SLUG}P` keys
- **Verify:** No cross-universe task leaks in the entries API

### 3. Auto-clone on visit
- **Current:** Removed (anonymous see template read-only)
- **New:** Confirmed correct — anonymous never get clones, login creates personal community
- **Verify:** No orphaned `u-*` or `anon-*` universes created

### 4. Entry abstraction vs legacy task API
- **Current:** Two code paths — `/api/projects/:key/tasks` (legacy) and `/api/v1/universes/:slug/entries` (new)
- **New:** Need to deprecate legacy path or ensure both return identical data
- **Migration plan:** Phase out legacy routes in v1.3

### 5. Theme engine vs palette switcher
- **Current:** `applyUniverseConfig` loads server theme.css, `experiment.js` manages palette localStorage
- **Conflict:** User palette override removes server theme on click
- **Fix needed:** Palette switcher should MODIFY the universe config, not override with localStorage

### 6. CRDT (Yjs) vs sync
- **Current:** Yjs CRDT for real-time collaborative editing (CO-31)
- **New:** CLI sync uses REST API (eventual consistency)
- **Compatibility:** CRDT handles real-time (web), sync handles offline (CLI). Both write to same entries table. CRDT writes on idle → entry update → sync detects change via hash. No conflict as long as CRDT flushes before sync pulls.

### 7. Obsidian plugin vs CLI sync
- **Current:** co-obsidian plugin syncs via Vault API
- **New:** CLI sync also uses Vault API
- **Compatibility:** Both use same API, same hash-based change detection. Running both simultaneously could cause duplicate pushes. Fix: use lockfile or last-push-wins.
