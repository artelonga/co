## As

a CO operator

## I Need

Cloudflare in front of `co.artelonga.com.br` with cache rules that respect static-asset extensions, bypass `/api/*`, and never cache responses carrying `Set-Cookie: session=`

## To

reduce origin load and improve global TTFB for static surfaces (theme.css, JS bundles, images) **without** breaking auth, without rewriting the Fly origin, and without introducing a second source of truth for routing

## Given / When / Then

GIVEN `co-web` runs on Fly behind a wildcard cert at `co.artelonga.com.br`,
WHEN we point the apex through Cloudflare with proxied A records and configure Page Rules / Cache Rules per the spec below,
THEN static assets return `cf-cache-status: HIT` after warmup, `/api/*` returns `BYPASS`, and `Set-Cookie: session=...` responses are never cached.

## Cache rule spec

| Path | Cache behavior | Edge TTL | Notes |
|------|----------------|----------|-------|
| `/theme*.css`, `/themes/*.css` | Cache everything | 1h | Theme CSS uses content-hash query suffix already |
| `/static/*`, `/_app/immutable/*` | Cache everything | 1y | SvelteKit immutable bundle |
| `/*.png`, `/*.svg`, `/*.webp`, `/*.avif` | Cache everything | 1d | |
| `/api/*` | Bypass cache | — | All API responses |
| `/api/v1/auth/*` | Bypass cache | — | Auth endpoints (defensive duplicate) |
| `/` (HTML) | Cache by status, respect origin TTL | 60s | Short TTL; ISR-like behavior |

Origin must continue to send `Cache-Control: private, no-store` on auth responses.

## Acceptance

- [ ] DNS migrated to Cloudflare with proxy enabled
- [ ] Cache rules applied per spec, verified with `curl -I` for each path class
- [ ] Auth flow (UAT login on prod): `password-login` returns `Set-Cookie` and is not served from cache on subsequent identical requests from another IP
- [ ] No Fly origin changes required (zero risk to current deploys)
- [ ] Synthetic load test from 5 geographies shows ≥40% reduction in p50 TTFB on static assets
- [ ] Documented in `docs/OPERATIONS.md` under "Edge / CDN"

## Out of scope

- Cloudflare Pages migration of the SPA — separate ticket if/when SvelteKit build moves out of `co-web`
- WAF rules — separate ticket
- Image optimization at edge — separate ticket

## Risks

- **Cookie leak via cache.** Mitigation: Cache Rules explicitly bypass `Set-Cookie` and a smoke check verifies no auth response is in cache.
- **Origin getting bypassed unexpectedly.** Mitigation: keep origin's `Cache-Control` headers honest; Cloudflare respects them.
