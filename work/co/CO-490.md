GIVEN access should key off the *sender's* CO identity, not the business number —
so a person acts across exactly the universes CO already grants them
(owned+member+subscribed via `/me/universes`), enforced by `check_universe_access`,
WHEN a user proves possession of their WhatsApp number and the bot acts *as them*
with a least-privilege scoped token,
THEN Yuri (subscribed to more) reaches more than Miguel — with CO, not the bot,
enforcing it.

## Acceptance

- [x] `POST /api/v1/whatsapp/link/start` + `/verify` — **stateless 8-digit OTP**
  (HMAC, current+previous 5-min bucket, constant-time) proof-of-possession sent via
  the Cloud API; `/verify` does app-level one-number-per-account uniqueness (409),
  sets `users.whatsapp` (digit-normalized), revokes prior `whatsapp-bot` tokens,
  mints a **least-privilege** scoped token (entries:read/write, universes:read),
  and pushes `{whatsapp,token,user_id}` to the bot over loopback with `X-Bot-Secret`.
  Token never echoed. No new schema migration (reuses v093 `users.whatsapp`).
- [x] Bot: dual-key identity store (whatsapp + user_id), per-sender `CoTools(token)`;
  unknown sender → read-only "link your account"; **no service-identity fallback**
  for user-facing requests (gated behind a verified `X-Bot-Secret`).
- [x] birthday consent stores the number digit-normalized (can't defeat uniqueness).
- [x] **Tier-2 scale:** co-web shared timed `reqwest::Client`, bounded reply
  `Semaphore` (`CO_WHATSAPP_REPLY_CONCURRENCY`), `wamid` dedup; bot
  model-concurrency `BoundedSemaphore` + per-message deadline + **opt-in Claude
  spill (OFF by default, local-only stays policy-accurate)** + SQLite-WAL identity
  store.
- [x] **Rate-limit fix:** exempt the HMAC-verified `/api/v1/whatsapp/webhook` from
  the IP limiter (was throttled as anon-write 5/min → Meta disables the sub).
- [x] Reviewed across security/correctness/privacy/scalability; all findings closed
  or tracked. `CHANGELOG-PENDING/CO-490.md`.
