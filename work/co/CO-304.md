## As

Anyone whose PR's CI fails on inherited e2e brittleness instead of their actual change

## I Need

A focused **e2e test-quality pass** on the 71 surviving tests from CO-302, fixing the systematic problems:

1. **Over-broad selectors** — `locator('.empty-state')` matches 9 elements across views; tests pick the wrong one and time out
2. **Timing assumptions** — tests poll for content with 5s defaults; CI Linux runners + clean data are slower than local macOS + dirty data
3. **Implicit state expectations** — tests assume "a project exists" without seeding it (passes locally on dirty data, fails in CI's fresh boot)
4. **Loose response assertions** — tests use `toContain` / `toMatch` on whole responses; SPA shape changes break unrelated tests

## So That

- CI failures actually point to **what the PR broke**, not what was already broken on main
- Stop the 40-fail / 40-pass coin flip on every PR that has nothing to do with the failing tests
- The "what does green CI mean" signal becomes trustworthy again

## Context

### Concrete failure pattern (from PR #99 + #100 CI logs)

```
Locator:  locator('.empty-state')
Expected: visible
Received: hidden
Timeout:  5000ms

Call log:
  - Expect "toBeVisible" with timeout 5000ms
  - waiting for locator('.empty-state')
    9 × locator resolved to <p class="empty-state">Carregando…</p>
      - unexpected value "hidden"
```

The test wants the empty-state for a specific view, but `.empty-state` is reused for: "no project selected", "no tasks in column", "loading data", and several view-tab placeholders. Playwright finds 9 matches, picks the first (a hidden loading variant), waits 5s, fails.

### Three failing modes

| Mode | Sample | Tests affected (rough) |
|---|---|---|
| Over-broad selector | `.empty-state` (9 matches), `.task-card`, `.modal` | ~15 tests |
| Timing | `expect(...).toBeVisible({ timeout: 5000 })` then immediately `.click()` before render settles | ~10 tests |
| Implicit state | Test expects a project to exist without `seedProject` fixture or explicit setup | ~10 tests |
| Loose response shape | `expect(body).toContain("foo")` instead of `expect(body.field).toBe(...)` | ~5 tests |

40 fail / ~84 total ≈ 47% brittle. **Not a bug in the platform.** A test-quality regression.

### Why these survived CO-302's cut

CO-302's spec said "cut redundant tests, archive shipped acceptance specs". The agent did that correctly. But the **remaining** tests inherited their original quality, which had drifted because the SPA changed substantially in the visibility-chain waves (CO-261/266/268/270/279) and CO-280 (sidebar restructure) without test-side updates.

## Decision — three-pass approach

### Pass 1 — instrument the SPA with data-testid attributes (~2h)

For each failing test, identify the element the test needs and add a unique `data-testid` to the SPA template. Examples:

```html
<!-- Before -->
<p class="empty-state">Carregando…</p>
<p class="empty-state">No project selected</p>
<p class="empty-state">No tasks</p>

<!-- After -->
<p class="empty-state" data-testid="loading-placeholder">Carregando…</p>
<p class="empty-state" data-testid="no-project-selected">No project selected</p>
<p class="empty-state" data-testid="kanban-empty-column">No tasks</p>
```

Tests then use `page.locator('[data-testid="no-project-selected"]')` — guaranteed unique, immune to className collisions.

This is conventional Playwright practice. ~30 testid additions across the SPA.

### Pass 2 — fix timing assumptions (~1.5h)

Replace blind `toBeVisible()` with explicit waits:

```js
// Before:
await page.goto("/co");
await expect(page.locator(".task-card")).toBeVisible();  // racy

// After:
await page.goto("/co");
await page.waitForResponse(r => r.url().includes("/api/projects/CO/tasks"));
await expect(page.locator('[data-testid="task-card"]').first()).toBeVisible();
```

Add a `waitForBoardReady(page)` helper in `e2e/helpers.ts` that:
1. Waits for the projects API response
2. Waits for the network to be idle (`waitForLoadState('networkidle')`)
3. Returns when the board has actually rendered

Use it at the top of every test that interacts with board content.

### Pass 3 — seed required state explicitly (~1h)

Tests that assume "a project exists" should use the `seedProject` fixture (added in earlier work) or call the API directly to ensure setup:

```js
// Before:
test("dragging a card updates the API", async ({ page }) => {
  await page.goto("/co");
  await page.locator(".task-card").dragTo(...);  // fails if no tasks exist
});

// After:
test("dragging a card updates the API", async ({ page, seedProject }) => {
  await seedProject({ tasks: [{ title: "Drag me", status: "todo" }] });
  await page.goto(`/co?project=${seedProject.key}`);
  await waitForBoardReady(page);
  await page.locator('[data-testid="task-card"]').first().dragTo(...);
});
```

Where `seedProject` is the existing fixture, now with a `tasks` option so tests can declare their starting state.

## Scope

PR #99 + PR #100 both shipped via admin merge because their e2e CI was failing on **pre-existing** brittleness — not on their own changes. Every subsequent PR (CO-296, CO-291, CO-282 still-open #97, sister-repo CO-285 PRs) will hit the same wall.

This ticket is a one-time **cost** that unblocks every future PR. After CO-304:

The signal:noise of CI improves dramatically.
