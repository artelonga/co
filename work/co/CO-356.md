## As

a mobile user (phone or tablet) viewing my CO board — today I can see tasks but I **cannot drag them between columns**. The board is read-only on touch devices, which silently degrades the primary CRUD interaction.

## I Need

drag-and-drop on the kanban board to work uniformly across mouse, touch, and pen — replacing the current HTML5 DnD (`ondragstart` / `ondragover` / `ondrop`) with a pointer-event-based implementation that fires correctly on touch screens.

## So That

- The board is fully usable on iOS Safari + Android Chrome — the dominant mobile entry points for ArteLonga visitors.
- The mobile "read-only board" UX bug closes; CO behaves consistently across devices.
- Future drag surfaces (Sala canvas — CO-352, possibly entry tree reorder) inherit a working pointer-event substrate.

## Context

### Today's broken state

- `/Users/artelonga/projects/co/co-web/static/variants/a/modules/views/kanban.js` uses HTML5 drag events: `ondragstart`, `ondragover`, `ondragend`, `ondrop` on `<div>` cards + columns.
- HTML5 DnD events **don't fire on touchscreens** without a polyfill — that's a 15-year-old browser limitation.
- The E2E test at `/Users/artelonga/projects/co/co-web/e2e/board-drag.spec.ts` currently skips with `vp.width <= 640` — explicitly papering over the issue.

### Library choice

| Option | Pros | Cons |
|---|---|---|
| `interact.js` | Small (~70 KB), dedicated to this | Third-party dep, vendor risk |
| `@dnd-kit/core` | Mature, well-maintained | React-only — would require migration |
| **Hand-rolled pointer-event listeners** | ~150 lines, no deps, full control | More code to maintain |

**Decision: hand-rolled.** The board has a single drag use-case (card → column), pointer events are well-supported (iOS 13+, all modern Android, all desktops). Avoid vendor risk and bundle bloat. The same primitive becomes reusable inside Sala (CO-352).

## Design

### Pointer events

Use `pointerdown` / `pointermove` / `pointerup` / `pointercancel` — these unify mouse + touch + pen in one event model. Avoid mixing with `touchstart` / `mousedown` (double-fire risk).

### Drag state machine (per board)

```
idle
  → pointerdown on a card (after 200 ms hold OR 8 px movement) → dragging
dragging
  → pointermove → update ghost position, highlight target column on hover
  → pointerup → drop into target column (or revert if no target)
  → pointercancel → revert
  → escape key (desktop) → revert
```

The **200 ms hold or 8 px movement** threshold prevents accidental drags on scroll/tap on mobile.

### DOM model

- Original card stays in place at reduced opacity during drag.
- A "ghost" element clones the card and is `position: fixed`-positioned under the pointer.
- Pointer capture (`element.setPointerCapture(id)`) ensures we keep getting events even if the pointer leaves the original element.

### Hit-testing

- On each `pointermove`, call `document.elementsFromPoint(x, y)` and find the first ancestor with `data-column-id`.
- Highlight that column; clear highlights on other columns.
- On `pointerup`, the highlighted column is the drop target.

### Scrolling co-existence

- Vertical scrolling must still work when starting a touch on a card.
- Strategy: don't preventDefault on `pointerdown`. Only after the 200 ms hold OR 8 px **horizontal** movement is exceeded, switch to drag mode and start calling `preventDefault` on `pointermove`.
- This matches the iOS convention (long-press to drag, swipe to scroll).
