GIVEN output C of the synthesis loop is a **board task**, and a missão prefix
(`MG-`, `MGMSE-`, `MGAGRO-`, `MGALPHA-`, …) already encodes which universe/project
it belongs to under the stakeholder↔project pattern (miguel↔mse: a personal/
stakeholder universe owning one or more project universes),
WHEN the router (CO-498) hands a task item carrying a missão, an optional owner,
and an optional prazo,
THEN the task is created on the **right project/universe** for that prefix, with
the assignee resolved (or `a definir` when no owner is given) and the prazo set —
filed by default, never parked waiting for a target to be chosen.

## Acceptance

- [x] **Missão-prefix → target map:** `MG-`/`MGMSE-`/`MGAGRO-`/`MGALPHA-` (and
  future prefixes) resolve to a project/universe key following the
  stakeholder↔project pattern; the map is **data-driven** (no hard-coded
  universe→repo mappings in Rust — store it so a new missão needs no deploy).
- [x] Creates a board **work-item** in the resolved universe with assignee + prazo;
  uses the existing board/work-items machinery (no parallel store).
- [x] **"a definir" fallback:** no owner → assignee `a definir`; unknown prefix →
  routed to the stakeholder universe with an explicit `a definir: missão` marker,
  not dropped.
- [x] Writes through the per-sender scoped token (CO-490); access to the target
  universe is enforced by `check_universe_access`, not by the bot.
- [x] Tests: each prefix → expected target, unknown prefix fallback, owner/no-owner,
  prazo parsing. `CHANGELOG-PENDING/CO-500.md`.

## Notes
- C is a write output (board mutation); pairs with A/Jardim (CO-501) as the two
  write sinks and B/Telemetria (CO-499) as the read sink.
- The prefix grammar mirrors the universe hierarchy in the workspace map
  (miguel→mse, and the MGAGRO/MGALPHA mission namespaces under it).
