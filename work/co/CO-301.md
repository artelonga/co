## As

The operator running co-auto multiple times per day, watching local disk fill up with stale worktrees (330 GB across 57 worktrees as of today)

## I Need

A **review → archive → compress → delete** lifecycle for co-auto worktrees that:

1. Captures a **versioned, queryable metadata bundle** per task (task ID ↔ commits ↔ PR ↔ summary ↔ files-changed)
2. Stores the bundle as a tiny (~10-50 KB) git-tracked artifact under `docs/task-archive/<TASK-ID>.json`
3. Safely removes the local worktree once the PR is merged (the merge commit on main is the authoritative record; the archive points to it)
4. Provides retrieval commands: `co-task show CO-279`, `co-task diff CO-279`, `co-task list` — answering "what did CO-N change, when, why" without re-creating the worktree

## So That

- Local disk stops being a sliding window of 50+ GB worktree accumulation
- The history of every co-auto run is **queryable forever** at the spec/commit/PR layer (the metadata is git-tracked)
- "What did CO-279 do?" is answerable from `git log docs/task-archive/CO-279.json` plus the linked merge commit, without needing the worktree
- New contributors can audit the project's evolution without inheriting accumulated artifact bloat

## Context

### What's eating disk today

```
.worktrees/           330 GB across N worktrees (build artifacts mostly)
.claude/worktrees/    3 GB across 24 agent worktrees
```

Each co-auto session creates a worktree (~30 MB-2.6 GB depending on build artifacts), and they don't get cleaned up. The PRs merge, but the worktrees linger.

### What's actually valuable about a worktree post-merge

After a PR merges, the **branch's commits are already on main**. The worktree's working tree is therefore redundant with `git log <merge-sha>`. What's NOT in git history:

- The agent's reasoning/summary (post-CO-275 it's in `agent_sessions` DB, but not in main)
- The link between task spec and merge commit (currently only in the PR description)
- The wall-clock duration, tokens, tools used (CO-275 captures these but they're DB-only)
- The CHANGELOG-PENDING entry (consumed by release-commit, then gone)

A per-task JSON archive captures exactly this delta — making the worktree truly disposable.

### The bundle shape

```json
{
  "task_id": "CO-279",
  "title": "Restore template CO project + default project per universe",
  "type": "user-story",
  "spec_path": "work/co/CO-279.md",
  "branch": "fix/issue-279-template-seed-defaults",
  "head_sha": "bea7b53",
  "merge_sha": "9e02c7e",
  "pr": { "url": "https://github.com/artelonga/co/pull/95", "number": 95 },
  "started_at": "2026-05-23T13:00:00Z",
  "merged_at": "2026-05-24T21:07:49Z",
  "duration_ms": 113269000,
  "files_changed": 4,
  "lines_added": 292,
  "lines_removed": 16,
  "labels": ["type:fix", "module:seed", "module:storage"],
  "changelog_entry": "...",  // the CHANGELOG-PENDING content
  "summary": "...",          // 200-char synopsis or agent's final report
  "agent_session_id": "uuid", // points to CO-275 agent_sessions row if exists
  "co_auto_version": "0.1.0"
}
```

~10-50 KB per task. For 300 tasks: ~10-15 MB total in git history. Trivial.

## Decision

### Three components

#### 1. `scripts/archive-task.sh <task-id>`

Reads:
- `work/<space>/<TASK-ID>.md` (spec frontmatter)
- `gh pr list` for the matching branch
- `git log` for the merge commit + stats
- `CHANGELOG-PENDING/<TASK-ID>.md` if still present
- `agent_sessions` table (if local DB available, post-CO-275)

Writes: `docs/task-archive/<TASK-ID>.json`

Runs once per task at archive time. Idempotent — re-running overwrites.

#### 2. `scripts/prune-worktrees.sh [--apply]`

The cleanup loop from this session:
- For each worktree in `.worktrees/` and `.claude/worktrees/`:
  - Find its branch's PR
  - If merged AND `docs/task-archive/<TASK-ID>.json` exists for this task → safe to remove
  - Else → keep + log "manual review needed"

Dry-run by default; `--apply` to actually prune.

#### 3. `scripts/co-task` query tool

A small bash/python tool exposing:

```bash
co-task list                  # all tasks with archive
co-task list --since 2026-05-23
co-task list --label module:storage
co-task show CO-279           # full JSON
co-task summary CO-279        # human-readable one-pager
co-task diff CO-279           # git show <merge_sha> --stat
co-task open CO-279           # opens PR URL in browser
```

Implementation: ~150 LOC shell or python wrapping `jq` queries over `docs/task-archive/*.json`.

### Lifecycle integration

Modify `scripts/safe-merge-pr.sh` (CO-257) so that after a successful merge:

1. Pull main (now has the merge commit)
2. Run `scripts/archive-task.sh <task-id>` 
3. Commit the archive file (`docs/task-archive/<TASK-ID>.json`) on main
4. Push the archive commit
5. Run `scripts/prune-worktrees.sh --apply` (auto-removes the just-merged worktree)

This makes the lifecycle hands-free: merge a PR → archive auto-created → worktree auto-pruned. No new manual steps; no disk creep.

### What we explicitly avoid

- **Don't keep full diffs in the archive** — the merge commit already has them. Storing the diff bytes again would 10x the archive size for no value.
- **Don't compress the archives into a tar.zst** — they're already tiny (~50 KB). Git deltas them efficiently. Adding compression breaks `git log -p docs/task-archive/`.
- **Don't archive in-progress tasks** — only run after merge. In-progress worktrees stay.
- **Don't push agent transcripts** — those can be huge and contain prompt-injection risk. Reference by session ID only; full transcripts stay in the agent_sessions DB (CO-275).

## Why now

User's exact ask (paraphrased): *"review, store, compress and delete local .worktree for a change-log-safe, version-retrievable link between co-auto task ID and changes added"*.

Three convergent reasons:

1. **Acute disk pressure**: 333 GB across `.worktrees/` + `.claude/worktrees/` is already a quarter of a typical dev laptop's SSD
2. **The session shipped 8+ tasks today** — without an archive layer, the rate of worktree accumulation will only increase
3. **CO-275 already captures per-run telemetry** — CO-301 makes that telemetry *retrievable as a project artifact*, closing the loop from "agent did something" to "you can audit it"

This pairs perfectly with the CO-282 (localhost distribution) + CO-284 (pluggable infra) direction: the platform becomes self-documenting at the operational level.
