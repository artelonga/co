## As
Yuri running both CO and Yggdrasil — wanting Yggdrasil's notes visible in CO without giving up Yggdrasil's local-first sovereignty

## I Need
A read-only ingestion of Yggdrasil's notes vault into CO's `yggdrasil` content universe, using the CO-337 remote-sync pattern adapted for HTTP API instead of git clone. CO surfaces, renders, and indexes the notes; CO never writes back.

## So That
- The Yggdrasil-absorption decision (sala YES, notes NO) is implementable end-to-end.
- Yggdrasil's notes appear in CO's vault view + graph (CO-345) + KB index (CO-367) without round-trip complexity.
- Recursive promotion (a Yggdrasil note → standalone CO sub-universe via folder move, CO-280) becomes a clean one-way operation.
- The Yggdrasil agent's Phase 0-4 plan ships standalone in Yggdrasil; CO consumes when ready (Phase 2 in the agent's terms, but CO-side only).

## Context

Per `project_yggdrasil_absorption` memory (2026-06-06): Yggdrasil retains notes; CO reads. The Yggdrasil agent's plan:
- Phase 0: NoteStore + wikilinks IN YGGDRASIL (`yggdrasil-core/src/instance/note.rs`, `instance.json` for layout, `notes/<slug>.md` for canonical markdown)
- Phase 1: notes-first UX in Yggdrasil's SPA
- Phase 2: Yggdrasil exposes notes vault — CO's ingest point
- Phase 3+: round-trip — explicitly OUT OF SCOPE for CO (no write-back)
- Phase 4: recursive promotion — folder move on Yggdrasil's volume, CO sees new universe

This spec covers ONLY CO's ingestion side (Phase 2 from CO's perspective).

## Design

### Yggdrasil's side (out of scope for this spec; tracked separately)

Yggdrasil exposes:
- `GET /api/v1/instances/{id}/notes` — list with title, slug, updated_at
- `GET /api/v1/instances/{id}/notes/{slug}` — raw markdown body
- `GET /api/v1/instances/{id}/notes/bulk?since=<iso>` — bulk export for sync (NEW; Yggdrasil-side spec)

Bulk export returns:
```json
{
  "notes": [
    { "slug": "ogunte", "title": "Ogunté", "body": "...", "updated_at": "..." }
  ],
  "deleted_slugs": ["old-slug"],
  "next_since": "2026-06-06T..."
}
```

### CO's side (this spec)

#### Universe binding

Yggdrasil's `yggdrasil` universe (already on prod via CO-347) gets a new field `notes_source_url`:

```sql
ALTER TABLE universes ADD COLUMN notes_source_url TEXT;
ALTER TABLE universes ADD COLUMN notes_last_sync TEXT;
ALTER TABLE universes ADD COLUMN notes_source_kind TEXT;  -- 'yggdrasil-api' | 'http-vault' | future
```

Migration v64. For `yggdrasil` universe:

```sql
UPDATE universes
SET notes_source_url = 'https://yggdrasil.artelonga.com.br',
    notes_source_kind = 'yggdrasil-api'
WHERE key = 'yggdrasil';
```

#### Sync worker

New `co-web/src/workers/yggdrasil_notes_sync.rs`:
1. Every 5 minutes, query Yggdrasil's bulk endpoint with `since = universes.notes_last_sync`
2. For each note: upsert into `entries` table as `entry_type: page`, `universe_key: yggdrasil`, `path: notes/<slug>.md`
3. For each deleted_slug: soft-delete in `entries` (preserve `deleted_at`, hide from listings)
4. Update `notes_last_sync = next_since`
5. Publish `event_type = sync.yggdrasil.notes` to CO-380 event bus

#### Read-only enforcement

`POST /api/v1/universes/yggdrasil/entries` (write attempt) returns 405 Method Not Allowed:

```json
{
  "error": "read_only_universe",
  "source": "yggdrasil",
  "source_url": "https://yggdrasil.artelonga.com.br",
  "message": "Yggdrasil notes are sourced read-only from yggdrasil-api. Edit at the source."
}
```

Same for PATCH, DELETE, PUT.

Vault writes to `notes/*` paths also blocked.

#### UI affordance

When viewing a note in CO's SPA:
- "Edit at source" button → opens Yggdrasil's editor URL
- Banner: "📥 Read-only — edited in Yggdrasil"
- No "Save" button on the markdown editor (or hidden)

#### Cross-universe wikilinks

CO-363 wikilink resolver already handles `[[key::path]]`. A Yggdrasil note with body `[[mbya::terms/ogunte]]` resolves to CO's mbya universe entry. Reciprocal — CO entries can reference `[[yggdrasil::notes/some-slug]]`.

#### Phase 4: promotion to sub-universe

Out of scope here. When user promotes a Yggdrasil note to a CO sub-universe:
1. Yggdrasil-side: folder move + nested `_universe.yaml` (Yggdrasil ships this in Phase 4)
2. CO-side: next sync sees the new sub-universe; surfaces it (existing CO-280 IA)
3. No CO-side code change needed for promotion

### Backwards compatibility

CO's existing `yggdrasil` universe content (game descriptions per CO-349 scaffolding) stays. Notes append; existing paths untouched.

### Local development

When running both CO and Yggdrasil on localhost:
- CO env: `CO_YGGDRASIL_NOTES_URL=http://localhost:3001`
- Sync still runs every 5 min; faster cycle for dev (configurable env)

### Telemetry

Per CO-380:
- `event_type = sync.yggdrasil.notes` per cycle (with note count, deleted count)
- `event_type = sync.yggdrasil.error` on fetch failure (visible in /agora live timeline)
