GIVEN `scripts/pipeline-deploy-gate.sh` checks disk via `flyctl ssh` (Fly-only) and the
CO-446 boot pre-flight covers a SQLite write but not a pre-deploy threshold, so the M4
self-host path has no native disk gate (the only check is the manual `df -h ~/.co/data`
note in SELF-HOST.md §5),
WHEN we self-host on the M4,
THEN a native disk gate blocks a deploy/boot when the co data volume is near-full,
mirroring the CO-446 disk-full hardening that caused the 2026-06-11/13 Fly outages.

## Acceptance

- [ ] `scripts/disk-gate-selfhost.sh [DATA_DIR]` (default `~/.co/data`): `df -P` the data
  dir, **block (non-zero exit) at > 85% full** with an actionable message (how to free /
  extend), warn at > 75%.
- [ ] Wired as an optional pre-step in the self-host boot path (`scripts/selfhost/run.sh`)
  and documented in `docs/SELF-HOST.md`.
- [ ] No `flyctl` dependency — pure local `df`.

## Notes
- Pairs with CO-536. Closes gap (b) from the M4-readiness review (disk gate is Fly-only).
- The in-binary CO-446 pre-flight (`CO_MIGRATION_MIN_FREE_BYTES`) still applies at boot;
  this is the earlier, operator-facing gate.
