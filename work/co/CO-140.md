## Problem

`co-dev` was a virtual universe served by `dev_board.rs` — it responded correctly at
`GET /api/v1/universes/co-dev` and `/co/co-dev`, but `list_universes_for_user` never
returned it because there was no row in the `universes` table.
Result: co-dev never appeared in Yuri's sidebar.

## Fix

Added `Storage::seed_co_dev_universe()` called on every boot (idempotent via
`INSERT OR IGNORE`). Creates a `co-dev` universe row owned by `system`, private,
`requires_login=1`, `scholarly-dark` theme, `board` layout.

`ensure_admin_universe_memberships` (already runs at startup) adds Yuri as a member,
so the universe appears in his sidebar on next login.

## Acceptance

- [x] `co-dev` row exists in `universes` table after deploy
- [x] Yuri's sidebar lists CO Dev after next login
- [x] `GET /api/v1/universes/co-dev` still served by `dev_board.rs` (takes route priority)
