## Scale notes

- Mermaid is **lazy-loaded** — only fetched when a page contains a `mermaid` block (saves ~1 MB initial bundle for non-doc pages)
- **Render cache** (CO-79): SHA256 of the diagram source as cache key; cache rendered SVG in IndexedDB so repeat views skip the parse+render step (~50-200ms saved per diagram)
- **Server-side pre-render (deferred)**: for SEO and printable export, an optional headless-Chrome render step could pre-bake SVG into entry payloads — not v1, but an obvious follow-on for static export
- **Bundle bloat ceiling**: if/when the bundle becomes a problem, swap to `mermaid` ESM with tree-shaking and load only the diagram types declared in the manifest (CO-63)

## Tradeoffs

- **Vendor vs CDN**: vendor wins because (a) Capacitor/Electron need offline assets, (b) CSP gets tighter, (c) latency stays bounded under flaky network. Cost: 1 MB in the asset bundle (lazy-loaded so not in the critical path)
- **Client-side render vs server-side**: client wins for v1 because it's instant and adapts to theme switches; server-side becomes worthwhile when SEO or print rendering shows up as a real need
- **Strict security level**: `securityLevel: 'strict'` blocks Mermaid's `<a href>` links inside diagrams. Acceptable trade — diagram-internal links can be added later as a typed extension after manifest support (CO-74) lands
