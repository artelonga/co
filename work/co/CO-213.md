## As

a user who wants to edit CO universe content from Obsidian (desktop
markdown editor of choice)

## I Need

a polished CO Obsidian plugin that:

- Pulls latest content from CO on vault open
- Auto-syncs on save (push to CO via Vault API)
- Shows a clear conflict UI when local + remote diverge
- Surfaces CO metadata (tags, project keys, frontmatter) in Obsidian-
  native panels

## So That

Obsidian becomes a first-class editor for CO content — power-users with
existing Obsidian workflows can edit their CO universes without
switching to the web SPA.

---

## Context

CO-68 floated this as INFRA-3 ages ago. Today there's a partial plugin
in some shape but not polished. This ticket is the finish.

Public CO API (CO-211) provides everything needed:

```
GET    /api/v1/universes/{slug}/vault/notes
GET    /api/v1/universes/{slug}/vault/note/{path}
PUT    /api/v1/universes/{slug}/vault/note/{path}
DELETE /api/v1/universes/{slug}/vault/note/{path}
```

Auth via API token (`Authorization: Bearer ...`) generated by user in
CO settings.

## Plugin architecture

Lives in **separate repo**: `artelonga/co-obsidian-plugin` (or
similar). NOT in co repo — Obsidian community plugins have their own
release pipeline.

## Features

### Initial setup

1. User installs plugin (via Obsidian community plugins or BRAT)
2. Settings → "CO" → connect:
   - URL: `https://co.artelonga.com.br`
   - API token (generated in CO settings)
   - Universe slug to sync
3. On save, plugin tests connection: `GET /api/v1/auth/me`
4. If valid, plugin creates a sub-folder in vault: `co/{universe-slug}/`
5. Pull initial content

### Pull-on-open

On vault open (or plugin enable):

1. Check last-sync timestamp in plugin data
2. Fetch list of notes from API: `GET /api/v1/universes/{slug}/vault/notes`
3. For each remote note newer than last-sync OR not in local:
   - Fetch content
   - Write to local
   - Update last-sync timestamp
4. Show progress in status bar
5. On error: notify + log, but don't block

### Auto-push on save

Listen to Obsidian `vault.on("modify", file => ...)`:

1. If file is in `co/{universe}/` subfolder
2. Debounce 2 seconds (batch rapid saves)
3. `PUT /api/v1/universes/{slug}/vault/note/{path}` with current content
4. On success: update last-sync, status bar shows "✓ synced"
5. On 409 conflict (remote changed since we last pulled): show
   conflict modal

### Conflict UI

When local + remote diverged:

```
┌────────────────────────────────────────────────────────┐
│ Conflito de sincronização: notes/inbox/2026-05-13.md   │
├──────────────────────────────────────────────────────┤
│                                                          │
│ Local                          Remoto                   │
│ ┌──────────────────────┐      ┌──────────────────────┐│
│ │ # Hoje                │      │ # Hoje                ││
│ │                       │      │                        ││
│ │ Tarefa A              │      │ Tarefa A              ││
│ │ Tarefa B (local)      │      │ Tarefa C (remoto)     ││
│ │                       │      │                        ││
│ └──────────────────────┘      └──────────────────────┘│
│                                                          │
│  [ Manter local ]  [ Manter remoto ]  [ Mesclar manualmente ]│
└────────────────────────────────────────────────────────┘
```

- "Manter local" → overwrites remote with local content
- "Manter remoto" → discards local edits, applies remote
- "Mesclar manualmente" → opens a 3-pane merge view (could reuse Obsidian's diff if available, or split-screen)

### Frontmatter awareness

CO uses YAML frontmatter for typed entries. Plugin should:

- Show frontmatter properties in Obsidian's "Properties" panel
- Validate against the universe's manifest schema (from `/api/v1/universes/{slug}/manifest`)
- Warn on invalid types (red highlight)

### Tags + project keys

CO entries have `tags` in frontmatter and sometimes `project_key`.
Plugin should:

- Register CO tags with Obsidian's tag panel
- Allow filtering by project_key from quick-switcher

## Acceptance

- [ ] Plugin installs cleanly from BRAT
- [ ] Settings panel collects URL + token + universe
- [ ] Connection test on save (200 OK from `/auth/me`)
- [ ] Pull-on-open fetches all remote notes into `co/{slug}/` folder
- [ ] Edit any note in `co/{slug}/` → auto-pushes within 2s of save
- [ ] Status bar shows sync state (idle, syncing, synced, error)
- [ ] Conflict scenario produces conflict modal with 3 resolution options
- [ ] Frontmatter properties surface in Obsidian Properties panel
- [ ] Disconnect command deletes local folder (with confirmation) +
      removes token
- [ ] Privacy: API token stored encrypted by Obsidian's data API
- [ ] Mobile (Obsidian Mobile) works for read-only initially; auto-push
      v2

## Out of scope

- **Multi-universe sync** in one Obsidian vault — v1 supports 1 universe
  per plugin instance (workaround: user can install multiple instances)
- **Real-time sync** (WebSocket / CRDT) — pull-on-open + push-on-save
  is enough for v1
- **Local-only mode** — plugin requires CO connection; for offline-only
  Obsidian use, don't enable plugin
- **CO Tasks integration** — surface CO tasks in Obsidian; separate
  follow-up

## Co-auto

Not co-auto compatible (separate repo + Obsidian-specific tooling).
Best done by humans + AI pair-programming on the plugin repo.
