## As

A user following a deep link into another user's universe (e.g. from a shared content link or a backlink)

## I Need

`https://co.artelonga.com.br/<universe>/<slug>` to either resolve the entry or return a real 404 page

## So That

I trust the URL: missing content fails loudly instead of silently landing me on the universe home, which looks like the link "worked" but the content is gone.

## Context

- **Surface:** `https://co.artelonga.com.br/artelonga/oportunidade-tese` (reported 2026-05-18) returns the `artelonga` universe home instead of a 404 page.
- **Suspected cause:** SPA route fallthrough — `/<universe>/<slug>` resolves to the universe-shell loader, which (when the entry lookup fails) renders the universe home instead of dispatching to the 404 view.
- **Where to look:** `co-web/src/server.rs` (or after CO-215, `co-web/src/server/router.rs`) — the route catching `/{universe}/{*rest}` and the SPA entrypoint dispatcher in `co-web/static/variants/a/`.
- **Related:** any backlink rendering downstream (AL-57, CO-141) will inherit this misbehavior unless fixed.

## Acceptance

- Visiting `/<universe>/<unknown-slug>` returns HTTP 404 with the standard 404 SPA view (Portuguese + English variants).
- Visiting `/<universe>/<known-slug>` continues to render the entry.
- Visiting `/<universe>/` (no slug) continues to render the universe home.
- A new e2e test asserts the 404 case across at least two universes (`template` + `artelonga`).
- The 404 view links back to the universe home and to the global home (so the user can recover).

## Blast radius

Low. Behavior change is localized to the unknown-slug branch; existing happy-path routes unchanged. Affects all universes uniformly.
