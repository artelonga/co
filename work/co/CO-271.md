## As

A user visiting `/co/license`

## I Need

The route to return 200 with the AGPL v3 license text, completing CO-264's file-compat trio (CHANGELOG ✅, README ✅, LICENSE ❌).

## So That

The recursive-universe file-compat principle holds end-to-end: every well-known root file works the same way across every universe.

## Context

CO-269 (v2.27.0, deployed):

- Modified `co-web/Dockerfile` line 66: `COPY CHANGELOG.md README.md LICENSE ./`
- Updated `co-web/src/storage/seed.rs::reseed_co_root_files` to walk an array including `LICENSE`
- Test passed locally; PR #85 merged + deployed

But `https://co.artelonga.com.br/co/license` still returns 404 in prod.

### Probable failure modes

1. **The seed walker reads from the wrong path in Docker** — the file is at `/app/LICENSE` (not `/app/seed-co/LICENSE`), but the walker is looking only inside `seed-co/`.
2. **Walker skips files without `.md` extension** — the repo file is `LICENSE` (no extension); walker matches `*.md` only.
3. **LICENSE in `seed-co/` isn't copied separately** — the Dockerfile COPIES from the project root, but only `work/co/` to `/app/seed-co/`. LICENSE lands at `/app/LICENSE` and the walker doesn't look there.
4. **The walker IS finding it, but writes to wrong entry path** — e.g., `path = 'license'` instead of `path = 'LICENSE.md'`. CO-264's alias resolution expects `LICENSE.md`.

## Diagnostic steps

```bash
# 1. SSH to fly:
flyctl ssh console -a co-artelonga

# 2. Confirm files arrived in image:
ls -la /app/CHANGELOG.md /app/README.md /app/LICENSE /app/seed-co/

# 3. Check seed logs at boot:
flyctl logs -a co-artelonga --no-tail | grep -i "license\|root_files\|reseed_co"

# 4. SQL check:
sqlite3 /data/universes/co/entries.db "SELECT path FROM entries WHERE path LIKE '%LICEN%';"
```

## Scope

Read `reseed_co_root_files` in `co-web/src/storage/seed.rs`. Confirm:

1. The function takes a `root_dir` parameter — what's it pointing to in Docker? Should be `/app/`, not `/app/seed-co/`.
2. The walker handles `LICENSE` (no extension) — read the file as-is, store at `path = 'LICENSE.md'` so the route alias works.
3. The seeding actually runs on boot. Check `seed_orchestrator.rs` calls `reseed_co_root_files`.

Fix whichever step is broken. Re-deploy. Verify `curl https://co.artelonga.com.br/co/license` returns 200.

## Acceptance

- `GET https://co.artelonga.com.br/co/license` → 200 with AGPL text in body
- `sqlite3 /data/universes/co/entries.db "SELECT body FROM entries WHERE path = 'LICENSE.md';"` returns the AGPL text
- Same for `README.md` (should still work) and `CHANGELOG.md` (should still work) — no regression
- Smoke test in CI: `co-web/tests/seed_root_files_tests.rs` asserts LICENSE entry exists after `reseed_co_root_files(repo_root)`
