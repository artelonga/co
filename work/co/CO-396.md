## As
Dono/membro de um universo-projeto (ex.: board do CO Platform, grcsamazonia,
mse) que hoje só enxerga o trabalho como quadro kanban

## I Need
Uma lens **project timeline**: as mesmas entradas do quadro renderizadas num
eixo de tempo — tarefas posicionadas por `due_at`/`event_at`/`created`, lanes
por épico/módulo/status, releases e milestones como marcos; modos `timeline`
e `gantt` do `<co-time-grid>` (CO-387)

## So That
Roadmap e revisão de projeto saem do mesmo markdown canônico (conteúdo ×
forma: quadro e timeline são duas formas das mesmas entradas), sem nova
estrutura de dados — e a engine é a mesma do mundo-timeline do Yggdrasil,
não uma implementação paralela

## Decisão de arquitetura — módulos compartilhados (a restrição central)

A matemática de lens/layout de timeline deve viver **uma vez**, num crate
compartilhado, consumida pelos dois hosts:

```
co/<crate compartilhado>::time_layout        (lens math + lane/positioning puro)
   ├── co-web  →  <co-time-grid> (CO-387) → lens "project timeline"  (esta story)
   └── yggdrasil-core (path dep, canal já existente do game-core)
            →  generators/timeline.rs (YG-123) → mundo-timeline do universo `time`
```

- Candidato natural: `co/game-core` (já é o canal path-dep que o Yggdrasil
  consome) — ou módulo em `core/` se o review preferir; decidir no PR.
- CO-387 coloca a conversão em `co-web/src/time/conversion.rs`: ao implementar,
  **içar** as funções puras (entry → LensPosition, lanes, escala) para o crate
  compartilhado; co-web e yggdrasil-core importam.
- Renderer JS: `static/.../lib/co-time.js` (CO-387) é o espelho client-side;
  o `renderTimeline()` do Yggdrasil (instance.js) consome a mesma lib ou um
  porte mínimo documentado — nunca um fork divergente.

## Escopo

- [ ] Extrair layout engine pura para o crate compartilhado (sem deps de web/server)
- [ ] Lens `project-timeline` no `_calendar.yaml`: lanes por `epic|module|status`, marcos por `type: release|milestone`
- [ ] Tarefa sem data não some: lane "sem data" (backlog) na margem
- [ ] Modos `timeline` + `gantt` do `<co-time-grid>` ligados ao quadro (toggle quadro ⇄ timeline no header do universo)
- [ ] Duração no gantt: `created → done` (ou `scheduled_at → due_at` quando presentes)
- [ ] YG-123 passa a consumir a engine compartilhada (remover qualquer layout duplicado)
- [ ] Testes da engine no crate compartilhado (TDD), independentes de co-web
- [ ] `CHANGELOG-PENDING/CO-396.md`
