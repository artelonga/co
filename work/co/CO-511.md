GIVEN a person should be able to run the whole of CO on their own box with no
guesswork — clone, build, bind, autostart, back up — and a self-hostable platform
needs a single runnable kit rather than scattered tribal knowledge,
WHEN we ship the self-host direction,
THEN there must be a `scripts/selfhost/` kit plus `docs/SELF-HOST.md` (operator
guide) and `docs/LOCAL-DEV.md` (contributor guide), the server must accept a
configurable bind host (`CO_WEB_HOST`), and the kit must cover autostart and live
backup so a self-hoster reaches a private, durable deployment without reading the
source.

## Acceptance checklist

- [x] `scripts/selfhost/` kit files exist (setup/run/backup helpers) and are runnable.
- [x] `docs/SELF-HOST.md` (operator guide) and `docs/LOCAL-DEV.md` (contributor guide) exist.
- [x] `CO_WEB_HOST` bind flag works (local → `127.0.0.1`, network → `0.0.0.0`); see CO-512.
- [ ] `audit_serve` runs clean against the default self-host config (no off-instance leaks).
- [ ] launchd plist autostarts co-web on macOS (login-independent, restart-on-crash).
- [ ] Litestream live backup wired with a `verify-restore` step that proves a restore.

## Notes
- Shipped by this PR (`feat/CO-511`): the kit + bind-host land here; the remaining
