## Universe Config

```yaml
# .universo.yaml for co-dev
name: co-dev
description: "Co — desenvolvimento e roadmap. Inscreva-se para acompanhar."

path: data/co              # reads CO-*.md task files
branch: main
```

## Content Source

Tasks come from `data/co/CO-*.md` files in the artelonga/co repo:
- Each file has frontmatter: id, title, status, priority, parent, labels, module
- Project metadata from `data/co/project.yaml`
- ROADMAP.md becomes a page entry
- ROADMAP-STABLE.md becomes a page entry
- ROADMAP-SYNC.md becomes a page entry

## Access Model

| User | Can see co-dev? | Can edit? | How? |
|------|----------------|-----------|------|
| Anonymous | No (not in sidebar, search requires login) | No | — |
| Logged-in (not subscribed) | Discoverable via search | No | Search → "Inscrever-se" |
| Subscribed | Yes (in sidebar) | Read-only | Click in sidebar |
| Yuri (owner) | Yes | Read + write (commits to repo) | Automatic |
| co auto agent | Yes | Read + write (via worktree) | `co auto --space co-dev` |

## co-auto Integration

- [ ] `co auto --space co-dev --cycle` reads tasks from the co-dev universe
- [ ] Task selection uses same priority/status/parent logic as local markdown files
- [ ] After task completion: `co auto` updates task status → pushes to repo → co-dev re-syncs
- [ ] Subscribers see the updated status in real-time (within 5 min lazy refresh)

## Build at Runtime

1. On first access (or subscription), server clones `artelonga/co` → reads `data/co/*.md`
2. Parses each file → creates Entry records
3. Stores commit hash + timestamp
4. On subsequent access: compare remote HEAD → if different, pull + re-index
5. Content is read-only for subscribers (no PUT/POST on entries)
6. Owner (Yuri) can edit via co auto or local sync → pushes to repo → re-index
