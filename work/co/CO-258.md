## As

A developer kicking 2+ co-auto runs in parallel against the same repo

## I Need

co-auto agents to **never modify** `CHANGELOG.md` or `Cargo.toml` (or any other version/release-coordination file). These mutations are reserved for the **release commit** that bundles a wave of merged tasks under a single semver bump.

## So That

Parallel branches don't collide on the two files that 100% of tasks touched today (Cargo.toml + CHANGELOG.md), eliminating the dominant source of rebase conflicts.

## Context

Every parallel pair we ran today produced this conflict shape:

```
CONFLICT (content): CHANGELOG.md
CONFLICT (content): Cargo.toml
```

Both files because:

- Each task agent bumps `version` in `Cargo.toml` — first to merge wins, second branch's bump becomes a no-op or worse, an out-of-order revert
- Each task agent prepends a `## [version]` block to `CHANGELOG.md` — guaranteed line-1 conflict

Other shared files we've seen overlap on (sidebar.js, i18n.js, state.js, modals.js) are real engineering coupling and need a different fix (CO-259 file-split). The Cargo.toml + CHANGELOG.md collision is **purely procedural** — the version number and changelog entry have zero engineering content; they just track the release.

## Decision — pull these out of agent scope

| File | Today (agent does it) | After CO-258 (agent forbidden) | Owner |
|---|---|---|---|
| `Cargo.toml` (workspace `version`) | yes | no | release commit |
| `CHANGELOG.md` | yes | no — agent writes to `CHANGELOG-PENDING/<task-id>.md` instead | release commit consolidates |
| `co-cli/Cargo.toml` (binary version) | yes | no | release commit |

## Scope

1. **Agent prompt template** (`dev/co-auto/src/prompts.rs` or wherever the agent's task brief is constructed):
   - Add explicit forbidden-file list: "Do NOT modify these files: Cargo.toml, co-cli/Cargo.toml, CHANGELOG.md. Write your changelog notes to CHANGELOG-PENDING/<TASK-ID>.md instead."
   - Add format spec for the pending note (h2 title, body, optional Why section).
2. **New directory `CHANGELOG-PENDING/`** at repo root + a `.gitkeep`. Agent writes one `<TASK-ID>.md` file per task there.
3. **Release-commit helper** `scripts/release-commit.sh`:
   - Bumps `Cargo.toml` + `co-cli/Cargo.toml` to `<NEW>`
   - Reads all files in `CHANGELOG-PENDING/`, prepends them under a new `## [<NEW>]` heading in `CHANGELOG.md`
   - Deletes the consumed pending files
   - Commits with conventional `chore(release): <NEW> — <theme>`
4. **ship-task.sh update**: after merging a task PR, the merged commit no longer touches Cargo.toml/CHANGELOG.md. The release commit is a separate step the operator runs.

## Acceptance

- A fresh co-auto run on a sample task does NOT modify `Cargo.toml` or `CHANGELOG.md`. Writes `CHANGELOG-PENDING/CO-XXX.md` instead.
- Two parallel co-auto runs land cleanly with no Cargo.toml/CHANGELOG.md conflicts in their rebases.
- `scripts/release-commit.sh 2.18.1` consumes all pending notes into a single 2.18.1 CHANGELOG entry, bumps version, deletes the pending files, and commits.
- Documentation in `co-auto-context.md` describes the new workflow.

## Blast radius

- ~30 LOC in agent prompt template
- ~80 LOC `scripts/release-commit.sh` (new file)
- New `CHANGELOG-PENDING/` directory with .gitkeep
- ~10 LOC ship-task.sh adjustment (remove its current Cargo.toml/CHANGELOG resolution rules — those files should never be in the conflict set anymore)
