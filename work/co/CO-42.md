GIVEN the current Content tab shows tasks/events/pages flat with truncated previews and pages aren't really clickable,
WHEN I redesign Content as a wiki-like browser with folder hierarchy, rendered markdown cards, PDF-style zoom viewer, double-click-to-edit, and a metadata panel,
THEN:

## Section Visibility (default state)

- [ ] **Páginas** — expanded by default, primary focus, takes top of view
- [ ] **Tarefas** — collapsed by default. Heading: "Tarefas (8)" with chevron, "redundante ao Kanban" tooltip
- [ ] **Próximos eventos** — collapsed by default. Heading: "Eventos próximos (3)"
- [ ] **Clipes** — collapsed by default if empty
- [ ] All sections collapsible/expandable, state persisted in localStorage

## Folder Hierarchy (recursive)

Pages have a `path` field (e.g., `content/sobre.md`, `content/projetos/web/api.md`). Folders are derived from path segments after `content/`.

### Display Logic
- **0 folders** (all pages at root): flat list, no folder UI
- **1+ folders at root**: each folder is a collapsible section with title + chevron + count badge; loose pages appear under "Sem pasta" or at top
- **Nested folders**: each level adds indentation (16px) and a smaller heading (h3 → h4 → h5)
- **Recursion**: builds tree on the client from `path` strings

### UI Elements

- [ ] `FolderNode` JS data structure: `{ name, path, items: [Entry], children: [FolderNode] }`
- [ ] `buildFolderTree(entries)` function
- [ ] `renderFolderTree(node, depth)` recursive renderer
- [ ] Folder header:
  - Chevron icon (▼ open / ▶ closed) — clickable to toggle
  - Material icon `folder` (filled when open, outline when closed)
  - Folder name (Newsreader headline-sm for Scholarly, plain for default)
  - Item count badge (e.g. "5")
  - Optional actions menu (rename, new page in folder)
- [ ] Indentation: each level = 16px left padding, optional vertical guide line
- [ ] Empty folders: shown with "—" placeholder
- [ ] Folder collapse state in localStorage by path
