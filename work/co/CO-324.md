## As
A user who wants a single universe to host a mix of content (some public, some private, some invitation-only)

## I Need
Each entry to declare its own visibility tier, independent of the universe's visibility

## So That
yuri.artelonga.com.br can serve public references + private notes + invitation-gated drafts, all in one universe.

## Scope

### Three tiers per entry
| Tier | Anonymous can see? | Logged-in non-owner | Owner |
|---|---|---|---|
| `public` | ✅ | ✅ | ✅ |
| `private` | ❌ | ❌ (404) | ✅ |
| `invitation` | ❌ | ✅ if invited (token-gated) | ✅ |

### Storage
- Add `visibility` column to `entries` table (per-universe DB)
- Default value: `private` (safe default)
- Migration: backfill existing rows to match the **universe's** visibility (universe `public-subscribable` → entry `public`; private universe → entry `private`)

### Frontmatter
- `visibility: public|private|invitation` in entry frontmatter
- `entry_routes::write_entry` reads this field and writes to the DB column
- Backward compat: missing field → use universe-level default

### Query filtering
- `GET /universes/<key>/entries` filters by caller's permission level
- Anonymous → only `visibility=public`
- Logged-in non-owner → `public + invitation-where-invited`
- Owner → all entries

### Invitation tokens
- New table `entry_invitations(entry_path, universe_key, token, invited_by, expires_at)`
- Generate via `POST /api/v1/universes/<u>/entries/<path>/invite` (owner only)
- Visitors with `?invite=<token>` see invitation-tier entries

## Acceptance
- [ ] `entries` schema has `visibility` column with check constraint
- [ ] Migration backfills existing rows
- [ ] Anonymous GET `/entries` filters to `visibility=public`
- [ ] Invitation token grants access only to that specific entry
- [ ] Per-entry visibility shown in entry editor UI (radio buttons)

## Blast radius
- 1 schema migration
- ~100 lines in entry query + write paths
- ~30 lines SPA UI for the visibility selector
- 1 new endpoint for invitations

## Why now
Required by CO-323 (subdomain) so yuri.artelonga.com.br anonymous visitors only see the public stuff.
