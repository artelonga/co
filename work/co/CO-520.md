GIVEN the wave review found cross-process bugs (erase/forget body, digest param,
window fallback) that passed CI because both sides were faked in their own unit tests,
while the e2e pipeline only exercises browser → co-web (never the agent → co-web path),
WHEN the agent and co-web exchange any request/response,
THEN a contract-test tier pins every shape against the co-web source so drift on
either side fails CI — closing the gap between unit-with-fakes and browser-e2e.

## Acceptance

- [ ] **Generalize `tools/whatsapp-bot/tests/test_co_contract.py`** into a contract-test
  suite covering EVERY agent↔co-web request/response shape (not just the one path it
  pins today).
- [ ] **Pinned against the co-web source** (not a hand-written fake): the suite derives
  expected shapes from co-web's actual handlers/schemas so drift on either side fails CI.
- [ ] **Regressions the review caught are covered**: erase/forget request body,
  digest param, window fallback — each has a contract assertion.
- [ ] **Tier documented**: docs name this layer as the missing tier between
  unit-with-fakes and browser-e2e, and when to add a contract test vs a unit/e2e test.
- [ ] **Generalist**: the suite targets the agent↔co-web contract generically (no tenant
  names); WhatsApp is one client of that contract, not the contract itself.

## Notes
- The faked-both-sides blind spot is structural: each side's unit tests agreed with its
  own fake, so a mismatch between the two real implementations slipped through.
- Pairs with the canonical tool contract (CO-503) — once tools share one shape, the
  contract suite pins that shape too.
