GIVEN `co-auto --headless` ran **in-place in the main repo checkout** (the CWD,
via `dev/co-auto/src/auto.rs`) and intermingled with a concurrently running
Workflow — the 2026-06-28 CO-496/CO-492 collision where two processes race-edited
the same working tree — and the only safe substrate is per-task isolation,
WHEN co-auto starts any task (headless or interactive),
THEN it ALWAYS runs in a per-task worktree it owns (never the CWD checkout), refuses
to start if the target repo is dirty or off main, and in the longer term shares ONE
worktree-isolation primitive with the Workflow tool so both reuse the same substrate.

## Acceptance

- [ ] **co-auto always isolates.** Every run — including `--headless` — creates and
  uses a per-task worktree; it never mutates the CWD checkout it was launched from.
- [ ] **Dirty/off-main guard.** A pre-flight refuses to start if the target repo has
  uncommitted changes or is not on `main`, with a clear message (no silent in-place run).
- [ ] **Shared isolation primitive (longer-term).** co-auto and the Workflow tool
  (CO-506) converge on ONE worktree-isolation primitive instead of two divergent
  implementations; collisions like CO-496/CO-492 become structurally impossible.
- [ ] **Generalist**: no tenant names, no per-repo special cases — isolation is a
  property of the substrate, not of the task. Swap the isolation backend is a flag,
  not a refactor.

## Notes
- Reference [[feedback_coauto_workflow_tree_collision]] — the in-place headless run is
  the root cause; isolation by default closes it.
- "agente não bot": co-auto is an agent runtime; the Workflow tool composes agents.
  Sharing the worktree substrate is part of the componentization review.
- Links CO-506 (workflows) for the shared substrate; the immediate fix (always
  isolate + guard) ships independently of the convergence work.
