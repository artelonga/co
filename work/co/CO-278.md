## As

The operator (yuri) and third-party developers / contributors / sister-universe owners

## I Need

A **public, versioned, documented HTTP API** at a stable surface (`https://co.artelonga.com.br/api/v1/...` and a future `api.artelonga.com.br`) that exposes the **shippable capabilities** of the platform:

| Capability | Endpoints (illustrative) | Backing |
|---|---|---|
| **Agent dispatch** (co-auto over HTTP) | `POST /agent/runs`, `GET /agent/runs/{id}`, `GET /agent/runs/{id}/log` | new agent-runner service wrapping `co-auto` |
| **Universe querying** | `GET /universes`, `GET /universes/{u}`, `GET /universes/{u}/entries`, `GET /universes/{u}/entries/{path}` | existing entries/storage layer |
| **CRUD requests** | `POST/PUT/PATCH/DELETE /universes/{u}/entries/{path}` | existing storage + vault routes |
| **Telemetry data** | `GET /agent/sessions` (post-CO-275), `GET /deployments` (post-CO-273) | new endpoints surfacing existing tables |
| **Analytics** | `GET /metrics/throughput`, `GET /metrics/token-budget`, `GET /metrics/release-cadence` | aggregations over agent_sessions + git history |

…with API tokens, rate limits, OpenAPI docs, and (eventually) an SDK.

## So That

1. **Bots / scripts / CI** can dispatch `co-auto` runs without needing a local CLI — sister repos (yggdrasil, rfq, qb, artelonga) can `curl POST /api/v1/agent/runs` from a GitHub Action.
2. **Third-party tooling** (Obsidian plugins, IDE extensions, dashboards) can query universes + entries through one documented contract.
3. **Operators** get a single panel-of-glass for telemetry + analytics: agent costs, release cadence, deployment health.
4. **Future SDKs** (Rust crate, TypeScript client, Python wrapper) ship against a stable OpenAPI schema — no ad-hoc reverse-engineering.

The platform has been growing endpoints ad-hoc through CO-220, CO-264, CO-267, CO-272, CO-273, CO-275. This epic **collects them under a versioned contract** before the next wave of endpoint churn fragments the surface further.

## Context

### Where the platform is today

- ~40 routes scattered across `co-web/src/{admin,auth,content,integrations,platform,social,universes}/`.
- Some are public (board CRUD), some are admin-only (admin routes), some are token-gated (vault).
- **No OpenAPI schema published.** No rate limiting at the route level. Versioning is `/api/v1/...` by convention only — no deprecation policy.
- co-auto runs **only locally** — there is no HTTP wrapper. Each kick is a `Bash` invocation.

### What "public API" means here

Two readings — both should be supported:

| Reading | Audience | Examples |
|---|---|---|
| **A. Open developer surface** | Anyone with a token | Universe queries, CRUD, telemetry (read-only) |
| **B. Self-service automation** | Owners + their bots | Agent dispatch, deploys (write), admin metrics |

A is mostly "make existing routes stable + documented". B is mostly "wrap co-auto + deploy as services".

### Why this is an epic, not a story

The work decomposes into 5-7 sub-stories, each independently shippable:

1. **CO-278-A — API versioning + deprecation policy** — formalize `/api/v1/...`, document deprecation window, add `X-API-Version` headers, response envelope (`{ data, meta, errors }`).
2. **CO-278-B — Token tiers + rate limits** — extend vault tokens with `tier: read | write | admin | agent`, add per-tier rate limits via tower middleware (e.g. 60 req/min for read, 10 req/min for write, 2/hour for agent).
3. **CO-278-C — OpenAPI schema generation** — annotate routes (utoipa crate), serve `/api/openapi.json` + Swagger UI at `/api/docs`.
4. **CO-278-D — Agent dispatch service** — `POST /api/v1/agent/runs` accepting `{ task_id, model?, dry_run?, timeout? }`; spawns co-auto in a worker; persists to `agent_runs` table; returns `{ run_id }`; clients poll `/runs/{id}` for status. **Hard requirement**: not panic-under-lock (see `feedback_no_panic_under_mutex`).
5. **CO-278-E — Telemetry + analytics endpoints** — surface `agent_sessions` (CO-275), `deployment_snapshots` (CO-273), git-derived cadence metrics.
6. **CO-278-F — Public docs + SDK seed** — `/api/docs` Swagger UI, README in the repo, optional `co-client` Rust crate stub.
7. **CO-278-G — Cross-universe auth federation** — sister repos use their vault token; co-artelonga validates issuer + scope. Builds on CO-267.

Each sub-story is its own ticket once this epic is opened.

## Decision — design principles for the public surface

### 1. Versioning is a feature, not a guess

- Path versioning: `/api/v1/...`, `/api/v2/...` (when needed).
- Every response includes `X-API-Version: 1.0` and `X-Co-Server-Version: 2.30.0` headers.
- Deprecation: any v1 route to be removed gets a `Deprecation: true` + `Sunset: <date>` header for at least 90 days before removal.

### 2. Envelopes — one shape for everything

```json
{
  "data": { ... },         // primary payload
  "meta": {                // pagination, version, request_id
    "request_id": "uuid",
    "api_version": "1.0",
    "page": 1,
    "page_size": 50,
    "total": 234
  },
  "errors": null           // or [{ code, message, field?, hint? }]
}
```

Non-2xx responses set `data: null` and populate `errors`. Existing routes get a thin adapter; new routes use the envelope from day 1.

### 3. Auth tiers via the vault token

| Tier | Capabilities | Rate limit |
|---|---|---|
| `anonymous` | Public reads (e.g. universe metadata, public entries) | 60 req/min |
| `read` | All reads on owned universes; reads on shared/public | 120 req/min |
| `write` | + CRUD on owned universes | 60 req/min |
| `agent` | + dispatch co-auto runs on owned universes | 2 req/hour per universe |
| `admin` | Everything + telemetry/analytics | 600 req/min |

A token's tier lives in the `api_tokens` table (already exists). The middleware reads it once per request and applies the limit.

### 4. Agent dispatch — async, observable

```
POST /api/v1/agent/runs
  Body: { task_id: "YG-64", universe: "yggdrasil", model?, dry_run?, no_pr?, timeout? }
  Returns: { run_id: "uuid", status: "queued" }

GET /api/v1/agent/runs/{run_id}
  Returns: { run_id, status: "queued|running|succeeded|failed",
             started_at, finished_at?, exit_code?, pr_url?,
             session_id?  // joins to CO-275 agent_sessions }

GET /api/v1/agent/runs/{run_id}/log?since=offset
  Returns: text/plain, streaming stdout/stderr

GET /api/v1/agent/runs?universe=yggdrasil&status=running
  Returns: paginated list
```

Backed by a new `agent_runs` worker (CO-223 Worker trait pattern) that spawns `co-auto` as a child process, captures stdout, persists to a `agent_runs` table, and emits a `DomainEvent::AgentRunComplete` (sibling to CO-275's `AgentSessionComplete`).

### 5. OpenAPI is the source of truth

Use `utoipa` to annotate handlers, generate `/api/openapi.json`, and serve Swagger UI at `/api/docs`. The schema is reviewed in PR alongside route changes — drift becomes a CI failure.

## Scope (the epic's exit criteria)

This epic is **done** when:

- [ ] `/api/openapi.json` is published and stable for v1
- [ ] `/api/docs` Swagger UI is publicly browsable
- [ ] All v1 routes use the standard envelope (`data` / `meta` / `errors`)
- [ ] Token tiers + rate limits are enforced via middleware
- [ ] `POST /api/v1/agent/runs` works end-to-end on `co.artelonga.com.br`: a token holder dispatches a run, polls status, fetches the log, sees the PR opened
- [ ] Telemetry endpoints (`agent/sessions`, `deployments`, `metrics/*`) return paginated data
- [ ] At least one sister repo (yggdrasil) has a GitHub Action that calls `POST /api/v1/agent/runs` for its own work-tracked tasks

## Why now

User just asked: *"we want a public api that we can release that can ship co auto and other rust based api endpoints (eg universe querying, crud requests, telemetry data, analytics)"*.

The platform has been **growing routes faster than discipline**. CO-275 just added an `agent/sessions` endpoint; CO-273 added a deployment dashboard; CO-272 added a kanban adapter; CO-267 added vault sync; CO-220 added an event bus. Each was right in isolation; collectively, the surface is now varied enough that *not formalizing it* costs more than formalizing it.

Plus: **agent dispatch over HTTP unblocks sister repos**. Yggdrasil, RFQ, QB, and ArteLonga today have no `co-auto` runner — they're locked to the host with the binary installed. A POST endpoint flips that: any GH Action can dispatch a CO-N task in any sister universe, and the entire ecosystem becomes a single deployment unit again.

This is the natural cap on the recent run of platform work (CO-258 through CO-277). After this epic, the **shape** of CO-N tasks shifts: less about adding capabilities, more about adding **endpoints to a documented contract**.
