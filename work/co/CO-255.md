## As

A user resizing the conteúdo split-pane with detail on the right side (obsidian-mode)

## I Need

The drag-to-resize splitter to behave symmetrically — work the same dragging from the right edge as it does from the left.

## So That

The split layout feels consistent regardless of which side the detail pane is on.

## Context

`co-web/static/variants/a/modules/views/conteudo.js:1140` `onMove`:

```js
const pct = ((e.clientX - rect.left) / rect.width) * 100;
splitEl.style.setProperty('--split-pct', `${clamped}%`);
```

CSS `co-web/static/variants/a/style.css:2620+`:

```css
.conteudo-detail-pane { flex: 0 0 calc(var(--split-pct) - 14px); }  /* normal mode */
.conteudo-split.obsidian-mode { flex-direction: row-reverse; }
.conteudo-split.obsidian-mode .conteudo-sections-pane { flex: 0 0 280px; }  /* fixed! */
.conteudo-split.obsidian-mode .conteudo-detail-pane { flex: 1 1 auto; }       /* ignores --split-pct */
```

**Bug**: In obsidian-mode, `--split-pct` is no longer wired to anything resizable — the sections pane has a fixed 280px and detail takes the rest. Dragging the splitter changes the CSS variable but neither pane uses it.

## Scope

Two-line fix in CSS + invert the JS calculation when in obsidian-mode:

```css
.conteudo-split.obsidian-mode .conteudo-sections-pane {
    flex: 0 0 calc(100% - var(--split-pct) - 14px);
}
```

```js
const isObsidian = splitEl.classList.contains('obsidian-mode');
const pctRaw = ((e.clientX - rect.left) / rect.width) * 100;
const pct = isObsidian ? 100 - pctRaw : pctRaw;
const clamped = Math.max(15, Math.min(85, pct));
splitEl.style.setProperty('--split-pct', `${clamped}%`);
```

## Acceptance

- In normal mode (detail left): drag splitter right → detail grows, sections shrinks. Same as today.
- In obsidian-mode (detail right): drag splitter left → detail grows, sections shrinks. (Visually mirrored to normal.)
- The split-pct value persists in localStorage and survives mode toggle.
- Touch + mouse both work in both modes.

## Blast radius

- ~5 LOC JS + ~3 LOC CSS in two files.
- No new state; reuses existing `--split-pct`.
