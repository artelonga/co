## As
Dono/membro de um universo-projeto que hoje move cartões à mão enquanto o
estado real do trabalho vive no git/jj e no deploy

## I Need
O pipeline padrão como feature do quadro: enum default
`[todo, started, in_progress, review, done]` e **transições dirigidas pelos
eventos de VC/deploy**, com a aprovação acontecendo vendo a coisa rodando
(localhost/UAT), não só lendo o diff

## So That
O quadro deixa de ser um espelho manual e vira o próprio pipeline de entrega:
o status do cartão é sempre o estado verdadeiro do trabalho, e "done" implica
"aprovado e em produção"

## Mapeamento (a regra)

| Status | Gatilho (evento) | Fonte |
|---|---|---|
| `todo` | cartão criado/priorizado | quadro |
| `started` | branch/worktree aberto com o id da tarefa (`feat/CO-<n>-…`) ou novo change jj | git/jj |
| `in_progress` | primeiro commit na branch | git |
| `review` | **PR aberto** + link de preview anexado ao cartão (`co serve` localhost / UAT quando user-facing) | GitHub + deploy |
| `done` | **PR merged** (o merge é o registro da aprovação) ⇒ dispara deploy de produção (UAT→prod quando aplicável) | GitHub + deploy |

## Escopo

- [ ] Enum default `[todo, started, in_progress, review, done]` no schema de task dos universos-projeto novos (template); boards legados `[todo, doing, done]` seguem válidos
- [ ] Eventos de transição no bus (CO-380): `task.status_changed{task, from, to, trigger}`
- [ ] Integração GitHub (reusa `co gh`/collab + WebhookWorker): branch criada com `CO-<n>` no nome ⇒ `started`; PR aberto referenciando a task ⇒ `review`; merge ⇒ `done`
- [ ] Cartão em `review` exibe as duas pernas: link do PR + link do preview (localhost/UAT); sem preview, o cartão sinaliza revisão incompleta
- [ ] `done` emite evento de deploy (gancho para CO-395 `construir` em universos de conteúdo e para o fluxo UAT→prod em código)
- [ ] Transição manual continua possível (drag) — automação preenche, não tranca
- [ ] Telemetria: lead time por coluna (todo→done) visível no dashboard
- [ ] Docs: `docs/delivery-pipeline.md` + CHANGELOG-PENDING/CO-398.md

## Not in scope

- Aprovação multi-revisor/quórum — uma aprovação de merge basta na v1
- Auto-deploy de produção sem gate humano em universos de conteúdo de cliente
  (o go do stakeholder continua explícito)
- Integração jj-nativa server-side (v1 observa o remote git; jj colocated já aparece via git)
