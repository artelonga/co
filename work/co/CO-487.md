GIVEN we want a warm, opt-in touch — a birthday WhatsApp greeting — and CO already
has the compliant `ChannelProvider` cascade (CO-479),
WHEN a user consents at login (records birthday `MM-DD` + WhatsApp number, an LGPD
opt-in) and a daily job greets consented users on their birthday once per year via
WhatsApp,
THEN users get "🎉 Feliz aniversário" on the day, gated on explicit consent, over
the official transport — fired the moment a WhatsApp channel is configured.

## Acceptance

- [x] Migration **v093**: `users.birthday` (`MM-DD`), `birthday_consent`,
  `whatsapp`, `birthday_greeted_year` (idempotency) — additive/guarded; LATEST=93.
- [x] `POST /api/v1/auth/birthday-consent` (authed) — validates `MM-DD`, stores
  birthday + consent + number (the opt-in at login).
- [x] `run_birthday_job` selects consented users with today's birthday (not yet
  greeted this year, with a number) → sends via the provider cascade (Cloud API →
  Evolution) → marks greeted. No lock held across the network await.
- [x] `POST /api/v1/admin/birthday/run` (seed-admin) triggers it on demand.
- [x] Pure `compose_greeting` + `valid_mmdd`; **e2e test**: a consented user with
  today's birthday is selected and greeted with the right message to the right
  number (a non-consenting same-birthday user is skipped). MockChannelProvider.
- [x] `cargo test` + `cargo clippy -- -D warnings` + `cargo fmt` clean.

## Notes / follow-up

- **Delivery needs a live WhatsApp channel** (Evolution QR-link or Meta Cloud
  token). With none configured, the job logs a dev-fallback (redacted number) and
  greets 0 — the moment a channel is set, real messages send.
- Consent UI hook: the login flow should call `/birthday-consent`.
- A scheduled daily worker (vs the admin trigger) — thin follow-up mirroring
  `notification_email_worker`.
