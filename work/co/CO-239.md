## As

An operator or admin checking `/storage` to forecast capacity

## I Need

Real values for `data_dir_total_bytes` and `data_dir_available_bytes`

## So That

I can see how much disk is left on the Fly volume before I need to expand it, instead of zero placeholders.

## Context

- **Principles:** §3 (static typing — values must reflect reality)
- **Scope:** `co-web/src/storage_dashboard.rs:114-122` returns hardcoded zeros for `data_dir_total_bytes` and `data_dir_available_bytes`. The comment says: 'statfs-based total/available requires a libc binding we don't currently depend on; skipped here.'

Add `nix = { version = "0.x", features = ["fs"] }` and call `nix::sys::statvfs::statvfs(data_dir)`. Compute:
- `total_bytes = f_blocks * f_frsize`
- `available_bytes = f_bavail * f_frsize`

Or use `libc::statvfs64` direct (no extra dep) if we want to keep the dependency surface minimal.

## Acceptance

- `/api/v1/admin/storage` returns non-zero values for both fields on a real volume.
- Linux-only (gated by `#[cfg(target_os = "linux")]`); macOS/Windows return None or zero with a `tracing::warn!`.
- Integration test against a tmpfs mount asserts total > used > 0.

## Blast radius

Tiny — one function + optional dep.
