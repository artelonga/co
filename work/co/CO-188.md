## As

a universe owner or admin who wants to grant access to a private/invitation-only universe

## I Need

a `POST /api/v1/universes/:slug/invitations` endpoint that mints a single-use invite token, emails the recipient (via the existing Resend cascade), and a complementary `POST /api/v1/invitations/:token/accept` that turns it into a `universe_members` row

## So That

logged-in users have a clean path to join private universes without admins running SQL by hand, AND the membership table is the single source of truth chat (Phase 4) will read from.

---

## Schema — migration v40

New table `universe_invitations` on the meta DB:

```sql
CREATE TABLE IF NOT EXISTS universe_invitations (
    token_hash      TEXT PRIMARY KEY,        -- sha256(token); raw token only in the email
    universe_key    TEXT NOT NULL,           -- target universe
    invited_by      TEXT NOT NULL,           -- inviter's user_id
    invited_email   TEXT,                    -- nullable when invited_user_id is set
    invited_user_id TEXT,                    -- nullable when invited_email is set
    role            TEXT NOT NULL DEFAULT 'member',  -- member|admin|viewer
    expires_at      TEXT NOT NULL,           -- now + 14 days
    consumed_at     TEXT,                    -- single-use
    revoked_at      TEXT,                    -- explicit revoke endpoint (out of scope here, column reserved)
    created_at      TEXT NOT NULL,
    FOREIGN KEY (universe_key) REFERENCES universes(key)
);
CREATE INDEX IF NOT EXISTS idx_invitations_universe
    ON universe_invitations(universe_key, consumed_at);
CREATE INDEX IF NOT EXISTS idx_invitations_recipient
    ON universe_invitations(invited_email, consumed_at);
```

Plus add `INSERT OR IGNORE INTO schema_version (version) VALUES (40)`.

CHECK constraint enforced in Rust (not SQL): `invited_email IS NOT NULL OR invited_user_id IS NOT NULL` — at least one identifier.

## Endpoints

### `POST /api/v1/universes/:slug/invitations` (auth required)

Body:
```jsonc
{
  "email": "guest@example.com",       // OR
  "usuario": "yuri",                   // OR
  "user_id": "usr_abc",                // any one of these is required
  "role": "member"                      // optional, defaults to "member"
}
```

Authorization: caller must be `owner_id` of the universe OR a `universe_members` row with role in (`owner`, `admin`).

Logic:
1. Resolve recipient identity:
   - If `email` → look up `users.email`; if matches existing user, set `invited_user_id`. If not, store `invited_email` only — they'll resolve at accept time (or sign up first).
   - If `usuario` → resolve via existing `get_user_by_usuario`.
   - If `user_id` → use directly.
2. Reject if recipient is already a member (`universe_members` row exists for that universe + user).
3. Mint a token (`nanoid!(32)`), store `sha256(token)` as `token_hash`.
4. Insert row, expires 14 days.
5. Send email (when `invited_email` set, regardless of whether `invited_user_id` matched) via existing Resend cascade. Subject: "Convite para {universe.name} no CO". Body: link to `{base}/invitations/{raw_token}`.
6. Return 201 `{token_hash, expires_at, sent_to: <masked>}` (NEVER return raw token to the API caller — it goes only to the recipient via email).

### `GET /api/v1/invitations/:token` (no auth)

Public preview so a recipient can see what they're being invited to before logging in / creating an account.

Hash the path segment (`sha256(token)`), query, return:
```jsonc
{
  "universe": { "key": "private-universe", "name": "Private Universe" },
  "invited_by": { "display_name": "Yuri" },
  "expires_at": "...",
  "already_consumed": false
}
```

404 if not found; 410 if expired; 200 with `already_consumed: true` if used (so UI can say "this invite was already accepted").

### `POST /api/v1/invitations/:token/accept` (auth required)

Logic:
1. Look up invitation by `sha256(token)`.
2. 410 if expired, 410 if consumed.
3. Ensure caller's identity matches:
   - If `invited_user_id` set → caller's `user_id` must match.
   - Else if `invited_email` set → caller's `users.email` must match (case-insensitive).
4. INSERT into `universe_members (universe_key, user_id, role, joined_at)` — `INSERT OR IGNORE` so re-accepting an existing membership is a no-op.
5. Mark invitation consumed (`consumed_at = now()`).
6. Return 200 `{universe_key, role}`.

## Email delivery

Reuse existing pattern from `recovery_routes::deliver_email_code`:
- Try Resend (already configured on prod with `senhas@seguranca.artelonga.com.br`).
- Fall back to SMTP if `CO_SMTP_*` set.
- Log + ok if neither (dev pattern).

Subject: `Convite para {universe.name} no CO`
Body PT:
```
Olá,

{inviter_display_name} te convidou para o universo {universe_name} no CO.

Aceitar:
{base_url}/invitations/{raw_token}

O convite expira em 14 dias.
```

`base_url` from `CO_BASE_URL` env or default `https://co.artelonga.com.br`.

## Routes wiring

In `server.rs`:

```rust
.route("/v1/universes/{slug}/invitations", post(create_invitation_handler))
.route("/v1/invitations/{token}", get(preview_invitation_handler))
.route("/v1/invitations/{token}/accept", post(accept_invitation_handler))
```

The first route already nests under `universe_api` (auth-gated). The other two go on a public router (auth required only on `/accept`, applied via per-route middleware).
