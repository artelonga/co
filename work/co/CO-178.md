## As

operator olhando `/analytics` em artelonga.com.br

## I Need

cada evento em `telemetry_events` enriquecido com `country` + `city` derivados server-side do IP (antes do hash + descarte)

## So That

a seção "Geolocalização" do dashboard pare de mostrar "Indisponível na fila local" e mostre distribuição real, sem nunca expor IP cru pro cliente.

---

## Estado atual

- Schema (`storage/migrations.rs:404-420`): tem `ip_hash`, sem geo.
- `marketing_events_handler` (telemetry.rs:731): extrai IP, hasheia via `hash_ip_daily()`, descarta. Lookup geo é o passo que falta.

## Design

### Schema migration v17

```sql
ALTER TABLE telemetry_events ADD COLUMN country TEXT;
ALTER TABLE telemetry_events ADD COLUMN city TEXT;
CREATE INDEX IF NOT EXISTS idx_telemetry_country ON telemetry_events(country);
```

Nullable: bot/internal/IP irreconhecível deixa NULL; rows antigas (sem IP cru pra reverso) ficam NULL pra sempre.

### Lookup: MaxMind GeoLite2 embarcado

- Crate `maxminddb`.
- Bundle `GeoLite2-City.mmdb` (~70 MB) na imagem ou download on boot.
- In-process, < 1 ms por evento.
- Free com atribuição (documentar em `docs/analytics-api.md`).

API externa (ipapi/ipinfo) rejeitada: latência por evento + modo de falha parcial.

### Integração

```rust
let raw_ip = extract_ip_from_headers(&headers);
let (country, city) = geo_lookup(&raw_ip);
let ip_hash = hash_ip_daily(&raw_ip);
// raw_ip cai do scope aqui — só ip_hash + geo persistem
```

`geo_lookup` retorna `(None, None)` pra IP privado/loopback/irreconhecível sem panic. Bot filter (`is_bot(&ua)`) já roda antes — não desperdiça lookup.

### Privacidade

- City granularity é "São Paulo", não "Av. X 1000". OK.
- IP cru nunca em log nem em row.
- Mesmo contrato que já está em `docs/analytics-api.md`.

## Implementação

1. Migration v17 adiciona colunas + index.
2. `co-web/src/geo.rs` com `geo_lookup(ip: &str) -> (Option<String>, Option<String>)`.
3. `EventRow` ganha `country: Option<String>`, `city: Option<String>`.
4. Ambos handlers (`marketing_events_handler`, `track_event_handler`) populam antes do INSERT.
5. INSERT SQL estendido.
6. Dockerfile / Fly: incluir .mmdb na imagem ou download on boot de URL conhecida.

## Tests

- `127.0.0.1` → `(None, None)`, sem panic.
- IP público conhecido → `("US", "Mountain View")` (do bundled DB).
- `192.168.1.1` → `(None, None)`.
- Migration v17 aplica clean em DB v16.
- Rows existentes continuam queryáveis (NULL country).

## Critérios de aceitação

- [ ] Migration v17 aplica sem perda.
- [ ] `country` / `city` populados em events novos.
- [ ] Nenhum IP cru em log ou row persistida.
- [ ] p95 lookup < 5 ms.
- [ ] `geo_lookup` falha gracefully em input ruim.
- [ ] ≥ 5 unit tests.
- [ ] `docs/analytics-api.md` atualizado com lifecycle do geo + atribuição GeoLite2.
