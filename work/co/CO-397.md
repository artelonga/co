## As
The platform operator opening CO to the public web at v3.0

## I Need
A first-pass rate-limit + abuse-protection layer on the public API surface, plus standard agent-dispatch headers, so the v3.0 public release survives the first crawler / accidental loop / drive-by abuse without going down.

## So That
- A misbehaving script can't exhaust the Fly machine's RAM or open file descriptors.
- A LLM agent hitting CO can identify itself and respect server-issued backoff.
- The 401/429 error shape is consistent across endpoints so client libraries handle it uniformly.
- This unblocks the v3.0 public launch — soft target ~6 weeks from now.

## Context

After v2.40, the public API is fully open: anonymous GET on `/api/v1/universes/*` returns content, suggest/feedback endpoints accept anonymous POST (with CO-339's basic validation). Today:
- **No global IP rate limit** beyond CO-339's 3/hour on feedback POST
- **No User-Agent identification** required
- **No backoff signaling** (no `Retry-After`, no `X-RateLimit-*` headers)
- **No 429 response** anywhere except CO-339's feedback path
- **No abuse heuristics** (e.g. repeated 404s, requests-from-cloud-IP detection)

The deeper per-tier work with billing semantics (CO-80, CO-278-A token tiers) is post-v3.0. This Phase 1 is the **minimum** to safely open the front door at v3.0 launch.

## Design

### Token-bucket per IP (default budgets)

Implementation: in-memory `governor` crate (axum middleware). Keyed by `X-Forwarded-For` (Fly proxy) with fallback to socket IP.

| Surface | Anonymous budget | Authenticated budget |
|---|---|---|
| GET endpoints | 60/min, burst 120 | 600/min, burst 1200 |
| POST suggest, feedback | 5/min, burst 10 | 30/min, burst 60 |
| Sala/workspace state writes | 30/min, burst 60 (auth only) | n/a |
| Admin endpoints | not allowed | per-route, default 60/min |

### Standard response headers on every `/api/v1/*` request

```
X-RateLimit-Limit:     <budget>
X-RateLimit-Remaining: <n>
X-RateLimit-Reset:     <unix-epoch>
X-Co-Server-Version:   2.40.0
```

On 429:
```
HTTP/1.1 429 Too Many Requests
Retry-After: <seconds>
Content-Type: application/json

{"error": "rate_limited", "retry_after_s": <n>}
```

### Agent-dispatch headers

- Mandatory: `User-Agent` (reject empty UA with 400 `missing_user_agent`)
- Encouraged: `X-Agent-Id` (e.g. `claude-code/2.40.0`), `X-Agent-Operator` (email or URL)
- Don't block on missing optional headers — log them for tuning

### Bot / scraper friendliness

New `GET /robots.txt`:
```
User-agent: *
Allow: /
Disallow: /api/v1/me/
Disallow: /gestao/
Disallow: /_proposals/

Sitemap: https://co-artelonga.fly.dev/sitemap.xml
```

New `GET /sitemap.xml` — auto-generated from public universe list + project list.

### Abuse heuristics (per-IP, 1-minute window)

| Pattern | Action |
|---|---|
| 30+ 404s | temp ban 15 min |
| 10+ 401s | temp ban 15 min |
| 100+ requests on single dynamic path with varying query strings | temp ban 15 min |
| Empty or single-character User-Agent | 400, no ban (just rejected) |

Ban list is in-memory; resets on restart. First-pass simplicity.

### Logging

Every rate-limit event (429, ban, malformed UA) emits a structured log line keyed `co_api_abuse{kind=X,ip_hash=Y}` that ties into CO-361's atividades log. Surface top abusers in `/gestao/resumo` dashboard (CO-360).

### Trusted IPs allowlist

Env var `CO_TRUSTED_IPS` (CSV of CIDRs) bypasses rate limits — for monitoring, GitHub Actions, your own laptop, etc.

## Acceptance

- [ ] 61st GET on `/api/v1/universes/co/entries` from same IP within a minute returns 429 with `Retry-After`
- [ ] All `/api/v1/*` responses include `X-RateLimit-*` headers
- [ ] Authenticated user has 10× higher budget than anonymous
- [ ] Empty User-Agent rejected with 400 `missing_user_agent`
- [ ] `/robots.txt` and `/sitemap.xml` resolve and contain expected entries
- [ ] 31 404s in a minute → temp ban; recovery after 15 min
- [ ] `CO_TRUSTED_IPS=127.0.0.1/32` bypasses limits when set
- [ ] Rate-limit events surface in `/gestao/resumo` activity feed (per CO-361)
- [ ] No regression in CO-339 feedback path (its own 3/hour budget still works)
- [ ] OpenAPI spec (CO-211) documents the 429 response shape

## Blast radius

- ~250 lines new middleware in `co-web/src/platform/rate_limit.rs`
- ~50 lines `robots.txt` + `sitemap.xml` route handlers
- ~30 lines OpenAPI doc updates for 429 response (CO-211 spec)
- ~80 lines abuse-heuristic tracker
- ~150 lines unit + integration tests
- 1 new env var (`CO_TRUSTED_IPS`)
- 0 schema migrations (in-memory state only)

## Dependencies

- CO-211 ✓ shipped — OpenAPI v1 contract; needs 429 response added
- CO-339 ✓ shipped — pattern reference for IP rate limit
- CO-361 (Wave 2 in flight) — atividades log; abuse events route into it

## Not in scope (deferred to CO-278-A or post-v3.0)

- **Per-tier rate limits** with billing semantics (CO-80)
- **API key issuance + tier upgrade UI** (CO-278-A)
- **Persistent ban list** (in-memory only; cold start clears)
- **Captcha** on suggest endpoint (observe abuse first)
- **DDoS protection at edge** (Cloudflare or Fly's own; separate ops decision)
- **Per-universe rate limits** (e.g. mbya = 100/min, yuri = 10/min)
- **Agent dispatch service** (CO-278-D — separate spec, post-v3.0)
