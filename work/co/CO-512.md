GIVEN a self-hoster needs to choose whether co-web is reachable only on the
loopback (single-box, safest default) or on the LAN (a node serving other devices),
and binding `0.0.0.0` by accident is an exposure footgun,
WHEN co-web starts,
THEN the bind host must be configurable via `CO_WEB_HOST`, defaulting to a
loopback-safe `127.0.0.1` for "local" and resolving to `0.0.0.0` only when the
operator explicitly opts into "network", so reachability is an explicit, audited
choice rather than a hard-coded default.

## Acceptance checklist

- [x] `CO_WEB_HOST` controls the listen address; `local` → `127.0.0.1`, `network` → `0.0.0.0`.
- [x] Default (unset) binds the loopback-safe `127.0.0.1`, never `0.0.0.0`.
- [ ] Invalid/unknown values fail loudly (clear error), not a silent fall-through to `0.0.0.0`.
- [ ] The chosen bind host is logged at boot so the operator can confirm reachability.
- [ ] `docs/SELF-HOST.md` documents the local vs network choice and its exposure implications.

## Notes
- Shipped by this PR (`feat/CO-511`) alongside the self-host kit.
- Pairs with the LAN-only hardening kit (CO-514): binding `0.0.0.0` should be done
  behind the pf firewall template + exposure-scan guard, never bare on an untrusted
  network. The default stays loopback so the safe path requires no extra config.
