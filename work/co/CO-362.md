## As
A visitor browsing /artelonga or any universe with historical markdown content

## I Need
HTTP image/script URLs embedded in markdown to be auto-rewritten to HTTPS at render time, so the browser doesn't log dozens of mixed-content warnings.

## So That
- The browser console stays clean — visitor trust signal preserved.
- No silent failures when browsers auto-upgrade fails (HSTS-strict environments).
- Old markdown referencing http-only badges (img.shields.io, f.cl.ly screenshots, etc.) renders cleanly.

## Context

Real example reported by user on `https://co-artelonga.fly.dev/artelonga`:
```
Mixed Content: http://img.shields.io/david/pillarjs/path-to-regexp.svg
Mixed Content: http://img.shields.io/npm/l/path-to-regexp.svg
Mixed Content: http://f.cl.ly/items/18471z1H402O24072r1J/Screenshot.png
Mixed Content: http://zeit-slackin.now.sh/badge.svg
... (8 warnings on /artelonga alone)
```

These come from `~/projects/ArteLonga/` README content with `http://` image URLs (mostly old npm badges + cl.ly screenshots). Browser auto-upgrades to HTTPS today but logs a warning per asset.

## Design

### Where to hook

The markdown-to-HTML renderer in `/Users/artelonga/projects/co/co-web/src/content/` — search for `pulldown_cmark` or `markdown` calls. The conversion happens on entry render (board, conteudo, graph side panel, all use the same renderer).

### The transform

After parsing markdown to HTML (or as a pulldown_cmark event-stream filter), rewrite:
- `<img src="http://...">` → `<img src="https://...">`
- `<a href="http://...">` → keep (links to http sites are OK, just not loaded assets — mixed-content rule only fires on loaded resources)
- `<script src="http://...">` → reject (don't load arbitrary http JS in markdown anyway; emit comment showing original URL for debugging)

Use a simple URL-rewrite function applied to the `src` attribute of `<img>` tags only. NOT a blind string replace (would catch `<a href>` too).

### Whitelist for known-broken-on-https domains

A few domains REFUSE https + need to stay http (or we replace with a placeholder). Maintain a tiny whitelist or fallback strategy:

```rust
fn rewrite_asset_url(url: &str) -> Cow<'_, str> {
    if !url.starts_with("http://") { return Cow::Borrowed(url); }
    // For img.shields.io, f.cl.ly, etc. — known https-supporting:
    Cow::Owned(url.replacen("http://", "https://", 1))
}
```

If a domain is known-broken (rare), prefix to a placeholder image instead.

### Telemetry hook (optional)

Log a one-line counter per render `co_md_http_assets_rewritten_total` so we can see how often this fires. Helps quantify when the source content is fully cleaned.

## Acceptance

- [ ] Markdown body containing `![badge](http://img.shields.io/x.svg)` renders as `<img src="https://...">`.
- [ ] Markdown body containing `[link](http://example.com)` keeps `href="http://..."` (links unchanged).
- [ ] Markdown body containing `<script src="http://...">` is dropped or commented out.
- [ ] `/artelonga` page loads with 0 mixed-content warnings in browser console.
- [ ] Unit test covers all 3 transforms.

## Blast radius

- ~30 lines in the markdown renderer
- ~50 lines unit tests
- No schema changes
- No frontend changes (renderer is server-side)

## Dependencies

- None — this is a content renderer self-contained change

## Not in scope

- Validating that the rewritten https URL actually serves (would need network calls at render time; not worth it)
- Migration of the source markdown to https (separate spec — would PR the ArteLonga repo directly)
- CSP header tightening (separate spec — useful but orthogonal)
- Sanitizing user-submitted HTML (already handled elsewhere via the markdown pipeline)
