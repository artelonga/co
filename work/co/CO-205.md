## As

a visitor on artelonga.com.br who wants to create an account (to access
member resources, join a universe, save preferences) without leaving
the artelonga.com.br domain

## I Need

artelonga.com.br to host a signup form that POSTs to a CO endpoint and
gets the user logged in, with a CO account that's tagged with origin
"artelonga" so we know where they came from

## So That

- artelonga.com.br stops being a static-only frontend dead-end (current
  contact form lands in `leads` table; account creation requires
  redirecting to co.artelonga.com.br)
- product can see which signups came from which entry point (artelonga
  landing, quilombo invite, co direct, yggdrasil game lobby)

---

## Today (2.3.3)

CO-190 (passwordless onboarding) and CO-175 (public username+password
signup) and CO-177 (Google OAuth) already provide all the account-
creation backend. **What's missing for artelonga.com.br:**

1. **CORS allowlist** doesn't yet include artelonga.com.br for the auth
   endpoints (only includes it for `/api/v1/leads` per CO-183).
2. **Origin tracking** — no column on `users` recording "where they
   signed up." When yuri's team launches an artelonga campaign, they
   want to know how many signups it produced.
3. **Cross-domain cookie** — auth cookies are set on `.artelonga.com.br`
   wildcard already (CO-186 handover supports this), but the signup
   POST from artelonga.com.br needs the right CORS + credentials
   handling.
4. **Frontend snippet** — artelonga.com.br needs the JS module to embed
   a signup form that talks to co.artelonga.com.br.

## Schema

```sql
-- Idempotent — runs every boot.
ALTER TABLE users ADD COLUMN origin TEXT;
-- Free-form short string: 'artelonga' | 'co' | 'quilombo' | 'yggdrasil' |
-- 'invitation' | 'google' | 'unknown' (default for pre-CO-205 users).
CREATE INDEX IF NOT EXISTS idx_users_origin ON users(origin);
```

Existing users get `NULL` (or `'unknown'` if we default). No backfill.

## Backend changes

### CORS allowlist

Add `https://artelonga.com.br` (and `https://www.artelonga.com.br`)
to the allowlist for these endpoints:

- `POST /api/v1/auth/onboard-with-email`
- `POST /api/v1/auth/onboard-with-email/verify`
- `POST /api/v1/auth/signup`
- `POST /api/v1/auth/login`
- `GET /api/v1/auth/me` (to check session after signup)
- `POST /api/v1/auth/logout`

Reuse the CORS layer already configured for `/api/v1/leads` (CO-183).

### Origin field on signup endpoints

All three signup paths accept an optional `origin` field. Server-side
sanitizes (max length 32, ASCII letters/numbers/hyphen only) and
persists to `users.origin`.

```jsonc
// POST /api/v1/auth/onboard-with-email
{
  "email": "guest@example.com",
  "origin": "artelonga"     // NEW — optional
}

// POST /api/v1/auth/signup (username+password)
{
  "usuario": "...",
  "senha": "...",
  "email": "...",
  "origin": "artelonga"     // NEW — optional
}

// POST /api/v1/auth/google/callback (or wherever Google completes)
// The state JWT minted at /auth/google/start captures the origin and
// passes it through to user creation.
```

### Cookie domain

For artelonga.com.br to read the session cookie set by co.artelonga.com.br,
the cookie domain must be `.artelonga.com.br` (with leading dot — covers
all subdomains). Already configured per CO-186 / CO-184 handover work;
verify it actually applies to the auth-issued cookies and not just
handover-token cookies.

Existing setting:
```rust
// in cookie header construction
let cookie_domain = config.cookie_domain.as_deref().unwrap_or("");
```

Should resolve to `.artelonga.com.br` when `CO_COOKIE_DOMAIN` env is set.

### Admin telemetry endpoint

`GET /api/v1/admin/users/origin-breakdown` (admin gate):

```jsonc
{
  "origins": [
    { "origin": "co", "user_count": 47 },
    { "origin": "quilombo", "user_count": 12 },
    { "origin": "artelonga", "user_count": 3 },
    { "origin": null, "user_count": 8 }
  ],
  "total_users": 70
}
```

Charts in a future admin dashboard ticket.

## Frontend — artelonga.com.br side

Lives in the **artelonga repo**, not CO. This ticket spec only describes
what the artelonga side needs to do; the actual file lands in that repo
as a sibling ticket (AL-N).

```html
<!-- artelonga.com.br/signup/index.html -->
<form id="al-signup" data-origin="artelonga">
    <input type="email" name="email" placeholder="email@exemplo.com" required>
    <button type="submit">Continuar</button>
</form>
<div id="al-code-step" hidden>
    <input type="text" inputmode="numeric" maxlength="6" placeholder="código">
    <button>Confirmar</button>
</div>

<script type="module" src="/al-signup.js"></script>
```

```js
// artelonga.com.br/al-signup.js — tiny module
const CO_BASE = 'https://co.artelonga.com.br';
const form = document.getElementById('al-signup');
form.addEventListener('submit', async e => {
    e.preventDefault();
    const email = form.email.value;
    const r = await fetch(`${CO_BASE}/api/v1/auth/onboard-with-email`, {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ email, origin: 'artelonga' }),
    });
    if (r.ok) showCodeStep();
});
```

After verify, the session cookie is set on `.artelonga.com.br` so
artelonga.com.br can detect logged-in state via `GET /api/v1/auth/me`
(also with `credentials: 'include'`).

## Acceptance

- [ ] CORS allows `https://artelonga.com.br` on auth endpoints with
      credentials.
- [ ] All three signup paths accept and persist `origin` field.
- [ ] `users.origin` populated correctly for new signups; existing
      users stay NULL.
- [ ] Cookie set after signup is readable on artelonga.com.br (manual
      browser check; document via `document.cookie` from devtools on
      artelonga.com.br after signing up cross-domain).
- [ ] Admin breakdown endpoint works.
- [ ] Origin sanitizer rejects malformed values silently (stores NULL
      rather than echoing user-supplied junk).
- [ ] No regression on existing co.artelonga.com.br signup flows.
- [ ] Tests: 6+ covering CORS preflight, origin persist, origin sanitize,
      admin breakdown.
