## As

the maintainer of the CO test suite

## I Need

mobile viewports to be first-class in CI — the Playwright config runs Pixel 7, iPhone 14, and iPad Pro on every PR, and the skip-on-mobile gates added back when the mobile UX was broken get removed where the feature now works.

## So That

mobile regressions get caught at PR time, not by users on phones two releases later. The current 8+ files that contain `test.skip(!!(vp && vp.width <= 640))` are an honest signal we never tested those flows on mobile; once CO-358 (mobile IA pass) lands, those gates are obsolete and must come off.

## Context

Files containing mobile skip gates today:

```
co-web/e2e/localhost-trial.spec.ts        (4 occurrences)
co-web/e2e/pipeline-workflow.spec.ts      (1)
co-web/e2e/codemirror.spec.ts             (1)
co-web/e2e/subtask-tree.spec.ts           (1)
co-web/e2e/board-drag.spec.ts             (1)
co-web/e2e/archived/auth-crdt.spec.ts     (1 — archived, ignore)
```

Plus implicit skips: 17 of 21 active spec files have no `devices['…']` projection in `playwright.config.ts`, so they only ever run desktop Chromium. That's the bigger gap.

Current `/Users/artelonga/projects/co/co-web/playwright.config.ts` is 87 lines and (presumably — confirm in build) defines a single desktop project. Need to extend to a matrix.

## Design

### 1. Playwright project matrix

Extend `/Users/artelonga/projects/co/co-web/playwright.config.ts`:

```ts
import { devices } from '@playwright/test';

projects: [
  { name: 'desktop-chromium', use: { ...devices['Desktop Chrome'] } },
  { name: 'pixel-7',          use: { ...devices['Pixel 7'] } },
  { name: 'iphone-14',        use: { ...devices['iPhone 14'] } },
  { name: 'ipad-pro',         use: { ...devices['iPad Pro 11'] } },
],
```

The existing `vp` viewport detection in tests (`page.viewportSize()` → `vp.width`) already differentiates correctly; no test-side changes needed for that signal.

### 2. Remove skip gates where mobile now works

After CO-358 ships, the following flows should pass on mobile:

| File | Skipped flow | Why it should now work |
|---|---|---|
| `localhost-trial.spec.ts` | sidebar interactions (4×) | drawer sidebar (CO-358 §2) |
| `pipeline-workflow.spec.ts` | sidebar | drawer sidebar |
| `codemirror.spec.ts` | sidebar | drawer sidebar |
| `subtask-tree.spec.ts` | sidebar | drawer sidebar |
| `board-drag.spec.ts` | drag-and-drop | board reflow + long-press-to-grab (CO-358 §4) |

Remove the `test.skip(!!(vp && vp.width <= 640), …)` lines in each. Where drag-and-drop on mobile is too flaky, replace with a "use Move-to menu" path (already exists as fallback per CO-358 §4).

Leave skipped:
- Sala canvas tests (CO-352 deferral — explicitly not mobile)
- Anything reading the desktop overflow menu literally (rewrite to use the mobile kebab)

### 3. GitHub Actions matrix

Edit `.github/workflows/ci.yml` (or whatever the current CI workflow is — confirm under `/Users/artelonga/projects/co/.github/workflows/`):

```yaml
jobs:
  e2e:
    strategy:
      fail-fast: false
      matrix:
        project: [desktop-chromium, pixel-7, iphone-14, ipad-pro]
    steps:
      ...
      - run: npx playwright test --project=${{ matrix.project }}
```

If CI runtime budget is a concern, run only `desktop-chromium` + `pixel-7` on every PR and the full matrix nightly + on release branches.

### 4. Coverage target

After CO-358 + this ticket, the following anonymous read-mode flows must pass on all 4 projects:

- Land on `/` → board visible, 7 tutorial tasks shown
- Switch theme (mobile via kebab → theme submenu)
- Switch language (PT ↔ EN)
- Open sidebar drawer, navigate to a universe entry
- Open an entry, scroll, close (back arrow)
- Search / locate
- Suggest mode (form-based — already mobile-friendly)
- Install prompt (mocked or asserted via `beforeinstallprompt` polyfill)

### 5. Selector hygiene

Where tests rely on hover-only desktop affordances (`page.hover('.foo')` revealing a button), refactor to use `data-testid` + tap directly, since mobile has no hover. Audit `helpers.ts` for any hover-based helpers and split desktop/mobile variants.

### 6. Test output

Set `reporter: [['html'], ['list']]` and upload the HTML report per matrix project to GH Actions artifacts (one artifact per project so failures are easy to triage by device).
