## As

a reader of `yoruba/terms/ogunte.md` (which embeds the meuorixa.wordpress.com excerpt with cross-links to seven other terms)

## I Need

CO to treat `references` as a first-class content type — extracting each `{url, source, retrieved}` object from term frontmatter into a `references` table, indexing the body excerpt under `## Referência: <source>` for full-text search, and exposing both via API

## To

make the dictionary self-extending: every reference is a candidate for new term entries (the wikilinks already mark which terms exist; `(TODO: criar entrada)` markers flag which don't), and a search across "all references citing meuorixa.wordpress.com" or "all excerpts mentioning Yemanjá" becomes possible

---

## Schema (per-universe `data.db`)

```sql
CREATE TABLE references_index (
    universe_key  TEXT NOT NULL,
    entry_path    TEXT NOT NULL,
    ref_index     INTEGER NOT NULL,         -- 0-based position in references[] array
    url           TEXT,
    source        TEXT NOT NULL,
    retrieved     TEXT,                      -- ISO 8601
    excerpt_body  TEXT,                      -- the full ## Referência: section body
    PRIMARY KEY (universe_key, entry_path, ref_index)
);

CREATE INDEX idx_refs_source ON references_index(source);
CREATE INDEX idx_refs_url    ON references_index(url) WHERE url IS NOT NULL;

-- FTS over the excerpt body so "search references for 'orixá da maternidade'"
-- returns the matching ## Referência: section verbatim.
CREATE VIRTUAL TABLE references_fts USING fts5(
    universe_key UNINDEXED,
    entry_path   UNINDEXED,
    ref_index    UNINDEXED,
    source,
    excerpt_body
);
```

## Extraction

On every entry write, after frontmatter parsing:

1. For each item in `frontmatter.references[]`, upsert a row into `references_index`.
2. Walk the body for `## Referência: <source>` headings; the section body up to the next H2 (or EOF) is the `excerpt_body`. Match heading source to a `references[]` entry (or fail loudly — heading without manifest entry is a content-author bug).
3. Update `references_fts` with the same content.

Backfill: one-shot pass on first boot after this deploy walks every entry in every universe and builds the table.

## API

```
GET /api/v1/universes/{u}/references
    ?source=<exact>      # filter by source
    ?url_contains=<sub>  # substring match on url
    ?q=<fts>             # FTS over excerpts
    → { references: [{path, ref_index, url, source, retrieved, excerpt_body}], total }

GET /api/v1/universes/{u}/references/orphan-wikilinks
    → list of `[[term-key]]` mentions inside ## Referência: sections that
      have no corresponding `terms/<term-key>.md` — the candidate-entry
      backlog
```

- [ ] On every entry write, references are extracted from frontmatter and body

- [ ] `GET /references?q=orixá+maternidade` returns the matching FTS row
- [ ] `GET /references/orphan-wikilinks` for `yoruba` returns terms mentioned inside ## Referência: sections that don't have entries yet (the backlog)

## Out of scope

- Cross-universe joins on references (e.g. "all terms across all language planes citing source X"). Possible follow-up; this ticket scopes to per-universe.
- Citation-style rendering (APA/MLA/Chicago). UI concern.
- Auto-fetching the URL for archival. CO-115 territory.
