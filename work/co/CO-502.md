GIVEN the loop is **input → síntese → A/B/C** with **no gate between organize and
map** (CO-498 executes by default), and the synthesized substrate should be
*seen* before it ships — A (co-web) and B (yggdrasil) both rendering the **same
content substrate** live on localhost — while publish/send stays the single
deliberate human hit,
WHEN an item is synthesized, A and B auto-render it locally (co-web on the
`89xx`/`8900-9699` range, yggdrasil on the `81xx`/`8100-8899` range) with
live-reload,
THEN the operator reviews the live A/B prototype and, with one command, publishes
(the one deliberate hit) — and with one command unpublishes (versioned rollback) —
with everything between input and that hit happening automatically.

## Acceptance

- [x] `scripts/ab-localhost.sh` brings up **A (co-web)** and **B (yggdrasil)** over
  the **same content substrate**, live-reloading on synthesis writes; A on a
  `co-web` port in **8900–9699**, B on a yggdrasil port in **8100–8899** (the
  CO↔yggdrasil port alignment — no collision).
- [ ] **No gate** between organize (A/Jardim) and map (B/render): both views update
  from the shared substrate automatically; the loop never pauses for approval here.
- [x] `scripts/publish.sh` is the **one deliberate hit** — promotes the reviewed
  substrate to the published target; **one-hit unpublish** does a **versioned
  rollback** (revert to the prior published version, not a destructive delete).
- [ ] **Shared-substrate contract** documented: what A and B both read, and the
  yggdrasil **live-reload coordination** (how a co-web write triggers the yggdrasil
  view to re-render the same content).
- [x] Scripts are idempotent and self-hostable (no managed infra required to run the
  A/B localhost loop). `CHANGELOG-PENDING/CO-502.md`.
