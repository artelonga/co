## What shipped (PR #152)

CO-340 shipped a different scope than this spec was originally drafted for. The actual shipped work:

- **`analytics_rollups` table** (migration v58, PK `(universe_key, day)`)
- **`POST /api/v1/analytics/public/rollups`** — idempotent upsert of `DailyRollup` from any producer; bearer `CO_ROLLUP_TOKEN` gate
- **`GET /api/v1/analytics/public/summary?universe=<id>`** — default `artelonga`; lets the general dashboard scope to any universe
- **Historical-path bridge**: event match `universe_key = X OR path LIKE '/X/%'` captures pre-CNAME `/yuri` traffic; rollups overlay at the cutover so no double-count

## Why this anomaly

The agent invoked under "CO-340" read an analytics-framework doc from `artelonga/ArteLonga/docs/analytics-framework.md` and implemented that instead of the wikilink resolver this file originally specified. Useful work, just surprise scope.

## Original intent moved to CO-363

The **cross-universe wikilink resolver** (`[[key::path]]` → `entry_relations.to_universe`) — which was the original CO-340 spec — has been moved to **CO-363**. CO-345 (cross-universe graph view) depends on CO-363, not on this file.
