GIVEN the open platform's **published docs** still name private tenants/repos —
`quilombo`, `rfq`, `pointset` appear in `co-web/src/MODULES.md`, the `CHANGELOG`, and
scattered docs — which leaks tenant identity into the generalist platform's
public-facing material,
WHEN we scrub those references and generalize the wording (describe the *capability*,
not the tenant),
THEN the published docs read as a tenant-agnostic general agent platform, with no
private-repo names in the surfaces a reader/consumer sees.

## Acceptance

- [ ] `co-web/src/MODULES.md` scrubbed of `quilombo` / `rfq` / `pointset` references;
  wording generalized (e.g. "a tenant universe" / "an external backend").
- [ ] `CHANGELOG.md` private-tenant mentions generalized in the **published** entries
  (respecting the forbidden-files release process — coordinate with the release commit,
  do not hand-edit version/headers).
- [ ] Other `docs/` surfaces grepped for the same names and generalized.
- [ ] Wording describes the **capability/pattern**, not the tenant (stays accurate
  without naming a private repo).
- [ ] `grep -riE 'quilombo|rfq|pointset' co-web/src/MODULES.md docs/` returns nothing
  in published material (beyond any intentional, owner-approved exception).

## Notes
- **Git-history rewrite is explicitly OUT OF SCOPE.** Commit-message mentions of a
  repo name are not secrets, and rewriting shared `main` history is destructive — owner
  decision is to **default-skip** the history rewrite. This task only touches current
  published docs/changelog content.
- Pairs with CO-509 (the code-extraction half); this is the docs/changelog half of
  generalist-cleanup.
- `CHANGELOG.md` is a forbidden file under the release process — generalize via the
  proper release flow, not a direct version-bumping edit.
