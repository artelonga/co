## As
Um desenvolvedor estendendo o co, QUERO adicionar um subscriber de evento, um
source novo (gitlab/notion) ou um backend de admin-auth (SAML/OIDC) plugando um
`impl` num registry — não editando os sites hardcoded — PARA estender sem fork.

## Contexto técnico (do audit 2026-06-12)
Três pontos de extensão hoje são hardcoded:
1. **EDA subscribers**: ~13 `spawn()` explícitos em `server/mod.rs` (atividades,
   analytics, sala, kb, comunicacao_live, yggdrasil_notes, delivery_pipeline,
   timeline, findings_persistor, pbi_backlogger, release_blocker,
   degradation_alerter, usage-bridge). Adicionar um exige editar o boot.
2. **Source sync**: o sync do Yggdrasil é um subscriber hardcoded
   (`comunicacao_live.rs`), não um `SourceAdapter` — gitlab/notion exigiriam
   subscriber custom. (O adapter `co source add github` do CO-417/423 é a outra
   metade a generalizar.)
3. **Admin auth**: `integrations/github_auth.rs` (PAT do GitHub) sem trait;
   usado em ≥4 arquivos. Trocar por SAML/OIDC exige reescrever os 4.

## Acceptance
- [ ] `trait EdaSubscriber { fn name(&self); fn filter(&self) -> Filter; async
      fn handle(&self, ev: &Event, ctx: &SubscriberCtx); }` + um registry; o boot
      itera o registry em vez de `spawn()` inline. Os subscribers atuais migram
      para o trait sem mudar comportamento. Um subscriber de teste registra-se
      sem tocar `server/mod.rs`.
- [ ] `trait SourceAdapter { fn kind(&self); async fn fetch/sync(...); }` com a
      impl `github` (consolidando CO-417/423); o sync do Yggdrasil expresso como
      adapter/registry. Adicionar um source novo = novo `impl` + registro.
- [ ] `trait AdminAuthProvider { async fn verify_admin(&self, token) ->
      Result<AdminIdentity>; }` extraído; `github_auth` vira a impl default; os
      ≥4 call-sites passam a depender do trait (injeção via Extension/estado).
- [ ] **Rate-limit trait (absorve CO-297 / CO-284-H):** `trait RateLimiter {
      fn try_acquire(...) }` extraído com a impl in-process (governor) atual como
      default; comportamento de rate-limit inalterado. É o último trait da série
      CO-284 ainda não extraído — completa o conjunto. (Sem impl Redis aqui.)
- [ ] **Sem mudança de comportamento**: mesmos subscribers/admins/limites ativos
      por default; `cargo test -p co-web` verde; clippy limpo; sem drift de rotas.
- [ ] Nada de MCP — superfícies CLI/arquivo/API/trait apenas (decisão 2026-05-04).

## Notas
Composição pura: cada seam é "registry + trait + impl default". Não muda o que
roda hoje; muda como se adiciona o próximo. Pode ser entregue em 3 commits
(um por seam) dentro de um PR.
