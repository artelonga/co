## Contexto
CO-278-A: dar à API pública **uma forma única** — `{ data, meta, errors }` — em
**todas** as rotas `/api/v1/*`, + headers de versão. Restrição dura medida em
2026-06-14: o SPA tem **55 chamadas `fetch()` cruas** (só parte passa pelo
`api/client.js`); um envelope **incondicional** quebra o SPA e consumidores
externos no deploy. Logo, o envelope é **opt-in** e implementado num **único
ponto** (response layer), não em 80 handlers.

## Design — UM ponto, opt-in, zero-break
- **Response layer** (axum `map_response`/middleware) sobre o router `/api/v1`:
  - Se o request traz **`X-API-Envelope: 1`** (ou `Accept: application/vnd.co.v1+json`),
    embrulha o corpo JSON de sucesso em `{ data: <body>, meta, errors: null }`.
  - Sem o marcador → **corpo cru, inalterado** (SPA e consumidores atuais intactos).
  - **NUNCA** embrulha respostas não-JSON (HTML/CSS/stream/binário) — passa direto.
- **Erros**: o `AppError::into_response` (existente), quando o marcador está ativo,
  emite `{ data: null, meta, errors: [{ code, message, field?, hint? }] }` com o mesmo
  status HTTP. Sem marcador → forma de erro atual.
- **`meta`**: `{ request_id (uuid), api_version: "1.0" }`; quando o handler já expõe
  paginação, propagar `page/page_size/total` (best-effort; não inventar).
- **Headers SEMPRE ligados (aditivos, não quebram parser de corpo)**:
  `X-API-Version: 1.0` e `X-Co-Server-Version: <workspace version>` em todas as
  respostas `/api/v1/*`.
- **Sem migração. Sem tabela nova.** (As migrações do épico — `agent_runs`,
  `api_tokens.tier` — são do CO-278-D / rate-limit, FORA desta fatia.)

## Acceptance
- [ ] Header opt-in (`X-API-Envelope: 1`) ativa o envelope em **qualquer** rota `/api/v1/*` de sucesso, via **um único response layer** (não edição por-handler).
- [ ] Sem o header, o corpo é **byte-idêntico** ao atual (prova de não-quebra).
- [ ] Erros (4xx/5xx) com header ativo → `{data:null, meta, errors:[{code,message,field?,hint?}]}`, mesmo status.
- [ ] Respostas não-JSON nunca são embrulhadas (theme.css, HTML, streams, blobs).
- [ ] `X-API-Version: 1.0` + `X-Co-Server-Version` presentes em todas as respostas `/api/v1/*` (com e sem opt-in).
- [ ] `meta.request_id` (uuid) + `meta.api_version` presentes; paginação propagada onde já existe.
- [ ] Testes de integração (tower::ServiceExt): (a) rota de sucesso com/sem header, (b) rota de erro com header, (c) rota não-JSON nunca embrulhada, (d) headers de versão presentes.
- [ ] **e2e VERDE sem mudar o SPA** — o SPA não manda o header, então não vê envelope; qualquer regressão e2e = bug do layer (gate duro: não faz merge se e2e quebrar).
- [ ] `api-catalog.md` documenta a convenção do envelope + o header opt-in; `openapi:check` sem drift; aparece no Swagger (CO-452).
- [ ] `cargo test` + `clippy -D warnings` + `fmt` limpos; sem MCP; sem migração.

## So that
A API pública ganha o **contrato de forma única** que o CO-278 pede — disponível
em todas as rotas **já**, sem coordenar a atualização de 55 call-sites do SPA nem
quebrar consumidores. Vira o default num PR de uma linha quando todos adotarem o
header (migração segura, não big-bang).

## Não no escopo
- Tornar o envelope **default/incondicional** (follow-up, após consumidores adotarem).
- Rate-limit por tier / `api_tokens.tier` (CO-278-B/-A rate-limit) · agent dispatch (CO-278-D) · SDK (CO-278-F).
- Atualizar os 55 fetch() do SPA (desnecessário enquanto opt-in).
