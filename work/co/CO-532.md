GIVEN the biggest efficiency lever in an agent loop is **how much the model has to
read** — and `chopratejas/headroom` demonstrates a context-compression technique
that cuts what the model ingests by **60-95%** with the same task outcome — and
CO-504's tool-calling loop is the single place that assembles the model's context,
WHEN we make the runtime efficient (compose > new code: absorb the *method*, add no
fork and no new dependency),
THEN the runtime compresses its context window in CO-504's loop (history, tool
results, retrieved passages) before each model call — a **technique, not a tool** —
landing the largest token-efficiency win without binary bloat.

## Acceptance

- [ ] **Technique, not a dependency.** The headroom context-compression *method* is
  absorbed into CO's own agent runtime — **no new crate/fork, no external service**.
  The implementation lives in the CO-504 loop, not behind a manifest.
- [ ] **Compresses what the model reads.** Before each model call the loop compresses
  the assembled context (conversation history, prior tool results, retrieved chunks),
  targeting the headroom **60-95%** reduction band while preserving task fidelity.
- [ ] **Measured.** The runtime records tokens-before vs tokens-after per call so the
  reduction is observable (and regressions catchable); a representative loop shows the
  drop.
- [ ] **Loss-bounded / opt-out.** Compression is bounded so it never silently drops
  load-bearing context; it is configurable (threshold / off) and degrades to passthrough.
- [ ] **Backend-agnostic.** Works for any model behind the CO-504 `Backend` trait
  (local Ollama default / Claude / any) — compression is upstream of the backend.
- [ ] CHANGELOG-PENDING/CO-532.md.
