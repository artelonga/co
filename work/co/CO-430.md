## Mythos — the foundational architecture pass

A final architectural audit (2026-06-12, four-angle: crate structure, internal
coupling, external consumption, extensibility seams) found a **clean domain
core** and a **proven layering template**, but the gains stopped at the spike.
"Mythos" finishes the narrative: make every co component a modular, composable
seam that **external services — universes, Yggdrasil, CLI/mobile, future S3 —
consume without forking core code.**

## Audit verdict (what's true today)

**Strong (keep, don't touch):**
- `core/` is a clean reusable domain library — no axum/tokio/rusqlite leakage.
- `EdaBus` trait + JSON events are an excellent external-integration contract
  (yggdrasil_notes / comunicacao_live subscribers prove federation works).
- Vault API is Obsidian-compatible and transport-agnostic.
- Storage is already split by impl-dispatch (26 files, ~10–25 methods each) — no
  god-struct; the seams to extract repositories from are clean.

**Weak (Mythos targets these):**
1. The **CO-390 layered template (domain/dto/repository/service/mapper) landed
   for `entries` only (~10% adoption).** Pattern proven, not propagated.
2. `content/` is a **god-folder** — 37 flat files, 10+ entities mixed.
3. Global **`Mutex<Storage>` bottleneck** — every handler locks one mutex;
   different universes serialize needlessly. Plus raw SQL in security/auth
   bypasses the storage layer.
4. The **`Universo` trait is clean but hardcoded to `UniversoLocal`** (no
   factory) and **lives in co-web, not core** — external consumers must pull the
   whole server to use it.
5. **`SecretsProvider` bypassed 124×** by direct `std::env` reads — blocks
   swappable secrets and the S3 config roadmap.
6. **Hardcoded extension wiring**: EDA subscribers spawned inline in
   `server/mod.rs`; GitHub admin auth has no trait; source sync (Yggdrasil) is a
   hardcoded subscriber, not a `SourceAdapter`.
7. **`game-core` Plugin trait hardcodes `axum::Router`** — forces every game
   impl (Yggdrasil, CLI, mobile) to depend on Axum.
8. `migrations.rs` (2769 LoC) + `seed.rs` (2530 LoC) are monoliths; seed belongs
   in boot, not the data-access layer.

## Principles (binding for all children)

- **No behavior change.** This is `type:refactor` — every PR keeps `cargo test`
  green and the HTTP/API/event contracts byte-identical. Characterization tests
  before extraction.
- **Trait at the seam, impl behind it.** Each task leaves a clean extension
  point so an external service adds an `impl`, never edits core.
- **Propagate, don't re-invent.** CO-390's entries layering is the template;
  copy it, don't redesign per entity.
- **Sequencing:** runs **after the CO-424 wave deploys** (CO-426/427/429 touch
  the same co-web/co-auto files) to avoid rebase collisions. One coherent
  refactor release (a MINOR — `refactor` that reshapes public seams).

## Execution decisions (owner, 2026-06-12) — BINDING
- **Executor model: Fable → Opus (2026-06-13), quality-first.** CO-431/432 ran on
  Fable. Mid-wave **both `mythos` and `fable` endpoints went `404`** (probed). For
  these **no-behavior-change architecture refactors the acceptance criteria are
  strict** (sharded locking proven by a contention test, zero raw SQL in handlers,
  identical contracts) — so the fallback is **Opus**, not Sonnet (owner steer
  2026-06-13: "not opus or mythos fallback? be extra careful with AC"). Quality
  over budget for this epic. Revert to mythos/fable when their endpoints recover.
- **Rigor: characterization-tested, SERIAL, full review per PR.** Each child
  writes characterization tests pinning current behavior BEFORE extracting; one
  co-auto run at a time; FF main between; a focused review of the high-risk areas
  (storage locks, raw-SQL removal, route/contract parity) before every merge.
- **Order:** CO-431 (domain→core seam) → CO-432 (content split) → CO-433
  (storage shard, depends on 431) → CO-434 (secrets) → CO-435 (registries) →
  CO-436 (game-core + migrations). 431 and 433 are the keystones; 434/435/436 are
  independent and can reorder.
- **Companion instrumentation:** CO-437 (under CO-424) enriches usage capture
  (tool usage, outputs, PR links) and adds per-model-per-universe breakdown so
  the cost of this refactor wave is measured and a future `mythos` model can be
  estimated against Fable/Opus/Sonnet.
