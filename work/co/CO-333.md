## As
A visitor to any universe (yuri.artelonga.com.br, artelonga.com.br, etc.) wanting to leave feedback on a specific entry, AND Yuri/owner wanting to review feedback **in locus** — at the entry where it was left, not in a separate inbox

## I Need
A feedback system that's API-compatible with Yggdrasil's existing one (so the same widget/UI works) AND extends it with per-entry scoping so feedback can be reviewed at the exact entry it pertains to.

## So That
- Visitors give feedback without leaving the page they were reading
- Owner reviews feedback inline on the entry view (single workflow)
- Same UI components can be shared across CO and Yggdrasil (or federated)

## Reference: Yggdrasil's shape

From `yggdrasil-web/src/feedback.rs` (study source, don't copy unless needed):
```sql
CREATE TABLE feedback (
    id TEXT PRIMARY KEY,
    universe TEXT NOT NULL,
    kind TEXT NOT NULL,         -- 'feedback' | 'duvida' | 'sugestao'
    message TEXT NOT NULL,
    name TEXT,                  -- optional
    email TEXT,                 -- optional
    user_sub TEXT,              -- JWT subject when logged in
    anonymous INTEGER NOT NULL, -- 0 or 1
    created_at INTEGER NOT NULL
);
```

Endpoint: `POST /api/v1/feedback { universe, kind, message, name?, email? }`.

## Design — additive extension

### Schema (one new column)

```sql
CREATE TABLE IF NOT EXISTS feedback (
    id           TEXT    PRIMARY KEY,
    universe_key TEXT    NOT NULL,
    entry_path   TEXT,                     -- NEW: NULL = universe-wide; set = per-entry locus
    kind         TEXT    NOT NULL CHECK (kind IN ('feedback','duvida','sugestao')),
    message      TEXT    NOT NULL,
    name         TEXT,
    email        TEXT,
    user_sub     TEXT,
    anonymous    INTEGER NOT NULL,
    created_at   INTEGER NOT NULL,
    status       TEXT    NOT NULL DEFAULT 'open'   -- 'open' | 'reviewed' | 'addressed'
);
CREATE INDEX idx_feedback_universe_path ON feedback(universe_key, entry_path, created_at);
CREATE INDEX idx_feedback_status ON feedback(status);
```

`entry_path` NULL preserves Yggdrasil's "universe-wide" semantic; set value attaches to that entry.

### API (Yggdrasil-compatible + locus extensions)

```
POST /api/v1/feedback                         (compat — universe-wide if no entry_path)
POST /api/v1/feedback/<universe>/<entry-path> (NEW — per-entry)
GET  /api/v1/feedback/<universe>              (list all; owner-only includes private notes)
GET  /api/v1/feedback/<universe>/entry/<path> (list for that entry, anonymous-safe)
PATCH /api/v1/feedback/<id> { status }        (owner-only status update)
```

CO accepts the original Yggdrasil shape (`universe` in body) and the locus extension (`entry_path` in URL).

### UI

#### Widget (visitor-facing)
- Drop-in `feedback.js` script tag works on any universe page
- Reads current URL → infers `universe` + `entry_path`
- Floating button bottom-left (yggdrasil places it bottom-right; left avoids the CO-332 chat widget collision)
- Modal: kind selector (feedback/dúvida/sugestão), message, optional name+email, anon checkbox
- Submits to `POST /api/v1/feedback/<universe>/<entry_path>`

#### Owner review (in locus)
- On the entry view: small badge `📩 3 unread` if there's open feedback on this entry
- Click → side panel slides in with all feedback for this entry, status-grouped
- Each item: actions `mark reviewed`, `mark addressed`, `reply via email` (if email provided)
- Mural view (cross-entry, mirrors Yggdrasil's): `/feedback` lists all open across all entries

#### Universe-level mural
- `GET /universe/<key>/feedback` page (owner sees all; anon sees public mural respecting `kind=sugestao` only or similar policy)

### Federation with Yggdrasil

CO ships its own feedback DB by default. Optional federation:
- Env var `CO_FEEDBACK_FORWARD_URL=https://yggdrasil.artelonga.com.br/api/v1/feedback`
- When set, every POST to CO is also fired off to that URL (async, non-blocking)
- Use case: Yggdrasil's mural can centralize feedback from all sister sites if desired
- No federation by default — single-DB is fine for v1

### Integration with CO-332 (chat)

Visitors using the chat assistant can leave feedback via the chat: assistant exposes a `submit_feedback(kind, message)` tool. LLM extracts intent ("this article isn't quite right, you got the year wrong") → calls the tool → message stored in the same feedback table.
