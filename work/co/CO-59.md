GIVEN co auto v1 requires `--space`, `--data-dir`, `--workspace` flags and assumes a specific `data/{space}/` layout inside another repo,
WHEN I rewrite co auto to take a single repo argument and handle everything internally,
THEN:

## Usage

```bash
co auto artelonga/co-dev              # Run once (next task)
co auto artelonga/co-dev --cycle      # Loop through all tasks
co auto artelonga/co-dev --task CO-49 # Run specific task
co auto artelonga/co-dev --dry-run    # Preview without executing
co auto .                             # Use current directory as repo
```

One argument. The repo slug (GitHub `owner/name`) or `.` for local directory.

## Pipeline

```
co auto artelonga/co-dev --cycle
  │
  ▼
┌─ 1. RESOLVE REPO ──────────────────────────┐
│  If "owner/repo" format:                    │
│    Check ~/.co/repos/artelonga/co-dev/      │
│    If exists: git pull origin main          │
│    If not: git clone --depth 1              │
│  If ".": use current directory              │
│  Result: local path to repo root            │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 2. LOAD PROJECT ──────────────────────────┐
│  Read project.yaml → key, next_id          │
│  Read .universo.yaml → name, config        │
│  Glob *.md matching {KEY}-*.md pattern      │
│  Parse frontmatter → Vec<Task>              │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 3. SELECT TASK ───────────────────────────┐
│  Same logic as v1:                          │
│  Filter: todo | in_progress                 │
│  Exclude: epic label                        │
│  Exclude: parent blocked                    │
│  Sort: in_progress → priority → id          │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 4. CREATE WORKTREE ──────────────────────┐
│  Branch: co-auto/{KEY}-{id}-{nanoid}       │
│  Worktree: ~/.co/worktrees/{branch}/       │
│  git worktree add <path> -b <branch>       │
│  Copies task context into worktree          │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 5. BUILD CONTEXT ────────────────────────┐
│  Same 5-layer approach as v1:              │
│  1. CLAUDE.md (from repo root)             │
│  2. Task body (the .md file)               │
│  3. Parent/epic context                    │
│  4. project.yaml                           │
│  5. ROADMAP.md (any ROADMAP*.md files)     │
│  + Completed tasks list                    │
│  → Written to .claude/co-auto-context.md   │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 6. LAUNCH CLAUDE CODE ──────────────────┐
│  claude -p "YOUR TASK: CO-49 — ..."       │
│  --dangerously-skip-permissions            │
│  Working directory: worktree path          │
│  Headless by default, --interactive flag   │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 7. REVIEW + COMMIT ────────────────────┐
│  Check: cargo test / cargo clippy passes │
│  Check: git diff shows changes           │
│  If pass:                                │
│    Update task status → done             │
│    git add + commit (conventional)       │
│    git push origin {branch}              │
│  If fail:                                │
│    Update task status → review           │
│    Keep worktree for inspection          │
└─────────────────────────────────────────────┘
  │
  ▼
┌─ 8. MERGE + CLEANUP ───────────────────┐
│  git checkout main                      │
│  git merge {branch} --no-ff             │
│  git push origin main                   │
│  git worktree remove <path>             │
│  git branch -d {branch}                 │
│  If --cycle: go to step 2               │
└─────────────────────────────────────────────┘
```

## Repo Layout Convention

Any repo can be a co auto workspace if it has:

```
my-repo/
├── project.yaml          # REQUIRED: key, name, next_id
├── .universo.yaml         # OPTIONAL: universe config (theme, visibility)
├── CLAUDE.md              # OPTIONAL: dev conventions (fed to Claude as context)
├── ROADMAP.md             # OPTIONAL: execution order
├── {KEY}-1.md             # Tasks (frontmatter: id, title, status, priority, labels)
├── {KEY}-2.md
└── ...
```

That's it. No `data/` subdirectory. No workspace nesting. The repo root IS the workspace.

## Local Repo Cache

```
~/.co/
├── repos/                    # Cloned repos (managed by co auto)
│   └── artelonga/
│       └── co-dev/           # git clone of artelonga/co-dev
├── worktrees/                # Active worktrees (temporary)
│   └── co-auto-CO-49-abc123/
└── config.yaml               # Global config (default model, etc.)
```

## Backward Compatibility

- `co auto --space co` still works (looks for `data/co/` in current workspace, v1 behavior)
- `co auto artelonga/co-dev` is the new v2 behavior
- `co auto .` uses CWD as repo root (detects project.yaml)
- `co auto --data-dir /path` still works (explicit override)

Detection: if first arg matches `owner/repo` pattern or is `.`, use v2. Otherwise fall back to v1 `--space` behavior.

## Auth for Private Repos

- Public repos: `git clone https://github.com/{owner}/{repo}.git`
- Private repos: `git clone git@github.com:{owner}/{repo}.git` (uses user's SSH key)
- The user's `~/.ssh/` keys are used automatically (standard git behavior)
- No special Co auth needed — if you can `git clone` the repo, co auto can too

## Parallel Execution

Worktrees enable parallelism:
```bash
# Terminal 1
co auto artelonga/co-dev --cycle

# Terminal 2 (simultaneously)
co auto artelonga/co-dev --cycle
```

Both instances:
1. Pull latest main
2. Select DIFFERENT next tasks (lockfile in `~/.co/locks/{KEY}-{id}.lock`)
3. Create separate worktrees
4. Execute in parallel
5. Merge sequentially (lock on main push)

Lockfile: created when task is picked, deleted when merged or after 30min timeout.
