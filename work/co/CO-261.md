## As

A visitor browsing the `co` (or `yggdrasil`, `rfq`, `qb`, `artelonga`) universe in CO

## I Need

The CO universe to **display the actual live `work/<space>/*.md` tasks** from the corresponding source repository — CO-1..CO-261, YG-1..YG-62, RFQ-1..RFQ-27, etc. — as native entries in that universe.

## So That

When I land on `/co`, I see the **real CO development board** (the tasks we're actually shipping this very session) — not a stale hardcoded set of "API / CW / DS / PLT" project containers. Same for `/yggdrasil`, `/rfq`, `/qb`: each universe is the **live dev board** for its repo.

## Context

### Current broken state (as of v2.21.0)

| Universe | What user expects | What they actually see |
|---|---|---|
| `/co` | CO-1..CO-261 dev tasks | 4 abstract projects: API, CW, DS, PLT |
| `/yggdrasil` | YG-1..YG-62 game-platform tasks | 0 projects, 3 entries — kanban renders empty |
| `/rfq` | RFQ-1..RFQ-27 market-making tasks | (untested — likely same problem) |
| `/qb` | QB-1..QB-25 quilombo tasks | (untested — likely same problem) |

### Why it's broken

- `work/co/CO-N.md` files are tracked in **git** (under `~/projects/co/work/co/`)
- They get committed via co-auto / ship-task during dev
- **But they are never POSTed to the CO universe via Vault API**
- The CO universe is populated by `co-web/src/storage/seed.rs reseed_template_content_pages` which seeds template content only — it does NOT walk `work/<space>/`
- Result: every CO-N spec we wrote this session lives in git but is invisible in the CO web UI

### The fix — pull `work/<space>/` into the CO universe automatically

Three approaches, in increasing scope:

**A. Boot-time seed walk** (simplest)

`seed.rs` walks `work/<space>/*.md` for each declared space at startup, posts every file as an entry of `type: user-story` (or `epic`, or `task` based on frontmatter). Idempotent — skips files where the on-disk content_hash matches the DB hash.

**B. File-watcher live sync** (best DX)

A worker watches `work/<space>/` for fs events (`notify` crate) and reflects changes into the universe DB in real-time. Removes the boot-time gap; supports edits made directly to .md files.

**C. Bidirectional Vault sync** (already partially there)

`co-sync` tool already pushes `work/<space>/*.md` to `/api/v1/universes/<space>/vault/<path>` via Bearer token. But it needs declarative wiring in `co-universes.yaml` that maps space dirs to universe slugs, and a cron/git-hook to trigger.

### Decision — start with A, layer B + C later

For this ticket, **A only**:

- New: `co-web/src/storage/work_seed.rs`
- On boot, for each `(space_dir, universe_slug)` pair in a new config block:
  - Walk `work/<space>/*.md` (excluding `.gitkeep`, `CLAUDE.md`, etc.)
  - For each file, parse frontmatter → `id`, `title`, `type`, `status`, `labels`, `priority`
  - Upsert entry at path `tasks/<basename>` with `entry_type: user-story` (or matching from frontmatter)
  - Compute hash of body; skip if unchanged
- Config mapping (in `Cargo.toml`-adjacent `co-universes.yaml` or hardcoded for now):
  ```
  co        → work/co/
  yggdrasil → work/yggdrasil/  (from ~/projects/yggdrasil/work/yggdrasil/ — needs cross-repo)
  rfq       → work/rfq/        (cross-repo)
  qb        → work/qb/         (cross-repo)
  artelonga → work/artelonga/  (cross-repo)
  ```
- For `/co` specifically (this repo), the walk is local. For sister repos, **defer to B + C** — too complex for v1.

### Project rendering

After A populates the entries:

- Kanban view should render entries with `type: user-story` AND `status: todo|in_progress|done` as cards
- "Projects" sidebar can still show abstract grouping (`module:state`, `module:scripts`, etc.) — but the entries themselves are real CO-N tasks
- Status mapping: spec frontmatter `status: todo/in_progress/done` → kanban column

### Yggdrasil + sister repos (post-A)

For non-local repos (yggdrasil, rfq, qb, artelonga), the deployer needs read access to their `work/<space>/` folders. Options:

- **Cross-repo seed at boot**: requires mounting each repo's work folder OR shipping snapshots — heavy.
- **Push from sister repos**: each repo's CI pushes its work/*.md to CO via `co-sync` on every merge — preferred, decoupled.
- **Git submodule** of work folders: cleanest but heavy adoption cost.

For v1 (this ticket), **only `/co` is synced from local repo**. Yggdrasil/RFQ/QB get a placeholder "Sync from sister repo not yet wired — see CO-261" message until B/C lands.

## Acceptance

- After deploy of CO-261, visiting `https://co.artelonga.com.br/co` shows the kanban with the real CO-N task entries (CO-129, CO-242, CO-244, CO-245, CO-256..261, etc.)
- Entries are clickable → opens the markdown body of the spec
- Tasks are grouped (kanban columns) by `status:` frontmatter field
- Reload after a new `git pull` reflects the new entries within one server restart
- Yggdrasil/RFQ/QB universes show a stub message pointing at CO-261's roadmap for the sister-repo sync (until B/C)
- Pre-existing API/CW/DS/PLT projects are kept (legacy data) but the new entries appear alongside

## Blast radius

- ~150 LOC for `work_seed.rs` (walk + parse + upsert)
- ~20 LOC for seed_orchestrator.rs wiring at boot
- ~30 LOC YAML config block in `co-universes.yaml` (or hardcoded mapping)
- Migration: optional new `entry_origin` column to track "synced from work/" vs "user-created" — defer if not strictly needed

## Why now

The user's report at this session's end ("tasks broken, tarefas not showing for yggdrasil, tarefas showing api for co") IS this gap. We've been writing 13+ CO-N specs that all live in git invisible to the CO web UI. This ticket is the bridge.

Without it, every future CO-N task we ship is **invisible to the platform that's supposed to track it**. With it, the CO universe truly mirrors its own dev board — the dogfooding the user asked for since the start of this session.
