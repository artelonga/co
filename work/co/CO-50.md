GIVEN each universe is a collection of markdown entries with frontmatter, and we want universes to be backed by Git repos (public or private) that build at runtime from the latest main branch,
WHEN I implement universe-as-repo with runtime builds,
THEN:

## Concept

Every universe maps to a Git repository:
```
universe "co-dev"  → github.com/artelonga/co (data/co/ directory)
universe "quilombo" → github.com/artelonga/quilomboaraucaria
universe "yuri"    → (no repo, local only — personal community)
```

### Config in `.universo.yaml`
```yaml
name: co-dev
repo: artelonga/co
path: data/co              # subdirectory within repo (optional)
branch: main
visibility: public-subscribable
co_auto: true              # enables co auto execution for subscribers
build_on: push             # rebuild when main is pushed
```

## Runtime Build Pipeline

```
1. Universe created/subscribed
2. Server clones repo: `git clone --depth 1 --branch main <repo_url>`
3. Reads all .md files from `path/` directory
4. Parses frontmatter → creates Entry records in entries table
5. Stores clone timestamp + commit hash
6. On subsequent access: if commit hash differs → re-sync
```

### Sync Strategy
- **Lazy refresh:** On first request after 5 minutes, check remote HEAD. If changed, pull + re-index.
- **Webhook (optional):** GitHub webhook → `POST /api/v1/universes/:slug/webhook` → immediate re-sync
- **Manual:** `POST /api/v1/universes/:slug/sync` (owner/admin only)

## Public vs Private Repos

| Repo visibility | Universe visibility | Auth method |
|----------------|--------------------|----|
| Public (github.com/artelonga/co) | `public-subscribable` | No auth needed for clone |
| Private (github.com/artelonga/quilomboaraucaria) | `requires_login` or `private` | SSH key from GitHub user linked to Co account |

### GitHub SSH Auth for Private Repos
- [ ] Co user links their GitHub account (OAuth or manual SSH key upload)
- [ ] When cloning private repo, server uses the user's SSH key
- [ ] `universe_members` table stores `github_username` for access verification
- [ ] If GitHub user has read access to the repo → Co can clone it
- [ ] For MVP: server has a deploy key that's added as a collaborator to private repos

## co-auto Compatibility

Universes with `co_auto: true` expose their tasks for `co auto` execution:
- Tasks are the `.md` files in the repo matching `*-N.md` pattern
- Frontmatter: `id`, `title`, `status`, `priority`, `parent`, `labels`, `module`
- `co auto --space co-dev --cycle` picks the next unblocked task
- Task status changes are committed back to the repo (if user has write access)

## Acceptance Criteria

- [x] Universe config specifies repo URL + path + branch
- [x] First access clones repo and indexes entries
- [x] Subsequent access uses cached entries, refreshes on commit hash change
- [x] Public repos work without auth
- [x] Private repos work with deploy key (MVP) or user SSH key (v2)
- [x] co-auto reads tasks from repo-backed universes
- [x] Webhook endpoint triggers re-sync on push
- [x] `cargo test` with mock git repos
