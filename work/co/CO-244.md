## As

A researcher or analyst querying universe content from Python or R

## I Need

A frictionless path to query a universe's entries / assets / events / relations from Python or R, with full SQL + DataFrame ergonomics

## So That

I can do ad-hoc analysis (visualizations, ML, batch transforms) on universe data without writing API clients — the per-universe SQLite is already the right shape.

## Context

- **Principles:** §4 (reduced coupling — data accessible without app intermediation)
- **Scope:** **Approach (zero new server code needed):** DuckDB attaches SQLite directly. From Python or R:

```python
import duckdb
con = duckdb.connect()
con.execute("ATTACH '/data/universes/artelonga/data.db' AS al (READ_ONLY)")
df = con.execute("""
    SELECT path, body_lines, updated_at, frontmatter_json::JSON->>'status' as status
    FROM al.entries WHERE entry_type='task' AND status='done'
    ORDER BY updated_at DESC LIMIT 100
""").df()
```

Same code in R via the `duckdb` package.

**Deliverables:**
1. A `co-py` Python helper package (~50 LOC) that:
   - Resolves universe slug → local data.db path (or downloads a snapshot via API)
   - Opens read-only DuckDB connection
   - Returns a connection ready for queries
2. A `co-r` R helper package (mirror of co-py).
3. (Phase 2) In-browser REPL: Pyodide + DuckDB-WASM running against an in-memory copy of the universe's data.db. Embedded as a `/repl` panel in the CO SPA. User writes Python in-page, queries their own data, no server roundtrip.
4. (Phase 2) Jupyter kernel `%co_query` magic that wraps the above.

**For hosted / read-only access** (when user doesn't have local data.db): add a `POST /api/v1/universes/{slug}/query` endpoint that accepts a SQL string, runs it against the universe DB read-only (with row-count + execution-time cap), returns results as JSON. Python/R packages fall back to this when the SQLite isn't local.

## Acceptance

Phase 1:
- `pip install co-py` + 3 lines of Python returns a working DuckDB connection to a universe.
- Same in R via `install.packages('co-r')`.
- Example notebook ships in repo: 'Querying CO universes with DuckDB'.

Phase 2:
- In-browser REPL at `/repl?u=<universe>` runs Pyodide queries against the universe.
- `POST /api/v1/universes/{slug}/query` available for hosted access (with auth + read-only).

## Blast radius

Small — packaging work, no server changes for Phase 1. Phase 2 adds a query endpoint + WASM bundle.
