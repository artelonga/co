## As

A developer about to demo or use `co serve` locally

## I Need

An end-to-end Playwright test that exercises the full localhost trial flow surfaced in this session, so regressions in any of CO-313 through CO-320 get caught before the next demo.

## So That

I don't have to manually re-test five separate symptoms (subscribe, unsubscribe, theme persistence, sister-repo seeding, sidebar discoverable visibility) after every UX change.

## Scope

Test file: `co-web/e2e/localhost-trial.spec.ts`

### Setup
Uses the existing `seedProject` / `apiContext` fixtures. Spawns a `TestServer` (CO-300) with `CO_ENV=local` so uat-login is allowed (CO-309). Sets `CO_LOCAL_REPOS_DIR` to a tempdir with one mock sister repo for CO-317/318 verification.

### Test cases

#### 1. Anonymous boot — sidebar shows only universe + project list
- Visit `/`
- Sidebar has no "Plataformas" section (CO-311)
- Sidebar has no raw `sidebar.co_dev_chip` text on the co row (CO-319)
- Sidebar has no "Descobríveis" section visible (CO-320)
- The `+ Buscar universos públicos` button appears only if discoverable list is non-empty for that user

#### 2. Subscribe flow — happy path
- Login as `yuri@uat.local`/`uat`
- Subscribe to a public-subscribable universe via API
- Reload sidebar — the universe appears in "Inscrito em" bucket
- The row has a `×` unsubscribe button (CO-320)

#### 3. Subscribe flow — blocked on static
- Attempt to subscribe to a `public-static` universe (`tempo`)
- API returns 400 with `is not public-subscribable`
- The discoverable list MUST NOT include public-static universes (CO-319)

#### 4. Unsubscribe — happy path
- Subscribed to universe `X` from test 2
- Click the `×` unsubscribe button
- Confirm dialog appears, accept it
- Reload — universe no longer in subscribed bucket (CO-320)

#### 5. Theme persistence
- Login, switch theme via header switcher
- Navigate to a different universe
- Theme remains the user's chosen one (CO-313 — no per-universe theme override)

#### 6. Sister repo seeding — pages + tasks
- Setup: write a tempdir with `<repo>/docs/page.md` and `<repo>/work/<space>/TEST-1.md`
- Start TestServer with `CO_LOCAL_REPOS_DIR=<tempdir>` and a mapping entry
- Verify `GET /api/v1/universes/<universe>/entries` includes `docs/page.md` (CO-317)
- Verify the kanban view shows `TEST-1` as a task with `project: TEST` (CO-318)
- Touch a new file `TEST-2.md`, restart server
- Verify `TEST-2` appears (CO-319 — re-sync every boot, no skip)

#### 7. Subscribe button — discoverable list correctness
- Open the search prompt (`+ Buscar universos públicos`)
- The displayed list MUST NOT include:
  - public-static (tempo/humanity/universo)
  - private universes
  - the user's own universe
  - universes the user already owns/member/subscribed
