## Contexto
A importação ao vivo do `claude-code` em prod (CO-429 Parte 1, pós-deploy v3.6.0,
2026-06-12) chegou a **114/164 entradas** e expôs três bugs reais. Cada um é
independente e corrigível; juntos bloqueiam um import limpo de universo privado.

## Bug 1 — seed cria universo órfão sub-provisionado
- [ ] O seed do CO-429 (`co-web/src/storage/seed.rs`) faz INSERT da linha
      `universes` para `claude-code`, mas sem pool/diretório/membership. Em prod
      (DB existente) isso cria um registro **órfão**: `POST /universes` retorna
      **409 "key taken"**, porém `GET /universes/claude-code` e a listagem
      retornam **404 / ausente**. Resultado: não dá pra criar nem importar sem
      `DELETE` manual primeiro.
- [ ] Fix: o seed ou provisiona o universo por completo (pool + owner +
      membership, mesmo caminho do create via sessão), ou **não** semeia
      universos importáveis (deixa o `co source add` criar). Idempotente em
      re-deploy. Teste: seed num DB existente → universo é GET-able OU ausente,
      nunca "taken mas 404".

## Bug 2 — GET por API-token dá 404 no universo privado do próprio dono
- [ ] `GET /api/v1/universes/{key}` autenticado por **api-token** retorna 404
      para um universo **privado** mesmo quando o token pertence ao **dono**;
      por **sessão (JWT)** o mesmo GET retorna 200. O `co source add` usa o
      api-token no `universe_exists` → acha que não existe → tenta criar → 401.
      (Workaround usado: passar o JWT de sessão como `--token`.)
- [ ] Fix: o gate de visibilidade (CO-161) deve tratar api-token e sessão de
      forma idêntica para o dono/admin. Teste: dono lê o próprio universo privado
      via api-token (200), não-dono não (404).

## Bug 3 — rate-limit bloqueia bulk import; sem skip/resume; admin não isenta
- [ ] O `co source add` faz PUT de TODAS as entradas do começo a cada run
      (idempotente mas sem skip), e o vault dá **429** após ~114 PUTs. Re-rodar
      gasta o orçamento nas 114 já presentes e nunca alcança as restantes →
      progresso trava determinístico.
- [ ] CLAUDE.md diz que admin-tier **pula** rate limit no vault; o import como
      `yuri` (admin) tomou 429 — a tier não chega ao rate-limiter pelo caminho
      de auth usado (liga ao Bug 2). Fix: (a) admin/owner isento de fato no
      bulk-sync, e/ou (b) `co source add` ganha `--throttle`/backoff e **skip de
      entradas já idênticas** (hash) para retomar sem re-PUT.
- [ ] Teste: importar um repo com >200 arquivos como admin completa sem 429; um
      re-sync só toca o que mudou.

## Estado atual (prod)
- `claude-code`: 114/164 entradas, `visibility=private`, `parent_key=co`,
  owner=yuri. Catálogo `tools/claude-code/*.md` (no universo `co`) já entregue
  pelo CO-429. Faltam ~50 entradas (subconjunto de plugins/skills docs) — entram
  sozinhas quando o Bug 3 for resolvido.

## Notas
Os 3 bugs são a razão de o import não fechar 164/164. Nada de MCP. Prioridade
alta porque travam qualquer `source:github` de universo privado em escala.
