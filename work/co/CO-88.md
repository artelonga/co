GIVEN the new `.co` format (CO-86) and composable layers (CO-87) introduce a non-trivial pipeline (markdown ↔ CoFile ↔ optionally compressed/encrypted/signed bytes ↔ filesystem/API/sync), and we need confidence that a file authored on localhost arrives byte-equivalent in the web UI through every layer combination,
WHEN we add a UAT pipeline test that exercises four code paths — local CLI, local server via API, UAT, prod read-only — and reports per-universe statistics (file count, raw bytes, encoded bytes, compression ratio, transfer ms, telemetry events),
THEN every release that touches the format or layers ships with a green pipeline run as a deploy gate, and the team has hard numbers for size/perf budgets across actual content (artelonga + quilomboaraucaria).

## Pipeline paths to verify

```
   ┌─ Authoring ──┐
   │ markdown.md  │
   └──────┬───────┘
          │ encode (CO-86)
          ▼
     CoFile bytes
          │
   ┌──────┴───────────────────────────────────────────┐
   │  Path A: localhost                                │
   │   Filesystem read/write only                      │
   │                                                   │
   │  Path B: local server via API                     │
   │   PUT /api/v1/universes/:slug/vault/...           │
   │   GET /api/v1/universes/:slug/vault/...           │
   │                                                   │
   │  Path C: UAT (full network)                        │
   │   PUT/GET against co-artelonga-uat.fly.dev         │
   │                                                   │
   │  Path D: prod (read-only smoke)                    │
   │   GET against co-artelonga.fly.dev (no writes)     │
   └──────┬───────────────────────────────────────────┘
          │ decode
          ▼
     CoFile + body
          │
          ▼
   markdown.md  ── must equal authoring input (modulo allowed YAML normalization)
```

For each path × each universe × each layer combination, capture a `RunReport`.

## Layer combinations to exercise

| Combo | Compression | Encryption | Signing | Notes |
|-------|-------------|------------|---------|-------|
| `raw` | none | none | none | Baseline |
| `zstd` | zstd-3 | none | none | Default for storage |
| `signed` | none | none | Ed25519 | Integrity only |
| `private` | zstd-3 | chacha20 | Ed25519 | The "real-world" combo |
| `legacy-md` | none (markdown bytes only) | none | none | Backwards compat: receiver auto-wraps |

Each combo runs against each universe's content corpus (artelonga, quilomboaraucaria, rfq) along all four paths. Total runs: 5 combos × 3 universes × 4 paths = 60 cells in the matrix.

## Tasks

### Pipeline runner (CO-88a)

- [ ] `co/scripts/pipeline-uat.py` (or Rust binary `co-pipeline` in `dev/`): orchestrates the 60-cell matrix
- [ ] Reads source corpora from local repos (`~/projects/ArteLonga`, `~/projects/quilomboaraucaria`, `~/projects/rfq-gateway`)
- [ ] For each path: drive the encode → transport → decode → compare cycle
- [ ] Times each phase via the `Telemetry` field on `CoFile` (CO-86)
- [ ] Compares decoded markdown to source; reports any drift
- [ ] Writes `co-pipeline-report-<date>.yaml` to `co/dev/reports/`

### Telemetry collection on the server (CO-88b)

- [ ] Extend `co-web/src/telemetry.rs` (CO-46) to record per-PUT/GET on Vault routes:
  - `co_format`: "markdown" | "co/protobuf"
  - `compression`: "raw" | "zstd-3" | "zstd-19" | "br-11"
  - `encryption`: "none" | "chacha20"
  - `size_uncompressed`, `size_on_wire`
  - `encode_ns`, `decode_ns`
- [ ] New aggregation query: `pipeline_summary(universe_key, since: timestamp)` returns the per-universe stats in the report shape
- [ ] Admin endpoint: `GET /api/v1/admin/pipeline/summary` (yuri tier) — JSON of the same shape
- [ ] Admin dashboard: `/co/co-dev/pipeline` (sister to `/co/co-dev/telemetria`) — pivots by universe + combo

### CI integration (CO-88c)

- [ ] CI job that runs `co-pipeline` against UAT on every push to main
- [ ] Posts the report as a build artifact + comments deltas vs the previous run on the PR (compression ratio change, transfer time regression, etc.)
- [ ] Fails the build if any cell in the matrix fails to decode/round-trip

### Per-release deploy gate (CO-88d)

- [ ] Pre-prod-deploy check: pipeline report from UAT must exist and be < 24h old; no errors; regressions within tolerance
- [ ] On prod-deploy success: run smoke (Path D, read-only) and append to the prod side of the report

## How this connects to CO-46 telemetry

CO-46 already collects user-facing events (page views, errors, performance). CO-88 adds *content-pipeline* events to the same `telemetry_events` table with a distinct `event_type` (`pipeline.encode`, `pipeline.decode`, `pipeline.transfer`). The same admin dashboard can pivot either dimension. No new infra beyond a few columns and a query.

## Why this is a release-gating concern

The `.co` format change (CO-86) plus the layer refactor (CO-87) are platform-shaping. Without a pipeline test, every release risks shipping a subtle encoder/decoder bug that corrupts content. The matrix run is cheap (~30 seconds against UAT for all 60 cells with <300 files) and catches drift before users see it.

## Acceptance

- `co-pipeline` runs the full matrix without manual intervention against UAT, completes < 60 seconds
- All 60 matrix cells produce a green decode-round-trip on the artelonga + quilomboaraucaria + rfq corpora
- Report YAML is deterministic (modulo wall-clock fields) so CI can diff between runs
- Admin dashboard renders pipeline summary per universe with sortable columns
- Pre-prod-deploy CI gate blocks merge if any cell fails or regression exceeds 20%
- Telemetry events appear in `telemetry_events` with `event_type='pipeline.*'` and feed the admin dashboard

## Out of scope (deferred)

- Local-machine encrypted pipeline (no recipient set without identity infrastructure — defer until users have keys)
- Mobile path (E) — Capacitor flow; deferred to whenever mobile ships
- Encrypted at rest on UAT (UAT is reset-friendly; encryption-at-rest is a prod-only requirement that comes with the multi-user moment)
- Cross-region transfer measurements (single fly region for now)
