## As

The platform operator (yuri) who has four content universes ready to publish — yuri, retro-umarizal, yoruba, neuro — none of which appear in prod CO today.

## I Need

Universe rows seeded on prod with `remote_url` populated, so the CO-337 15-min sync task pulls their content automatically, with proper visibility and (for yuri) anon-published-only filtering.

## So That

Visitors to https://co-artelonga.fly.dev see these four universes in the sidebar and can browse their content. No Docker rebuild required per content update — CO-337 handles the sync.

## Context

State of the four universes:

| Universe | Source | Notes |

| **yuri** | `~/projects/ArteLonga/yuri/` (sub-folder of artelonga repo) | Personal vault; needs subfolder strategy. `anon_published_only=1`. |
| **retro-umarizal** | https://github.com/artelonga/retro-umarizal (standalone) | Has `_universe.yaml` and `profile.yaml`. Direct clone. |

| **neuro** | `~/projects/ArteLonga/neuro/` (sub-folder of ArteLonga) | Same subfolder-of-artelonga strategy as yuri. |

CO-337 (v56 migration) introduced `remote_url`, `remote_ref`, `remote_last_sync` on `universes`. The seed orchestrator runs a clone+walk on boot and every 15 min for any row with `remote_url IS NOT NULL`. `content_subdirs` (CO-330) constrains which sub-paths of the cloned repo are walked — this is the lever for yuri/neuro (subfolders of artelonga) and yoruba (subfolder of comunicacao).

Two missing pieces today:

1. **PATCH endpoint** at /Users/artelonga/projects/co/co-web/src/content/universe_routes.rs:1289 already accepts `local_repo_path` + `content_subdirs` + `anon_published_only` + `remote_url` + `remote_ref` (CO-337 shipped this). Good — the endpoint is ready.
2. **No standalone repo for yoruba/neuro/yuri.** The seed orchestrator needs to clone the *parent* repo (artelonga or comunicacao) and restrict walking to one subdir.

## Design

### Idempotent seed in `seed_admin_content_universes`

Add four rows in /Users/artelonga/projects/co/co-web/src/storage/seed.rs (extend the array at line 774) with the new shape — the existing `INSERT OR IGNORE` already prevents stomping user edits:

```rust
("yuri", "Yuri", "Caderno pessoal — yuri.artelonga.com.br", "public-subscribable", None),
("retro-umarizal", "Retro Umarizal", "Memória do bairro — retro-umarizal.artelonga.com.br", "public-subscribable", None),
("yoruba", "Yorùbá", "Léxico Yorùbá — termos, divindades, conceitos", "public-subscribable", Some("comunicacao")),
("neuro", "Neuro", "Cartografia neuro — laudo, recursos", "public-subscribable", Some("artelonga")),
```

The existing seed loop only writes name/desc/visibility/parent. To carry the remote sync fields, add a parallel one-shot UPDATE block (idempotent — `WHERE remote_url IS NULL`) so existing rows pick up the new sync config without stomping operator edits:

```rust
let backfills: &[(&str, &str, &str, Option<&str>, bool)] = &[
    // (key, remote_url, remote_ref, content_subdirs_json, anon_published_only)
    ("yuri",           "https://github.com/artelonga/artelonga",   "main", Some("[\"yuri\"]"),  true),
    ("retro-umarizal", "https://github.com/artelonga/retro-umarizal", "main", None,             false),
    ("yoruba",         "https://github.com/artelonga/comunicacao", "main", Some("[\"yoruba\"]"), false),
    ("neuro",          "https://github.com/artelonga/artelonga",   "main", Some("[\"neuro\"]"), false),
];
for (key, url, gitref, subdirs, anon_only) in backfills {
    let _ = self.conn.execute(
        "UPDATE universes SET remote_url = ?2, remote_ref = ?3, content_subdirs = ?4, anon_published_only = ?5 \
         WHERE key = ?1 AND remote_url IS NULL",
        rusqlite::params![key, url, gitref, subdirs, *anon_only as i64],
    );
}
```

### Verify `content_subdirs` honours sub-folder roots

CO-330 walked `content_subdirs` of `local_repo_path`. Confirm CO-337's `run_remote_sister_repo_seeds` (server/seed_orchestrator.rs:270) honours the same field for the cloned repo. If it walks the root only, extend it to apply `content_subdirs` filtering to the cloned tree.

### anon_published_only for yuri

The yuri vault contains private day-by-day notes. With `anon_published_only=1`, anonymous reads only return entries whose frontmatter has `published: true`. Yuri (logged in as admin) sees everything. Confirm the anon-published filter (CO-319) already drives every entry-fetch path; if not, this is a CO-347 sub-task.

### Manual backfill on prod (one-time, after deploy)

The seed UPDATEs run on every boot, so just deploy + restart:

```
flyctl deploy
flyctl machine restart -a co-artelonga
# Wait ~5 min for first sync cycle
curl -s https://co-artelonga.fly.dev/api/v1/universes | jq '.[].key' | grep -E 'yuri|retro|yoruba|neuro'
```

If sqlite3 access is needed for diagnostics, note that the Fly container does not ship sqlite3 (separate ticket if recurring) — use `flyctl ssh console -a co-artelonga` + the admin SQL route if it exists, or temporarily install sqlite3 in the Dockerfile.
