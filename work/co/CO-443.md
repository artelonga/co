## Sintoma
O verificador de DoD (`co-web/scripts/dod/verify.ts`) casa o texto dos critérios
de aceite com nomes de testes **e2e/spec**. Funciona para tasks `feat` (rotas
HTTP → e2e), mas **falha em tasks de refactor**: CO-431..436 (Mythos) pontuaram
**0–25%** apesar de completos e verificados à mão — porque o AC é estrutural
("promover Universo para core", "split migrations.rs", "game-core sem axum") e
não mapeia para nome de teste e2e. Resultado: toda release de refactor precisou
de `--ignore-dod`, substituído por verificação manual (contention test, grep de
SQL cru, `cargo tree | grep axum`, etc.).

## Fix
- [ ] O matcher passa a reconhecer **testes Rust** (lib `#[test]`/`#[tokio::test]`
      + integração) por nome de função, não só specs e2e.
- [ ] Aceitar **asserções estruturais** verificáveis por build/grep como evidência
      (ex.: critério "X trait existe" → grep `trait X`; "axum-free" →
      `cargo tree -p game-core | grep -c axum == 0`). Um mapa critério→prova
      opcional no frontmatter (`dod_check: "grep:trait EntryStore"`).
- [ ] Tasks de refactor com AC estrutural alcançam ≥ limiar sem `--ignore-dod`.

## Acceptance
- [ ] Re-rodar o verificador nos CO-431..436 → cada um ≥ 80% sem override.
- [ ] Doc curto em `docs/scrum/` de como escrever AC verificável por prova.

## Notas
Não é bloqueante (o override existe), mas forçou verificação manual a wave
inteira da Mythos. Médio: melhora o gate, não a funcionalidade.
