## As
The platform operator who reads /api/v1/me/notifications

## I Need
The feedback submission endpoint to reject probe traffic (empty bodies + smoke/test/probe paths) so my inbox surfaces only real visitor feedback.

## So That
- I see one real visitor comment instead of 16 probe entries blocking the signal.
- Smoke tests + scanners don't pollute the feedback table.
- Anonymous abuse cost goes up (must include actual content).

## Context

The feedback table on prod currently holds 16 entries, ALL empty-body, with paths like `/probe`, `/_smoke`, `/_selftest`, `/telemetry-check`, `/analytics-smoke`, `/_proof`, `/_t`. These are CI smoke tests + scanners hitting the open `POST /api/v1/feedback` endpoint introduced for the CO-333 visitor widget.

Endpoint at `/Users/artelonga/projects/co/co-web/src/integrations/feedback_routes.rs` (lines 34-54 wire 7 routes). Anonymous POST is allowed by design (visitor feedback), but there's no shape validation on the body.

## Design

### Validation rules (server-side, applied to every POST that creates a feedback row)

1. **Body length**: trim whitespace, reject if `body.len() < 5` with `400 Bad Request, {"error": "body_too_short"}`.
2. **Probe path blocklist**: reject if `entry_path` matches any of:
   - starts with `/_` (e.g. `/_smoke`, `/_proof`, `/_t`, `/_selftest`)
   - exact match: `/probe`, `/smoke`, `/selftest`, `/telemetry-check`, `/analytics-smoke`, `/healthcheck`
   - reject with `400 Bad Request, {"error": "probe_path_blocked"}`
3. **Rate limit per IP**: token-bucket — 3 submissions per IP per hour. Reject with `429 Too Many Requests, {"error": "rate_limited", "retry_after_s": <n>}`.

### Bulk-cleanup of existing rows

One-shot SQL migration that marks the 16 probe entries `status = 'wont-fix'` so they don't show in open queues but remain audit-visible:

```sql
UPDATE feedback
   SET status = 'wont-fix',
       resolved_at = datetime('now'),
       resolution_note = 'auto-resolved: probe traffic (CO-339)'
 WHERE status = 'open'
   AND (body IS NULL OR TRIM(body) = '' OR LENGTH(TRIM(body)) < 5)
   AND created_at < (strftime('%s','now') - 60);  -- only entries older than 1 min
```

Run as part of a migration so it idempotently no-ops on fresh DBs.

### Where to hook validation

In `submit_universe_wide` + `submit_per_entry` handlers (around lines 95-180 of `feedback_routes.rs`). Single helper `fn validate_feedback_body(body: &str, entry_path: Option<&str>) -> Result<(), AppError>` called at the top of each handler.

## Acceptance

- [ ] `POST /api/v1/feedback {body: ""}` returns 400 `body_too_short`
- [ ] `POST /api/v1/feedback {body: "ok", entry_path: "/_probe"}` returns 400 `probe_path_blocked`
- [ ] `POST /api/v1/feedback {body: "Found a bug in mbya terms", entry_path: "/yuri"}` succeeds with 201
- [ ] 4th submission from same IP within 1 hour returns 429
- [ ] Migration marks the 16 existing probe rows `wont-fix`
- [ ] No regression in CO-333 widget submission flow
