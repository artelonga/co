## As
A user maintaining a personal bibliography of mixed media (songs, poems, videos, notebook notes)

## I Need
A flexible type system that supports a "music" category aggregating across subtypes (song, album, mp3), composition (a song *contains* a video on YouTube + a Spotify entry + a raw mp3), and a special `notas` abstraction for physical notebook references

## So That
At the yuri.artelonga.com.br index I can query "show me all music" and get songs + albums + videos uniformly, OR query for "songs by author=Yuri" and get a tighter result

## Scope

### Type categories
- `song` (subtype of `music`)
- `album` (subtype of `music`)
- `poem` (subtype of `writing`)
- `essay` (subtype of `writing`)
- `video` (subtype of `media`)
- `url` (subtype of `reference`)
- `quote` (subtype of `reference`)
- `notas` (subtype of `reference`, see below)

Category lookup at boot via `core/src/feature/`. Each subtype declares its category in the schema; queries can filter by either category or specific type.

### Recursive composition via `references`
```yaml
type: song
title: "Grace Kelly"
references:
  youtube: "https://..."
  spotify: "https://..."
  mp3: "files/grace-kelly.mp3"
```

`references` is a free-form map. Query DSL: `type:song AND references.youtube IS NOT NULL`. Optional: declare a `ref_index` table so this is efficient.

### `notas` — physical notebook references
- New entry type `notas`
- Required frontmatter:
  - `caderno_id` (string) — which notebook
  - `pagina` (int) — page number
  - `data` (optional ISO date) — when written
- Body is markdown transcription of the physical content
- Indexed by `caderno_id` so all pages of a notebook query together
- Per CO-141 (cross-language) consideration: notas can have `language: <code>` and link to topologia entries

### Query DSL extensions
- `type:music` → returns all music subtypes (song, album)
- `type:song AND author:"Yuri"` → tight filter
- `caderno_id:"black-2024"` → all pages from one notebook
- `before:2026-05-01` and `after:2025-01-01` for date ranges

## Why now
The yuri index needs to query across types (music aggregated, notas filtered by caderno, dates). Without the category system this is per-type-only.
