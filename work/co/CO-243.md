## As

A developer editing CO universe content from VS Code, Neovim, Helix, or Zed

## I Need

An extension or LSP server that exposes the universe's content as a virtual file system (or LSP workspace) so my editor talks to the CO Vault API natively

## So That

I can use my regular editor + extensions (linters, AI assistants, formatters) on universe content without leaving the tool, and CO's vault stays the source of truth.

## Context

- **Principles:** §4 (reduced coupling — same content, multiple front-ends)
- **Scope:** Three viable integration approaches; pick one (or two complementary):

**Option A — VS Code extension** (recommended for Phase 1):
Register CO as a remote workspace via `vscode.workspace.registerFileSystemProvider`. The extension:
- Logs in (re-uses the API token CLI from CO-236)
- Lists universes the user can access
- 'Open Remote Workspace' shows the entries tree as files
- Read = vault GET, write = vault PUT
- File metadata (mtime, size) maps to entry frontmatter

**Option B — LSP server** (Phase 2 — broad editor reach):
A `co-lsp` binary that any LSP-aware editor can launch. Implements:
- File completion for wikilinks (`[[...]]`)
- Hover for cross-entry references
- Definition for entry IDs
- Diagnostics for broken links + missing frontmatter
Works in VS Code, Neovim, Helix, Zed, Emacs Eglot.

**Option C — WebDAV mount** (Phase 3 — every editor):
Expose Vault API via WebDAV. User does `mount -t davfs https://co.artelonga.com.br/dav/<slug> /mnt/co`. Heaviest (needs auth proxy, locking semantics) but works in every editor including emacs/vim/Sublime.

## Acceptance

Phase 1 (Option A):
- `co-vscode` extension published to the marketplace (or sideloadable VSIX).
- After install + auth, 'Open Remote → CO' lists user's universes.
- Edit a .md file in VS Code, save → vault PUT succeeds, CO web shows the change.
- Optional: auto-completion of wikilinks from the entries index.

Phase 2 (Option B):
- `co-lsp` binary, configurable per-editor.
- Tested in at least VS Code + Neovim.

## Blast radius

Medium — separate repo (co-vscode) for the extension; doesn't touch co-web. LSP is its own crate.
