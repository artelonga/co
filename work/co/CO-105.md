GIVEN we have a `telemetry_events` table accumulating data and a marketing-site endpoint flip planned (CO-97 prep), AND the operator (yuri) cannot currently see whether traffic is actually arriving, what universes people open, or signup-conversion in real time, AND every public-test decision (rate limits, hardware sizing, what to demo at events) needs a glance at "what's actually happening,"
WHEN we add a single admin endpoint + a no-framework static admin page that surfaces the rollups,
THEN running the platform stops being a dark room. Operator decisions become evidence-backed in five seconds.

## Endpoint

`GET /api/v1/admin/dashboard`

**Auth:** JWT required, AND the caller's email must match `CO_SEED_ADMIN_EMAIL`. Returns 403 otherwise. (Avoid coupling to `tier` per CO-90 — admin is per-universe ownership, not a global flag.)

**Response:**
```json
{
  "version": "1.21.1",
  "as_of": "2026-04-29T18:30:00Z",
  "totals": {
    "users": 12,
    "universes": 58,
    "universes_active_7d": 14,
    "entries": 4823
  },
  "daily": [
    {"date": "2026-04-23", "pageviews": 142, "uniques": 38, "signups": 1, "errors": 3},
    {"date": "2026-04-24", "pageviews": 218, "uniques": 51, "signups": 2, "errors": 1},
    ...
    {"date": "2026-04-29", "pageviews": 87, "uniques": 22, "signups": 0, "errors": 0}
  ],
  "top_universes": [
    {"key": "tempo", "name": "Tempo", "events_7d": 1240},
    {"key": "humanity", "name": "Humanidade", "events_7d": 980},
    ...
  ],
  "auth": {
    "logins_today": 5,
    "failed_logins_today": 1,
    "active_sessions": 8
  }
}
```

**Caching:** 5-minute in-memory, evicted on universe creation / signup. No DB writes per request.

**Source data:**
- `telemetry_events.pageview` → daily aggregate
- `telemetry_events.auth.login` → logins_today / failed_logins_today
- `users` → user count, signups daily
- `universes` → total + active filter via last entries.updated_at
- `entries` → per-universe events_7d for top-universes

## Static page

`GET /admin` (Cookie auth, redirects to login if not authenticated; 403 if not the seed admin).

Plain HTML — no SvelteKit, no framework. Inline CSS. Inline `<script>` calling `/api/v1/admin/dashboard` and rendering:

1. **Top strip** — totals (users, universes, entries) as big numbers
2. **Daily traffic sparkline** — inline SVG, last 14 days, pageviews + uniques on dual axis
3. **Top 10 universes table** — key, name, events touched in 7d, last activity
4. **Auth panel** — logins today / failed / active sessions

Total page weight: ≤ 30 KB HTML+CSS+JS. Loads in under 500ms.

Auto-refresh every 60 seconds.

## Security

- Page must include `X-Frame-Options: DENY`.
- No third-party JS / CDN.
- Endpoint validates JWT signature first, email second; never reveals existence of admin email if signature invalid.
- Rate-limited like everything else (CO-80 once shipped).

## Out of scope

- Real-time updates (websocket; defer until value justifies cost).
- Multi-admin support (CO-90 territory).
- Custom date ranges / filters.
