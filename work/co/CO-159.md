## As

a user expecting [`time/moon-phases/2026/`](https://co-artelonga.fly.dev/co/time) to contain every lunar phase for the current year as a queryable entry

## I Need

a tool that scrapes (or calls the API of) [INMET's lunar phases page](https://portal.inmet.gov.br/paginas/luas) and emits one `.md` per phase into the `time` universe — with `at_iso` (UTC), `at_local` (BRT), `geo` (Brasília reference), and `source: inmet.gov.br`

## To

stop hand-authoring moon phases (which is where bugs live) and let the timeline self-populate

---

## Source

INMET publishes a yearly table of lunar phases at:

```
https://portal.inmet.gov.br/paginas/luas
```

The table is HTML; each row is `<phase-name> | <date> | <BRT-time>`. Phases:

- Lua nova (new moon) → `kind: moon.new`
- Quarto crescente (first quarter) → `kind: moon.first-quarter`
- Lua cheia (full moon) → `kind: moon.full`
- Quarto minguante (last quarter) → `kind: moon.last-quarter`

Times are in BRT (UTC-3, no DST). `at_iso` = `at_local` + 3h.

## Implementation

`scripts/import-moon-phases.py <year>`:

1. Fetch the INMET page; if a year-specific URL is needed (`?ano=<year>`), use it.
2. Parse the table with `BeautifulSoup` (already a common dep) or stdlib `html.parser`.
3. For each row, build a `time/moon-phases/<year>/<yyyy-mm-dd>-<phase>.md` with the templated frontmatter from `time/templates/moon-phase.md`.
4. Idempotent: if the file already exists with the same `at_iso`, skip; if the time differs, update the existing one (re-imports get refreshed).
5. Emit a summary: `imported 48 phases for 2026 (12 new, 36 unchanged)`.

## Output frontmatter (from the template)

```yaml
---
title: "Lua nova — 2026-12-09 (BRT)"
type: moon-phase
kind: moon.new
at_iso: 2026-12-09T03:51:00Z
at_local: 2026-12-09 00:51:00 -03:00
geo:
  lat: -15.78
  lon: -47.93
  region: Brasília (national reference)
  timezone: America/Sao_Paulo
source: inmet.gov.br
source_url: https://portal.inmet.gov.br/paginas/luas
imported_at: 2026-05-03T15:00:00Z
imported_by: scripts/import-moon-phases.py@<commit-sha>
seed_status: draft
tags: [astronomy, moon, brazil, 2026]
---
```

## Acceptance

- [ ] `python3 scripts/import-moon-phases.py 2026` writes 48 files (12 phases per quarter × 4) under `time/moon-phases/2026/`
- [ ] Re-running the same command is a no-op (no phantom changes; sha256 of generated files stable)
- [ ] If INMET's table format changes (a heading text shifts, a column reorders), the script fails loudly with a parse error — don't silently produce wrong data
- [ ] Cross-year (`2027`) works without code change
- [ ] Test fixture: a saved snapshot of the INMET page for 2026 lives in `tests/fixtures/inmet-luas-2026.html` so CI doesn't depend on the live URL

## Out of scope

- Verification against NASA's IMCCE database (CO-158 work; second authority would land as a different `edition_id` for the same `work_id` event).
- Importing eclipses, equinoxes, solstices. Same shape; separate scripts per source. File CO-159b/c when needed.
- Continuous re-import via cron. Manual-trigger v1; once stable, /schedule a yearly run.
