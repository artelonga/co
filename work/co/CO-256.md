## As

A developer running `ship-task.sh` against a co-auto worktree

## I Need

The script to detect when its auto-resolve loop has produced a commit identical to `origin/main` (an "empty" commit that git silently drops) and **abort with a clear hint** instead of force-pushing the branch with no changes.

## So That

The implementer's actual work never gets silently lost during a rebase. Today's failure mode: agent commits 200 LOC, ship-task's auto-resolve takes `--ours/--theirs` for every conflict file, the resulting commit equals main, git drops it, the script pushes the now-empty branch, the PR gets created with `additions: 0`, and the gh-merge attempt closes the PR — work disappears.

## So That (operational)

The CO-238, CO-239, CO-241, CO-238-redo, CO-253 cascade we just walked through (each requiring a hand-stitched cherry-pick) had a single underlying bug: the auto-resolve loop didn't distinguish "rebase succeeded with no conflicts" from "rebase resolved every conflict to upstream and produced nothing."

## Context

`scripts/ship-task.sh` lines ~110-145 contain the resolve loop:

```bash
while [[ -n "$(git diff --name-only --diff-filter=U 2>/dev/null)" ]]; do
  for f in $(git diff --name-only --diff-filter=U); do
    # apply auto-resolve rules
    ...
  done
  git -c core.editor=true rebase --continue 2>&1 | tail -3
done
```

After `rebase --continue`, the script doesn't check whether the resulting commit is empty. Git's default behavior is to **drop empty commits silently** during rebase. The branch ends up at the same SHA as origin/main with no warning.

## Scope

Add a post-rebase verification step:

```bash
# After the resolve loop exits, before push:
BRANCH_HEAD=$(git rev-parse HEAD)
MAIN_HEAD=$(git rev-parse origin/main)
if [[ "$BRANCH_HEAD" == "$MAIN_HEAD" ]]; then
    echo "ERROR: After auto-resolve, branch is identical to origin/main." >&2
    echo "       The task's commit was dropped as empty. This is the rebase-empty bug." >&2
    echo "       Manual recovery: reset the branch, cherry-pick the original commit," >&2
    echo "       and resolve conflicts preserving the task's intent." >&2
    echo "       Original commit SHA (from reflog):" >&2
    git reflog --pretty='%h %s' | grep -m1 "commit:" >&2
    exit 3
fi
```

Add exit code 3 to the script header doc.

## Acceptance

- If ship-task.sh's resolve loop reduces the branch to origin/main, the script exits **3** with the hint above.
- The branch is NOT pushed; the PR is NOT created.
- Reflog hint points the operator at the original task commit so they can cherry-pick manually.
- Existing exit codes 0/1/2 preserved.
- Smoke test: run against a worktree where every change is in conflict and resolves to --ours/--theirs matching main — script exits 3.

## Blast radius

~15 LOC in `scripts/ship-task.sh`. No production code. Single repo.
