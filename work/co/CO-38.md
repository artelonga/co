GIVEN game-core implements 5 server-side games (Tetris, Snake, Invaders, PointSet, Poker) with REST endpoints for stats/leaderboards (`/v1/games/:name/result`, `/v1/games/:name/leaderboard`, `/v1/games/:name/stats`, `/v1/profile`), but no browser UI exists for them and they're hidden behind a Godot client,
WHEN I create **Yggdrasil** as a special "universe of universes" — a meta-universe that hosts all minigames in the browser, gated behind login, with player profiles and global rankings,
THEN:

## Concept

**Yggdrasil = the world tree where all game universes branch from.**

Each minigame is a sub-universe within Yggdrasil:
- `yggdrasil/tetris`
- `yggdrasil/snake`
- `yggdrasil/invaders`
- `yggdrasil/pointset`
- `yggdrasil/poker`

The hub itself (`/co/yggdrasil`) is a game lobby with:
- Player profile card (avatar, level, total score, games played)
- Game grid (5 game cards, each clickable)
- Global leaderboard (top 10 across all games)
- Recent activity feed (your games + friends' games)
- Achievements section

Visiting `/co/yggdrasil/{game}` launches the game in the browser.

## Access Control

- [ ] **Yggdrasil requires login** — anonymous visitors see a "Login to play" screen with a CTA
- [ ] All other universes (template, user clones) remain accessible to anonymous users
- [ ] On login, every user gets automatic access to Yggdrasil (no per-user clone needed)
- [ ] Yggdrasil is shared (single universe, all logged-in users see the same hub)
- [ ] User stats/profiles per-user via existing `users` + `game_stats` tables

## Backend: Browser-Playable Games

Currently games are Rust-only and served via REST. Need browser implementations.

### Strategy A (Recommended): JS implementations of the 5 classic games

Pure JS games are small (~5KB each), no WASM compile complexity, easy to ship:

- [ ] `co-web/static/games/tetris.html` + `tetris.js` — classic Tetris in canvas
- [ ] `co-web/static/games/snake.html` + `snake.js` — classic Snake
- [ ] `co-web/static/games/invaders.html` + `invaders.js` — Space Invaders
- [ ] `co-web/static/games/pointset.html` + `pointset.js` — point-and-click puzzle
- [ ] `co-web/static/games/poker.html` + `poker.js` — single-player video poker (multiplayer Poker stays Rust-only)

Each game:
- Pure HTML5 canvas + JS, no framework
- Uses CO theme tokens via CSS custom properties (renders in active theme)
- On game over: POST to `/api/v1/games/{name}/result` to record score
- On load: GET `/api/v1/games/{name}/stats` to show personal best
- Requires JWT (only logged-in users)
- Mobile-friendly: touch controls + on-screen buttons

### Strategy B (Future): Godot HTML5 export
Godot supports HTML5 export. Would allow reusing the Rust server logic via WebSocket. Out of scope for v1.
