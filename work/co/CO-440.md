## Sintoma
A wave Mythos (CO-431/432 em Fable, com `CO_USAGE_ENDPOINT` setado) **não
populou** o dashboard `/usage` em prod — segue 0 sessões. E o CO-432 terminou
com **"Nothing to ship — no commits ahead"** apesar de o refactor (109 arquivos)
ter sido feito (estava staged, não commitado — salvei à mão).

## Diagnóstico (feito 2026-06-12)
- ✅ **Fable emite usage**: `claude -p --output-format stream-json --verbose
  --model fable` produz eventos `assistant` e `result` com `message.usage`
  (`input_tokens`, `output_tokens`, cache) — probe direto confirmou.
- ✅ **Invocação do co-auto está certa**: `auto.rs` passa `--output-format
  stream-json --verbose --model <m>` (linhas ~1019-1027).
- ✅ **`parse_stream_json` espera o formato certo** (`message.usage.input_tokens`).
- ❌ **Mas no run real**: `stream_usage` veio **None** — não imprimiu a linha de
  resumo (auto.rs:525), não re-emitiu o texto do assistant ao log (auto.rs:1058),
  e não chamou `post_usage_to_co` (557). O log do co-auto do CO-432 inteiro tinha
  ~20 linhas (banner → "DONE 5/5"), **sem nenhuma saída da run headless**.

Ou seja: `output.stdout` da run headless veio **vazio / sem o stream-json**, num
run longo (refactor de vários minutos), embora o trabalho tenha sido feito. A
mesma anomalia explica o "nothing to ship": o co-auto não viu o commit/saída.

## Hipóteses a investigar
- [ ] `wait_with_output()` em run longo: stdout grande sendo perdido/truncado, ou
      o processo claude sendo re-spawnado/resumido sem capturar o pipe original.
- [ ] `--name co-auto-<task>` muda o modo de saída? (remover e comparar)
- [ ] Sessão headless de Fable escrevendo stream-json em outro fd / arquivo de
      sessão em vez do stdout capturado.
- [ ] Watchdog/timeout do co-auto reaproveitando uma sessão sem o pipe.

## Acceptance
- [ ] Um run headless real (Fable, multi-turno) tem `stream_usage = Some` com
      tokens > 0 e **POSTa** para `/usage/sessions` → dashboard mostra a sessão.
      Adicionar um debug opcional (`CO_AUTO_DUMP_STDOUT=path`) que grava o stdout
      bruto da run pra inspeção.
- [ ] O mesmo run **commita** o trabalho (sem "nothing to ship" quando há
      mudanças staged) — confirmar que a captura de saída e o passo de commit não
      compartilham o bug de pipe.
- [ ] Teste/repro do caminho de captura para run longo (stdout > N MB).
