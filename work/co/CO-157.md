## As

a content author who just dropped a new PDF into `mbya/refs/` (or any universe's reference directory)

## I Need

a tool that reads the PDF and auto-populates a reference-card `.md` sibling with title, authors, year, page count, language detection, abstract (when extractable), DOI (when present), and the file's sha256 — so the human is editing already-correct metadata, not authoring from scratch

## To

reduce the friction of adding a reference from "open the PDF, eyeball the title page, type frontmatter, pray you didn't typo the year" to "drop the PDF, run the tool, review and commit"

---

## CLI shape

```
scripts/extract-pdf-meta.py <pdf-path> [--out <md-path>]
```

If `--out` is omitted, writes to `<pdf-basename>.md` in the same directory. If the .md already exists, prints a diff against the auto-extracted values; only overwrites with `--force`.

## Data sources (in priority order)

1. **PDF /Info dictionary** — `Title`, `Author`, `Subject`, `Keywords`, `CreationDate`, `ModDate`. Often present, often unreliable.
2. **First-page text + heuristics** — large bold lines = candidate title; "by ..." or "Author: ..." patterns = candidate author; ISBN/DOI regex matches.
3. **`langdetect` on extracted body text** — populates `language`.
4. **Page count** — `pdfinfo` output.
5. **sha256 of the PDF bytes** — populates `sha256` (for CO-158 versioning).

## Output frontmatter

```yaml
---
title: <best-guess>
type: reference
medium: pdf
file: <basename>.pdf
mime: application/pdf
size_bytes: <stat>
sha256: <hex>
language: <detected>
authors: [<extracted>]
year: <CreationDate or first-page extracted>
pages: <int>
keywords: [<from /Info>]
doi: <regex match or null>
isbn: <regex match or null>
abstract: |
  <first 500 chars after the "Abstract:" heading, or null>
extracted_by: scripts/extract-pdf-meta.py@<commit-sha>
extracted_at: <ISO>
seed_status: stub
tags:
- reference
- pdf
- card
- auto-extracted
---

# <title>

<auto-generated short prose linking the PDF and noting where it was extracted from. Human-edited section starts after the next heading.>

## Auto-extracted abstract

<from the body, when found>

## Notes

- (placeholder for the human-author's editorial)
```

## Implementation

Python with `pypdf` and `langdetect` keeps deps minimal and matches the rest of `scripts/`. Alternative: Rust binary in `scripts/` if performance matters (it doesn't; one PDF at a time on author's laptop).

## Acceptance

- [ ] `python3 scripts/extract-pdf-meta.py mbya/refs/PICH0255-T.pdf` writes `PICH0255-T.md` with at minimum `title`, `pages`, `sha256`, `language`, `extracted_at`
- [ ] When `/Info.Title` is absent, the heuristic title-from-first-page picks something better than "Untitled" (or fails loudly)
- [ ] DOI regex catches the standard `10.\d{4,9}/.*` form and populates `doi:`
- [ ] Re-run with `--force` updates the `extracted_*` fields but preserves any human-authored body content (i.e. only the auto-block at the top is replaced)
- [ ] Diff mode (`--out` exists, no `--force`): writes to stderr, exits non-zero if differences exist
- [ ] Test fixture: a tiny stub PDF in `tests/` whose extraction is asserted

## Out of scope

- OCR for image-only PDFs (separate ticket; `tesseract` is a heavy dep). The tool flags `extraction: text-only-failed` so the human knows to OCR manually.
- Cross-PDF deduplication ("this PDF is the same work as <other.md>"). CO-158 covers that via `work_id` + `editions[]`.
- Calling the source URL (e.g. fetching CrossRef metadata from a DOI). Useful follow-up but adds network failure modes; out of scope for v1.
