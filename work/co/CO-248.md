## As

A developer running co-auto in `--cycle` mode against a long backlog

## I Need

Co-auto to automatically push the per-task branch and open a PR via `gh` once acceptance criteria are met — without me having to babysit each terminal and run `git push` + `gh pr create` by hand after each task

## So That

The handoff from "co-auto says task done" to "PR is open and reviewable" is one command, not five. Phase C cycles forward without per-task manual intervention.

## Context

Phase C revealed that co-auto's worktree-per-task model creates the branch + commit but **does not push or open a PR**. After CO-215, RFQ-17, AL-51, YG-38 all completed locally, each sat unpushed until I manually rebased + pushed + `gh pr create` from each worktree. That's the orchestration gap.

This task adds a `--auto-pr` flag that delegates to `scripts/ship-task.sh <TASK-ID>` immediately after the acceptance review passes.

## Scope

### Already shipped in this PR

- **`scripts/ship-task.sh`** — standalone shell wrapper that:
  - Walks known repos (`/Users/artelonga/projects/{co, rfq-gateway-refactor, ArteLonga-refactor, yggdrasil-refactor, quilomboaraucaria-refactor, quilombo-blog-refactor, ...}`) to find the worktree for a given `TASK-ID`.
  - `git fetch origin main && git rebase origin/main` (aborts gracefully on conflicts with a recovery hint).
  - Reads conventional-commit prefix + title from the spec file.
  - Pushes the branch, opens the PR with `gh pr create`.
  - Optional `--draft` flag.

- **co-auto `--auto-pr` flag** — when set, after a task's acceptance review passes (auto.rs around line 249, the `tracker.tasks_completed.push(...)` site), co-auto shells out to `ship-task.sh <TASK-ID>`. Best-effort: failures are logged but don't abort the cycle. The user can re-run `ship-task.sh` manually for recovery.

### Follow-ups (NOT in this PR)

- **CO-N** — make `ship-task.sh` independent of the hardcoded canonical CO path (use `CO_REPO` env var or detect the gh CLI install dir). Today it falls back to `/Users/artelonga/projects/co/scripts/ship-task.sh` if no co-located script is found.
- **CO-N** — extend `ship-task.sh` to skip the push if the PR already exists (re-runs become no-op).
- **CO-N** — emit a JSON event after each PR for telemetry / dashboard hooks.

## Acceptance

- `co-auto --help` lists `--auto-pr`.
- `scripts/ship-task.sh CO-215` (or any completed task ID) works standalone: rebase + push + PR.
- `co-auto --cycle --auto-pr` ships each task's PR automatically after success.
- Rebase conflict on ship-task.sh exits with a recovery hint (non-zero exit, exit code 2).
- Smoke test on QB-1 confirmed end-to-end (push + PR #3 on artelonga/quilombo-blog — note: that PR ended up in the wrong repo per the larger quilomboaraucaria reorientation; the script works correctly, the *task spec* was where the mismatch was).

## Blast radius

Tiny. New shell script + ~50 LOC patch to co-auto. Existing co-auto runs (without `--auto-pr`) behave exactly as before. The patch shells out via `std::process::Command` — co-auto doesn't link against `gh` or assume its availability.
