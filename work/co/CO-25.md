GIVEN the palette system has 5 named palettes (Modern, Scholarly Light/Dark, Relic Light/Dark) and 8 variants,
WHEN I gate theme access by authentication status,
THEN:

- [ ] Define theme tiers:
  - **Free (anonymous):** Scholarly Light, Scholarly Dark, Relic Light, Relic Dark (4 palettes)
  - **Logged-in:** All above + Modern + all 8 variants (a-h) + custom palette editor
- [ ] `GET /api/v1/themes/available` — returns list of available themes based on auth status
  - Anonymous: `{ palettes: ["scholarly", "scholarly-dark", "relic", "relic-light"], variants: [] }`
  - Logged-in: `{ palettes: ["", "scholarly", "scholarly-dark", "relic", "relic-light"], variants: ["a".."h"], custom: true }`
- [ ] Palette switcher in header: only shows available palettes (filter NAMED_PALETTES by tier)
- [ ] Variant switcher: hidden for anonymous users, visible for logged-in
- [ ] Custom palette editor (the color swatch popover in experiment.js): hidden for anonymous
- [ ] Universe owner can set any theme they have access to as universe default
- [ ] If owner sets a premium theme and their session expires, universe still renders with that theme (form config persists, gating only applies to the switcher UI)
- [ ] API enforcement: `PUT /api/v1/universes/:slug/config` validates theme_preset against user's tier
- [ ] Update experiment.js: `renderHeaderSwitcher()` checks auth status before rendering full palette list
- [ ] Test: anonymous sees 4 palettes, login → sees all, set premium theme → logout → universe still uses it
- [ ] `cargo test` passes, `cargo clippy -- -D warnings` clean
