## As
A universe author working locally with `co launch` / jujutsu

## I Need
A `co push` command that uploads a local universe (its `_universe.yaml` + `content/`
markdown) to a deployed CO server over HTTP, wrapping the same REST CRUD the web uses —
so the CLI and web are one tool with identical semantics.

## So That
- Adding/updating a universe on prod needs **no `seed.rs` edit and no deploy** — it's a
  CRUD call (honors `feedback_no_hardcoded_content_mappings`).
- Authors who keep universes in their own repos (e.g. `grcsamazonia`, tracked in
  jujutsu, no GitHub) can publish via CO's Vault API instead of a git remote (honors
  `feedback_no_git`: CO is the sync, not git).
- `scripts/bulk-upload.py` (ad-hoc Vault loop) is replaced by a first-class verb.

## Context

Today the universe-add CRUD exists on both surfaces but they don't meet (see
`docs/universe-crud.md`):

- **Local:** `co launch` creates + binds + seeds into *local* SQLite.
- **Prod:** the Vault API (`PUT /api/v1/universes/{slug}/vault/{path}`) accepts content,
  but only the web/scripts call it.
- **Missing:** the CLI cannot push a local universe to a *remote running server*.

`co push` closes that edge by wrapping `POST /api/v1/universes` + Vault `PUT`s.

## Design

### Command

```
co push --remote <base-url> --token <api-token> [--key <key>] [--dry-run] [--delete-missing]
```

- Resolves the universe from the CWD repo root (same discovery as `co launch`);
  reads `_universe.yaml` for `key`, `name`, `visibility`.
- **Create/update universe:** `POST /api/v1/universes` (404→create) then
  `PUT /api/v1/universes/{key}` for name/visibility (idempotent).
- **Push entries:** walk `content/**/*.md`; for each, `PUT …/vault/{path}` with the
  file body. Skip `_source/` and anything `.gitignore`d.
- **Reconcile (optional):** with `--delete-missing`, `GET …/vault/` and
  `DELETE …/vault/{path}` for server entries no longer present locally.
- `--dry-run` prints the plan (creates / updates / deletes) without writing.
- Token via `--token` or `CO_TOKEN` env; base URL via `--remote` or `CO_REMOTE`.

### Reuse

- HTTP client: add `reqwest` to `co-cli` (not currently a dep) — the only new dep.
- Endpoints already exist (`create_universe`, `update_universe`, vault `PUT`/`GET`/`DELETE`).
- Path walking + frontmatter parsing already in `co-cli` seed helpers.

### Idempotency & safety

- Re-running `co push` converges (POST-or-update, PUT overwrites). Safe to repeat.
- Never pushes `_source/` (PII originals) — respect `.gitignore` + an explicit
  `_source/` skip, so the LGPD `_source` policy from `docs/universe-crud.md` holds.

## Acceptance

- [ ] `co push --remote <url> --token <t>` creates the universe if absent, updates if present
- [ ] All `content/**/*.md` land as entries via the Vault API; `GET …/vault/` confirms count
- [ ] `--dry-run` prints create/update/delete plan, writes nothing
- [ ] `--delete-missing` removes server entries absent locally; without it, no deletes
- [ ] `_source/` and `.gitignore`d paths are never pushed
- [ ] Re-running is idempotent (no dupes, converges)
- [ ] `CO_TOKEN` / `CO_REMOTE` env fallbacks honored
- [ ] Doc `docs/universe-crud.md` updated to mark the gap closed

## Blast radius

- ~150 LOC new `co-cli/src/commands/push.rs` + subcommand wiring
- +1 dep (`reqwest`) on `co-cli`
- 0 server changes (endpoints already exist)
- 0 schema changes

## Not in scope

- Pull/round-trip sync (`co pull`) — separate task
- Conflict resolution on push (last-write-wins via Vault PUT for v1; CO-385 handles
  cross-device conflicts on the server side)
- Binary asset upload (focus on markdown entries first)
