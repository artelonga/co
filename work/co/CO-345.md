## As

An author or visitor exploring the network of meaning across CO universes (co, mbya, yoruba, comunicacao, topologia, …)

## I Need

The graph view to span multiple universes in a single canvas, and the ability to save a parameterised view (`{universes, types, depth, root}`) as a shareable URL.

## So That

- Cross-universe wikilinks (`mbya::iya → yoruba::iya`, `co::CO-141 → topologia::guarani-mbya/concept`) become visible — today's graph hides every edge whose `to_universe` is not the current slug.
- Researchers can publish curated views (e.g., "yoruba × mbya divinity overlap") as a stable URL without re-tweaking filters each time.
- The graph stops lying about isolation — the data already has cross-universe edges (CO-153, CO-74); only the API filters them out.

## Design

### API: multi-universe graph

Extend `GraphQuery` in /Users/artelonga/projects/co/co-web/src/content/graph_routes.rs:

```rust
pub struct GraphQuery {
    pub universes: Option<String>,      // NEW — comma list; default: route slug only
    pub include_types: Option<String>,
    pub relation: Option<String>,
    pub root: Option<String>,           // accepts "key::path" for cross-universe root
    pub max_depth: Option<usize>,
    pub published_only: Option<bool>,
}
```

When `universes` is set, the loader queries nodes from each universe (`entries WHERE universe_key IN (…)`), and the edges query drops the `to_universe IS NULL` filter — admit any edge where both endpoints land in the node set. Node IDs become `<universe>::<path>` for global uniqueness. Same-universe edges (`to_universe IS NULL`) bind to the row's own universe.

### API: saved views

New table:

```sql
CREATE TABLE graph_views (
  slug TEXT PRIMARY KEY,            -- url-safe; user-chosen or auto from name
  owner_id TEXT NOT NULL,
  name TEXT NOT NULL,
  universe_filter TEXT NOT NULL,    -- JSON array
  type_filter TEXT,                 -- JSON array, nullable
  relation_filter TEXT,
  depth INTEGER,
  root TEXT,                        -- "key::path" or null
  layout_seed INTEGER,
  visibility TEXT NOT NULL,         -- 'public' | 'unlisted' | 'private'
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

Endpoints:

- `POST /api/v1/me/graph-views` — create (auth required)
- `GET  /api/v1/me/graph-views` — list owner's views
- `GET  /api/v1/graph-views/{slug}` — fetch (respects visibility)
- `PATCH /api/v1/graph-views/{slug}` — update (owner)
- `DELETE /api/v1/graph-views/{slug}` — owner
