## As

a CO operator promising "operator cannot read user content"

## I Need

a separate Fly app (`co-privileged-zone`) running in a different region with no public ingress, only inbound from `events.encrypted.*` topics and only outbound to `events.aggregated.*` topics, where Flink jobs run with key-unwrap permission

## To

create the **only** place in the system where user-content keys can be unwrapped, fenced off from everything else, so that compromise of `co-web` does **not** grant access to plaintext user data

## Given / When / Then

GIVEN encryption-at-rest (CO-86) means R2 holds ciphertext only and `K_u` (per-universe key) is wrapped under a user-token-derived KEK,
WHEN we deploy a separate Fly app in a different region with strict network policy + dedicated IAM principal that holds the master unwrap secret,
THEN the only path that produces decrypted bytes lives in the zone, the only outputs are k-anonymous aggregations (CO-131), and every unwrap is logged (CO-132).

## Hardening controls (must all be present)

| # | Control | How |
|---|---------|-----|
| 1 | Network isolation | Separate Fly org/app; `FLY_PRIVATE_NETWORK` only inbound from Redpanda; no public listener |
| 2 | Key access logging | Every `K_u` unwrap → audit log (CO-132); audit log is write-only from inside, read-only from `co-web` |
| 3 | DLP at egress | All output rows pass k-anonymity check (k≥5); narrow rows rejected (CO-131) |
| 4 | Job allow-list | Aggregation jobs are pre-registered code, not arbitrary SQL; no interactive notebooks |
| 5 | Time-bounded keys | Job leases `K_u` for its run; key released on job completion or timeout |

§C.2 of the platform roadmap review names these five as the **bar**. Anything less is marketing, not engineering.

## Acceptance

- [ ] Fly app `co-privileged-zone` exists in a region distinct from `co-artelonga`
- [ ] Fly secrets `MASTER_UNWRAP_KEY` set; not present on `co-artelonga`
- [ ] Network policy: outbound only to Redpanda + audit-log sink; inbound only from internal network
- [ ] Synthetic test: a Flink job inside the zone unwraps `K_u`, computes a sum, writes to `events.aggregated.demo`; an attempt to write anywhere else fails closed
- [ ] An attempt to query the zone's HTTP/SSH from the public internet returns connection-refused
- [ ] Runbook for zone operations in `docs/OPERATIONS.md` (separate access procedure, separate on-call)

## Out of scope

- Hardware-rooted attestation (Nitro Enclaves / SGX) — Phase 5+ revisit; document as the ceiling on this trust model
- Confidential VMs — same
- Homomorphic encryption — see HE+FP review; partial-HE for narrow counters may complement this in later phases

## Risks

- **Operational toil.** Mitigation: document the on-call procedure; restrict access to the smallest set of operators
- **Key compromise via compromise of zone.** Mitigation: rotation cadence (quarterly); audit log makes detection possible even if prevention fails
