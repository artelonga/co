GIVEN `bridge/voice.py` has an injectable local-whisper backend for speech-to-text,
and the canonical tool contract (CO-503) distinguishes deterministic script-tools from
predictive LLM-backed tools,
WHEN we expose voice transcription under the canonical contract,
THEN voice-transcribe is a `tool_type: predictive` tool — local-only STT that never
sends audio to the cloud — serving as the reference LLM-backed extraction tool
alongside yt-summarizer.

## Acceptance

- [ ] **voice-transcribe extracted** under the canonical tool contract
  (`name` / `description` / `input_schema` / `run`).
- [ ] **`tool_type: predictive`** in `tools/schema.yaml` — distinguished from the
  deterministic script-tools (CO-521).
- [ ] **Injectable local-whisper backend** from `bridge/voice.py` is the runtime; the
  backend is swappable behind the tool (swap = a flag).
- [ ] **Local-only STT**: audio never leaves the instance — no cloud transcription path
  in the default (aligns with the CO-497 data-residency invariant).
- [ ] **Reference predictive adapter**: stands alongside yt-summarizer as the canonical
  LLM-backed extraction example for future tool authors.
- [ ] **Generalist**: no tenant names; WhatsApp is one caller of the tool, not baked in.

## Notes
- Depends on CO-503 (canonical tool contract). Sibling to CO-521 (the deterministic
  batch) — together they demonstrate both `tool_type` paths.
- "agente não bot": voice-transcribe is a capability an agent invokes; local-only keeps
  the self-host posture intact.
