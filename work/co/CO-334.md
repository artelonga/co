## As
Yuri (and visitors) wanting one place to see what's happening across the whole platform — CO releases, sister-repo releases (ArteLonga, Quilombo, Yggdrasil, RFQ), all surfaced together

## I Need
The existing CO `/changelog` view to also include parsed entries from each sister repo's `CHANGELOG.md`, with version bumps and summaries, interleaved by date.

## So That
Looking at one page tells me the recent activity across every deployable I maintain — without having to visit each repo's CHANGELOG separately.

## Background

Current CO `/changelog` shows only CO's own `CHANGELOG.md` (managed by `release-commit.sh`). Sister repos each have their own:
- `~/projects/ArteLonga/CHANGELOG.md` (828 lines, latest `0.14.0`)
- `~/projects/quilomboaraucaria/CHANGELOG.md` (463 lines, latest `0.12.6`)
- `~/projects/yggdrasil/CHANGELOG.md` (635 lines, latest releases)
- `~/projects/rfq-gateway/CHANGELOG.md` (611 lines, latest `0.6.0`)

All follow Keep-a-Changelog format with `## [version] — date — theme` headers. Same parser works on all of them.

## Design

### Parser

Single helper `parse_keep_a_changelog(md: &str) -> Vec<ReleaseNote>`:
```rust
struct ReleaseNote {
    repo: String,        // "artelonga" | "quilomboaraucaria" | ...
    version: String,     // "0.14.0"
    date: chrono::NaiveDate,
    theme: Option<String>,
    body_md: String,     // raw markdown between this version header and the next
    body_text: String,   // body with markdown stripped for search/summary
}
```

Regex captures the `## [N.N.N] — YYYY-MM-DD — theme` header and body until the next `##` or EOF.

### Source resolution (CO-330 reuses)

Each universe with `local_repo_path IS NOT NULL` is candidate. The aggregator reads `<local_repo_path>/CHANGELOG.md` if it exists. Universes without a path: skipped (no source).

Default mapping for sister deployables (already in CO-330 backfill):
- artelonga → ArteLonga/CHANGELOG.md
- quilomboaraucaria → quilomboaraucaria/CHANGELOG.md
- yggdrasil → yggdrasil/CHANGELOG.md
- rfq → rfq-gateway/CHANGELOG.md
- comunicacao, mbya, topologia, yuri → skipped (no CHANGELOG.md yet; gracefully ignore)
- co (self) → already shown via the existing `/changelog`; mark as repo="co"

### Storage

New table `release_notes`:
```sql
CREATE TABLE release_notes (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    repo          TEXT    NOT NULL,
    version       TEXT    NOT NULL,
    date          TEXT    NOT NULL,     -- ISO date
    theme         TEXT,
    body_md       TEXT    NOT NULL,
    body_text     TEXT    NOT NULL,     -- for FTS later
    ingested_at   INTEGER NOT NULL,
    UNIQUE(repo, version)
);
CREATE INDEX idx_release_notes_date ON release_notes(date DESC);
CREATE INDEX idx_release_notes_repo ON release_notes(repo, date DESC);
```

### Ingestion

`run_release_notes_refresh(config)` orchestrator step that:
1. Iterates universes with `local_repo_path IS NOT NULL`
2. For each, reads `<repo>/CHANGELOG.md`
3. Parses with `parse_keep_a_changelog`
4. UPSERT each `(repo, version)` row (idempotent)
5. Also ingest the CO repo's own CHANGELOG.md

Runs on every `co serve` boot AND on a configurable interval (default: every 5 min) so newly committed changelog entries show up without restart.

### API

```
GET /api/v1/changelog/feed                   — interleaved by date, paginated
GET /api/v1/changelog/feed?repo=artelonga    — filter to one repo
GET /api/v1/changelog/feed?since=2026-05-01  — date filter
GET /api/v1/changelog/repos                  — list known repos + their latest version
```

Each item:
```json
{
  "repo": "yggdrasil",
  "version": "0.18.2",
  "date": "2026-05-31",
  "theme": "tema Relic Archive em toda a plataforma",
  "body_md": "...",
  "body_html": "...rendered..."
}
```

### UI

`/changelog` page extended:
- Top: filter dropdown (all | co | artelonga | quilombo | yggdrasil | rfq)
- Each entry: repo badge (colored), version + date + theme, expandable body
- Default: all repos, newest first, paginated (50 per page)
- Direct deep-link: `/changelog?repo=yggdrasil&version=0.18.2` opens that release expanded

CO's own changelog page continues to also be available at `/co/changelog` for the CO-only view.

### Performance

- Parse runs at boot + every 5 min. Releases are O(100) per repo, parsed in <50ms.
- DB queries are indexed on date — paginated list is O(log N + page_size).
- HTML rendering cached per release-note (the body_md is immutable once written).

- No SPA-side changes break the existing `/changelog` view (additive)

## Dependencies

- **CO-330** ✓ shipped — uses `universes.local_repo_path` to know where each repo lives
- **CO-323** ✓ shipped — `/changelog` route already exists; this extends its data source

## Not in scope

- Writing back to sister-repo CHANGELOG.md from CO — out of scope; CO is read-only
- Remote-fetched changelogs (GitHub API for unconfigured repos) — out of scope; local clone required
- Slack/Discord notifications on new release — separate spec if desired
- Pre-release / draft changelog ingestion — out of scope; only released versions counted
- Search across changelog bodies (FTS5) — `body_text` column ready for it but UI defers to v2

## Why now

- Yuri reviewing the platform wants one pane to see what's recent across all 5 sister deployables + CO
- Eliminates context-switching between repos
- Pairs with CO-329 `/analytics` — one shows real-time activity, the other shows release-level history
- Each sister repo already commits to its CHANGELOG.md on every release (via release-commit.sh or equivalent); no process change for those teams
