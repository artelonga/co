## As

a developer reading the philosophy in `topologia/docs/universe-as-list-of-lists.md` ("universe is a list of lists — one universal schema, one universal API")

## I Need

(a) a unified `reference` content type that wraps any non-markdown asset (PDF, image, video, audio, external URL) with a metadata `.md` card carrying `{file, mime, size_bytes, medium, …}`, and
(b) a single telemetry envelope every entry/asset/relation CRUD + WS connection-state change emits, so `/co/co/telemetria` is a view over one event stream

## To

formalize what's already happening ad-hoc — `mbya/refs/*.md` siblings to PDFs, the pindovy 4-way mapping pattern, the YouTube card stub — into a content type that's first-class, indexable, and observable

---

## Part A — `reference` as a first-class content type

### Manifest declaration

Universes that want references add `reference` to `content_types`:

```yaml
# _universe.yaml
content_types:
  - term
  - reference
  - …

properties_per_type:
  reference:
    file:
      kind: text
      description: Filename of the bound asset (sibling in same dir); null for external URL refs.
    url:
      kind: text
      description: Full URL for external refs (YouTube, web pages, citations).
    mime:
      kind: text
      required: true
    medium:
      kind: enum
      values: [pdf, image, video, audio, web, citation]
      required: true
    size_bytes:
      kind: int
    language:
      kind: text
    authors:
      kind: list
    keywords:
      kind: list
    transcription:
      kind: text
      description: For video/audio refs; full text for FTS.
    chapters:
      kind: list
      description: Array of {start_seconds, end_seconds, title} for video/audio.
    seed_status:
      kind: enum
      values: [stub, reviewed, native-confirmed]
      required: true
```

### Indexable shadow table

```sql
CREATE TABLE references_meta (
    universe_key  TEXT NOT NULL,
    entry_path    TEXT NOT NULL,
    file          TEXT,                   -- sibling asset filename
    blob_sha256   TEXT,                   -- resolved on first index
    url           TEXT,
    medium        TEXT NOT NULL,
    mime          TEXT,
    size_bytes    INTEGER,
    language      TEXT,
    seed_status   TEXT NOT NULL,
    indexed_at    TEXT NOT NULL,
    PRIMARY KEY (universe_key, entry_path)
);

CREATE INDEX idx_refs_medium      ON references_meta(medium);
CREATE INDEX idx_refs_seed_status ON references_meta(seed_status);
CREATE INDEX idx_refs_blob        ON references_meta(blob_sha256) WHERE blob_sha256 IS NOT NULL;

CREATE VIRTUAL TABLE references_fts USING fts5(
    universe_key UNINDEXED,
    entry_path   UNINDEXED,
    title,
    body,
    transcription
);
```

### API

```
GET  /api/v1/universes/{u}/references                         (list, filters: medium=pdf|video|…, seed_status=…, q=fts)
GET  /api/v1/universes/{u}/references/{path}                  (one card)
POST /api/v1/universes/{u}/references                         (create card; if `file` set, expects sibling blob already at /assets)
PUT  /api/v1/universes/{u}/references/{path}                  (update card)
DELETE /api/v1/universes/{u}/references/{path}                (delete card; blob unaffected)

GET  /api/v1/universes/{u}/references/orphan-blobs            (assets with no card)
GET  /api/v1/universes/{u}/references/broken-cards            (cards whose `file` doesn't resolve to an existing asset)
```

The orphan/broken endpoints close the loop: every reference should have both card and blob (or card + URL for external refs); auditing surfaces drift.

### Card-blob binding

When a `.md` card has `file: foo.pdf`, the loader:
1. Stats `<universe-root>/<dir>/foo.pdf` and computes sha256 if present.
2. Stores sha256 in `references_meta.blob_sha256`.
3. Optionally hard-links to the asset's content-addressed location (`assets/<aa>/<bb>/<sha>`) if the asset endpoint already has it.

If the blob is absent on disk, `seed_status: stub` is enforced (you can't claim `reviewed` without the artifact).

## Part B — Universal telemetry envelope

Every state change emits a single event shape into `telemetry_events`:

```json
{
  "id": "evt_xxx",
  "kind": "entry.upsert" | "entry.delete" | "asset.upload" | "asset.delete" |
          "relation.create" | "relation.delete" | "ws.connect" | "ws.disconnect" |
          "ws.lag" | "auth.login" | "auth.logout" | …,
  "universe": "mbya",
  "list": "refs",                       // content type / dir, when applicable
  "key": "youtube-czwpPvu3ziQ.md",      // entry_path or asset sha256
  "actor": "usr_3ded7630" | null,
  "session_id": "ses_yyy" | null,
  "deployment_version": "1.38.7",
  "timestamp_ns": 1714750000000000000,
  "extra": { … kind-specific extras … }
}
```

Event sites to instrument (kind, where):

| Kind | Hook |
|---|---|
| `entry.upsert` | `EntryIndex::upsert`, `vault_routes::put_vault_file`, `processos::*` |
| `entry.delete` | `vault_routes::delete_vault_file`, `processos::revert` |
| `asset.upload` | `asset_routes::upload_asset` |
| `asset.delete` | `asset_routes::delete_asset` |
| `relation.create` | `relation_index::*::insert` |
| `relation.delete` | `relation_index::*::delete` |
| `ws.connect` | `sync_ws::handle_sync_socket` (post-auth) |
| `ws.disconnect` | `sync_ws::handle_sync_socket` (loop exit) |
| `ws.lag` | broadcast `Lagged` branch |
| `auth.login` | `auth::password_login_handler`, `uat_login`, magic-link verify |
| `auth.logout` | `auth::logout_handler` |

Existing `telemetry_events` table (CO-46) is the sink; this just unifies the producer.

## Acceptance

### Part A
- [ ] `_universe.yaml` parser accepts `properties_per_type` with the per-content-type property map
- [ ] `references_meta` + `references_fts` tables created on per-universe DB v8 migration
- [ ] On every reference-card write, the row is upserted in `references_meta`; sha256 of the bound asset is computed and stored
- [ ] `GET /references?medium=pdf` returns rows from the `mbya` universe matching every PDF in `mbya/refs/`
- [ ] `GET /references/orphan-blobs` lists assets with no `.md` card
- [ ] `GET /references/broken-cards` lists cards whose `file:` doesn't resolve

### Part B
- [ ] Every site in the kind-table emits one `telemetry_events` row per event
- [ ] `deployment_version` matches `cargo workspace.package.version` at write time
- [ ] `session_id` is the JWT `jti` (or anon-cookie hash for unauthenticated callers)
- [ ] `/co/co/telemetria` admin dashboard surfaces the new event kinds with default 24-hour window
- [ ] Documentation: `docs/telemetry-envelope.md` lists every kind + its `extra` shape

## Out of scope

- Server-side OCR / transcript extraction from PDFs and videos (separate ticket; these cards stay user-authored or external-API-fed for v1).
- Cross-universe reference rollups (e.g. "every reference citing Dooley 2006 across all universes"). Possible follow-up; v1 scopes per-universe.
- Telemetry retention / archival to a cold tier. Existing CO-46 retention applies.
