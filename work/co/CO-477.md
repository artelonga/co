## Contexto
Vários testes de `co-web` falhavam de forma intermitente **apenas** sob `cargo test`
paralelo (passavam isolados) porque mutam o **ambiente compartilhado do processo**
via `std::env::set_var` / `remove_var`, corrida com outros testes. O ofensor mais
visível, `platform::telemetry_api::tests::jwt_session_passes_gate`, esperava `200`
mas via `401` quando um teste concorrente reescrevia `JWT_SECRET` entre o
sign-do-token e a validação-no-gate (o gate relê `JWT_SECRET` do ambiente vivo via
`EnvSecretsProvider`). Confirmado empiricamente: numa bateria de 5 execuções
completas, a RUN 2 reproduziu `jwt_session_passes_gate ... FAILED`.

Causa raiz dupla:
1. **Valores divergentes de `JWT_SECRET`** entre testes (`"test-jwt-secret"` vs
   `"test-secret"` vs `"test-feedback-secret"`). Nenhum teste **remove** `JWT_SECRET`,
   então escritas de **valor idêntico** são inofensivas — o problema era a divergência.
2. **Locks por-módulo fragmentados** (`ENV_LOCK` em `kb_routes`, `ADMIN_ENV_LOCK` em
   `lead_routes`, `ENV_MUTEX` em `webhook`/`notification_providers`). Mutexes
   separados **não** serializam entre si, então um teste guardado num módulo ainda
   corria contra um teste de outro módulo.

## Acceptance
- [x] Todos os testes que escrevem `JWT_SECRET` convergem para o valor canônico `"test-jwt-secret"`.
- [x] Um único lock de ambiente process-wide (`crate::test_support::env_lock` / `env_lock_blocking`) substitui os locks fragmentados por-módulo.
- [x] Testes que mutam vars não-JWT com `remove_var`/valor único (`CO_KB_TOKEN`, `CO_SEED_ADMIN_EMAIL`, `CO_AUTO_SOFT_LIMIT_5H_TOKENS`, `CO_TRANSLATE_BACKEND`, `CO_BACKUP_BACKEND`, `CO_CACHE_TEST_CACHE_MAX_ENTRIES`) seguram o lock compartilhado por toda a janela set→build→request→assert.
- [x] Asserções dos testes de funnel (`funnel_routes`) deixam de aceitar `200 OR 403` e passam a exigir `200` estrito (anti-flake real, sem enfraquecer asserção).
- [x] `cargo test -p co-web --lib` (paralelo, default) verde em 2+ execuções completas, 0 falhas.
- [x] `cargo clippy -p co-web --lib -- -D warnings` limpo; `cargo fmt` aplicado.
- [x] Nenhum teste foi `#[ignore]`-ado nem teve asserção enfraquecida para "passar".

## So that
A suíte de testes de `co-web` fica **confiável sob paralelismo default**, removendo
falsos vermelhos de CI e o ruído de re-execução, sem `#[ignore]` nem asserções
frouxas. O lock único também é à prova de futuro: um novo teste que mutar ambiente
em qualquer módulo só precisa pegar o mesmo lock.
