GIVEN the sizing analysis (`infra/` review 2026-06-24) showed a user can be seeded
with the whole **public** platform for ~90 MB (66 MB stripped self-contained
binary with the SPA embedded + ~23 MB content) and kept current with ~KB–MB/day,
WHEN `co bundle` emits a verifiable, self-contained snapshot — the binary + a
content pack of **only the public-classed universes** + a clean registry (no
telemetry/index/version bloat) + a signed manifest,
THEN any user gets a single drop that runs offline and is the seed for daily delta
sync (CO-485), realizing CO's local-first endgame.

## Acceptance

- [ ] `co bundle [--out DIR] [--public-only]` produces: the stripped `co-web`
  binary, a content pack (per-universe `data.db` for universes where
  `data_class: open` AND `visibility` public), a **fresh `meta.db`** containing
  only the universe registry/members (NOT `telemetry_events`/`entry_versions`/FTS
  — those are rebuilt on first run), and a `manifest.json` (version, per-file
  sha256, universe list + license + data_class).
- [ ] **Licensing gate:** excludes `data_class ∈ {personal, proprietary,
  sensitive-TK}` and any non-public visibility (yuri/miguel/neuro/rfq/mbya never
  ship). Exclusions are **logged**, never silent (the "no silent caps" rule).
- [ ] Bundle is reproducible + checksum-verifiable; a `co bundle --verify DIR`
  validates the manifest.
- [ ] Size budget asserted (~90 MB all-public) and printed; binary is stripped.
- [ ] Docs: `docs/distribution/bundle.md` (what's in it, the licensing exclusions,
  how it pairs with CO-485 sync).

## Out of scope / follow-ups

- The delta sync + binary self-update → **CO-485**.
- meta.db growth (so the source store is clean to export from) → **CO-486**.
- GUI installer / Electron-Capacitor wrapper (roadmap).
