## As
A product owner running scrum on top of CO

## I Need
Scrum artifacts (Product Backlog Item, Sprint, Sprint Backlog Item, Definition of Done, Role) to be first-class CO entry types — so the backlog renders as a board, the sprint goal lives in a sprint entry, and DoD checkboxes hang off PBIs.

## So That
- The scrum process becomes data, not a separate tool — PBIs ARE entries; sprints ARE entries; DoD IS an entry.
- A universe with a `_scrum.yaml` automatically gets a "Product Backlog / Sprint Backlog / Increment" three-column board view.
- The retrospective simulation (CO-369), sprint calendar (CO-372), and funnel report (CO-371) all read the same entry tables — no parallel data model.
- ArteLonga's `~/projects/ArteLonga/scrum/` draft becomes an executable workspace.

## Context

`~/projects/ArteLonga/scrum/scrum.md` establishes the framework:
- 3 roles: Product Owner, Scrum Master, Developers
- 5 events: Sprint, Planning, Daily, Review, Retro
- 3 artifacts: Product Backlog (→ Product Goal), Sprint Backlog (→ Sprint Goal), Increment (→ Definition of Done)

CO already has the substrate: `entries` table with `entry_type`, frontmatter, body, relations. Adding scrum types is additive — no new tables, no breaking changes.

## Design

### New entry types

| `entry_type` | Frontmatter shape | Body |
|---|---|---|
| `pbi` | `priority`, `points` (story points or t-shirt: XS/S/M/L/XL), `status` (backlog/ready/in-sprint/done), `acceptance` (array of strings), `sprint` (ref to sprint entry), `assignees` (array of user_ids), `epic` (optional ref) | Description + user story |
| `sprint` | `number` (int), `start_at`, `end_at`, `goal` (string), `release_tag` (e.g. "v2.41.0"), `status` (planning/active/review/closed) | Sprint plan notes |
| `sbi` | (alias for PBI when `sprint` is set; no separate type unless we need per-sprint task subdivision) | — |
| `dod` | `applies_to` (entry_type or universe-wide), `checklist` (array) | Markdown explanation |
| `role` | `name` (Product Owner / Scrum Master / Developer), `user_id`, `universe_key` | Role description |

### Per-universe `_scrum.yaml`

Optional file at universe root:

```yaml
enabled: true
sprint_length_days: 14
sprint_start_day: thursday      # bi-weekly cadence
sprint_start_time: "15:00"       # BRT
sprint_start_anchor: "2026-06-11T15:00:00-03:00"   # first sprint anchor for cadence calculation
release_tag_pattern: "v{major}.{minor}.0"  # how sprints map to git tags
roles:
  product_owner: yuri@artelonga.com.br
  scrum_master: ""
  developers:
    - claude
    - yuri@artelonga.com.br
default_dod:
  - "Acceptance criteria checkboxes all green"
  - "cargo test + cargo clippy -D warnings clean"
  - "PR merged to main"
  - "CHANGELOG-PENDING entry written"
```

Loader sits in `co-web/src/scrum/manifest.rs`. Universes without `_scrum.yaml` keep behavior unchanged.

### Board view extension

When `_scrum.yaml.enabled = true`, the universe's board view (`/co-web/static/variants/a/modules/views/kanban.js`) adds a "Scrum" tab next to "Kanban/Table/Timeline/Conteudo" with 3 columns:
- **Product Backlog** — PBIs with `status: backlog | ready`
- **Sprint Backlog** — PBIs with `status: in-sprint` (filtered to current sprint)
- **Increment** — PBIs with `status: done` (current sprint only)

DoD checklist renders inline on each PBI card. Sprint goal shows above the columns.

### Endpoints

- `GET /api/v1/universes/{key}/scrum/manifest` — returns parsed `_scrum.yaml` + computed current sprint
- `GET /api/v1/universes/{key}/scrum/sprints` — list sprint entries
- `GET /api/v1/universes/{key}/scrum/sprints/current` — current sprint (computed from cadence)
- `GET /api/v1/universes/{key}/scrum/backlog?status=ready` — filtered PBI list
- `POST /api/v1/universes/{key}/scrum/pbi` — create PBI (sugar over POST entries with type=pbi)
- `PATCH /api/v1/universes/{key}/scrum/pbi/{id}/dod` — check off a DoD item

### Current sprint computation

Pure function: `current_sprint(now, anchor, length_days) -> {number, start_at, end_at}`. No DB state.

`number = floor((now - anchor) / length_days) + 1`

If `now` is between Wednesday 23:59 and Thursday 15:00 BRT, the system reports BOTH (closing sprint + next sprint) — `release_window: true` — so the SPA shows "Release in 3 hours: v2.41.0".

### PR cutoff rule (informational, not enforced here)

CO-372 calendar surfaces this; cron-driven release ships at Thursday 15:00 BRT only PRs merged ≤ Wednesday 23:59. Enforced by `scripts/release-commit.sh` calendar awareness in CO-372.

### Schema

No migration. `entry_type` is already a TEXT column. New types are additive.

### Telemetry

Per CO-361 atividades:
- `event_type = scrum.pbi.created | scrum.pbi.dod_checked | scrum.sprint.opened | scrum.sprint.closed`
