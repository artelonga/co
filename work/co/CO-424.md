## Epic

Com o lançamento do **Fable 5 / Mythos 5**, tokens são o recurso a maximizar.
O caso de uso mais pesado do CO é **interagir com launchers ("agents") de
sessões co-auto em várias máquinas e deployments**. Este epic entrega:

1. **Visão centralizada** — um dashboard em tempo real de projetos, quadros e
   launchers ativos, com usage de tokens por universo/quadro/task/modelo/máquina.
2. **Token-efficiency por engenharia de contexto** — cada sessão co-auto recebe
   o mínimo necessário: digest recursivo e breve de cada universo (via
   `parent_key`), camadas de contexto enxutas, prefixo estável para prompt
   caching.
3. **Uso flexível de modelos** — modelo por task (frontmatter) + política
   priority→model + downshift quando a janela de uso aperta, para gastar
   opus/fable só onde importa.
4. **claude-code como universo** + catálogo de superfícies de integração
   (tools) consistente com os modelos (templates) do CO.

## Requirements (ultrathink — 2026-06-12)

### O problema
- co-auto hoje lança `claude -p` headless (dev/co-auto/src/auto.rs) com UM
  modelo global por run (default sonnet) e **descarta** todo o telemetry de
  usage. Não há visão de quanto cada task/universo/máquina consome, nem de
  quanto resta da janela (5h / semanal) da assinatura.
- O contexto injetado (`.claude/co-auto-context.md`) é remontado por task sem
  preocupação com tamanho nem com estabilidade de prefixo (perde prompt cache).
- Vários launchers em várias máquinas/deployments não se enxergam: não há
  registry central de sessões ativas.

### Superfícies do Claude Code utilizáveis (inventário)
| Superfície | Uso neste epic |
|---|---|
| `claude -p --output-format stream-json` | usage por mensagem em tempo real (input/output/cache tokens, modelo) + evento `result` com totais — base do CO-425 |
| `--model <m>` por invocação | model routing por task (CO-427) |
| `~/.claude/projects/*.jsonl` | backfill/auditoria de usage histórico (já minerado por `co-mine-claude-sessions.py`) |
| CLAUDE.md hierárquico (global → projeto → space) | camada estática barata; digest de universos gerado entra aqui (CO-428) |
| Skills / slash commands (`.claude/skills`) | operações comuns do CO viram skills curtas em vez de prosa no contexto (CO-428) |
| Hooks (`settings.json`: Stop/SessionEnd) | fallback de report de usage quando stream-json não estiver disponível (CO-425) |
| OpenTelemetry (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, OTLP) | opcional v2 — métricas `claude_code.token.usage` direto num collector; fora do MVP |
| `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` | já usado pelo co-auto; usage por subagente agregado no evento result |

### Restrições (decisões já tomadas — não rediscutir)
- **Sem MCP** — integração é por API/event bus do CO, nunca MCP server.
- **Sem polling** cross-deployment — launchers fazem *push* para o event bus
  (heartbeat é push, não poll).
- **Nenhum mapeamento universo→repo hardcoded em Rust** — registry no DB.
- Migrations: nunca engolir SELECT em coluna nova com `.ok()`.
- Workers não podem dar panic segurando `Mutex<Storage>`.
- Theme-per-release: este epic = um minor bump único no release commit.

### Critério de sucesso do epic
- [ ] Um único lugar (dashboard Gestão) mostra: launchers ativos (máquina,
      task, modelo, status), usage acumulado por universo/quadro/modelo, e
      consumo da janela corrente.
- [ ] Tasks de prioridade baixa rodam em haiku/sonnet sem intervenção manual;
      opus/fable reservados a `priority: high` — verificável no dashboard.
- [ ] Contexto médio por sessão co-auto cai ≥40% (medido em input tokens
      não-cacheados, antes/depois do CO-428).
- [ ] `claude-code` aparece em `/api/v1/universes` com digest e catálogo de
      tools navegável.
