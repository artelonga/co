## GIVEN / WHEN / THEN

- GIVEN a universe DB whose pragmas fail to apply (disk full, I/O error,
  corrupt -shm), WHEN the pool opens it at startup
  (`co-web/src/platform/universe_pool.rs:312` — currently
  `.expect("universe db pragmas")`), THEN the server STILL BOOTS: the failing
  universe is marked unavailable (503 for its routes, error surfaced in
  /gestao + atividades), all other universes serve normally.
- GIVEN the env failure clears (space freed, volume extended), WHEN the pool
  retries lazily on next access (or via an admin reopen endpoint), THEN the
  universe comes back without a machine restart.
- A startup-path audit accompanies the fix: grep co-web startup for other
  `.expect()`/`.unwrap()` on environment-dependent operations (fs, sqlite
  open, migrations) and convert the same way. Panic-on-env at startup is the
  same family as the 2026-05-12 mutex-poisoning incident: one bad condition
  must never take the whole site down.

## Context

2026-06-11 outage: SQLITE_IOERR_SHMSIZE on a full disk panicked main at
startup → exit 101 → Fly crash loop → max-restart cap → total outage. The
panic converted a partial failure (one pool open) into a global one.
