## GIVEN / WHEN / THEN

- GIVEN a universe DB whose pragmas fail to apply (disk full, I/O error,
  corrupt -shm), WHEN the pool opens it at startup
  (`co-web/src/platform/universe_pool.rs:312` — currently
  `.expect("universe db pragmas")`), THEN the server STILL BOOTS: the failing
  universe is marked unavailable (503 for its routes, error surfaced in
  /gestao + atividades), all other universes serve normally.
- GIVEN the env failure clears (space freed, volume extended), WHEN the pool
  retries lazily on next access (or via an admin reopen endpoint), THEN the
  universe comes back without a machine restart.
- A startup-path audit accompanies the fix: grep co-web startup for other
  `.expect()`/`.unwrap()` on environment-dependent operations (fs, sqlite
  open, migrations) and convert the same way. Panic-on-env at startup is the
  same family as the 2026-05-12 mutex-poisoning incident: one bad condition
  must never take the whole site down.

## Context

2026-06-11 outage: SQLITE_IOERR_SHMSIZE on a full disk panicked main at
startup → exit 101 → Fly crash loop → max-restart cap → total outage. The
panic converted a partial failure (one pool open) into a global one.

## Acceptance

- [x] A universe whose pool open/pragmas/migrations fail no longer panics:
      `UniversePool::try_get_or_open` returns `Err(PoolError)` and marks the
      universe unavailable (logged for atividades) instead of crashing.
- [x] The server still BOOTS when a universe is bad — `seed_template_universe`
      skips + logs on template open failure rather than panicking `Storage::new`.
- [x] The failing universe's routes return **503** (via `universe_visibility_gate`,
      the CO-161 chokepoint) with a clear reason; all other universes serve 200.
      Proven in-process (`co406_one_bad_universe_503_others_serve`, tower oneshot,
      tempfile dirs, no real ports).
- [x] Lazy retry: once the environment failure clears, the next access recovers
      the universe without a machine restart; an admin `POST
      /gestao/universos/{key}/reabrir` forces immediate recovery
      (`GET /gestao/universos/indisponiveis` lists unavailable ones).
- [x] Per-universe migrations converted from `.expect()` panics to `Result`
      propagation (`run_universe_migrations`, `ensure_universe_column`,
      `recreate_references_meta_v8`).
- [x] Startup-path audit documented (converted vs deliberately-left-fatal:
      meta.db / shared singletons stay fail-fast) in `CHANGELOG-PENDING/CO-406.md`.
- [x] No `Mutex<Storage>` held across an `.await`; no panic under the lock.
- [x] Gates green: `cargo fmt`, `cargo clippy -p co-web -- -D warnings`,
      `cargo test -p co-web`.
