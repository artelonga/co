GIVEN a node bound to the LAN (`CO_WEB_HOST=network`, CO-512) must stay private —
firewalled to the local network, never accidentally exposed to the public internet,
killable on demand, with secrets encrypted at rest — and today this guidance lives
as prose in `infra/SELF-HOST-SECURITY.md` rather than runnable tooling,
WHEN a self-hoster opts into LAN exposure,
THEN there must be a hardening kit that promotes that prose into runnable scripts: a
pf firewall template, exposure-scan automation (nmap / the e2e exposure guard), a
kill-switch, and secrets-at-rest guidance — so privacy is enforced and verifiable,
not just documented.

## Acceptance checklist

- [ ] pf firewall template restricts co-web to the LAN subnet (deny public; installable script).
- [ ] Exposure-scan automation (nmap + the e2e exposure guard) flags any unintended public reachability.
- [ ] Kill-switch script stops co-web immediately and confirms the port is closed.
- [ ] Secrets-at-rest guidance (encrypted store for tokens/JWT_SECRET) documented and scripted.
- [ ] `infra/SELF-HOST-SECURITY.md` prose is promoted into runnable scripts under `scripts/selfhost/`.

## Notes
- Promotes `infra/SELF-HOST-SECURITY.md` (LAN-only firewall, kill-switch, integrity,
  the `.git`-over-`:8000` postmortem) from documentation into runnable, testable scripts.
- Pairs with CO-512 (the bind-host choice): binding `0.0.0.0` should always be done
  behind this kit. Reuses the existing exposure-scan e2e guard rather than inventing a
  new scanner.
