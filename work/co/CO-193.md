## As

a logged-in user who belongs to a universe (owner, admin, member, or
subscriber per CO-191 bucketing)

## I Need

a per-universe chat with a `general` room out-of-the-box and the ability
for owners/admins to create additional named rooms, with REST endpoints
to list rooms, post messages, and paginate history

## So That

universe members have a real-time conversation surface scoped to their
shared space — and the yggdrasil game lobby (the first chat consumer,
shipped in CO-195) can serve a chat panel that reuses the same backend.

## Schema — migration

New tables on the meta DB. Reuse the recent `ensure_table` idempotent-
backfill pattern (no version slot needed; runs every boot, no-op once
table exists):

```sql
CREATE TABLE IF NOT EXISTS chat_rooms (
    id              TEXT PRIMARY KEY,            -- room_xxxxx
    universe_key    TEXT NOT NULL,
    name            TEXT NOT NULL,               -- 'general', 'random', ...
    slug            TEXT NOT NULL,               -- lowercased, unique-per-universe
    description     TEXT,
    created_by      TEXT NOT NULL,               -- user_id of creator
    created_at      TEXT NOT NULL,
    archived_at     TEXT,
    is_default      INTEGER NOT NULL DEFAULT 0,  -- 1 for the auto-created 'general'
    FOREIGN KEY (universe_key) REFERENCES universes(key)
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_chat_rooms_universe_slug
    ON chat_rooms(universe_key, slug);
CREATE INDEX IF NOT EXISTS idx_chat_rooms_universe_archived
    ON chat_rooms(universe_key, archived_at);

CREATE TABLE IF NOT EXISTS chat_messages (
    id              TEXT PRIMARY KEY,            -- msg_xxxxx
    room_id         TEXT NOT NULL,
    author_id       TEXT NOT NULL,               -- user_id
    body            TEXT NOT NULL,               -- markdown allowed (rendered client-side)
    created_at      TEXT NOT NULL,
    edited_at       TEXT,
    deleted_at      TEXT,                        -- soft delete (CO-196)
    reply_to_id     TEXT,                        -- threading via parent message id (optional)
    FOREIGN KEY (room_id)     REFERENCES chat_rooms(id),
    FOREIGN KEY (author_id)   REFERENCES users(id),
    FOREIGN KEY (reply_to_id) REFERENCES chat_messages(id)
);
CREATE INDEX IF NOT EXISTS idx_chat_messages_room_created
    ON chat_messages(room_id, created_at);
CREATE INDEX IF NOT EXISTS idx_chat_messages_room_deleted
    ON chat_messages(room_id, deleted_at);
```

**Default-room seeding.** On universe creation (extending the existing
`storage::universe::create_universe` path), insert one row into
`chat_rooms` with `slug='general'`, `name='Geral'`, `is_default=1`. A
boot-time backfill (similar to existing recovery-channel-backfill
pattern) inserts a `general` room for every pre-existing universe that
doesn't have one yet — idempotent.

## Authorization model

A caller can:

| Action | Required role |
|---|---|
| List rooms | Member or above (`owner|admin|member|viewer|subscriber`) |
| Read messages | Same as list rooms |
| Post message | Member or above; **viewers and subscribers cannot post** |
| Create room | `owner` or `admin` |
| Archive room | `owner` or `admin` |

`viewer` / `subscriber` get a read-only chat experience. The
`universe_members` table (populated by CO-188 invitations + earlier
join flows) is the source of truth. The CO-191 `/me/universes` shape
already exposes `role` per universe; chat endpoints just re-check it
server-side.

Anonymous callers: **no chat access**. Chat is a logged-in-only
feature. This is deliberate — chat is identity-bound.

## Endpoints

### `GET /api/v1/universes/:slug/chat/rooms` (auth required)

```jsonc
{
  "rooms": [
    { "id": "room_abc", "slug": "general", "name": "Geral",
      "description": null, "is_default": true,
      "created_by": "usr_xxx", "created_at": "..." }
  ]
}
```

Archived rooms excluded by default. `?include_archived=true` to include.

### `POST /api/v1/universes/:slug/chat/rooms` (auth, owner/admin)

```jsonc
// Request
{ "name": "random", "description": "Off-topic" }

// Response
{ "id": "room_xyz", "slug": "random", ... }
```

Slug auto-derived from name (lowercased, non-alphanumeric → `-`).
409 if slug collides within the same universe.

### `GET /api/v1/universes/:slug/chat/rooms/:room_slug/messages?before=<msg_id>&limit=50`

Auth required, member-or-above. Default page size 50, max 200. Returns
`{messages: [...], has_more: bool}` ordered newest-first. `before`
cursor pages backward through history.

Each message:
```jsonc
{
  "id": "msg_abc",
  "author": { "user_id": "usr_yyy", "display_name": "Yuri", "usuario": "yuri" },
  "body": "Olá",
  "created_at": "...",
  "edited_at": null,
  "deleted_at": null,
  "reply_to_id": null
}
```

Soft-deleted messages return with `body: "[mensagem removida]"` and
`deleted_at: "..."` so the UI can show a tombstone.

### `POST /api/v1/universes/:slug/chat/rooms/:room_slug/messages` (auth, member+)

```jsonc
// Request
{ "body": "Olá pessoal!", "reply_to_id": null }

// Response
{ "id": "msg_xyz", ... }
```

Validation: `body` non-empty, ≤4000 chars. Rate-limit 20 messages per
user per minute (reuse `rate_limit` module — new key
`chat:post:<user_id>`).

## Storage helpers

In `co-web/src/storage/chat.rs` (new):

```rust
impl Storage {
    pub fn ensure_default_room(&self, universe_key: &str) -> anyhow::Result<()>;
    pub fn list_chat_rooms(
        &self,
        universe_key: &str,
        include_archived: bool,
    ) -> Vec<ChatRoom>;
    pub fn create_chat_room(
        &self,
        universe_key: &str,
        name: &str,
        description: Option<&str>,
        created_by: &str,
    ) -> anyhow::Result<ChatRoom>;
    pub fn get_chat_room_by_slug(
        &self,
        universe_key: &str,
        slug: &str,
    ) -> Option<ChatRoom>;
    pub fn list_chat_messages(
        &self,
        room_id: &str,
        before: Option<&str>,
        limit: usize,
    ) -> Vec<ChatMessageWithAuthor>;
    pub fn post_chat_message(
        &self,
        room_id: &str,
        author_id: &str,
        body: &str,
        reply_to_id: Option<&str>,
    ) -> anyhow::Result<String /* message_id */>;
    pub fn backfill_default_rooms(&self) -> usize;
}
```

`backfill_default_rooms` runs on boot like other backfill paths
(`backfill_email_recovery_channels`, etc.) — inserts a `general` row
for any universe that lacks one.

## Routes wiring

Mount under the existing universe-scoped router so the slug-resolution
+ membership middleware can be reused if/when one exists. If today's
routes use ad-hoc per-handler checks (as some recent ones do), keep
that pattern — explicit `storage.is_universe_member(slug, user_id)` +
`get_member_role` calls inside each handler.

```rust
.route("/v1/universes/{slug}/chat/rooms", get(list_rooms).post(create_room))
.route("/v1/universes/{slug}/chat/rooms/{room_slug}/messages",
        get(list_messages).post(post_message))
```

## Acceptance

- [ ] `chat_rooms` + `chat_messages` tables created via idempotent
      `ensure_table` (re-running boot is a no-op).
- [ ] On universe creation, a `general` room is auto-inserted.
- [ ] Boot-time backfill inserts a `general` room for every pre-existing
      universe that lacks one.
- [ ] `GET /rooms` returns 401 anonymous, 403 non-member, 200 with
      `general` for member.
- [ ] `POST /rooms` works for owner/admin, 403 for member/viewer.
- [ ] `POST /messages` works for member+, 403 for viewer/subscriber,
      400 if body empty / too long, 429 over rate limit.
- [ ] `GET /messages` paginates correctly via `?before=<id>&limit=N`.
- [ ] Soft-deleted messages return tombstone text + `deleted_at`.
- [ ] Tests: 12+ covering happy-path read/write, every auth gate,
      pagination, rate limit, default-room seed, backfill idempotency,
      slug-collision 409, viewer/subscriber read-only.
