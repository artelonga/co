## As

An anonymous or logged-in user browsing the `/co` universe

## I Need

The CO-N task entries that CO-261's seed walker inserted to be **visible via the standard `/api/v1/universes/co/entries` API** and rendered in the SPA's kanban/conteudo views.

## So That

The "live dev board" CO-261 promised actually works. Today's symptom (v2.23.0):

- `GET /api/v1/universes/co` returns `content_count: 927`
- Server logs confirm `seed_co_universe_tasks: seeded 238 CO tasks (skipped 169); co now has 927 entries total`
- BUT `GET /api/v1/universes/co/entries?limit=5` returns `total: 0, items: []`
- AND `GET /api/v1/universes/co/entries/CO-261.md` returns 404
- AND `GET /api/v1/universes/co/entries/tasks/CO-261.md` returns 404

So the rows are physically in the database (the count is right) but they don't surface through the entries API.

## Hypotheses to verify

1. **Path-shape mismatch**: walker writes path like `work/co/CO-261.md` but API expects `tasks/CO-261.md` or just `CO-261.md`. Verify by SQL: `SELECT path FROM entries WHERE universe_key='co' LIMIT 5;`
2. **Visibility filter**: walker writes with `is_public: 0` or similar; the read endpoint filters out non-public entries for anonymous users. Check the read query's WHERE clause.
3. **Entry type filter**: walker writes `entry_type: task` but the default `/entries` endpoint filters out a specific type. Check.
4. **Wrong universe_key**: walker inserts with `universe_key='co'` but the read uses a different identifier (e.g., universe_id integer).
5. **content_count out of sync**: the 927 is misleading; rows aren't actually present where we think they are.

## Scope

- SSH into prod (or replicate locally with same seed-co data) and run direct SQL queries against the universe DB to confirm path shape + entry_type + any visibility column
- Fix the walker OR the API filter so reads match writes
- Add an integration test that asserts: after seed, `GET /entries?limit=10` returns at least one row matching the seeded data
- Smoke test: anonymous visitor on `/co` sees at least the most recent task entries in the conteudo view

## Acceptance

- After redeploy, `GET /api/v1/universes/co/entries?limit=5` returns `total > 0` and `items.length > 0`
- One of `GET /api/v1/universes/co/entries/<some-path>` resolves to 200 with body text matching a real CO-N task
- SPA at `/co` shows entries (in whatever view is the default — conteudo or kanban)
- Migration v14 (if added by walker) is idempotent on re-run

## Blast radius

- ~20 LOC fix in `storage/seed.rs` or `entry_routes.rs` depending on root cause
- 1 new integration test in `co-web/tests/co_universe_dev_board_tests.rs`
