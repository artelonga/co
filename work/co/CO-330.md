## As
A user who wants to (a) add new repos to CO without deploys and (b) host a single universe that mixes public/draft content (e.g., yuri.artelonga.com.br reading the published subset of the yuri vault)

## I Need
Universe→repo bindings as runtime configuration AND per-universe opt-in filtering of anonymous reads to entries marked `published: true` in their frontmatter

## So That
Adding any repo (public or private) is a database-only operation, and a single universe can serve as both private board (owner sees all) and public surface (anon sees only `published: true` entries).

## Background

This consolidates two pieces that were originally separate (CO-330 + CO-324) but share the same runtime-configurable design surface:

1. **Universe→repo binding** lives in `universes` table, not hardcoded Rust
2. **Anon published-only filter** is an opt-in universe flag + a frontmatter convention — no per-entry schema change (per architectural review 2026-06-01)

## Scope

### Schema (migration v51)

Three new columns on `universes`, all additive + nullable / default-false:

```sql
ALTER TABLE universes ADD COLUMN local_repo_path TEXT;
ALTER TABLE universes ADD COLUMN content_subdirs TEXT;             -- JSON array, e.g. ["docs","content"] or [""]
ALTER TABLE universes ADD COLUMN anon_published_only INTEGER NOT NULL DEFAULT 0;
```

**No schema change to `entries`** — the published gate reads from `frontmatter` JSON column at query time.

### One-time backfill (idempotent — `WHERE local_repo_path IS NULL`)

```sql
UPDATE universes SET local_repo_path='~/projects/ArteLonga', content_subdirs='["docs","content"]' WHERE key='artelonga' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/quilomboaraucaria', content_subdirs='["docs","content"]' WHERE key='quilomboaraucaria' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/yggdrasil', content_subdirs='["docs","content"]' WHERE key='yggdrasil' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/rfq-gateway', content_subdirs='["docs","content"]' WHERE key='rfq' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/comunicacao', content_subdirs='["docs","content"]' WHERE key='comunicacao' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/mbya', content_subdirs='["docs","content"]' WHERE key='mbya' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/topologia', content_subdirs='["docs","content"]' WHERE key='topologia' AND local_repo_path IS NULL;
UPDATE universes SET local_repo_path='~/projects/yuri', content_subdirs='[""]', anon_published_only=1 WHERE key='yuri' AND local_repo_path IS NULL;
```

### Seed orchestrator refactor

`co-web/src/server/seed_orchestrator.rs::run_sister_repo_seeds`:

```rust
// BEFORE: hardcoded mapping array (deleted)
// AFTER:
let rows = storage.conn.prepare(
    "SELECT key, local_repo_path, content_subdirs FROM universes \
     WHERE local_repo_path IS NOT NULL AND COALESCE(hidden,0)=0",
)?;
for (key, path, subdirs_json) in rows { ... }
```

`~` expansion via `dirs::home_dir`. `subdirs_json` parsed as JSON array, defaults to `["docs","content"]` if NULL/invalid.

### New API endpoint

`PATCH /api/v1/universes/<key>/source` (owner only):

```json
{
  "local_repo_path": "~/projects/something",
  "content_subdirs": ["docs", "content"],
  "anon_published_only": false
}
```

All fields optional; only provided ones updated. Returns updated universe.

### Anon published-only filter (the CO-324 piece)

Extend the existing `is_public_for_anon` filter at `co-web/src/content/entry_routes.rs` (around lines 190-240):

```rust
// When the universe has anon_published_only=1 AND the caller is anonymous (no UserId extension):
//   add `AND json_extract(entries.frontmatter, '$.published') = 1` to the WHERE clause
// Owner / authenticated callers: no additional filter — they see everything
```

Apply to all read endpoints: `GET /entries`, `GET /entries/<path>`, `GET /entries/tree`, search.

Index for performance: `CREATE INDEX IF NOT EXISTS idx_entries_published ON entries(universe_key, json_extract(frontmatter, '$.published'))` — partial index keyed on the json field.

### `co launch` extension

`co-cli/src/commands/launch.rs`: after creating the universe row, also set `local_repo_path` to the resolved repo root. So `cd ~/projects/foo && co launch` produces a universe pre-wired to its source — no separate PATCH call needed.

## Why now
User feedback 2026-06-01: hardcoded mappings break the "any content from any repository should be integrable database-only without a deploy" principle. Also unblocks yuri.artelonga.com.br vision (the recommendation from artelonga repo review) by enabling anon-published filtering on a single universe without schema gymnastics.
