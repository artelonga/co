GIVEN logged-in users should be able to discover public universes (like co-dev) and subscribe to them,
WHEN I add search + subscription endpoints and UI,
THEN:

## Backend

### Search endpoint
- [x] `GET /api/v1/universes/search?q=<query>&limit=20` — public only
  - Searches universe `name` and `description` (case-insensitive LIKE)
  - Returns: `[{ key, name, description, subscriber_count, entry_count, owner_display_name }]`
  - Excludes: template, private, user's already-subscribed universes

### Subscription endpoints
- [x] `POST /api/v1/universes/:slug/subscribe` — auth required
  - Creates row in `subscriptions` table
  - Returns 201 Created
  - Idempotent (re-subscribing returns 200)
- [x] `DELETE /api/v1/universes/:slug/subscribe` — auth required
  - Removes subscription
  - Returns 204 No Content
- [x] `GET /api/v1/universes/:slug/subscribers` — owner/admin only
  - Returns subscriber list with count

### Database
- [x] New table `subscriptions`:
  ```sql
  CREATE TABLE subscriptions (
    user_id TEXT NOT NULL,
    universe_key TEXT NOT NULL,
    subscribed_at TEXT NOT NULL,
    PRIMARY KEY (user_id, universe_key)
  );
  ```
- [x] `list_universes_for_user` updated to include subscribed universes (UNION with subscriptions table)

## Frontend

### Search UI
- [x] Search bar in sidebar (below communities header) or modal
- [x] Type → debounced search → results dropdown
- [x] Each result: name, description snippet, subscriber count, "Inscrever-se" button
- [x] Click "Inscrever-se" → POST subscribe → universe appears in sidebar
- [x] Already subscribed → show "Inscrito ✓"

### Sidebar integration
- [x] Subscribed universes appear in sidebar below owned communities
- [x] Visual distinction: owned = bold, subscribed = normal weight
- [x] Right-click or long-press → "Cancelar inscrição"

### co-dev Discovery Flow
```
1. Yuri logs in → sees personal "yuri" board
2. Clicks search icon in sidebar
3. Types "co-dev"
4. Sees result: "co-dev — Co development tasks and roadmap"
5. Clicks "Inscrever-se"
6. co-dev appears in sidebar
7. Clicks co-dev → sees all CO-* tasks as a Kanban board
8. Tasks are read-only (unless yuri has write access)
```
