## As
Yuri editing notes on the laptop offline AND on the phone offline; both reconnect later

## I Need
When CO-380 detects divergent edits to the same entry (different `body_hash`, same `(universe_key, path)`), present a Mac-style file-conflict UI with 5 actions mapped to CRUD operations — bulk-applicable across all conflicts.

## So That
- The bi-directional sync (CO-384 bridge) has a deterministic conflict-resolution UI; merges aren't black-box.
- The IaaS principle holds: the action tree is the bounded service; which option the user picks is the free brain's judgment.
- Cross-device editing works as a first-class experience, not an edge case.
- CO-383's "remote wins" default (v3.0) gets a richer UX (v3.1) — same code path, smarter UI.

## Context

The user model (decided 2026-06-06):

> "user can choose to keep both (newest by name gets _1 or something as a copy), ignore/skip (items with no hash changes, names without edits get ignored, not even loaded — important for scaling), replace (force all old to be replaced with all new), update (merge solutions before such that updated edits get the new versions, unmodified ignore) and upsert (same as before, but new items get inserted)"

This maps to CRUD:

| User-facing action | CRUD operation(s) | Hash check |
|---|---|---|
| **Keep both** | C (create with suffix) | hashes differ |
| **Ignore / Skip** | (no-op) | hashes match → cheap |
| **Replace** | U (overwrite local) | hashes differ |
| **Update (merge)** | U (3-way merge via CO-162) | hashes differ |
| **Upsert** | C + U (merge existing + insert new) | hashes differ; new items have no local counterpart |

Plus an implicit **Delete** action:
- **Accept remote delete** → D (mirror)
- **Keep local (resurrect)** → C (re-create from local snapshot)

## Design

### Conflict detection

A conflict exists when:
- Same `(universe_key, path)` exists on local + remote
- `body_hash` differs (CO-146 CAS already provides sha256-keyed bodies)
- Both sides modified since `last_synced_at`

Pure function `detect_conflicts(local_entries, remote_entries) -> Vec<Conflict>` runs at:
- Reconnect after offline (CO-384 bridge replay drain)
- Cross-device event arrival when local cache is stale
- Manual sync trigger

### Conflict type

```rust
#[derive(Clone, Debug, Serialize)]
pub struct Conflict {
    pub universe_key: String,
    pub path: String,
    pub local: EntryRevision,
    pub remote: EntryRevision,
    pub common_ancestor: Option<EntryRevision>,  // for 3-way merge
    pub kind: ConflictKind,
}

#[derive(Clone, Debug, Serialize)]
pub enum ConflictKind {
    BothModified,        // local + remote both changed
    LocalOnlyNew,        // local has it, remote doesn't (no conflict if remote never saw it)
    RemoteOnlyNew,       // remote has it, local doesn't
    LocalDeletedRemoteModified,
    LocalModifiedRemoteDeleted,
}
```

### The action tree

```rust
#[derive(Clone, Debug, Serialize)]
pub enum Action {
    /// Keep both. Newer one renamed with _1/_2/... suffix.
    KeepBoth { suffix: String },
    /// No-op. Hashes match; not really a conflict (defensive).
    Ignore,
    /// Overwrite local with remote.
    Replace,
    /// 3-way merge (CO-162 primitive) — body merged; frontmatter union.
    Update,
    /// For bulk: update existing diff + insert new items.
    Upsert,
    /// Mirror remote delete.
    AcceptDelete,
    /// Re-create from local snapshot (resurrect).
    KeepLocal,
}
```

Per-conflict, the UI offers only the applicable actions (e.g. `AcceptDelete` only when `kind = RemoteDeleted...`).

### Bulk apply

"Apply this action to all conflicts" — a sticky checkbox at the top:

```
☐ Apply [Update] to all remaining 12 conflicts
```

When checked + user clicks an action on one row, the same action applies to all subsequent conflicts of the same shape.

### Atomicity

Each action applied as a transaction:
1. Begin tx
2. Apply action (write new entry; soft-delete; rename; etc.)
3. Publish `sync.conflict_resolved` event to CO-380 bus
4. Update `last_synced_at`
5. Commit tx

If any step fails → rollback → user sees error → no partial state.

### Endpoint

```
POST /api/v1/sync/conflicts/{conflict_id}/resolve
{
  "action": "update",
  "apply_to_all_matching": false
}
```

Returns the resulting `EntryRevision` and the events published.

### Conflict list endpoint

```
GET /api/v1/me/sync/conflicts?universe=...
```

Returns all unresolved conflicts for the current user across their universes.

### Scaling: hash-skip optimization

When draining the bridge's replay queue (CO-384), events are first hash-checked:
- If `event.payload.body_hash == local.body_hash` → no conflict, skip render entirely
- Only divergent events enter the conflict pipeline

This implements the user's "ignore/skip items with no hash changes — important for scaling" requirement at the bridge layer.

### CO-383 integration

For v3.0, CO-383's default conflict policy is "remote wins" (Yggdrasil is source-of-truth for `yggdrasil` universe). When CO-385 ships in v3.1, CO-383 becomes a consumer:
- Same conflict detection
- For `yggdrasil` universe specifically: default Action is `Replace` (remote→local) since it's read-only-from-CO
- For user's own universes: full action tree exposed

### Live timeline integration

Each `sync.conflict_detected` event surfaces in `/agora` (CO-381) with an inline "Resolve →" button linking to the conflicts UI.

### Schema

Migration v67 adds the conflict table:

```sql
CREATE TABLE sync_conflicts (
    id TEXT PRIMARY KEY,            -- ULID
    universe_key TEXT NOT NULL,
    path TEXT NOT NULL,
    local_body_hash TEXT NOT NULL,
    remote_body_hash TEXT NOT NULL,
    common_ancestor_hash TEXT,
    kind TEXT NOT NULL,
    detected_at TEXT NOT NULL,
    resolved_at TEXT,
    resolution_action TEXT,
    resolved_by TEXT,
    FOREIGN KEY (universe_key) REFERENCES universes(key)
);
CREATE INDEX idx_sync_conflicts_unresolved ON sync_conflicts(detected_at) WHERE resolved_at IS NULL;
```

### Telemetry

Per CO-380:

- `sync.conflict_resolved{universe, path, action}` per resolution
- `sync.conflict_resolved_bulk{count, action}` per bulk apply

Visible in /agora live timeline.

## Not in scope

- **AI-suggested action** (machine picks the "right" option) — defer; the user's judgment is the brain
- **Conflict avoidance** (predict + prevent before merge) — defer
- **Cross-universe atomic resolution** (resolve N conflicts as one txn) — defer; per-conflict atomicity is enough
- **Diff renderer beyond unified diff** (rich semantic diff) — defer
- **Audio diff** (read both versions aloud) — accessibility, defer
- **Per-field conflict resolution** (resolve title separately from body) — start with whole-entry; defer field-level
- **Time-travel conflict view** (see all historical divergences) — defer; CO-369 retro covers history
