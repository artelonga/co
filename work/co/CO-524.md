GIVEN the richest external tool is not a one-shot `run(args) → result` but a
**stateful session/kernel** — an R kernel (Rserve / an R REPL) whose variables and
plots persist across calls — and CO should offer an RStudio-like web REPL whose
working dir is the **local universe/scripts** (local-first), running through the
canonical tool contract (CO-503) and the external-tool adapter (CO-523),
WHEN we extend the tool model with a **session sub-kind** (`start` / `exec` / `stop`,
not just one-shot `run`) and proxy an R kernel through co-web behind a web REPL
front-end,
THEN an agent or a user can open a persistent R session scoped to the local
universe's `scripts/` dir, evaluate code incrementally, and tear it down — the
external-tool composability engine extended to long-lived kernels.

## Acceptance

- [ ] **Session sub-kind on the tool contract** — `start` (spawn kernel, return a
  session handle), `exec(session, code) → result`, `stop(session)`; distinct from the
  one-shot `run` shape (CO-503), registered under the same registry/`tool_type`.
- [ ] **R kernel binding** — proxy an R REPL via Rserve (or a managed R subprocess REPL)
  through the external-tool adapter (CO-523); manifest declares the kernel command/port.
- [ ] **co-web proxy** — start/exec/stop routed through co-web, one kernel per session,
  state (variables, loaded data, plots) persists across `exec` calls within a session.
- [ ] **Web REPL front-end** — an RStudio-like surface in the SPA to open a session,
  send code, see stdout/results/plots, and stop the session.
- [ ] **Working dir = the local universe/scripts** — the kernel's cwd is the local
  universe's `scripts/` dir (local-first); no remote execution by default.
- [ ] **Lifecycle + trust** — sessions are opt-in (CO-523 default-OFF gating), bounded
  (idle timeout / explicit stop), and run inside the CO-523 sandbox/trust boundary;
  never hold a `Mutex<Storage>` across a kernel `await`.

## Notes
- Depends on CO-503 (canonical contract) + CO-523 (external-tool adapter, manifest
  discovery, trust boundary). This is the **session-kind extension** of that engine —
  the richest external tool, hence its own task.
- Local-first by construction: the REPL operates on the operator's universe/scripts on
  their box, aligning with the self-host invariant (`infra/SELF-HOST-SECURITY.md`).
- Term is **tool/ferramenta** and **agent/agente** — never "bot".
