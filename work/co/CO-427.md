## As
Operador da frota co-auto, QUERO que cada task rode no modelo certo —
opus/fable para o que é difícil, sonnet/haiku para o resto — escolhido
automaticamente por prioridade e pela janela de uso corrente, PARA maximizar o
que a assinatura entrega por janela em vez de queimar opus em chore.

## Contexto técnico
Hoje o modelo é um flag global do run (`co-auto --model`, default sonnet) em
`dev/co-auto/src/main.rs` / `auto.rs`. O frontmatter das tasks
(`work/<space>/CO-N.md`) já carrega `priority`; falta um campo `model` e uma
política de resolução.

## Resolução do modelo (ordem de precedência)
1. `--model` explícito na CLI (override do operador — comportamento atual).
2. `model:` no frontmatter da task (ex.: `model: opus`).
3. Política por prioridade (config do co-auto, com defaults):
   `high → opus`, `medium → sonnet`, `low → haiku`.
4. **Downshift por janela**: antes de lançar, consultar
   `GET /api/v1/usage/summary?window=5h` (CO-426); se o consumo passou do
   soft-limit configurado, degradar um nível (opus→sonnet→haiku) e logar
   claramente o motivo. Sem rede / endpoint indisponível → seguir sem
   downshift (fail-open).

## Acceptance Criteria
- [ ] Parser de task aceita `model:` opcional no frontmatter; valor inválido →
      warning + ignora (cai na política).
- [ ] Política priority→model configurável no config do co-auto
      (`routing: { high: opus, medium: sonnet, low: haiku }`), defaults acima.
- [ ] Downshift implementado com soft-limit configurável
      (`usage_soft_limit_5h_tokens`); decisão e motivo impressos no log do
      launcher e incluídos no report de usage (CO-425) —
      `model_requested` vs `model_used`.
- [ ] `--model` da CLI continua vencendo tudo (sem regressão).
- [ ] `--cycle` resolve o modelo POR TASK (não mais um modelo para o run
      inteiro).
- [ ] Testes: precedência (4 níveis), frontmatter inválido, fail-open sem
      rede, resolução por task no cycle.
- [ ] Docs: seção "Model routing" no README do co-auto + exemplo de
      frontmatter em work/co/CLAUDE.md.

## Notas
- Nomes de modelo são aliases do CLI (`haiku`/`sonnet`/`opus`/...) — passar
  adiante sem validar contra lista hardcoded de IDs (a lista muda; o `claude`
  CLI é a autoridade).
- Não rebalancear tasks já em execução; routing é decidido no launch.
