GIVEN `~/projects/mbya` is a Rust workspace built around a Mbya Guarani lexicon (`mbya_lexicon.db`) extracted from two scanned PDFs (`GNDicInt.pdf`, `GNDicLex (1).pdf`) via `extract_pdf.py`, AND we want a 4th content universe with substantial volume (hundreds to thousands of entries) to load-test scaling work in CO-77 / CO-79 / CO-80, AND the existing universes are too small to surface contention or query plan issues at meaningful concurrency,
WHEN we add a `mbya` universe seeded from the lexicon (one markdown entry per Mbya Guarani lexeme: term, gloss, etymology, examples, references) AND wire it into `seed-prod-universes.sh` and `scripts/backup-to-disk.sh` (CO-108) as a 4th source,
THEN we have a read-heavy, dense content universe that doubles as: (a) load-test substrate; (b) a permanent record of an indigenous Brazilian language project; (c) demo material showing Co's range beyond yuri's working notes.

## Why Mbya specifically

- **Volume:** lexicon entries number in the **thousands** (typical bilingual dictionary: 5k-20k headwords). Generates real content density without synthetic noise.
- **Structural variety:** each entry has fields (lema, classe gramatical, glosa em português, exemplos, etimologia, referências) — exercises the frontmatter-preview path (CO-94 Phase 1) and future schema validator (CO-71).
- **Mission alignment:** Co's broader project is to host community knowledge that doesn't fit into commercial platforms. The Mbya Guarani lexicon is exactly that.
- **Stress-test primitive that survives demos:** unlike synthetic load data, real content can be shown to users.

## Generation pipeline

`~/projects/mbya/extract_pdf.py` already produces `mbya_lexicon.db`. Add a second-stage script that emits one markdown file per lexeme:

```
~/projects/mbya/scripts/lexicon-to-markdown.py
```

Output:

```
~/projects/mbya/content/lexicon/<initial_letter>/<slug>.md
```

Each file:

```yaml
---
type: lexeme
slug: ndee
lema: ndee
classe: pronome
glosa_pt: você (singular)
ipa: nde.e
familia: tupi-guarani
fonte: GNDicLex p.142
created: 2026-04-30T00:00:00Z
modified: 2026-04-30T00:00:00Z
---

# ndee

**ndee** /nde.e/ — *pronome*

> você (singular)

## Exemplos

- *Mba'epa ndee?* — Como vai você?
- *Ndee reip[eko'ãrõnaite]* — Você vai bem?

## Etimologia

Reflexo do proto-tupi-guarani **\*ne**.

## Referências

- GNDicLex p.142
- GNDicInt p.78
EOF
```

Volume estimate: 5,000-15,000 markdown files. Average ~500 bytes uncompressed. Total raw: 2.5-7.5 MB.

## Seeding workflow

1. **Extract** — run `extract_pdf.py` (already exists) → `mbya_lexicon.db`
2. **Transform** — new `scripts/lexicon-to-markdown.py` (CO-109 deliverable) → `content/lexicon/*/*.md`
3. **Upload** — extend `scripts/seed-prod-universes.sh`:
   ```bash
   create_with_cookie mbya "Mbya Guarani" "Léxico Mbya Guarani — entradas..."
   upload_universe_delta mbya /Users/artelonga/projects/mbya/content "$AUTH"
   ```
4. **Verify** — entry count via `/api/v1/universes/mbya/entries?type=lexeme`
5. **Archive** — automatically picked up by CO-108's backup script

## Cultural / academic notes

- **Sourcing:** the original PDFs (GNDicLex, GNDicInt) are scanned reference works. Confirm copyright / fair-use status before publishing the universe as `public`. May need to start as `private` and only publish after permission.
- **Orthography:** Mbya Guarani has no single standardized orthography; the lexicon uses one academic convention (likely Dooley's). Document the orthography choice in the universe's `index.md`.
- **Future:** community curators (Mbya speakers) should eventually have edit access. Co's per-universe member system (CO-49) supports this.
