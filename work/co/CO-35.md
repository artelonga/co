GIVEN the Obsidian plugin (CO-34) needs a backend API to sync universe ↔ vault, and Obsidian Clipper (https://github.com/obsidianmd/obsidian-clipper) clips web content as markdown with frontmatter,
WHEN I add vault-compatible REST endpoints to co-web and Clipper paste support,
THEN:

## Vault REST API (Obsidian Local REST API compatible)

Endpoints modeled on `coddingtonbear/obsidian-local-rest-api` so existing tools/agents work:

### File CRUD
- [ ] `GET /api/v1/universes/:slug/vault/` — list all files (returns `[{ path, stat: { ctime, mtime, size } }]`)
- [ ] `GET /api/v1/universes/:slug/vault/{path}` — read file content + metadata (returns `{ path, content, frontmatter, tags, stat }`)
- [ ] `PUT /api/v1/universes/:slug/vault/{path}` — create or overwrite file (body = markdown text, creates parent dirs)
- [ ] `POST /api/v1/universes/:slug/vault/{path}` — append to file
- [ ] `PATCH /api/v1/universes/:slug/vault/{path}` — targeted edit via headers:
  - `Target-Type: heading` + `Target: ## Section Name` → replace section content
  - `Target-Type: frontmatter` + `Target: tags` → update frontmatter field
  - `Target-Type: block` + `Target: ^block-id` → replace block
  - `Operation: append | prepend | replace`
- [ ] `DELETE /api/v1/universes/:slug/vault/{path}` — delete file (soft: move to trash, hard: permanent)

### Search & Metadata
- [ ] `POST /api/v1/universes/:slug/vault/search` — fuzzy text search across all files (body: `{ query }`, returns `[{ path, score, matches: [{ context, start, end }] }]`)
- [ ] `GET /api/v1/universes/:slug/vault/tags` — list all tags with counts (derived from frontmatter `labels`/`tags` + inline `#tags`)
- [ ] `GET /api/v1/universes/:slug/vault/tree` — file tree (folders + files, nested JSON)

### Vault ↔ SQLite Bridge

How vault files map to CO's existing SQLite data:

- [ ] `projects/<key>/_project.md` ↔ `projects` table row (frontmatter: name, description, created_at)
- [ ] `projects/<key>/<id>.md` ↔ `tasks` table row (frontmatter: title, status, priority, labels, parent, assignee, due_date; body: description)
- [ ] `projects/<key>/comments/<task_id>-<comment_id>.md` ↔ `comments` table row
- [ ] `content/<path>.md` ↔ future content entries (jardim, relatos, etc.)
- [ ] On write: parse markdown + frontmatter → upsert into SQLite → update `content_count`
- [ ] On read: query SQLite → generate markdown with frontmatter → return
- [ ] File stat: `ctime` = `created_at`, `mtime` = `updated_at`, `size` = body length

### Auth for Vault API

- [ ] Bearer token auth (same JWT as board API)
- [ ] API token generation: `POST /api/auth/token` — returns long-lived token (90 days) for plugin use
- [ ] Token management: `GET /api/auth/tokens` (list), `DELETE /api/auth/tokens/:id` (revoke)
- [ ] Rate limit: 60 requests/minute per token

## Obsidian Clipper Integration

Obsidian Clipper (browser extension) clips web pages as markdown with frontmatter. CO should accept this format.

### Clipper Format Support
- [ ] Clipper outputs markdown with frontmatter like:
  ```yaml
  ---
  title: "Article Title"
  source: "https://example.com/article"
  author: "Author Name"
  published: "2026-04-06"
  created: "2026-04-06T13:00:00Z"
  tags: [web-clip, topic]
  ---
  
  # Article Title
  
  Clipped content here...
  ```
- [ ] `POST /api/v1/universes/:slug/vault/clip` — dedicated endpoint for Clipper:
  - Accepts raw markdown (same format Clipper produces)
  - Auto-generates slug from title
  - Stores in `content/clips/` directory within vault
  - Maps Clipper `tags` to CO `labels`
  - Preserves `source` URL in frontmatter
  - Returns `{ path, slug, url }` of created entry

### Clipper Browser Extension Config
- [ ] CO exposes Clipper-compatible endpoint that can be configured in Obsidian Clipper settings
- [ ] Or: document how to configure Clipper's "Custom" destination to point to CO's vault API
- [ ] Clipper template for CO: provide a `.json` template users can import into Clipper that formats clips for CO's frontmatter schema

### Copy/Paste in Board UI
- [ ] Paste handler in board UI: detect Clipper-formatted markdown in clipboard
- [ ] On paste: parse frontmatter, create task or content entry from clipped content
- [ ] "Paste as task" vs "Paste as content" choice when ambiguous
- [ ] Copy from board: "Copy as Obsidian markdown" option on tasks — generates `.md` with full frontmatter + wikilinks
- [ ] Keyboard shortcut: Ctrl/Cmd+Shift+V = "Paste as CO content" (parse Clipper format)
