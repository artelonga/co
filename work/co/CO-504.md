GIVEN CO's `agents/*.md` are **inert** today (metadata, not executable) while the
whatsapp bridge's `lifecycle_brain.py` is the de-facto agent runtime — it has the
tool-calling loop, the model backends (local Ollama + Claude), and per-user
identity — everything CO's native agents lack,
WHEN we make `agents/` **executable** by defining an agent as `persona + model
backend + capability set (tools) + per-user identity` running the tool-calling loop,
THEN CO has a native agent runtime that any client (CLI, co-web, WhatsApp) can drive,
and the loop logic lives in CO instead of only in the bridge.

## Acceptance

- [ ] An **agent definition** binds: a persona (system prompt / behavior), a model
  backend (`ollama` | `claude`), a capability set (the tools from CO-503), and a
  per-user identity context.
- [ ] **Tool-calling loop promoted into CO** from `lifecycle_brain.py` (prompt →
  model → tool calls → results → continue until done), backend-agnostic over the
  canonical tool contract (CO-503).
- [ ] **Local-model default** (privacy): an agent runs on local Ollama unless the
  user/universe explicitly opts into a hosted backend. No identifying/sensitive data
  leaves the instance by default (aligns with CO-497 data-residency invariant).
- [ ] **Per-user identity** flows through the loop (who is asking, what they may see/do),
  reusing CO's existing auth/identity rather than the bridge's ad-hoc store.
- [ ] `agents/*.md` definitions are **loaded and executed** (no longer inert) — at least
  one existing agent runs end-to-end through the native runtime.
- [ ] **Generalist**: the runtime carries no tenant names and no WhatsApp-specific
  assumptions; WhatsApp is one client (CO-507), not baked into the runtime.
- [ ] **Model-agnostic via one `Backend` trait**: the runtime drives any model
  (Ollama-local default / Claude / any) through a single `Backend` trait — swapping the
  model is a flag, not a refactor. The `Vectorizer` (CO-517) is the sibling
  representation-agnostic trait (input → `Vec<f32>`), the same principle for vectors.

## Notes
- Depends on CO-503 (canonical tool contract) for the capability set; pairs with
  CO-505 (capability packs) for grouping/config and CO-506 (workflows) for composition.
- "agents not bot": this is the runtime that earns CO the word **agent/agente**. The
  bridge becomes a thin client over it (CO-507), not the brain.
- Local-first model choice keeps the self-host/managed invariant intact (CO-497).
