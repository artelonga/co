## Context

### The data model mismatch

Today's SPA has two parallel data models:

1. **Legacy projects → tasks** (`/api/projects/{key}/tasks?u={slug}`)
   - Hardcoded at universe-creation time
   - Examples: "AL" / "Arte Longa", "QA" / "Quilombo Araucária", "CO" / "Tutorial"
   - This is what the kanban renders today

2. **Entries** (`/api/v1/universes/{slug}/entries`)
   - Populated by CO-261's seed walker
   - Has the actual `work/<repo>/<TASK>.md` content
   - Accessible at `/<universe>/work/<repo>/<TASK>.md` but invisible in kanban

The two never merged. The kanban view code path doesn't know about entries.

### Plus: CO-270 items=0 still

Even if the kanban could see entries, the list endpoint returns items=0 for anonymous. So you couldn't enumerate them anyway.

CO-272 closes BOTH gaps.

## Scope

### Backend — entry-to-task adapter

Add a view in the universe DB that exposes entries as task-shaped rows:

```sql
CREATE VIEW v_entry_as_task AS
SELECT
    -- Synthesize a task key from the path: 'work/co/CO-261.md' → 'CO-261'
    REPLACE(REPLACE(SUBSTR(path, INSTR(path, '/') + 1), '.md', ''), '_', '-') AS key,
    title,
    COALESCE(json_extract(frontmatter_json, '$.type'), 'task') AS task_type,
    COALESCE(json_extract(frontmatter_json, '$.status'), 'todo') AS status,
    COALESCE(json_extract(frontmatter_json, '$.priority'), 'medium') AS priority,
    body AS description,
    created_at,
    updated_at,
    path
FROM entries
WHERE entry_type IN ('user-story', 'task', 'epic')
  AND path LIKE 'work/%';
```

Or do the mapping in Rust (no view needed) in a new endpoint:

```
GET /api/v1/universes/{slug}/dev-tasks?status=todo&limit=50
→ { tasks: [{ key: "CO-261", title, status, priority, description, ... }] }
```

### Frontend — kanban view consumes dev-tasks

In `co-web/static/variants/a/modules/views/kanban.js`:

- When the universe has `is_public AND visibility = 'public-subscribable'` AND the legacy `/projects` returns the canonical project name matching the universe key (e.g., universe `co` → project `CO`): also fetch `/api/v1/universes/{slug}/dev-tasks` and merge into the kanban.
- Render columns by `status:` field (todo / in_progress / done / blocked).
- Task card shows: ticket key, title, priority chip, type chip (feat/fix/refactor), date.
- Click a card → opens the entry's body in a side panel (markdown render).
