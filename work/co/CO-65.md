> **Done.** Owners can flip visibility via `PUT /api/v1/universes/:slug` with a `visibility` field. Shipped in 1.18.x.

GIVEN `PUT /api/v1/universes/:slug` only accepts `name` and `description`, with no API path to change visibility (private ↔ public-subscribable ↔ requires_login),
WHEN we extend the handler to accept `visibility` with validation and atomic update of legacy columns (`is_public`, `requires_login`),
THEN owners can flip visibility from the UI and from scripts, removing the need for one-off SQL.

Code already written at `co-web/src/universe_routes.rs:259-289`. Validates against `private | public-subscribable | requires_login`; `template` is system-only and rejected. Updates `is_public` and `requires_login` columns coherently. Build clean, clippy clean, all 132 unit tests pass.
