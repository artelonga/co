GIVEN current entries have only `created_at` / `updated_at`, tasks have a one-off `due_at`, and the manifest epic supports content types like `evento` (events) where dates carry semantic meaning,
WHEN we promote dates to first-class typed fields with declared semantics in the manifest,
THEN calendar views, Gantt views, "events this week", "items expiring soon" become free queries.

## Architecture

- Manifest declares `date_field: { type: date, semantic: <semantic> }` per content type
- Storage: dates live in `payload` JSON (CO-71), but server maintains `entry_dates(universe_key, entry_path, semantic, value)` for indexed temporal queries
- API: `GET /api/v1/universes/:slug/entries?date_semantic=event_at&from=…&to=…`
- Calendar/Gantt views in board UI pull from this endpoint

## Date semantics (v1)

| Semantic       | Meaning                              |
|----------------|--------------------------------------|
| `created_at`   | Auto, immutable                      |
| `updated_at`   | Auto, mutable                        |
| `event_at`     | When something happens               |
| `due_at`       | Deadline for action                  |
| `scheduled_at` | Planned start                        |
| `published_at` | Public-facing publish date           |
| `expires_at`   | When content becomes invalid         |
| `effective_at` | When this version takes effect       |

## Tasks

- [ ] Migration: create `entry_dates` table, indexed by `(universe_key, semantic, value)`
- [ ] Write hook: on entry PUT, extract declared date fields and upsert to `entry_dates`
- [ ] Query API: `GET /api/v1/universes/:slug/entries?date_semantic=…&from=…&to=…`
- [ ] Calendar view: SvelteKit component reading from query API
- [ ] Gantt view: declared in manifest (`views: [{ type: gantt, date_start, date_end }]`)
- [ ] Time zone: store UTC, render per-user TZ from cookie/profile

## Scale notes

- `entry_dates` at 1M entries × ~3 dates avg = 3M rows per universe — fits SQLite easily
- Per-universe DB (CO-77) scopes temporal queries to one DB file
- Index on `(semantic, value)` enables range queries with logarithmic complexity
- Cross-universe temporal queries ("all my events this week across all my universes") need the metadata DB (CO-77) as aggregator

## Acceptance

- Calendar view shows events on correct dates, in user's timezone
- "Events this week" returns correct results in < 50ms for a universe with 100K entries
- Gantt view declared in manifest renders without code changes
