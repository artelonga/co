## As
Yuri running events with noindex slide-decks that shouldn't reveal their existence

## I Need
Analytics rollups + funnel reports to strip path-level data for pages that declare `noindex,nofollow` or live under universe roots with `private: true`, so an admin viewing `/gestao/resumo` can't see individual private URLs.

## So That
- Private event pages (`/2026-05-29/`, `/2026-06-15-some-event/`) don't leak their existence via admin analytics.
- Aggregate counts (total visits, unique IPs, country breakdown) remain — only path strings get redacted.
- BaaS sovereignty principle holds: the brain owner controls what's visible, not just to search engines but to platform operators.

## Context

User observation 2026-06-05: `/2026-05-29/` slide-deck for "1º Encontro · Neuro Notebook Brasil" is `noindex,nofollow` but `/assets/analytics.js` telemetry fires page_view events that land in `analytics_rollups` keyed `universe_key='artelonga'`. Admin querying via CO-360 dashboard can see:
- That the URL exists
- Traffic count on that URL
- 4 `js_promise_rejection` events from Des Moines (forensic detail)

The page meta intent (`noindex,nofollow`) is violated by the platform's own admin surface. Either:
1. We honor `noindex` — strip path detail when present
2. We make analytics respect a per-entry `private: true` frontmatter flag
3. Both — defense in depth

## Design

### Detection rules

A path is **private for analytics** if ANY of:
- Source HTML returns `<meta name="robots" content="noindex">` (or `nofollow`, `none`)
- Source entry frontmatter has `private: true`
- Path matches `/(_drafts|_proposals|_smoke|_t|_proof|probe)/`
- Universe has `analytics_private: true` in its `_universe.yaml`

Detection happens at telemetry-ingest time, not query time, so analytics rows never store full path for private pages.

### Schema change

Migration v62 adds `path_private` column to `analytics_rollups`:

```sql
ALTER TABLE analytics_rollups ADD COLUMN path_private INTEGER DEFAULT 0;
```

When `path_private = 1`:
- `path` column stores a redacted form: `<private-path-{hash16}>` (deterministic hash for joining without revealing)
- Aggregate counts (visits, unique_ips, dwell_ms) stored normally
- Country/device breakdown stored normally

### Query API change

`GET /api/v1/analytics/public/summary` (existing):
- Default: returns ONLY non-private paths in `top_pages`
- Private paths show as `(private)` with their count
- Admin can pass `?include_private=true` to see redacted hashes (still can't reconstruct URL)

`GET /api/v1/analytics/public/funnel` (CO-371):
- Per-path drop-off respects same rule
- Private paths contribute to `total` but not to `by_path`

### Migration backfill

For existing rollup rows where the path matches our detection rules, mark `path_private=1` and overwrite `path` with redacted form. One-shot in migration v62.

### Surface in `/gestao/resumo` (CO-360)

The top-pages table shows:
- Public paths normally
- Private paths as `🔒 (private — N entries)` clustered into one row
- Operator can drill in only with `?include_private=true` + a confirmation modal warning "you are about to view redacted private path data"

### Robots-meta detection

Server-side: when an entry is served via SPA shell, check rendered HTML for `<meta name="robots">`. If `noindex` or `nofollow` present → mark the URL pattern as private in a small in-memory cache (`private_paths_cache`). Telemetry-ingest consults the cache.

For static pages outside CO (like `/2026-05-29/` served by ArteLonga repo), the rollup producer (the surface's `analytics.js`) needs to send a `private: true` field — extend the ingest contract.

### Backward compatibility

CO-340 producers (yuri, neuro, etc.) that don't send `private` field: server defaults to detecting from path patterns + universe config. No producer breakage.
