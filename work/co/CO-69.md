GIVEN browser users on flaky networks need to edit while disconnected, and the existing service worker only caches static assets,
WHEN we add IndexedDB-backed entry cache and Background Sync API for offline writes,
THEN the web client matches the offline ergonomics of desktop tray + Obsidian plugin.

## Tasks

- [ ] IndexedDB schema: entries cache mirrored from server, keyed by `(universe_key, path)`
- [ ] Read-through: GET /vault/* checks IndexedDB first, server second; populate cache on success
- [ ] Write-through: PUT/POST writes to IndexedDB immediately, queues for server push
- [ ] Background Sync registration on offline write
- [ ] Conflict banner: "You have N offline changes — review and sync"
- [ ] Install prompt: "Add Co to Home Screen"
- [ ] Service worker version bump triggers cache refresh

## Scale notes

- IndexedDB per-origin quota is browser-dependent (typically 50% of free disk); document this for users
- Background Sync uses retry with exponential backoff — don't overwhelm server on mass-reconnect
- Cache eviction strategy: LRU per universe; reset cache on universe-key change
- On the server side, mass-reconnect means a thundering herd of pending writes — CO-78 job queue absorbs the spike
