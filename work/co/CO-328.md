## As
Yuri wanting AI assistance on his content without sending it to external APIs

## I Need
A local LLM running on macOS for everyday queries + a Claude Code hook for when I want the heavier model

## So That
I can ask questions about my notes/references and get answers, with full visibility into what's running where

## Scope

### Two AI providers
1. **Local LLM** (Ollama or llama.cpp + a Qwen/Llama model)
   - Loaded on first use, kept warm
   - Used for: short queries, semantic search on notes, summaries
   - No data leaves the machine
2. **Claude Code hook** (subprocess invocation of `claude` CLI)
   - User asks a deeper question → spawn `claude` headless session
   - Stream output back to UI
   - User sees: "🤖 Claude is thinking..." indicator + live token stream

### Provider trait
- New trait `AiProvider` in `co-web/src/infra/ai.rs` (follows CO-296 AuthProvider pattern)
- Impls: `OllamaProvider`, `ClaudeCodeProvider`, `MockProvider` (for tests)
- Routing: `AiRouter` picks the right provider based on query complexity or explicit hint

### Local LLM via Ollama (recommended)
- Detect `ollama` binary at boot (or document install)
- Default model: `qwen2.5-coder:7b` or `llama3.2:3b` (small enough for laptops)
- HTTP API: `POST http://localhost:11434/api/generate`

### Claude Code hook
- Detect `claude` CLI at boot
- Spawn subprocess: `claude --print "<prompt>"` or use `--output-format=stream-json`
- Stream stdout back via WebSocket to UI
- Show in CO-329 background process panel

### Status surface
- New endpoint `GET /api/v1/ai/status` returns:
  ```json
  {
    "ollama": {"available": true, "model": "qwen2.5-coder:7b", "warm": true},
    "claude": {"available": true, "version": "1.x"},
    "active_sessions": [{"id": "...", "provider": "claude", "started_at": "..."}]
  }
  ```
- UI surfaces this in the header (small AI status dot)

## Acceptance
- [ ] `POST /api/v1/ai/query` with `{provider: "ollama", prompt: "..."}` returns response
- [ ] `POST /api/v1/ai/query` with `{provider: "claude", prompt: "..."}` spawns claude + streams back
- [ ] AI status endpoint reflects reality
- [ ] If neither is installed, query returns 503 with helpful install hint
- [ ] CO-327 desktop notification fires when claude session needs input or finishes

## Blast radius
- 1 new infra trait module
- ~300 lines (Ollama HTTP client + Claude subprocess manager + status surface)
- 1 SPA AI status indicator + chat panel
- Optional: ollama as a runtime dep (document install, don't bundle)

## Why now
Yuri wants AI on his own data without external dependencies as the default. Claude Code stays available as the heavier escalation path.
