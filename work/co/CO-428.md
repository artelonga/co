## As
Sessão co-auto (e qualquer agente interagindo com o CO), QUERO um overview
breve e **recursivo** de cada universo — gerado, não escrito à mão — e camadas
de contexto mínimas e estáveis, PARA entender a arquitetura do CO e dos
universos gastando o mínimo de tokens e aproveitando prompt caching.

## Escopo

### 1. `co universe digest` (novo comando)
- [ ] `co universe digest [<key>] [--depth N] [--format md|json]`: emite, por
      universo, um bloco curto (alvo ≤200 tokens): key, nome, propósito (1–2
      frases da descrição/index), parent, filhos (recursão via `parent_key`),
      contagens (entradas, tasks por status), modelos (templates) disponíveis,
      último update. Sem `<key>`: floresta completa a partir das raízes.
- [ ] Fonte = DB/API (registry de universos), nunca mapeamento hardcoded.
- [ ] Determinístico e estável: mesma entrada → mesmo texto byte-a-byte
      (ordenação fixa), para o bloco ser cache-friendly como prefixo.

### 2. Camadas de contexto do co-auto (auto.rs `build_context`)
- [ ] Auditar as camadas atuais do `.claude/co-auto-context.md`: medir tokens
      por camada (estimativa chars/4 serve) e logar no launch.
- [ ] Reordenar: conteúdo estável primeiro (arquitetura, digest, convenções),
      task-specific por último — maximiza prefixo cacheável entre tasks do
      mesmo universo.
- [ ] Substituir prosa repetida por **ponteiros**: em vez de embutir documentos
      inteiros, listar caminhos ("leia work/co/CLAUDE.md se precisar de X") —
      o agente lê on-demand.
- [ ] Incluir o digest do universo alvo (+ pais e filhos diretos, depth 1) no
      lugar de qualquer overview manual.

### 3. Skills
- [ ] Criar `.claude/skills/` no repo co com 2–3 skills curtas para operações
      recorrentes de sessões co-auto (ex.: "rotas+migrations no co-web",
      "publicar entrada via vault API") extraídas do que hoje é prosa no
      contexto/CLAUDE.md — e ENCURTAR os CLAUDE.md correspondentes na mesma
      medida (sem duplicação: o conteúdo mora num lugar só).

## Acceptance Criteria (gerais)
- [ ] Antes/depois medido em uma task real: input tokens não-cacheados por
      sessão caem ≥40% (meta do epic CO-424) — registrar números no PR.
- [ ] `co universe digest` com testes (fixture de árvore de universos com 3
      níveis; estabilidade byte-a-byte).
- [ ] i18n: digest respeita o padrão do projeto (domínio pt, técnico en).

## Notas
- Não inventar resumos por LLM neste passo — digest é extração determinística
  de metadados. Sumarização por modelo é candidata a task futura (tem custo).
