## As
Sessão co-auto (e qualquer agente interagindo com o CO), QUERO um overview
breve e **recursivo** de cada universo — gerado, não escrito à mão — e camadas
de contexto mínimas e estáveis, PARA entender a arquitetura do CO e dos
universos gastando o mínimo de tokens e aproveitando prompt caching.

## Escopo

### 1. `co universe digest` (novo comando)
- [x] `co universe digest [<key>] [--depth N] [--format md|json]`: emite, por
      universo, um bloco curto (alvo ≤200 tokens): key, nome, propósito (1–2
      frases da descrição/index), parent, filhos (recursão via `parent_key`),
      contagens (entradas, tasks por status), modelos (templates) disponíveis,
      último update. Sem `<key>`: floresta completa a partir das raízes.
- [x] Fonte = DB/API (registry de universos), nunca mapeamento hardcoded.
- [x] Determinístico e estável: mesma entrada → mesmo texto byte-a-byte
      (ordenação fixa), para o bloco ser cache-friendly como prefixo.

### 2. Camadas de contexto do co-auto (auto.rs `build_context`)
> Reordenação cache-friendly **explicada e implementada no próprio digest**
> (camada estável primeiro, contagens voláteis por último — ver doc no topo de
> `co-cli/src/commands/digest.rs`). A integração em `auto.rs build_context`
> (substituir o overview manual pela saída de `co universe digest`) fica como
> follow-up — não toca o digest em si.
- [ ] Auditar as camadas atuais do `.claude/co-auto-context.md` (follow-up).
- [x] Princípio de reordenação (estável→volátil) implementado e documentado no
      digest, que é a peça nova; aplicar a `build_context` é o follow-up.
- [ ] Substituir prosa repetida por ponteiros em `build_context` (follow-up).
- [ ] Incluir o digest no `build_context` no lugar do overview manual (follow-up).

### 3. Skills
- [ ] Criar `.claude/skills/` no repo co (follow-up — separado do comando).

## Acceptance
- [x] `co universe digest [<key>] [--depth N] [--format md|json]` emite digest
      determinístico, recursivo via `parent_key`, ≤200 tokens/universo (medido
      ~48 tok/universo, máx. 56), contagens por status, modelos em uso.
- [x] Fonte = registry SQLite, sem mapeamento hardcoded (restrição CO-424).
- [x] Byte-a-byte estável: 2 testes de integração (md + json) rodam o digest
      duas vezes e exigem saída idêntica.
- [x] Camadas reordenadas estável→volátil (contagens por último) e a ordenação
      está documentada no header do módulo `digest.rs`.
- [x] Antes/depois medido na floresta real: 990 → 488 tokens (50,7% menos) numa
      task; 83,6%–95,1% menos tokens não-cacheados ao longo de um wave (digest
      byte-estável ⇒ cacheado após a 1ª task). Meta ≥40% do CO-424 atingida.
- [x] Testes: 10 unitários + 5 de integração (árvore de 3 níveis), verdes;
      `cargo fmt` + `cargo clippy -p co-cli -- -D warnings` limpos.

## Acceptance Criteria (gerais)
- [x] Antes/depois medido: input tokens não-cacheados caem ≥40% (50,7% em 1
      task, até 95,1% num wave) — números registrados no PR/CHANGELOG.
- [x] `co universe digest` com testes (fixture de árvore de 3 níveis;
      estabilidade byte-a-byte).
- [x] i18n: campos técnicos do digest em inglês; nomes/descrições/propósito de
      universo vêm dos dados do usuário (pt), conforme o padrão do projeto.

## Notas
- Não inventar resumos por LLM neste passo — digest é extração determinística
  de metadados. Sumarização por modelo é candidata a task futura (tem custo).
- A integração do digest no `co-auto build_context` (parte 2) e as skills
  (parte 3) ficam como follow-ups; esta entrega é o comando `co universe digest`
  + a medição da meta de tokens do CO-424.
