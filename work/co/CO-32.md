GIVEN CO deploys to Fly.io manually via `flyctl deploy`,
WHEN I create Ansible playbooks for reproducible deployment,
THEN:

- [ ] New directory `co-deploy/` at workspace root with standard Ansible structure
- [ ] `inventory/fly.yml` — Fly.io target (uses flyctl under the hood)
- [ ] `inventory/vps.yml` — generic VPS target (DigitalOcean, Hetzner, etc.)
- [ ] `playbooks/provision.yml`:
  - Create `co` user (unprivileged)
  - Install deps: ca-certificates, sqlite3 CLI (for backup)
  - Create dirs: `/opt/co/`, `/var/lib/co/data/`
  - Setup firewall: allow 80, 443, deny rest
- [ ] `playbooks/deploy.yml`:
  - Build co-web release binary (cross-compile via `cross` or build on host)
  - Copy binary to `/opt/co/co-web`
  - Copy static assets (or use rust-embed)
  - Run seed SQL if first deploy
  - Restart systemd service
  - Verify health: `curl /api/health`
- [ ] `playbooks/backup.yml`:
  - SQLite `.backup` command (online, consistent)
  - Compress with zstd
  - Rotate: 7 daily + 4 weekly (configurable)
  - Optional: upload to S3/B2 via rclone
  - Cron: daily at 03:00 UTC
- [ ] `templates/co-web.service.j2` — systemd unit (ExecStart, WorkingDirectory, Environment)
- [ ] `templates/caddy.conf.j2` — reverse proxy, auto-SSL, compression, security headers
- [ ] `group_vars/all.yml` — shared config (co_version, co_port, domain)
- [ ] `group_vars/production.yml` — secrets via ansible-vault (JWT_SECRET, RESEND_API_KEY)
- [ ] Fly.io specific: `playbooks/fly-deploy.yml` wrapping `flyctl deploy` with pre/post hooks (backup before deploy, health check after)
- [ ] README: quickstart for VPS (`ansible-playbook -i inventory/vps.yml playbooks/deploy.yml`)
- [ ] Test: provision + deploy on local Docker container (molecule or vagrant)
- [ ] Idempotent: running any playbook twice produces same result
