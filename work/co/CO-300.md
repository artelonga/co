## What this slice does

Introduces a `co::testkit::TestServer` API that spawns a real `co serve` instance in a tempdir for integration tests. Replaces brittle in-process `build_test_router` patterns with full-server tests that exercise the actual binary. Catches bugs that in-process tests miss (auth middleware ordering, real HTTP semantics, serialization edge cases).

## Scope

1. New crate `co-testkit/` or module `co-web/src/testkit/` exposing:
   ```rust
   pub struct TestServer {
       pub base_url: String,
       data_dir: tempfile::TempDir,
       process: tokio::process::Child,
   }
   
   impl TestServer {
       pub async fn start() -> Result<Self>;
       pub async fn start_with(config: TestServerConfig) -> Result<Self>;
       pub fn client(&self) -> reqwest::Client; // pre-configured base URL
       pub async fn shutdown(self) -> Result<()>;
   }
   ```
2. `TestServerConfig` lets tests inject `Arc<dyn SecretsProvider>`, custom port, `--staging` mode, OTLP endpoint
3. Picks an ephemeral port (`SocketAddr::from(([127,0,0,1], 0))`), parses the actual bound port from server output
4. Graceful shutdown on Drop (sends SIGTERM, waits for clean exit)
5. Port ≥5 existing tests to use TestServer instead of `build_test_router`:
   - `co-web/tests/template_tests.rs` (full HTTP flow)
   - `co-web/tests/sync_pipeline_tests.rs` (real WebSocket)
   - One auth-flow test
   - One vault-write-and-read test
   - One agent_sessions POST/GET test

## Acceptance

- [ ] `co-testkit::TestServer::start()` spawns a real `co serve` in <2s
- [ ] Tests using it pass and exercise the full code path (no mocked middleware)
- [ ] At least 5 existing tests are migrated to TestServer
- [ ] Drop / shutdown cleans up the data dir and the process; no orphan `co` processes after tests run

## Not in this phase

- Parallel-test concurrency (each TestServer is its own port — already parallel-safe)
- Cluster-mode TestServer (spawning multiple coordinated nodes — Phase 4 territory)
