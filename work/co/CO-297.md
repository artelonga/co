## What this slice does

Wraps the existing `governor`-based per-route rate-limiting behind a `RateLimiter` trait. Future Redis-backed sliding-window impl plugs in when multi-machine rate-limit aggregation becomes needed.

## Scope

1. New trait in `co-web/src/infra/ratelimit.rs`:
   ```
   #[async_trait]
   trait RateLimiter: Send + Sync {
       async fn try_acquire(&self, key: &str, quota: Quota) -> Result<(), RateLimited>;
       async fn current_usage(&self, key: &str) -> Option<UsageSnapshot>;
   }
   ```
2. Default impl `InProcessRateLimiter` wrapping the current `governor` crate usage
3. `Quota` carries per-tier limits (CO-278's tier system: anonymous / read / write / agent / admin)
4. Migrate the rate-limit middleware to use the trait

## Acceptance

- [ ] Trait `RateLimiter` exists; `InProcessRateLimiter` implements it
- [ ] All current rate-limit behavior unchanged
- [ ] Tests pass

## Not in this phase

- Redis impl
- Cross-machine aggregation
- Dynamic quota updates from admin UI
