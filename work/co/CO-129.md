## As

a CO user wanting to see how a universe evolved over time across devices and collaborators

## I Need

a changelog view that reads the op-log (CO-61) and renders a jujutsu-style commit DAG — branches, merges, conflict resolutions — with diffs per node and "restore to here" actions

## To

ship the second user-named v1 requirement the SR plan omitted (§C.3) and to operationalize the jujutsu mental model the user has explicitly named as the design north star

## Given / When / Then

GIVEN CO-61 and CO-95 produce a content-addressed op-log per universe with parent links and merge nodes,
WHEN we wire a renderer that reads the log and visualizes it,
THEN a 3-commit branch + merge appears as a 5-node DAG (3 commits + branch point + merge), each node clickable for diff + restore.

## Why jujutsu, not git

CO's op-log is closer to jj's flat history model than to git's parent-pointer-only model:
- **No staging area** — every op is a commit
- **First-class conflicts as commits** — a conflict resolution is itself a node, not a magic merge
- **Branchless workflow** — branches are just labels on commits, easy to add/remove
- **Operation log** — jj records how the history changed, not just what it is

The renderer should expose these primitives: ops, conflicts-as-commits, branch labels.

## Acceptance

- [ ] DAG renderer component reads `/api/v1/universes/{u}/oplog` and produces an SVG/Canvas timeline
- [ ] Each node shows: op id (short), author, timestamp, change summary
- [ ] Click a node → side panel with full diff + "Restore to here" button
- [ ] Conflicts (CO-128 outputs) appear as distinct node types
- [ ] Branch labels rendered when present
- [ ] Performance: 1000-node DAG renders in <200ms (virtualized)
- [ ] Theme-aware (matches all 12 CO themes)

## Out of scope

- Editing op log from the UI — read-only for v1
- jj CLI integration — separate; the renderer reads CO's op-log, not a `.jj/` directory
- Cross-universe DAG views — Phase 5

## Risks

- **DAG layout perf at scale.** Mitigation: server-paginates by date range; client virtualizes
- **Mental-model mismatch with users who only know git.** Mitigation: tooltip explanations on hover; link to a "How CO history works" doc
