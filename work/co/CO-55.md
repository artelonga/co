GIVEN private universe repos require authentication to clone, and the user wants SSH clearance for GitHub users associated with their Co account,
WHEN I implement GitHub account linking for private repo access,
THEN:

## MVP: Deploy Key

- [ ] Generate an SSH key pair per Co instance (once, at first boot)
- [ ] Store in `/data/.ssh/co_deploy_key`
- [ ] When cloning a private repo: `GIT_SSH_COMMAND="ssh -i /data/.ssh/co_deploy_key" git clone ...`
- [ ] Owner adds the public key as a deploy key on GitHub (manual step, documented in CLAUDE.md)
- [ ] Works for all repos that have the deploy key added

## v2: GitHub OAuth + User SSH Keys

- [ ] `POST /api/v1/auth/github/link` — OAuth flow to link GitHub account
- [ ] Store `github_username` and `github_access_token` in users table
- [ ] When user subscribes to a private universe: verify GitHub access via API (`GET /repos/:owner/:repo` with user's token)
- [ ] Clone using user's token: `git clone https://{token}@github.com/{owner}/{repo}.git`
- [ ] Token refresh via OAuth refresh flow

## v3: Fine-grained GitHub App

- [ ] GitHub App installation on org/user
- [ ] Installation token per repo
- [ ] No user-level tokens needed

## Acceptance Criteria (MVP)

- [ ] Deploy key generated at first boot
- [ ] Public key displayed at `GET /api/v1/admin/ssh-key` (admin only)
- [ ] Private repos clone successfully with deploy key
- [ ] Public repos still clone without key
- [ ] Key persists across deploys (stored on volume)
- [ ] Documented: how to add deploy key to GitHub repo
