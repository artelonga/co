## As
A visitor to yuri.artelonga.com.br who wants to reach out

## I Need
A "send a message" form that delivers to both yuri@artelonga.com.br (email) and the in-app notifications panel (CO-197/198/199)

## So That
Yuri doesn't miss messages whether they're checking inbox or the CO app

## Scope

### Form
- Endpoint: `POST /api/v1/universes/yuri/messages` (and similarly for any universe owner)
- Body: `{ from_email, from_name, subject, body }`
- Rate limit: 5/hour per IP (anti-spam)
- Optional: captcha or honeypot field
- Form rendered at `/contact` (or embedded on yuri's index)

### Email delivery
- Use existing `MailProvider` trait (CO-196)
- LogMailProvider in dev → prints to stdout
- In prod: Postmark / SES / Mailgun (configurable via env)

### In-app notification
- Insert row into `notifications` table for user_id=yuri's id
- Type: `direct_message`
- Body: prepopulated with sender + subject
- Existing notifications UI shows it

### Reply flow (deferred)
- v1: reply via email only (not a CO threaded reply)
- v2 (future spec): in-app reply if sender has a CO account

## Acceptance
- [ ] `POST /messages` accepts form data, returns 200
- [ ] Email arrives at yuri@artelonga.com.br (verify via log or actual delivery)
- [ ] In-app notification appears for yuri on next page load
- [ ] Rate limit kicks in at 6th message in an hour from same IP
- [ ] Form has honeypot field that drops spam silently

## Blast radius
- 1 new route + handler
- ~50 lines SPA form
- Reuses MailProvider + notifications infra
- 1 new row in `notification_types` enum

## Why now
yuri.artelonga.com.br needs a contact surface. Without it visitors have to find yuri's email another way.
